## 1. 问题：机器人怎么从 A 走到 B？

### 1.1 现实世界是连续的，算法需要离散的格子

真实的机器人在地板上移动，位置是连续的小数，比如 `(1.234, -0.567)` 米。
但绝大多数路径规划算法处理的是**离散的格子**：

```text
真实世界（连续）                 栅格地图（离散）
                                列 →
                            ┌───┬───┬───┬───┬───┐
   ┌──────────────┐         │ # │ # │ # │ # │ # │  ↑
   │              │         ├───┼───┼───┼───┼───┤ 行
   │   ● 机器人   │   ──►   │ # │ S │ . │ . │ # │
   │        ● 目标 │         ├───┼───┼───┼───┼───┤
   │              │         │ # │ . │ # │ . │ # │
   └──────────────┘         ├───┼───┼───┼───┼───┤
                            │ # │ . │ . │ G │ # │
                            ├───┼───┼───┼───┼───┤
                            │ # │ # │ # │ # │ # │
                            └───┴───┴───┴───┴───┘
```

- `S` = start，起点
- `G` = goal，终点
- `#` = 障碍
- `.` = 可通行

**为什么要离散化？**
因为连续空间里有无限多个点，计算机没法一个一个试。切成有限个格子后，
问题就变成“在有限个节点里找一条路”，可以用数据结构来搜。

> 代价：格子越粗，规划越快，但可能贴着障碍；格子越细，路径越精细，但计算量越大。
> 这就是 `resolution`（分辨率）的取舍。

### 1.2 分辨率和原点：格子 ↔ 世界坐标

代价地图通常有三个关键参数：

| 参数 | 含义 | 本项目示例 |
|---|---|---|
| `resolution` | 一个格子多少米 | `0.05` m/cell |
| `origin_x`, `origin_y` | 地图左下角在世界坐标里的位置 | 由地图决定 |
| `size_x`, `size_y` | 地图有多少列、多少行 | `384 × 384` |

**世界坐标 → 格子坐标**（`worldToMap`）：

```text
mx = (wx - origin_x) / resolution
my = (wy - origin_y) / resolution
```

**格子坐标 → 世界坐标**（`mapToWorld` / `gridToWorld`）：

```text
wx = origin_x + (mx + 0.5) * resolution
wy = origin_y + (my + 0.5) * resolution
```

注意 `+0.5`：它取的是**格子中心**，不是格子左下角。
如果忘了 `+0.5`，路径会整体偏移半个格子（本项目 0.025 米）。

**举个具体例子**：
地图原点 `(-10.0, -10.0)`，分辨率 `0.05`，机器人世界坐标 `(-3.2, 2.1)`：

```text
mx = (-3.2 - (-10.0)) / 0.05 = 6.8 / 0.05 = 136
my = ( 2.1 - (-10.0)) / 0.05 = 12.1 / 0.05 = 242
```

所以机器人在第 136 列、第 242 行。

**一维索引**：
代码里通常把二维格子压成一维数组，节省内存、访问更快：

```text
index = y * width + x
```

反过来：

```text
x = index % width
y = index / width
```

> 这个转换在 `astar_algorithm.cpp` 里到处都是。看到 `% width_` 和 `/ width_`
> 就是在还原 x、y。

### 1.3 寻路问题的输入输出

**输入**：

- 一张 `width × height` 的代价表（每个格子一个 `uint8_t`，0~255）；
- 起点格子 `(sx, sy)`；
- 终点格子 `(gx, gy)`；
- 一些选项（能不能走对角、能不能走未知区域、启发式权重等）。

**输出**：

- 一条从起点到终点的格子序列：`[(sx,sy), ..., (gx,gy)]`；
- 或者“无路可走”；
- 以及统计信息：扩展了多少节点、路径代价多少、耗时多少。

> 注意：算法输出的是**格子序列**，不是 `nav_msgs::Path`。
> 把格子序列变成 ROS 路径，是“适配层”的工作。这是第 06 篇的主题。

## 2. 把地图变成“图”

### 2.1 节点、边、权重

在算法眼里，每个可通行格子是一个**节点（node）**，相邻格子之间有一条**边（edge）**，
边上有一个**权重（weight / cost）**，表示走这条边要花多少代价。

```text
4 邻域（上下左右）              8 邻域（还可以斜着走）
      ↑                              ↖ ↑ ↗
   ←  ●  →                          ← ● →
      ↓                              ↙ ↓ ↘
```

- **4 邻域**：只能上下左右，直移代价通常为 `1`。
- **8 邻域**：还可以走对角，对角代价通常为 `√2 ≈ 1.414`。

为什么对角是 `√2`？因为对角线长度是边长的 `√2` 倍：

```text
┌───┬───┐
│ ● │   │   直移：长度 1
├───┼───┤
│   │ ● │   对角：长度 √(1²+1²) = √2
└───┴───┘
```

### 2.2 路径代价 = 边上代价之和

一条路径的总代价，就是沿途每条边代价的累加：

```text
S → A → B → G
代价 = cost(S,A) + cost(A,B) + cost(B,G)
```

如果走对角，每段加 `√2`；如果叠加地形代价，每段再加一点。

**“最短路径”到底指什么？**

- 如果每条边代价都是 1（4 邻域），最短 = 步数最少；
- 如果对角代价是 `√2`，最短 = 几何长度最短；
- 如果叠加了地形代价，最短 = “综合代价”最小，可能绕远但避开难走区域。

> 这是初学者最容易混淆的点：**最短不一定是“看起来最近”**。
> 你把 `cost_weight` 调大，A* 就会宁愿绕路也不走障碍旁边的格子。

### 2.3 障碍怎么表示

在纯算法里，通常用一个 `can_traverse(x, y)` 函数判断：

```cpp
bool can_traverse(int x, int y) {
    return inside_map(x, y) && cost(x, y) < 254;   // 254 是致命障碍
}
```

在 Nav2 的 costmap 里，`254` 是真实障碍，`253` 是“内切膨胀”
（已进入碰撞风险区，是否允许走取决于规划器策略），`255` 是未知区域。
第 9 节会详细讲这个坑。

## 3. 最直观的搜索：BFS（广度优先搜索）

### 3.1 思路：像水波一样一圈圈扩散

从起点开始，先看距离 1 的所有格子，再看距离 2 的，再看距离 3 的……

```text
第 0 圈：        S
第 1 圈：      ■ ■ ■
第 2 圈：    ■ ■ ■ ■ ■
第 3 圈：  ■ ■ ■ ■ ■ ■ ■
```

BFS 用**队列（queue）**实现：先进先出。

```text
queue.push(start)
while queue 不空:
    cur = queue.pop_front()
    if cur == goal: 找到
    for neighbor in cur 的邻居:
        if neighbor 没访问过 and 可通行:
            visited[neighbor] = true
            parent[neighbor] = cur
            queue.push_back(neighbor)
```

### 3.2 BFS 的优点和局限

**优点**：

- 简单，容易写对；
- 在**每条边代价相同**的图里，第一次到达终点就是步数最少的路径。

**局限**：

- 不能处理不同权重（对角 `√2`、地形代价）；
- 会向四面八方均匀扩散，明明终点在右边，它也会往左搜很多；
- 在带权图里，“步数少”不等于“代价小”。

> 本项目不用 BFS，但理解它很重要：Dijkstra 和 A* 都是它的“升级版”。

## 4. Dijkstra：按“已走代价”排序

### 4.1 从队列换成优先队列

BFS 按“发现顺序”出队；Dijkstra 按“从起点走到这里的已知最小代价 `g`”出队。

```text
g(n) = 从起点到节点 n 的实际最小代价
```

每次从待考察集合里取 **`g` 最小**的节点扩展。这需要**优先队列（最小堆）**，
不能再用普通队列。

```text
g[start] = 0
open.push({g=0, start})

while open 不空:
    cur = open.pop_min_g()
    if cur == goal: 找到
    if closed[cur]: continue
    closed[cur] = true

    for neighbor in cur 的邻居:
        if 不可通行 or closed[neighbor]: continue
        tentative_g = g[cur] + cost(cur, neighbor)
        if tentative_g < g[neighbor]:
            g[neighbor] = tentative_g
            parent[neighbor] = cur
            open.push({g=tentative_g, neighbor})
```

### 4.2 Dijkstra 保证什么

只要所有边权**非负**，Dijkstra 第一次弹出终点时，得到的就是**最小代价路径**。

为什么？因为优先队列每次拿出的都是当前“已知代价最小”的节点。
如果还有更便宜的路径，那条路径上的某个节点一定更小，会先被拿出来。

### 4.3 Dijkstra 的问题：没有方向感

Dijkstra 只按 `g` 排序，不知道终点在哪。它像一个蒙着眼的人：
以起点为圆心，一圈圈向外扩张，直到碰到终点。

```text
终点在右边，但 Dijkstra 左边也搜了很多：

        ■ ■ ■ ■ ■ ■ ■
      ■ ■ ■ ■ ■ ■ ■ ■ ■
    ■ ■ ■ ■ S ■ ■ ■ ■ ■ → 终点
      ■ ■ ■ ■ ■ ■ ■ ■ ■
        ■ ■ ■ ■ ■ ■ ■
```

地图越大，浪费越多。能不能让搜索“朝终点偏一点”？

能。这就是 A*。

## 5. A*：给搜索装一个“指南针”

### 5.1 三个量：g、h、f

A* 在 Dijkstra 的基础上，加入一个**启发式估计**：

| 符号 | 含义 | 谁提供 |
|---|---|---|
| `g(n)` | 从**起点**到 n 的**实际**代价 | 搜索过程中累加 |
| `h(n)` | 从 n 到**终点**的**估计**代价 | 启发式函数（人写的） |
| `f(n)` | `g(n) + h(n)`，经过 n 的总代价估计 | 计算得到 |

A* 每次从 open list 里取 **`f` 最小**的节点扩展。

```text
       起点 S                        终点 G
         ●───────────────────────────●
          \                         /
           \  g(n)：已经走过的代价
            ● n ────────────────────
                 h(n)：到终点的估计
                 
            f(n) = g(n) + h(n)
```

**直觉**：

- `g` 告诉你“已经花了多少”；
- `h` 告诉你“大概还要花多少”；
- `f` 告诉你“走这条路总共大概要花多少”。

Dijkstra 只看 `g`（已经花了多少），所以它会往所有方向试；
A* 还看 `h`（离终点还有多远），所以它优先试“看起来更有希望”的方向。

### 5.2 A* 主循环

```text
g[start] = 0
open.push({f = h(start), g = 0, start})

while open 不空:
    cur = open.pop_min_f()
    if closed[cur]: continue          // 跳过堆里的旧副本
    closed[cur] = true

    if cur == goal: 找到，回溯路径

    for neighbor in cur 的邻居:
        if 不可通行 or closed[neighbor]: continue
        tentative_g = g[cur] + cost(cur, neighbor)
        if tentative_g < g[neighbor]:
            g[neighbor] = tentative_g
            parent[neighbor] = cur
            f = tentative_g + h(neighbor)
            open.push({f, tentative_g, neighbor})
```

和 Dijkstra 只差两处：

1. 入队时 `f = g + h`，不是只存 `g`；
2. 出队时按 `f` 排序，不是按 `g`。

> 如果令 `h(n) = 0`，A* 就退化成 Dijkstra。
> 所以你可以把 A* 理解成“带方向感的 Dijkstra”。

### 5.3 手算一个 5×5 例子

地图（`#` 障碍，`S` 起点，`G` 终点）：

```text
列 →  0   1   2   3   4
行 0  #   #   #   #   #
行 1  #   S   .   .   #
行 2  #   .   #   .   #
行 3  #   .   .   G   #
行 4  #   #   #   #   #
```

- 起点 `S = (1,1)`
- 终点 `G = (3,3)`
- 障碍 `(2,2)`
- 只允许 **4 邻域**
- 启发式用**曼哈顿距离**：`h = |dx| + |dy|`

先算每个格子的 `h`（到终点 `(3,3)` 的曼哈顿距离）：

```text
h 值分布：
      x=0  x=1  x=2  x=3  x=4
y=0     -    -    -    -    -
y=1     -    4    3    2    -
y=2     -    3    #    1    -
y=3     -    2    1    0    -
y=4     -    -    -    -    -
```

搜索过程（每一步都列出弹出的节点）：

| 步 | 弹出 (x,y) | g | h | f = g+h | 说明 |
|---:|---|---:|---:|---:|---|
| 1 | (1,1) S | 0 | 4 | 4 | 起点入队时 f=4 |
| 2 | (2,1) | 1 | 3 | 4 | 向右走 |
| 3 | (1,2) | 1 | 3 | 4 | 向下走 |
| 4 | (3,1) | 2 | 2 | 4 | 继续向右 |
| 5 | (1,3) | 2 | 2 | 4 | 继续向下 |
| 6 | (3,2) | 3 | 1 | 4 | 从 (3,1) 向下 |
| 7 | (2,3) | 3 | 1 | 4 | 从 (1,3) 向右 |
| 8 | (3,3) G | 4 | 0 | 4 | 到达终点 |

最终路径：

```text
(1,1) → (2,1) → (3,1) → (3,2) → (3,3)
```

画在地图上：

```text
#####
#S**#
#.#*#
#..G#
#####
```

**关键观察：所有被弹出节点的 `f` 都等于 4，而 4 正是最优路径代价。**

这不是巧合。对最优路径上的每个节点，`g + h` 恰好等于整条最优路径的代价
（因为 `h` 是精确的曼哈顿距离）。所以 A* 无法仅凭 `f` 区分它们，
只能按入队顺序依次扩展。

这也解释了一个常见现象：**`f` 相同很常见，tie-breaking（平局处理）会影响扩展顺序和数量**，
但不会影响最优性（只要 `h` 可采纳）。

用工具验证：

```bash
python3 docs/tools/astar_playground.py --no-diagonal --trace --no-color
```

输出应该和上表完全一致。

### 5.4 为什么 A* 比 Dijkstra 少搜？

把地图换大一点，终点在右下角：

```bash
python3 docs/tools/astar_playground.py --demo-map --compare --no-color
```

本机输出（数值会因机器略有差异，但趋势一致）：

```text
astar        路径格数=14   代价=13.00   扩展=34    打开=37
astar(w=2)   路径格数=14   代价=13.00   扩展=18    打开=25
dijkstra     路径格数=14   代价=13.00   扩展=40    打开=40
bfs          路径格数=14   代价=13.00   扩展=40    打开=40
```

- Dijkstra 扩展 40 个节点（几乎把能到的都翻了）；
- A*（w=1）扩展 34 个，因为它优先朝终点方向搜；
- A*（w=2）只扩展 18 个，更快，但**不再保证最优**（本例恰好还是最优）；
- BFS 也扩展 40 个，因为它没有方向感。

> “扩展节点数”是衡量规划器效率最直观的指标。
> 本项目日志里的 `扩展 N 节点` 就是它。

## 6. 启发式 h 怎么选：不要瞎猜

### 6.1 h 必须和“允许的移动方式”匹配

| 移动方式 | 推荐 h | 公式 | 为什么 |
|---|---|---|---|
| 4 邻域（上下左右） | 曼哈顿距离 | `|dx| + |dy|` | 4 邻域下的精确最小步数 |
| 8 邻域（含对角） | Octile 距离 | `(dx+dy) + (√2−2)·min(dx,dy)` | 8 邻域下的精确最小步数 |
| 任意方向（连续） | 欧氏距离 | `√(dx²+dy²)` | 连续空间下的直线距离 |

### 6.2 为什么 8 邻域不用欧氏距离？

欧氏距离在 8 邻域里是**可采纳**的（不会高估），但**太松**：

```text
dx = 10, dy = 10
真实 8 邻域最短 = 10√2 ≈ 14.14
欧氏距离      = √(10²+10²) ≈ 14.14   ← 这个例子恰好一样
```

换一个：

```text
dx = 10, dy = 1
真实 8 邻域最短 = 9 + √2 ≈ 10.414   （先斜走 1 步，再直走 9 步）
欧氏距离        = √(101) ≈ 10.050    ← 低估了约 0.36
```

低估不会破坏最优性，但会让 `h` 变小、`f` 更接近 `g`，A* 就更像 Dijkstra，
扩展更多节点。Octile 是 8 邻域下的**精确值**，最紧，所以最好。

### 6.3 为什么 4 邻域不能用欧氏距离？

欧氏距离 `√(dx²+dy²)` 在 4 邻域下**小于**真实步数 `|dx|+|dy|`，
所以它不会高估，仍然是可采纳的。但它比曼哈顿松，会让 A* 多扩展节点。

所以：

- 4 邻域 → 曼哈顿（最紧）；
- 8 邻域 → Octile（最紧）；
- 欧氏 → 可用，但更松，通常更慢。

### 6.4 什么是“可采纳（admissible）”

> 如果对任意节点 n，都有 `h(n) ≤ 从 n 到终点的真实最小代价`，
> 就说 h 是**可采纳的**。

**可采纳 = 从不高估剩余代价。**

为什么重要？因为 A* 靠 `f = g + h` 排序。如果 `h` 高估了，某个其实很差的节点
可能因为“看起来很近”而被优先扩展，真正的最优路径反而被推迟，最终可能返回次优解。

**反例：8 邻域却用曼哈顿距离**

```text
dx = 1, dy = 1
真实对角代价 = √2 ≈ 1.414
曼哈顿 h     = 2          ← 高估了 0.586
```

这就是**不可采纳**。在小地图上可能看不出问题，但在复杂地图上可能规划出明显绕远的路径。

### 6.5 一致性（consistent）

比可采纳更强的条件：

```text
h(n) ≤ cost(n, n') + h(n')
```

也就是“从 n 到终点的估计，不应该比先走一步到 n' 再估计更贵”。
曼哈顿、Octile、欧氏在对应邻域下都满足一致性。

一致性有什么用？它保证每个节点**第一次被扩展时，g 就已经是最优的**，
所以 `closed` 一旦标记就不用再改。本项目的实现依赖这一点。

> 如果 h 只是可采纳但不一致，严格来说需要更复杂的处理（例如允许重新打开 closed 节点）。
> 教学实现用一致的 h，避免这个复杂度。

### 6.6 加权 A*：用最优性换速度

```text
f = g + w · h        （w ≥ 1）
```

- `w = 1.0`：标准 A*，保证最优（h 可采纳时）；
- `w > 1.0`：更相信启发式，搜索更“贪心”，更快，但**可能不是最短路**；
- `w` 很大：退化成“一直朝终点走”的贪心搜索，可能撞墙、绕远。

理论保证（h 可采纳时）：加权 A* 返回的路径代价不超过最优代价的 `w` 倍。
实践中 `w = 1.1 ~ 1.5` 往往能明显加速，路径只差几个百分点。

本项目参数：

```yaml
heuristic_weight: 1.0   # 1.0=最优；>1 更快但非最优
```

> 不要把它和 `cost_weight` 搞混：
> - `heuristic_weight` 影响**搜索方向**（h 的倍数）；
> - `cost_weight` 影响**路径代价**（地形代价的倍数）。

## 7. 算法骨架与数据结构

### 7.1 四个核心数组

| 结构 | 作用 | 本项目实现 |
|---|---|---|
| `g_score` | 起点到每个节点的已知最小代价 | `vector<double>`，初始 `∞` |
| `parent` | 每个节点是从哪个节点走过来的 | `vector<unsigned int>` |
| `closed` | 是否已经正式扩展过 | `vector<uint8_t>` |
| `open_list` | 待考察节点，按 f 排序 | `priority_queue`（最小堆） |

### 7.2 为什么需要 `closed` 判重

`std::priority_queue` **不支持修改堆里已有元素的优先级**，也不支持删除。
所以同一个节点可能被多次 `push`：

```text
第一次发现 n：g=10，push (f=10)
后来发现更优：g=8，push (f=8)
此时堆里有两个 n 的副本
```

弹出时，先弹出 `f=8` 的副本，扩展它；再弹出 `f=10` 的旧副本时，
必须跳过：

```cpp
if (closed[current.index]) continue;
```

这叫**懒删除（lazy deletion）**。

> 另一种做法是“弹出时比较 g”：如果堆里的 g 大于 `g_score[index]`，说明是旧副本，跳过。
> 本项目用 `closed`，更直观。

### 7.3 为什么不在堆里“更新”节点

因为标准优先队列没有 `decrease-key` 操作。要么自己实现可索引堆，
要么接受“重复插入 + 懒删除”。后者实现简单，代价是堆里元素可能变多，
但对栅格地图通常可以接受。

### 7.4 完整伪代码（和本项目一致）

```text
plan(start, goal):
    校验 start/goal 在界内
    校验 goal 可通行
    if start == goal: 返回单点路径

    g[start] = 0
    parent[start] = start
    open.push(f = h(start), g = 0, start)
    closed = 空

    while open 不空:
        每 256 次检查一次 cancel
        cur = open.pop_min_f()
        if closed[cur]: continue
        closed[cur] = true
        if cur == goal: 回溯路径，返回成功
        if 扩展次数 > max_expansions: 返回失败

        for neighbor in 邻居(cur):
            if 越界 or closed[neighbor] or 不可通行: continue
            if 对角移动 and 两个相邻直移格不可通行: continue   // 切角检查
            tentative_g = g[cur] + move_cost(cur, neighbor)
            if tentative_g < g[neighbor]:
                g[neighbor] = tentative_g
                parent[neighbor] = cur
                open.push(f = tentative_g + h(neighbor), g = tentative_g, neighbor)
    return 无路
```

### 7.5 对角移动的“切角”检查

如果只检查目标格是否能走，A* 会从两个障碍的缝隙里斜穿过去：

```text
  ███ 障碍
  S ─┐
     │╲
  ███ │ ●   ← 对角目标格，但路径穿过了两个障碍的角
```

机器人有体积，这样走会撞到障碍角。所以对角移动时，必须**同时**检查
两个相邻的直移格：

```cpp
if (diagonal) {
    if (!可通行(cx + dx, cy) || !可通行(cx, cy + dy)) continue;
}
```

本项目在 `astar_algorithm.cpp` 的 `plan()` 里实现了这个检查。

### 7.6 取消与扩展上限

规划可能很慢（大地图、复杂障碍）。Nav2 允许用户取消目标，所以
`createPlan` 会收到一个 `cancel_checker`。算法需要定期检查：

```cpp
if (cancel_checker && (expansions % 256 == 0) && cancel_checker()) {
    return Result::CANCELLED;
}
```

`max_expansions` 是保险丝：防止病态地图让搜索跑太久。

## 8. 为什么 A* 第一次弹出终点就是最优解？

这是 A* 最重要的性质。用反证法理解。

### 8.1 证明（直观版）

假设：

- `h` 可采纳（从不高估）；
- 所有边权非负；
- 算法在**弹出**终点时停止。

设终点为 `G`，第一次弹出 `G` 时的代价为 `g(G)`。
假设存在一条更优路径，代价为 `C* < g(G)`。

考虑那条更优路径上、当时还没被扩展的某个节点 `n`。
因为 `h` 可采纳：

```text
f(n) = g(n) + h(n) ≤ g(n) + 真实剩余代价 = C* < g(G)
```

所以 `f(n) < g(G)`。而优先队列按 `f` 排序，`n` 应该比 `G` 更早被弹出，
矛盾。

因此，第一次弹出 `G` 时，不可能存在更优路径。证毕。

### 8.2 三个前提，缺一不可

1. **h 可采纳**：如果 h 高估，证明不成立；
2. **边权非负**：如果有负权边，已经走过的路可能“倒赚”，g 不再单调；
3. **在弹出时判断终点**：如果在入队时判断，可能拿到一个还没证明最优的路径。

> 本项目在 `current.index == goal_index` 时 `break`，是“弹出时判断”，正确。

### 8.3 加权 A* 为什么不保证最优

因为 `w·h` 可能高估。证明里的 `f(n) ≤ C*` 不再成立。
所以 `w > 1` 时，可能先弹出终点，但还存在更优路径。

## 9. 从纯算法到真实代价地图

前面讲的都是“纯算法”。真实 Nav2 里，输入不是简单的 `#` 和 `.`，
而是一张 0~255 的**代价地图**。

### 9.1 代价的语义

| 值 | 名称 | 含义 | 能不能走 |
|---:|---|---|---|
| `0` | `FREE_SPACE` | 空闲 | ✓ |
| `1~252` | 膨胀代价 | 越大越靠近障碍 | ✓，但代价高 |
| `253` | `INSCRIBED_INFLATED_OBSTACLE` | 内切膨胀，已进入碰撞风险区 | 策略相关 |
| `254` | `LETHAL_OBSTACLE` | 真实障碍 | ✗ |
| `255` | `NO_INFORMATION` | 未知区域 | 由 `allow_unknown` 决定 |

**关键区别：253 和 254**

- `254` 是物理障碍，不能走；
- `253` 是“膨胀层”算出来的内切膨胀区，表示“机器人中心在这里可能已经碰撞”。
  **它不是物理障碍，但也不代表绝对安全**；是否允许走，是规划器的策略选择。
  很多规划器允许起点落在 253（否则贴墙停车时无法出发），但对整条路径是否
  允许经过 253，要结合 footprint 和膨胀参数决定。

### 9.2 本项目踩过的坑：起点在 253

最初代码把可通行阈值设成 `< 253`，结果经常报“无可行路径”。

调试发现：**机器人贴墙停车时，起点格子的代价正好是 253**，周围也全是 253。
于是 `253 < 253 == false`，所有邻居都被判为不可通行，A* 一个邻居都扩展不出去。

本项目的取舍：

```cpp
return cost < 254;   // 只有真实障碍不可通行
```

这样贴墙停车时起点不会直接判死。代价是：路径可能贴着 253 走，
严格按 footprint 检查时可能离障碍太近。

> 官方 Navfn 在 `createPlan()` 层只对**终点**检查 `254`，但它内部的代价转换
> 会把 `253` 当障碍处理；不同版本/实现的策略不同。不要把“官方只检查终点”
> 误解成“官方允许路径穿过 253”。本项目是教学实现，选择了更宽松的策略；
> 生产环境应结合 footprint 碰撞检查或增大 `inflation_radius`。

> 这是本项目最有价值的教训之一：
> **报“无路可走”时，先打印起点和终点的代价，不要先怀疑算法。**
> 详见 [03 阶段 6.4](03_教学进度记录.md)。

### 9.3 地形代价 `cost_weight`

除了“能不能走”，还可以让算法“尽量少走贵的地方”。

本项目的做法：

```cpp
double cost = diagonal ? sqrt(2) : 1.0;

if (cost_weight > 0) {
    double normalized = cell_cost / 252.0;   // 0~1
    cost += cost_weight * normalized;
}
```

- `cost_weight = 0`：只按距离，最短路；
- `cost_weight = 2~5`：明显远离障碍，路径更“保守”；
- 太大：可能为了远离障碍而绕很远，甚至找不到路。

> 注意：这里把 0~252 线性映射到 0~1，是一种简化的“教学代价模型”。
> 工业级规划器（如 Smac Planner）会用更精细的代价函数和惩罚项。

### 9.4 未知区域 `allow_unknown`

- `allow_unknown = true`：`255` 可以走，适合探索任务；
- `allow_unknown = false`：`255` 不可走，适合已知地图。

如果地图里未知区域很大，而你又关了 `allow_unknown`，很容易“无路可走”。

### 9.5 为什么纯算法不直接依赖 costmap

本项目把算法和 ROS 解耦：

```text
astar_algorithm.cpp   ← 只认识 vector<uint8_t> 和格子坐标
astar_planner.cpp     ← 负责把 costmap 转成 vector<uint8_t>，再调用算法
```

好处：

1. 算法可以脱离 ROS 做单元测试；
2. 换地图、换机器人、换消息类型，算法不用改；
3. 出问题时可以单独验证“是算法错还是数据错”。

这正是第 06 篇要讲的“三层架构”的第一层。

## 10. 复杂度、性能与调优

### 10.1 复杂度

| 项 | 复杂度 | 说明 |
|---|---|---|
| 时间 | `O(E log V)` | `V` 是格子数，`E` 是边数（4 邻域约 `4V`，8 邻域约 `8V`） |
| 空间 | `O(V)` | `g_score`、`parent`、`closed` 都是每格一份 |
| 最坏情况 | 整张地图扩展一遍 | h 很松时退化成 Dijkstra |

本项目 384×384 地图（约 14.7 万格）通常几毫秒完成。

### 10.2 影响性能的因素

| 因素 | 影响 | 怎么调 |
|---|---|---|
| 地图大小 | 格子越多越慢 | 用多分辨率/局部规划 |
| 邻域数 | 8 邻域比 4 邻域分支多 | 需要斜走就开，否则关 |
| 启发式质量 | h 越紧，扩展越少 | 用匹配邻域的曼哈顿/Octile |
| 权重 w | w 越大越快，可能非最优 | 1.0~1.5 试 |
| 地形代价 | 计算量略增，路径更绕 | 0~5 试 |
| 障碍复杂度 | 狭窄通道会扩展更多 | 调膨胀半径、cost_weight |
| 平局处理 | 影响扩展顺序和数量 | 可用 h 作为第二排序键 |

### 10.3 一个实用的调参顺序

1. 先保证**能找到路**：`allow_unknown=true`，`cost_weight=0`，`heuristic_weight=1`；
2. 看日志的**扩展节点数**和**耗时**；
3. 想更快：`heuristic_weight` 从 1.0 慢慢加到 1.5，观察路径是否变差；
4. 想远离障碍：`cost_weight` 从 0 加到 2~5，观察路径；
5. 最后再考虑路径平滑（那是 `smoother_server` 的事，不是 A* 的事）。

## 12. 常见误区与练习

### 12.1 常见误区

| 误区 | 为什么错 |
|---|---|
| “h 越大，A* 越快，所以越大越好” | 高估会破坏最优性；w 太大可能绕远甚至找不到路 |
| “A* 一定比 Dijkstra 快” | 如果 h 很松（比如全 0），A* 就是 Dijkstra |
| “第一次遇到终点就可以停” | 应该在**弹出**终点时停，入队时停可能不是最优 |
| “closed 判重可有可无” | 没有它会重复扩展，甚至把已扩展节点改坏 |
| “对角移动只看目标格就行” | 会从障碍缝隙斜穿，必须检查两个相邻直移格 |
| “253 是物理障碍，绝对不能走” | 253 是内切膨胀，不是物理障碍；但是否允许走要结合 footprint，不能简单当空闲 |
| “格子坐标就是世界坐标” | 差一个 `resolution` 和 `origin`，还有 `+0.5` 的格子中心 |
| “路径点越密越好” | 太密会增加控制器负担；按 `interpolation_resolution` 即可 |
| “A* 能处理车辆运动学” | 普通 A* 不考虑转弯半径；需要 Hybrid A* |

### 12.2 练习（答案在后面）

**练习 1**：在上面 5×5 地图上，把终点改成 `(1,3)`，4 邻域，手算 A* 的扩展顺序和路径。

**练习 2**：8 邻域下，曼哈顿距离是否可采纳？举一个反例。

**练习 3**：4 邻域下，欧氏距离是否可采纳？它比曼哈顿更好还是更差？为什么？

**练习 4**：为什么本项目允许起点代价为 253，但终点为 254 时要报错？

**练习 5**：如果去掉对角移动的“切角检查”，会出现什么现象？画图说明。

**练习 6**：把 `heuristic_weight` 设为 3.0，路径一定更短吗？为什么？

### 12.3 练习答案

**答案 1**：
起点 `(1,1)`，终点 `(1,3)`，障碍 `(2,2)`。
最优路径：`(1,1) → (1,2) → (1,3)`，代价 2。
扩展顺序（4 邻域，曼哈顿）：
`(1,1) f=2` → `(2,1) f=4` 或 `(1,2) f=2` 先弹出 `(1,2)` → `(1,3) f=2`。
实际上 `(2,1)` 的 f=1+3=4，不会先于 `(1,2)` 的 f=1+1=2。
所以扩展 3 个节点就到达。可以用工具验证：

```bash
# 仓库里已准备好目标在 (1,3) 的地图
python3 docs/tools/astar_playground.py \
  --map docs/tools/maps/exercise1.txt --no-diagonal --trace --no-color
```

**答案 2**：不可采纳。反例：`dx=1, dy=1`，真实对角代价 `√2≈1.414`，
曼哈顿 `h=2 > 1.414`，高估了。

**答案 3**：可采纳，因为 `√(dx²+dy²) ≤ |dx|+|dy|`。
但它比曼哈顿**更松**（更小），会让 A* 扩展更多节点，所以 4 邻域下曼哈顿更好。

**答案 4**：起点是机器人当前位置，即使落在 253 的膨胀区，也应该允许它出发；
否则贴墙停车时会被判“起点不可通行”。终点如果是 254，说明目标在真实障碍里，
没有意义，应该报 `GoalOccupied`，让行为树触发恢复。
但要注意：允许起点在 253，不等于允许整条路径随便穿 253；生产环境还要做
footprint 碰撞检查。

**答案 5**：A* 会从两个对角障碍的缝隙中斜穿：

```text
  ███
  S ─┐
     │╲
  ███ │ ●
```

路径在几何上穿过了障碍角，机器人足迹会碰撞。必须检查
`(cx+dx, cy)` 和 `(cx, cy+dy)` 两个格子。

**答案 6**：不一定。`w > 1` 让 h 可能高估，A* 可能更“贪心”，
更快但可能返回次优路径。只有在 h 可采纳且 w=1 时才保证最优。

## 13. 一页总结

```text
┌─────────────────────────────────────────────────────────────┐
│  输入：代价地图 + 起点格子 + 终点格子                        │
│                                                             │
│  g(n)：起点到 n 的实际代价                                   │
│  h(n)：n 到终点的估计代价（曼哈顿 / Octile）                 │
│  f(n) = g(n) + h(n)                                         │
│                                                             │
│  open list：按 f 排序的最小堆                                │
│  closed：已扩展节点                                           │
│  parent：回溯路径                                             │
│                                                             │
│  每次弹出 f 最小的节点：                                      │
│    是终点 → 回溯，结束                                        │
│    否则 → 扩展邻居，更新 g，push (f, g, neighbor)             │
│                                                             │
│  h 可采纳 + 边权非负 + 弹出时判终点 → 第一次到终点即最优       │
└─────────────────────────────────────────────────────────────┘
```
