# 从纯算法到 Nav2 插件实战

> **这篇是整套文档的核心。**
> 它回答：我脑子里有一个算法（或者从论文里抄了一段伪代码），
> 怎么把它变成 **Nav2 能加载、能调用、能上车** 的插件？
>
> **前置**：
> - 懂 A* 基本概念（至少读完 [04](04_A星算法零基础课.md) 的第 1~8 节）；
> - 知道 ROS2 节点/话题/动作/参数/生命周期是什么（至少读完 [05](05_ROS2与Nav2接口入门.md) 的第 1~5 节）。
>
> **学完你应该能**：
> 1. 设计“算法层 / 适配层 / 插件注册”三层结构；
> 2. 从零建一个 Nav2 全局规划器包；
> 3. 把任意栅格算法替换进 `createPlan`；
> 4. 用 7 层验证法定位“到底是算法错、参数错、还是插件没加载”；
> 5. 知道“能跑”和“工程可用”之间还差什么。

---

## 0. 先看清差距：算法不是插件

### 0.1 论文里的算法 vs 工程里的插件

| 维度 | 纯算法 | 工程插件 |
|---|---|---|
| 输入 | 一个二维数组、起点、终点 | ROS 消息：`PoseStamped` + 代价地图 + TF |
| 输出 | 一串格子 | `nav_msgs/Path`，带时间戳、坐标系、朝向 |
| 失败 | 返回 `false` / `nullptr` | 抛**特定类型**的异常，让行为树恢复 |
| 配置 | 函数参数 | ROS 参数，带实例名前缀 |
| 生命周期 | `main()` 里调用一次 | configure → activate → 多次 createPlan → deactivate → cleanup |
| 线程 | 单线程 | 与代价地图更新线程、多个 action 并发 |
| 内存 | 局部变量 | 成员变量，跨调用复用，注意释放 |
| 坐标 | 格子 | 世界坐标 ↔ 格子坐标，`map` 坐标系 |
| 打包 | 一个 `.cpp` | `package.xml` + CMake + XML + 导出宏 + YAML |
| 测试 | 固定输入输出 | 单元测试 + 插件加载测试 + 仿真集成测试 |

**结论**：

> 算法只占整个插件工作量的 **30%**。
> 剩下 70% 是“翻译、生命周期、错误处理、打包、验证”。

这不是坏事。把 70% 的工程工作标准化后，你换算法就只需要改 30%。

### 0.2 三层架构

本项目采用三层，建议你也照抄：

```text
┌─────────────────────────────────────────────────────────────┐
│ 第 3 层：插件注册（pluginlib）                                │
│   global_planner_plugin.xml                                 │
│   package.xml 的 <nav2_core plugin=...>                      │
│   CMakeLists 的 pluginlib_export_plugin_description_file     │
│   PLUGINLIB_EXPORT_CLASS                                    │
│   作用：让 planner_server 能在运行时找到并创建你的类           │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│ 第 2 层：ROS 适配层（astar_planner.cpp）                      │
│   - 实现 nav2_core::GlobalPlanner                            │
│   - 读参数、拿 costmap、加锁、坐标转换                        │
│   - 调用算法、把结果插值成 nav_msgs::Path                     │
│   - 把算法错误翻译成 nav2_core 异常                           │
└──────────────────────────┬──────────────────────────────────┘
                           │  vector<uint8_t> + GridCoord
┌──────────────────────────▼──────────────────────────────────┐
│ 第 1 层：纯算法（astar_algorithm.cpp）                        │
│   - 不 include 任何 ROS 头文件                                │
│   - 输入：代价数组、宽高、起点格子、终点格子                   │
│   - 输出：格子路径 + 统计信息 + 结果枚举                       │
│   - 可以脱离 ROS 用 g++ 直接编译、单测                         │
└─────────────────────────────────────────────────────────────┘
```

**依赖方向只能向下**：

```text
插件注册 → 适配层 → 算法层
```

算法层**不能**反过来依赖 ROS，否则就无法单测、无法复用。

### 0.3 先设计契约，再写代码

在动手前，先把下面这些问题写清楚（可以写在纸上）：

```text
输入：
  - 代价地图：vector<uint8_t>，长度 = width * height
  - 宽、高
  - 起点格子、终点格子
  - 选项：4/8 邻域、未知区、代价权重、启发式权重、扩展上限

输出：
  - 结果枚举：SUCCESS / NO_PATH / START_INVALID / GOAL_INVALID / CANCELLED
  - 格子路径（起点 -> 终点）
  - 统计：扩展节点数、打开节点数、路径长度、路径代价、耗时

错误：
  - 算法层返回枚举，不抛 ROS 异常
  - 适配层把枚举翻译成 nav2_core 异常

线程：
  - 算法对象由插件持有
  - plan() 本身不加锁；适配层应保证同一实例不被并发调用
    （本项目教学实现默认无并发；生产环境需要加 mutex，见 9.4）
  - 读 costmap 时加 costmap 的锁

坐标：
  - 算法层只认格子
  - 适配层负责 worldToMap / mapToWorld
```

契约定好后，三层可以**并行开发、分层验证**：

- 算法层用固定地图单测，不需要 ROS；
- 适配层先用假数据/日志验证；
- 最后再进仿真。

## 2. 第 1 步：写纯算法层

### 2.1 头文件：只暴露“算法需要的东西”

```cpp
// include/my_astar_planner/astar_algorithm.hpp
#ifndef MY_ASTAR_PLANNER__ASTAR_ALGORITHM_HPP_
#define MY_ASTAR_PLANNER__ASTAR_ALGORITHM_HPP_

#include <cstdint>
#include <functional>
#include <queue>
#include <vector>

namespace my_astar_planner
{

struct GridCoord
{
  int x;
  int y;
};

class AStarAlgorithm
{
public:
  using CostMap = std::vector<uint8_t>;

  enum class Result
  {
    SUCCESS,
    NO_PATH,
    START_INVALID,
    GOAL_INVALID,
    CANCELLED
  };

  struct Options
  {
    bool allow_diagonal = true;
    bool allow_unknown = true;
    double cost_weight = 0.0;
    double heuristic_weight = 1.0;
    size_t max_expansions = 1000000;
  };

  struct Stats
  {
    size_t nodes_expanded = 0;
    size_t nodes_opened = 0;
    size_t path_length = 0;
    double path_cost = 0.0;
    double planning_time_ms = 0.0;
  };

  void setCostmap(const CostMap & costs, unsigned int width, unsigned int height);
  void setTraversabilityChecker(
    std::function<bool(unsigned int index, uint8_t cost)> checker);
  void setOptionOverrides(
    bool allow_diagonal, bool allow_unknown,
    double cost_weight, double heuristic_weight,
    size_t max_expansions);

  Result plan(
    const GridCoord & start, const GridCoord & goal,
    std::function<bool()> cancel_checker = nullptr);

  const std::vector<GridCoord> & getPath() const {return path_;}
  const Stats & getStats() const {return stats_;}

private:
  struct Node
  {
    double f = 0.0;
    double g = 0.0;
    unsigned int index = 0;
    bool operator>(const Node & other) const {return f > other.f;}
  };

  double heuristic(unsigned int from, unsigned int to) const;
  double moveCost(unsigned int from, unsigned int to, bool diagonal) const;
  bool inBounds(int x, int y) const;
  unsigned int toIndex(int x, int y) const;
  bool isTraversable(unsigned int index) const;

  CostMap costs_;
  unsigned int width_ = 0;
  unsigned int height_ = 0;
  Options options_;
  std::vector<GridCoord> path_;
  Stats stats_;
  std::function<bool(unsigned int, uint8_t)> traversability_checker_;
};

}  // namespace my_astar_planner

#endif
```

**设计要点**：

1. 没有任何 `#include "rclcpp/..."`；
2. 输入是 `std::vector<uint8_t>`，不是 `nav2_costmap_2d::Costmap2D`；
3. 错误用 `enum class Result`，不是 ROS 异常；
4. `getPath()` / `getStats()` 返回 `const &`，避免拷贝；
5. 可通行判定通过 `std::function` 注入，算法不依赖具体地图实现。

### 2.2 实现：核心循环

完整实现见本项目 `src/astar_algorithm.cpp`。这里只强调几个关键点：

```cpp
AStarAlgorithm::Result AStarAlgorithm::plan(
  const GridCoord & start, const GridCoord & goal,
  std::function<bool()> cancel_checker)
{
  path_.clear();
  stats_ = Stats();

  if (!inBounds(start.x, start.y)) return Result::START_INVALID;
  if (!inBounds(goal.x, goal.y)) return Result::GOAL_INVALID;

  const unsigned int start_index = toIndex(start.x, start.y);
  const unsigned int goal_index = toIndex(goal.x, goal.y);

  if (!isTraversable(goal_index)) return Result::GOAL_INVALID;
  if (start_index == goal_index) {
    path_.push_back(start);
    stats_.path_length = 1;
    return Result::SUCCESS;
  }

  const size_t map_size = static_cast<size_t>(width_) * height_;
  const double INF = std::numeric_limits<double>::infinity();

  std::vector<double> g_score(map_size, INF);
  std::vector<unsigned int> parent(map_size, std::numeric_limits<unsigned int>::max());
  std::vector<uint8_t> closed(map_size, 0);
  std::vector<uint8_t> in_open(map_size, 0);

  std::priority_queue<Node, std::vector<Node>, std::greater<Node>> open_list;

  g_score[start_index] = 0.0;
  open_list.push({heuristic(start_index, goal_index), 0.0, start_index});
  in_open[start_index] = 1;
  stats_.nodes_opened++;

  bool found = false;
  size_t expansions = 0;

  while (!open_list.empty()) {
    if (cancel_checker && (expansions % 256 == 0) && cancel_checker()) {
      return Result::CANCELLED;
    }

    Node current = open_list.top();
    open_list.pop();
    in_open[current.index] = 0;

    if (closed[current.index]) continue;   // 懒删除
    closed[current.index] = 1;
    stats_.nodes_expanded++;

    if (current.index == goal_index) {found = true; break;}
    if (++expansions > options_.max_expansions) break;

    const int cx = static_cast<int>(current.index % width_);
    const int cy = static_cast<int>(current.index / width_);
    const int dir_count = options_.allow_diagonal ? 8 : 4;

    for (int d = 0; d < dir_count; ++d) {
      // ... 计算 nx, ny，检查越界、closed、可通行、切角 ...
      // tentative_g = g_score[current.index] + moveCost(...)
      // 如果更优：更新 g_score、parent，push 新 Node
    }
  }

  if (!found) return Result::NO_PATH;
  // ... 从 goal 沿 parent 回溯到 start，反转 ...
  return Result::SUCCESS;
}
```

### 2.3 关键：算法层可以脱离 ROS 编译

这是三层架构最大的好处。你可以用 `g++` 直接编译一个命令行测试：

```cpp
// /tmp/astar_cli.cpp
#include <iostream>
#include <vector>
#include "my_astar_planner/astar_algorithm.hpp"

int main()
{
  using my_astar_planner::AStarAlgorithm;
  const int W = 5, H = 5;
  std::vector<uint8_t> map(W * H, 0);

  auto set = [&](int x, int y, uint8_t v) {map[y * W + x] = v;};
  for (int x = 0; x < W; ++x) {set(x, 0, 254); set(x, 4, 254);}
  for (int y = 0; y < H; ++y) {set(0, y, 254); set(4, y, 254);}
  set(2, 2, 254);   // 中间一个障碍

  AStarAlgorithm astar;
  astar.setCostmap(map, W, H);
  astar.setTraversabilityChecker(
    [](unsigned int, uint8_t c) {return c < 253;});
  astar.setOptionOverrides(false, true, 0.0, 1.0, 1000000);

  auto result = astar.plan({1, 1}, {3, 3});
  if (result != AStarAlgorithm::Result::SUCCESS) {
    std::cout << "no path\n";
    return 1;
  }
  for (const auto & c : astar.getPath()) {
    std::cout << "(" << c.x << "," << c.y << ") ";
  }
  std::cout << "\ncost=" << astar.getStats().path_cost
            << " expanded=" << astar.getStats().nodes_expanded << "\n";
  return 0;
}
```

```bash
  -Isrc/my_astar_planner/include \
  /tmp/astar_cli.cpp \
  src/my_astar_planner/src/astar_algorithm.cpp \
  -o /tmp/astar_cli

/tmp/astar_cli
```

```cpp
using my_astar_planner::AStarAlgorithm;

namespace
{
std::vector<uint8_t> makeMap(int w, int h, uint8_t fill = 0)

}

TEST(AStarAlgorithm, FindsPathOnEmptyMap)
{

  AStarAlgorithm astar;
```

## 3. 第 2 步：写 ROS 适配层

适配层的职责就一句话：

> **把 ROS 世界的数据翻译成算法世界的数据，再把算法的结果翻译回 ROS 世界。**

### 3.1 头文件：持有算法和 ROS 资源

```cpp
// include/my_astar_planner/astar_planner.hpp
#ifndef MY_ASTAR_PLANNER__ASTAR_PLANNER_HPP_
#define MY_ASTAR_PLANNER__ASTAR_PLANNER_HPP_

#include <memory>

#include "rclcpp/rclcpp.hpp"
```

**为什么用 `unique_ptr` 持有算法？**

- 算法对象只属于这个插件实例；
- `configure` 时创建，`cleanup` 时释放；
- 不需要共享，`unique_ptr` 语义最清楚。

**为什么用 `WeakPtr` 持有父节点？**

- 父节点是 `planner_server`，它已经由 `shared_ptr` 管理；
- 插件再持有一个 `shared_ptr` 会造成循环引用，节点永远不释放；
- `WeakPtr::lock()` 临时拿到 `shared_ptr`，用完就释放。

### 3.2 `configure()`：只做一次的事

```cpp
void AStarPlanner::configure(
  const rclcpp_lifecycle::LifecycleNode::WeakPtr & parent,
  std::string name,
  std::shared_ptr<tf2_ros::Buffer> tf,
  std::shared_ptr<nav2_costmap_2d::Costmap2DROS> costmap_ros)
{
  parent_node_ = parent;
  auto node = parent_node_.lock();
  if (!node) {
    throw nav2_core::PlannerException("父节点已失效");
  }

  logger_ = node->get_logger();
  clock_ = node->get_clock();

  name_ = name;
  tf_ = tf;
  costmap_ros_ = costmap_ros;
  global_frame_ = costmap_ros_->getGlobalFrameID();

  astar_ = std::make_unique<AStarAlgorithm>();

  // 参数必须带实例名前缀
  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".allow_diagonal", rclcpp::ParameterValue(true));
  node->get_parameter(name_ + ".allow_diagonal", allow_diagonal_);

  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".allow_unknown", rclcpp::ParameterValue(true));
  node->get_parameter(name_ + ".allow_unknown", allow_unknown_);

  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".cost_weight", rclcpp::ParameterValue(0.0));
  node->get_parameter(name_ + ".cost_weight", cost_weight_);

  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".heuristic_weight", rclcpp::ParameterValue(1.0));
  node->get_parameter(name_ + ".heuristic_weight", heuristic_weight_);

  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".interpolation_resolution", rclcpp::ParameterValue(0.05));
  node->get_parameter(name_ + ".interpolation_resolution", interpolation_resolution_);

  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".max_expansions", rclcpp::ParameterValue(1000000));
  node->get_parameter(name_ + ".max_expansions", max_expansions_);

  nav2_util::declare_parameter_if_not_declared(
    node, name_ + ".use_final_approach_orientation", rclcpp::ParameterValue(false));
  node->get_parameter(
    name_ + ".use_final_approach_orientation", use_final_approach_orientation_);

  RCLCPP_INFO(logger_, "AStarPlanner(%s) 已配置", name_.c_str());
}
```

**逐点解释**：

| 代码 | 为什么 |
|---|---|
| `parent_node_ = parent` | 存弱引用，后面读参数/日志 |
| `lock()` 判空 | 父节点可能已经销毁，防御 |
| `logger_ = node->get_logger()` | 日志前缀会带 `planner_server`，方便过滤 |
| `clock_ = node->get_clock()` | 用 ROS 时间，仿真时 `use_sim_time` 才正确 |
| `name_ = name` | 参数前缀，例如 `GridBased` |
| `global_frame_ = getGlobalFrameID()` | 返回路径的坐标系 |
| `make_unique<AStarAlgorithm>()` | 创建算法对象 |
| `declare_parameter_if_not_declared` | 没在 YAML 里写也能用默认值 |
| `name_ + ".xxx"` | 多插件隔离，**不能漏** |

### 3.3 `createPlan()`：每次请求都走一遍

这是插件的核心。按顺序拆成 10 步：

#### 第 1 步：准备返回消息

```cpp
nav_msgs::msg::Path global_path;
global_path.header.stamp = clock_->now();
global_path.header.frame_id = global_frame_;
```

#### 第 2 步：防御性检查

```cpp
if (!astar_) {
  throw nav2_core::PlannerException("AStarPlanner 尚未 configure");
}

costmap_ = costmap_ros_->getCostmap();
if (!costmap_) {
  throw nav2_core::PlannerException("无法获取代价地图");
}
```

#### 第 3 步：加锁

```cpp
std::unique_lock<nav2_costmap_2d::Costmap2D::mutex_t> lock(
  *(costmap_->getMutex()));
```

#### 第 4 步：世界坐标 → 格子坐标

```cpp
unsigned int mx_start, my_start, mx_goal, my_goal;

if (!costmap_->worldToMap(
    start.pose.position.x, start.pose.position.y, mx_start, my_start))
{
  throw nav2_core::StartOutsideMapBounds("起点超出地图范围");
}

if (!costmap_->worldToMap(
    goal.pose.position.x, goal.pose.position.y, mx_goal, my_goal))
{
  throw nav2_core::GoalOutsideMapBounds("终点超出地图范围");
}
```

**注意**：`worldToMap` 返回 `false` 可能不只是“越界”，也可能是坐标是 `NaN`。
先抛 `StartOutsideMapBounds` / `GoalOutsideMapBounds`，让行为树知道。

#### 第 5 步：终点致命障碍检查

```cpp
if (costmap_->getCost(mx_goal, my_goal) == nav2_costmap_2d::LETHAL_OBSTACLE ||
    costmap_->getCost(mx_goal, my_goal) == nav2_costmap_2d::INSCRIBED_INFLATED_OBSTACLE)
{
  throw nav2_core::GoalOccupied("终点位于致命障碍上");
}
```

> 当前同时拒绝253和254；255由allow_unknown处理。异常起点的出发特例不等于路径可穿越253。参见[04第9节](04_A星算法零基础课.md)和[26故障复盘](26_MPC停走故障复盘.md)。


#### 第 6 步：起点等于终点的特殊情况

```cpp
if (mx_start == mx_goal && my_start == my_goal) {
  geometry_msgs::msg::PoseStamped pose;
  pose.header = global_path.header;
  pose.pose = start.pose;
  if (!use_final_approach_orientation_) {
    pose.pose.orientation = goal.pose.orientation;
  }
  global_path.poses.push_back(pose);
  return global_path;
}
```

为什么不直接让算法跑？因为算法会返回单点路径，但这里还要处理朝向：
如果用户要求“终点朝向 = 目标朝向”，就用 `goal` 的朝向；否则保留起点朝向。

#### 第 7 步：把代价地图交给算法

```cpp
const unsigned int size_x = costmap_->getSizeInCellsX();
const unsigned int size_y = costmap_->getSizeInCellsY();
const unsigned char * char_map = costmap_->getCharMap();

std::vector<uint8_t> costs(
  char_map, char_map + static_cast<size_t>(size_x) * size_y);
astar_->setCostmap(costs, size_x, size_y);
```

#### 第 8 步：配置可通行判定和选项

```cpp
astar_->setTraversabilityChecker(
  [allow_unknown = allow_unknown_](unsigned int, uint8_t cost) -> bool {
    if (cost == nav2_costmap_2d::NO_INFORMATION) {
      return allow_unknown;
    }
    return cost < nav2_costmap_2d::INSCRIBED_INFLATED_OBSTACLE;   // < 253
  });

astar_->setOptionOverrides(
  allow_diagonal_, allow_unknown_, cost_weight_,
  heuristic_weight_, max_expansions_);
```

> lambda 里用 `allow_unknown = allow_unknown_` 是 C++14 的**初始化捕获**，
> 把成员变量拷贝进 lambda，避免悬空 `this`。等价于先写 `const bool au = allow_unknown_;`
> 再在 lambda 里用 `au`。

#### 第 9 步：调用算法并翻译错误

```cpp
GridCoord start_grid{static_cast<int>(mx_start), static_cast<int>(my_start)};
GridCoord goal_grid{static_cast<int>(mx_goal), static_cast<int>(my_goal)};

const auto result = astar_->plan(start_grid, goal_grid, cancel_checker);

switch (result) {
  case AStarAlgorithm::Result::SUCCESS:
    break;
  case AStarAlgorithm::Result::CANCELLED:
    throw nav2_core::PlannerCancelled("规划被取消");
  case AStarAlgorithm::Result::NO_PATH:
    throw nav2_core::NoValidPathCouldBeFound("A* 未找到可行路径");
  case AStarAlgorithm::Result::START_INVALID:
    throw nav2_core::StartOutsideMapBounds("起点非法");
  case AStarAlgorithm::Result::GOAL_INVALID:
    throw nav2_core::GoalOccupied("终点非法或位于障碍上");
  default:
    throw nav2_core::PlannerException("A* 规划失败，未知原因");
}
```

**为什么用 `switch` 而不是直接返回空路径？**

`planner_server` 会根据异常类型填 `error_code`，行为树据此决定：

- `GOAL_OCCUPIED` → 可能清除代价地图后重试；
- `NO_VALID_PATH` → 可能放弃或换目标；
- `PLANNER_CANCELLED` → 停止当前 action。

返回空 `Path` 会让上层以为“成功但路径为空”，恢复逻辑不会触发。

#### 第 10 步：插值成世界坐标路径

```cpp
const auto & grid_path = astar_->getPath();
if (grid_path.empty()) {
  throw nav2_core::NoValidPathCouldBeFound("A* 返回了空路径");
}

global_path = interpolatePath(grid_path, costmap_, interpolation_resolution_);

// 终点朝向 = 目标朝向
if (!global_path.poses.empty()) {
  global_path.poses.back().pose.orientation = goal.pose.orientation;
}

// 可选：末端朝向沿路径切线，避免原地转向
if (use_final_approach_orientation_ && global_path.poses.size() >= 2) {
  const auto & last = global_path.poses.back().pose.position;
  const auto & prev = global_path.poses[global_path.poses.size() - 2].pose.position;
  const double theta = std::atan2(last.y - prev.y, last.x - prev.x);
  global_path.poses.back().pose.orientation.x = 0.0;
  global_path.poses.back().pose.orientation.y = 0.0;
  global_path.poses.back().pose.orientation.z = std::sin(theta / 2.0);
  global_path.poses.back().pose.orientation.w = std::cos(theta / 2.0);
}

return global_path;
```

### 3.4 路径插值：为什么不能直接返回格子

A* 输出的是：

```text
(1,1) → (2,1) → (3,1) → (3,2) → (3,3)
```

每个格子间距是 `resolution`（本项目 0.05 m）。直接发出去会有两个问题：

1. 点太少，控制器在转弯处跟踪质量差；
2. 相邻点之间是折线，朝向突变。

`interpolatePath()` 在相邻格子之间线性插值，保证点间距 ≤ `interpolation_resolution`：

```cpp
const int num_steps = std::max(
  1, static_cast<int>(segment_length / interpolation_resolution));

for (int s = 1; s <= num_steps; ++s) {
  const double t = static_cast<double>(s) / num_steps;
  pose.pose.position.x = wx_prev + t * dx;
  pose.pose.position.y = wy_prev + t * dy;
  // ...
}
```

然后给每个点设置朝向（沿路径切线）：

```cpp
const double yaw = std::atan2(dy, dx);
q.z = std::sin(yaw / 2.0);
q.w = std::cos(yaw / 2.0);
```

> 插值不是“越密越好”。点太密会让控制器计算量变大。
> 通常 `interpolation_resolution` 和地图分辨率一致即可。

### 3.5 生命周期方法

```cpp
void AStarPlanner::activate()
{
  RCLCPP_INFO(logger_, "AStarPlanner(%s) 已激活", name_.c_str());
}

void AStarPlanner::deactivate()
{
  RCLCPP_INFO(logger_, "AStarPlanner(%s) 已去激活", name_.c_str());
}

void AStarPlanner::cleanup()
{
  RCLCPP_INFO(logger_, "AStarPlanner(%s) 清理资源", name_.c_str());
  astar_.reset();
}
```

本项目没有后台线程，所以 `activate/deactivate` 只打日志。
如果你在插件里启动线程，必须：

- `activate` 启动；
- `deactivate` 停止并 join；
- `cleanup` 再释放；
- 析构函数确保不会留下运行中的线程。

### 7.2 算法层测试用例清单

| 用例 | 输入 | 期望 |
|---|---|---|

- 插件能否被 `pluginlib` 创建（看日志）；

- `createPlan` 返回的 `Path.header.frame_id` 是否正确；
- 起终点越界是否抛对异常（看 action `error_code`）。

### 7.4 集成层测试

- 在固定地图上发一个目标，检查 `Goal succeeded`；
- 把起点设在 253，确认不再报“无路”；
- 把 `allow_unknown` 设为 false，确认未知区不穿越；
- 人为把初始位姿设错，确认能复现“无路可走”，再改回来。

## 8. 调试手册：症状 → 原因 → 命令

### 8.1 插件加载类

| 症状 | 最可能原因 | 检查 | 修复 |
|---|---|---|---|
| `Unable to find class ...` | ament 索引没有 | `cat` 索引文件 | 检查 `package.xml` 导出和 CMake 函数 |
| `Failed to load library ...` | `.so` 路径/名字不对 | `ls install/.../lib` | `library path` 与 `add_library` 名字一致 |
| 能 dlopen 但找不到工厂 | 缺 `PLUGINLIB_EXPORT_CLASS` | `nm -D ... | grep AStarPlanner` | 加上导出宏 |
| 改了代码但行为没变 | 没重新 source / 没重编译 | `colcon build` + `source install/setup.bash` | 重编译，确认 install 时间戳 |
| 插件加载的是旧版本 | 多个工作空间覆盖 | `ros2 pkg prefix my_astar_planner` | 清理/调整 source 顺序 |

### 8.2 参数类

| 症状 | 最可能原因 | 检查 | 修复 |
|---|---|---|---|
| 参数全是默认值 | 少了 `name_ + "."` | `ros2 param list /planner_server` | 改成 `GridBased.xxx` |
| 参数在 list 里但读不到 | 类型不匹配 | `ros2 param get` 看类型 | double 写 `1.0` |
| 改 YAML 没生效 | 没重启/没 configure | 重启节点 | 重新启动 |
| 多个插件参数互相覆盖 | 实例名重复 | 看 `planner_plugins` | 每个实例唯一 |

### 8.3 规划失败类

| 症状 | 最可能原因 | 检查 | 修复 |
|---|---|---|---|
| `NO_VALID_PATH` | 起点/终点被障碍包围 | 打印起点/终点代价和 11×11 邻域 | 改初始位姿/目标 |
| `START_OUTSIDE_MAP` | 起点不在 map 内 | `ros2 topic echo /global_costmap/costmap_raw --once` | 检查 TF/初始位姿 |
| `GOAL_OUTSIDE_MAP` | 目标点超出地图 | 看 RViz 上目标是否在地图外 | 换目标 |
| `GOAL_OCCUPIED` | 目标在 254 上 | `getCost` 打印 | 换目标 |
| 路径贴墙/穿墙 | 可通行阈值/切角检查 | 看代码 `cost < 253`、对角检查 | 修正判定 |
| 规划很慢 | 地图大/权重低 | 看扩展节点数 | 调 `heuristic_weight`、降分辨率 |
| 路径忽长忽短 | 代价地图在变/没加锁 | 检查锁 | 加 `unique_lock` |

### 8.4 一个必须学会的调试动作：打印起点邻域

报“无路可走”时，不要先改算法。先打印起点附近的代价：

```cpp
RCLCPP_WARN(
  logger_,
  "[DEBUG] map=%ux%u start=(%d,%d) goal=(%d,%d) start_cost=%u goal_cost=%u",
  size_x, size_y, start_grid.x, start_grid.y, goal_grid.x, goal_grid.y,
  costmap_->getCost(mx_start, my_start),
  costmap_->getCost(mx_goal, my_goal));
```

然后打印 11×11 邻域（`I`=253，`F`=254，`.`=0~252）：

```cpp
for (int dy = -5; dy <= 5; ++dy) {
  std::string row;
  for (int dx = -5; dx <= 5; ++dx) {
    int x = static_cast<int>(mx_start) + dx;
    int y = static_cast<int>(my_start) + dy;
    if (x < 0 || y < 0 || x >= static_cast<int>(size_x) ||
        y >= static_cast<int>(size_y)) {
      row += "?";
      continue;
    }
    uint8_t c = costmap_->getCost(x, y);
    row += (c == 254) ? 'F' : (c == 253) ? 'I' : (c == 255) ? '?' : '.';
  }
  RCLCPP_WARN(logger_, "%s", row.c_str());
}
```

> 本项目就是靠这个发现“机器人被 254 围住”，根因是 AMCL 初始位姿设错。

### 8.5 TF/生命周期类

| 症状 | 检查 | 修复 |
|---|---|---|
| `planner_server` 激活失败 | `ros2 run tf2_ros tf2_echo map base_link` | 设初始位姿/检查 AMCL |
| `TF_ERROR` | 看 action `error_msg` | 等 TF 就绪/检查 frame_id |
| `Node not found` | `ros2 node list --no-daemon` | 加 `--no-daemon` |
| `Costmap timed out` | `ros2 topic hz /global_costmap/costmap_raw` | 检查 costmap 更新 |

### 8.6 日志级别

```bash
ros2 run nav2_planner planner_server --ros-args \
  --log-level planner_server:=debug
```

代码里：

```cpp
RCLCPP_DEBUG(logger_, "每次规划的详细数据");   // 默认不打印
RCLCPP_INFO(logger_, "配置完成/规划完成");      // 重要节点
RCLCPP_WARN(logger_, "可疑但不致命");           // 无路、参数异常

```

## 9. “能跑”到“工程可用”还差什么

### 9.1 正确性

- [ ] 起点在 253 时能出发；
- [ ] 终点在 254 时报 `GoalOccupied`；
- [ ] `allow_unknown` 生效；
- [ ] 对角切角检查生效；
- [ ] 起点=终点返回单点路径；
- [ ] 路径首点接近起点，末点接近终点；
- [ ] `Path.header.frame_id` 正确；
- [ ] 取消能及时返回 `PlannerCancelled`。

### 9.2 安全性

- [ ] 不穿越真实障碍；
- [ ] 不忽略机器人足迹（A* 只做点规划，足迹由 costmap 膨胀层保证）；
- [ ] 未知区域策略明确；
- [ ] 规划超时/扩展上限有保护；
- [ ] 异常不会被吞掉。

### 9.3 性能

- [ ] 大图不卡死（`max_expansions`）；
- [ ] 不在每次规划里做重复的大分配（可预分配 `g_score` 等）；
- [ ] 锁的粒度合理（本项目为教学简化，生产可缩短）；
- [ ] `interpolation_resolution` 不要过小；
- [ ] 日志级别合理。

### 9.4 并发

- [ ] `createPlan` 可被多个 action 并发调用吗？
- [ ] 算法对象是否被多个线程共享？
- [ ] costmap 读是否加锁？
- [ ] 成员变量是否有竞态？

> 本项目一个插件实例、一个算法对象。如果 `planner_server` 并发调用
> `createPlan`，`astar_` 的内部状态（`path_`、`stats_`）会被踩。
> 教学场景通常不会并发；生产环境建议：
> - 在 `createPlan` 里用 `std::mutex` 保护算法对象；或
> - 每次规划创建局部算法对象（简单但慢）；或
> - 让算法 `plan()` 变成无状态函数（推荐，但改动大）。

### 9.5 参数与可观测性

- [ ] 每个参数有默认值、单位、范围说明；
- [ ] 参数名带实例前缀；
- [ ] 关键日志包含耗时、扩展数、路径长度；
- [ ] 失败日志包含起点、终点、代价；
- [ ] 支持 `ros2 param set` 动态调参（可选）。

### 9.6 打包与交付

- [ ] `package.xml` 依赖完整；
- [ ] `CMakeLists` 安装 XML/params/launch；
- [ ] 有 README/使用说明；
- [ ] 有测试；
- [ ] 版本号；
- [ ] 许可证；
- [ ] 在干净环境能 `colcon build`。

### 9.7 Definition of Done

一个插件可以认为“工程可用”，至少满足：

```text
1. 单元测试覆盖核心算法分支；
2. 插件能被 pluginlib 加载；
3. 参数能正确读取；
4. 生命周期可反复 configure/activate/deactivate/cleanup；
5. 起终点异常能抛对类型；

```

## 10. 换成你自己的算法

适配层的价值就在这里：**换算法不用动插件注册和 ROS 接口**。

### 10.1 只改算法层

| 你想换成 | 改哪里 | 额外工作 |
|---|---|---|
| Dijkstra | `heuristic()` 返回 0 | 无 |
| BFS | 用队列替代优先队列；边权全 1 | 无 |
| Weighted A* | `heuristic_weight > 1` | 无 |
| Theta* | 扩展时做“视线检查”，允许任意角度 | 需要 `lineOfSight` |
| JPS | 跳点搜索 | 需要邻居剪枝规则 |
| RRT / RRT* | 采样树 | 需要随机数、碰撞检查 |
| Hybrid A* | 状态加入朝向、运动学 | 需要车辆模型、转向代价 |
| D* Lite | 动态重规划 | 需要维护反向搜索树 |

### 10.2 保持契约不变

不管内部怎么换，对外仍然是：

```cpp
Result plan(const GridCoord & start, const GridCoord & goal,
            std::function<bool()> cancel_checker);
```

这样：

- 适配层不用改；
- 插件注册不用改；
- YAML 不用改；
- 测试可以复用。

### 10.3 如果新算法需要额外输入

比如 Hybrid A* 需要车辆最小转弯半径、步长；RRT 需要采样范围。
**不要**把这些塞进算法层去读 ROS 参数。正确做法：

1. 算法层的 `Options` 增加字段；
2. 适配层从 ROS 参数读，填进 `Options`；
3. 算法层仍然只依赖普通 C++ 类型。

```cpp
struct Options
{
  // ... 原有字段 ...
  double min_turning_radius = 0.5;
  double step_size = 0.1;
};
```

### 10.4 如果新算法输出不是格子路径

比如 RRT 输出的是树节点，Theta* 输出的是任意角度线段。
适配层需要把它们统一成：

```text
vector<GridCoord>  （或者更通用的 vector<Pose2D>）
```

两种做法：

- 在算法层做一次“离散化/重采样”，输出格子；
- 或者把算法层输出改成 `vector<WorldPose>`，适配层直接用。

教学项目建议保持“输出格子”，简单、好测试。

## 11. 练习（从易到难）

### 练习 1【必做】加 `tolerance`

官方 `NavfnPlanner` 有 `tolerance`：终点在容差内就算到达。
给本项目加一个 `tolerance` 参数：

- 在 `Options` 里加 `double tolerance = 0.0;`
- 算法里判断“当前节点到终点的世界距离 ≤ tolerance”；
- 适配层读参数；
- YAML 加 `tolerance: 0.5`；
- 测试：目标点在障碍旁边时，能否落到容差内。

### 练习 2【必做】把 A* 换成 Dijkstra

只改 `heuristic()` 返回 0，其他不动。
用同一张地图对比：

- 路径是否一样？
- 扩展节点数差多少？
- 用时差多少？

### 练习 3【必做】加单元测试

按第 2.4 节，至少写 5 个用例：

- 空旷地图；
- 一堵墙；
- 起点=终点；
- 起点 253；
- 终点 254。

跑 `colcon test`，确保全绿。

### 练习 4【选做】动态参数

在 `activate()` 注册 `add_on_set_parameters_callback`，
让 `heuristic_weight` 可以在运行时修改，不用重启。

### 练习 5【选做】路径剪枝

A* 输出的路径有很多共线点。写一个后处理：

- 如果连续三个点在同一直线上，删掉中间点；
- 减少 `Path.poses` 数量，降低控制器负担；
- 注意不要破坏起终点。

### 练习 6【选做】碰撞检查

现在的可通行判定只看“格子代价 < 253”。
尝试加入机器人足迹检查：

- 用 `costmap_ros_->getRobotFootprint()`；
- 对每个路径点检查足迹是否碰撞；
- 碰撞则拒绝该路径或重新规划。

### 练习 7【挑战】换一个算法

选一个你感兴趣的算法（Theta*、JPS、RRT*），
保持 `plan()` 契约不变，替换实现。
要求：

- 算法层不 include ROS；
- 原有单元测试仍能通过（或说明为什么不能）；
- 在仿真里能完成导航。

## 12. 一页总结

```text
算法 → 插件，分三层：

1. 纯算法层
   - 输入：vector<uint8_t> + 宽高 + 起终点格子
   - 输出：格子路径 + 统计 + 结果枚举
   - 不 include ROS
   - 可 g++ 直接编译、可 gtest 单测

2. ROS 适配层
   - 实现 nav2_core::GlobalPlanner
   - configure：读参数、存 costmap、建算法
   - createPlan：加锁、worldToMap、拷贝地图、调算法、插值、抛异常
   - 生命周期：activate/deactivate/cleanup

3. 插件注册层
   - XML：library / type / base_class_type
   - package.xml：<nav2_core plugin=...>
   - CMake：pluginlib_export_plugin_description_file
   - cpp：PLUGINLIB_EXPORT_CLASS

验证八层（L0~L7）：
  编译 → 索引 → 符号 → 加载 → 参数 → 生命周期 → 规划 → 导航

工程化：
  单测 + 参数校验 + 异常映射 + 锁 + 取消 + 日志 + 文档
```
