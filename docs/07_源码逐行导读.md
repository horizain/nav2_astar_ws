## 1. `astar_algorithm.hpp`：算法的“说明书”

### 1.1 头文件保护与 include

```cpp
#ifndef NAV2_ASTAR_PLANNER__ASTAR_ALGORITHM_HPP_
#define NAV2_ASTAR_PLANNER__ASTAR_ALGORITHM_HPP_

#include <vector>
#include <queue>
#include <limits>
#include <cmath>
#include <cstdint>
#include <algorithm>
#include <functional>
#include <utility>
```

**逐行看**：

| include | 用途 |
|---|---|
| `<vector>` | `std::vector` 存代价地图、路径、g_score |
| `<queue>` | `std::priority_queue` 做 open list |
| `<limits>` | `std::numeric_limits<double>::infinity()` |
| `<cmath>` | `std::sqrt`、`std::abs` |
| `<cstdint>` | `uint8_t` |
| `<algorithm>` | `std::min`、`std::max` |
| `<functional>` | `std::function`（可通行判定、取消回调） |
| `<utility>` | `std::move`、`std::pair` |

> 注意：**没有一个 ROS 头文件**。这是刻意的设计。
> 如果这里出现 `#include "rclcpp/rclcpp.hpp"`，说明分层被破坏了。

### 1.2 `GridCoord`

```cpp
struct GridCoord
{
  int x;
  int y;
};
```

- 单位是**格子**，不是米；
- `x` 是列，`y` 是行；
- 原点在左上角还是左下角？**在本项目中，`y=0` 是地图的第一行（通常对应世界坐标的较低 y）**。
  具体方向由 costmap 的 `origin` 和 `worldToMap` 决定，算法本身不关心。

### 1.3 `CostMap`

```cpp
using CostMap = std::vector<uint8_t>;
```

- 一维数组；
- 长度 = `width * height`；
- `index = y * width + x`；
- 值 0~255，语义由外部决定（算法只通过 `traversability_checker_` 判断）。

### 1.4 `Result`

```cpp
enum class Result
{
  SUCCESS,
  NO_PATH,
  START_INVALID,
  GOAL_INVALID,
  CANCELLED
};
```

`enum class` 的好处：不会隐式转换成 `int`，避免和别的枚举混用。

每个值的含义：

| 值 | 什么时候返回 |
|---|---|
| `SUCCESS` | 找到路径（包括起点=终点） |
| `NO_PATH` | open list 空了，或扩展次数超限 |
| `START_INVALID` | 起点越界 |
| `GOAL_INVALID` | 终点越界，或终点不可通行 |
| `CANCELLED` | `cancel_checker()` 返回 true |

> 算法层**不抛异常**。异常是 ROS 适配层的事。
> 这样算法可以脱离 ROS 单测，也不会把 `nav2_core` 拖进算法层。

### 1.5 `Options`

```cpp
struct Options
{
  bool allow_diagonal = true;
  bool allow_unknown = true;
  double cost_weight = 0.0;
  double heuristic_weight = 1.0;
  size_t max_expansions = 1000000;
  bool treat_unknown_as_lethal = false;
};
```

| 字段 | 作用 | 调大/调小的效果 |
|---|---|---|
| `allow_diagonal` | 是否允许 8 邻域 | false 路径更“楼梯”，但更安全 |
| `allow_unknown` | 255 是否可走 | false 不穿越未知区 |
| `cost_weight` | 地形代价权重 | 调大更远离障碍，但可能绕远 |
| `heuristic_weight` | h 的倍数 | 调大更快，可能非最优 |
| `max_expansions` | 扩展上限 | 防止病态地图卡死 |
| `treat_unknown_as_lethal` | 把未知当致命 | 目前适配层没暴露，见下文 |

> `treat_unknown_as_lethal` 目前在 `setOptionOverrides()` 里没有被设置，
> 所以永远是默认 `false`。这是一个“预留但未接线”的选项。
> 想用它，需要在 `Options`/`setOptionOverrides` 里加参数，并在 YAML 里暴露。
> 这也是一个很好的练习：**把未接线的参数接上**。

### 1.6 `Stats`

```cpp
struct Stats
{
  size_t nodes_expanded = 0;
  size_t nodes_opened = 0;
  size_t path_length = 0;
  double path_cost = 0.0;
  double planning_time_ms = 0.0;
};
```

| 字段 | 含义 | 用途 |
|---|---|---|
| `nodes_expanded` | 正式扩展（弹出且未 closed）的节点数 | 衡量搜索效率的核心指标 |
| `nodes_opened` | 曾进入 open list 的不同节点数 | 观察搜索范围 |
| `path_length` | 路径格子数 | 观察路径粒度 |
| `path_cost` | 路径总代价（g 值） | 比较不同算法/参数 |
| `planning_time_ms` | 规划耗时 | 性能 |

> `nodes_opened` 和 `nodes_expanded` 的区别：
> 一个节点可能被 push 多次（懒删除），但只算一次 opened、只扩展一次 expanded。

### 1.7 公开 API

```cpp
void setCostmap(const CostMap & costs, unsigned int width, unsigned int height);
void setTraversabilityChecker(
  std::function<bool(unsigned int index, uint8_t cost)> checker);
void setOptionOverrides(...);
Result plan(const GridCoord & start, const GridCoord & goal,
            std::function<bool()> cancel_checker = nullptr);
const std::vector<GridCoord> & getPath() const;
const Stats & getStats() const;
```

调用顺序（本项目）：

```text
setCostmap(...)                 // 每次规划前，喂最新地图
setTraversabilityChecker(...)   // 每次规划前，注入可通行规则
setOptionOverrides(...)         // 每次规划前，同步参数
plan(start, goal, cancel)       // 跑搜索
getPath() / getStats()          // 取结果
```

> 为什么每次都设置？因为参数可能在运行中变化，地图也每次都在变。
> 代价是每次规划都要拷贝地图，但 384×384 只有 147 KB，可以接受。

### 1.8 `Node`

```cpp
struct Node
{
  double f = 0.0;
  double g = 0.0;
  unsigned int index = 0;
  unsigned int parent = 0;

  bool operator>(const Node & other) const {return f > other.f;}
};
```

- `f` 是排序键；
- `g` 冗余存储，方便日志/调试（真正用的是 `g_score` 数组）；
- `parent` 也冗余（真正回溯用的是 `parent` 数组）；
- `operator>` 反转比较，让 `std::priority_queue`（默认最大堆）变成**最小堆**。

> `std::priority_queue<Node, vector<Node>, std::greater<Node>>` 会调用 `operator>`。
> 所以 `f` 小的 Node 会被认为“更大”，从而先出队。第一次看容易绕晕。

### 1.9 私有成员

```cpp
CostMap costs_;
unsigned int width_ = 0;
unsigned int height_ = 0;
Options options_;
std::vector<GridCoord> path_;
Stats stats_;
std::function<bool(unsigned int, uint8_t)> traversability_checker_;
```

**注意**：`plan()` 会修改 `path_`、`stats_`，所以**同一个算法对象不是线程安全的**。
适配层需要保证同一实例不被并发调用（见第 6 节）。

## 2. `astar_algorithm.cpp`：算法实现

### 2.1 匿名命名空间里的常量

```cpp
namespace
{
constexpr uint8_t LETHAL_THRESHOLD = 254;
constexpr uint8_t NO_INFORMATION = 255;
}
```

- `LETHAL_THRESHOLD = 254`：只有 254 是致命障碍；
- `NO_INFORMATION = 255`：未知区域，单独处理；
- 用 `constexpr` 而不是 `#define`，有类型、有作用域。

> 这里没有直接 include `nav2_costmap_2d/cost_values.hpp`，是为了保持算法层
> 不依赖 ROS。数值 254/255 是 Nav2 的约定，作为“算法层与外部世界的契约”写死在这里。
> 如果你要复用到别的系统，改这两个常量即可。

### 2.2 `setCostmap()`

```cpp
void AStarAlgorithm::setCostmap(
  const CostMap & costs, unsigned int width, unsigned int height)
{
  costs_ = costs;
  width_ = width;
  height_ = height;

  if (!traversability_checker_) {
    traversability_checker_ = [](unsigned int, uint8_t cost) {
        return cost < LETHAL_THRESHOLD;
      };
  }
}
```

逐行：

1. `costs_ = costs`：**拷贝**，不是引用。算法对象拥有自己的地图副本；
2. 记录宽高；
3. 如果还没设置判定器，给一个默认的“非 254 即可走”。

> 适配层随后会调用 `setTraversabilityChecker()` 覆盖默认值。
> 默认值只是防止“忘了设置”时崩溃。

### 2.3 `setTraversabilityChecker()`

```cpp
void AStarAlgorithm::setTraversabilityChecker(
  std::function<bool(unsigned int index, uint8_t cost)> checker)
{
  traversability_checker_ = std::move(checker);
}
```

- 参数是 `std::function`，可以传函数指针、lambda、`std::bind`；
- `std::move` 避免拷贝；
- 回调签名带 `index`，方便将来做“基于位置的规则”（比如禁行区）。

### 2.4 `isTraversable()`

```cpp
bool AStarAlgorithm::isTraversable(unsigned int index) const
{
  if (index >= costs_.size()) return false;

  const uint8_t cost = costs_[index];

  if (cost == NO_INFORMATION) {
    if (!options_.allow_unknown || options_.treat_unknown_as_lethal) {
      return false;
    }
    return true;
  }

  if (traversability_checker_) {
    return traversability_checker_(index, cost);
  }
  return cost < LETHAL_THRESHOLD;
}
```

逻辑树：

```text
index 越界？
  └─ 是 → false
  └─ 否 → 取 cost
        ├─ cost == 255？
        │    ├─ allow_unknown == false → false
        │    ├─ treat_unknown_as_lethal == true → false
        │    └─ 否则 → true
        └─ 否则 → 交给 traversability_checker_
                    └─ 没设置 → cost < 254
```

**为什么未知区域要单独处理？**

因为 `allow_unknown` 是“策略”，不是“代价”。255 不是“很贵的障碍”，
而是“不知道”。要不要走，取决于任务（探索 vs 已知地图）。

### 2.5 `heuristic()`

```cpp
double AStarAlgorithm::heuristic(unsigned int from, unsigned int to) const
{
  const int fx = static_cast<int>(from % width_);
  const int fy = static_cast<int>(from / width_);
  const int tx = static_cast<int>(to % width_);
  const int ty = static_cast<int>(to / width_);

  const double dx = std::abs(tx - fx);
  const double dy = std::abs(ty - fy);

  double h;
  if (options_.allow_diagonal) {
    h = (dx + dy) + (std::sqrt(2.0) - 2.0) * std::min(dx, dy);  // Octile
  } else {
    h = dx + dy;                                                // Manhattan
  }

  return h * options_.heuristic_weight;
}
```

**第一步**：一维索引还原成二维坐标：

```text
x = index % width
y = index / width
```

**第二步**：算 Octile 或曼哈顿。

**第三步**：乘权重 `heuristic_weight`。

> 注意：`heuristic_weight` 是在最后乘的。`cost_weight` 是在 `moveCost()` 里加的。
> 两者作用完全不同，不要混。

### 2.6 `moveCost()`

```cpp
double AStarAlgorithm::moveCost(
  unsigned int from, unsigned int to, bool diagonal) const
{
  double cost = diagonal ? std::sqrt(2.0) : 1.0;

  if (options_.cost_weight > 0.0) {
    const uint8_t cell_cost = costs_[to];
    if (cell_cost != NO_INFORMATION) {
      const double normalized = static_cast<double>(cell_cost) / 252.0;
      cost += options_.cost_weight * normalized;
    }
  }

  return cost;
}
```

- 基础代价：直移 1，对角 `√2`；
- 地形代价：取**目标格**的代价，归一化到 0~1，再乘 `cost_weight`；
- 未知区域不加地形代价（它由 `allow_unknown` 管）。

**为什么除以 252？**

Nav2 的代价 0~252 是可通行区间的“连续代价”，253/254/255 是特殊值。
把 0~252 映射到 0~1，方便用 `cost_weight` 控制量级。

### 2.7 `plan()`：主流程

#### 2.7.1 计时与重置

```cpp
const auto t_start = std::chrono::steady_clock::now();
path_.clear();
stats_ = Stats();
```

每次规划都清空上一次的路径和统计。

#### 2.7.2 边界检查

```cpp
if (!inBounds(start.x, start.y)) return Result::START_INVALID;
if (!inBounds(goal.x, goal.y)) return Result::GOAL_INVALID;
```

`inBounds()` 在头文件里：

```cpp
return x >= 0 && y >= 0 &&
       x < static_cast<int>(width_) && y < static_cast<int>(height_);
```

#### 2.7.3 转一维索引

```cpp
const unsigned int start_index = toIndex(start.x, start.y);
const unsigned int goal_index = toIndex(goal.x, goal.y);
```

`toIndex()`：

```cpp
return static_cast<unsigned int>(y) * width_ + static_cast<unsigned int>(x);
```

#### 2.7.4 起点/终点可通行检查

```cpp
if (costs_[start_index] >= LETHAL_THRESHOLD &&
    costs_[start_index] != NO_INFORMATION) {
  // 起点在致命障碍内，仍允许尝试（机器人可能刚被推入），但记录
}
if (!isTraversable(goal_index)) {
  return Result::GOAL_INVALID;
}
```

**重要**：

- 起点的 `if` 是**空代码块**，只留了注释。意思是：**不拒绝起点**。
  即使机器人被推到 254 里，也让它尝试出发（可能能爬出来）。
- 终点必须可通行，否则直接 `GOAL_INVALID`。

> 为什么起点不检查？因为规划器无法把机器人“瞬移”出来；
> 如果起点真的被墙围死，搜索自然会返回 `NO_PATH`。
> 更重要的是：贴墙停车时起点可能是 253，不能因此判死。

#### 2.7.5 起点=终点

```cpp
if (start_index == goal_index) {
  path_.push_back(start);
  stats_.path_length = 1;
  // ... 计时 ...
  return Result::SUCCESS;
}
```

单点路径。适配层还会处理朝向（见 4.5 节）。

#### 2.7.6 分配数组

```cpp
const size_t map_size = static_cast<size_t>(width_) * height_;
const double INF = std::numeric_limits<double>::infinity();

std::vector<double> g_score(map_size, INF);
std::vector<unsigned int> parent(map_size, std::numeric_limits<unsigned int>::max());
std::vector<uint8_t> closed(map_size, 0);
std::vector<uint8_t> in_open(map_size, 0);
```

| 数组 | 初始值 | 作用 |
|---|---|---|
| `g_score` | `∞` | 起点到每个节点的已知最小代价 |
| `parent` | `UINT_MAX` | 回溯路径 |
| `closed` | `0` | 是否已扩展 |
| `in_open` | `0` | 是否已在 open list（用于统计 opened） |

#### 2.7.7 初始化 open list

```cpp
std::priority_queue<Node, std::vector<Node>, std::greater<Node>> open_list;

g_score[start_index] = 0.0;
{
  Node n;
  n.index = start_index;
  n.g = 0.0;
  n.f = heuristic(start_index, goal_index);
  n.parent = start_index;
  open_list.push(n);
  in_open[start_index] = 1;
  stats_.nodes_opened++;
}
```

- 起点 `g=0`；
- `f = h(start)`；
- `parent[start] = start`（回溯时用来终止）；
- `nodes_opened = 1`。

#### 2.7.8 方向数组

```cpp
static const int DIRS[8][2] = {
  {1, 0}, {-1, 0}, {0, 1}, {0, -1},      // 4 直移
  {1, 1}, {1, -1}, {-1, 1}, {-1, -1}     // 4 对角
};
```

- `static`：只初始化一次；
- 前 4 个是直移，后 4 个是对角；
- `dir_count = allow_diagonal ? 8 : 4` 控制用几个。

> 顺序会影响平局时的扩展顺序，但不影响最优性。

#### 2.7.9 主循环开头：取消检查

```cpp
while (!open_list.empty()) {
  if (cancel_checker && (expansions % 256 == 0) && cancel_checker()) {
    return Result::CANCELLED;
  }
```

- 每 256 次扩展检查一次，避免频繁调用回调；
- `expansions` 在下面才自增，所以第一次进入时是 0，会检查一次；
- 返回 `CANCELLED`，适配层会抛 `PlannerCancelled`。

#### 2.7.10 弹出与懒删除

```cpp
Node current = open_list.top();
open_list.pop();
in_open[current.index] = 0;

if (closed[current.index]) continue;
closed[current.index] = 1;
stats_.nodes_expanded++;
```

- 弹出 `f` 最小的节点；
- `in_open` 清零（表示不在 open list 里了）；
- 如果已经 `closed`，说明是旧副本，跳过；
- 否则标记 `closed`，扩展数 +1。

> `in_open` **不是**用来阻止重复 push 的。重复 push 仍然会发生，
> 它只用于统计“有多少不同节点进过 open list”。

#### 2.7.11 到达终点 / 扩展上限

```cpp
if (current.index == goal_index) {
  found = true;
  break;
}

if (++expansions > options_.max_expansions) {
  break;
}
```

- **弹出时**判断终点，保证最优（见 04 第 8 节）；
- 先判断终点，再判断扩展上限，所以 `max_expansions=0` 时起点仍会被扩展一次；
- 超过上限就退出，按 `NO_PATH` 处理。

#### 2.7.12 扩展邻居

```cpp
const int cx = static_cast<int>(current.index % width_);
const int cy = static_cast<int>(current.index / width_);
const int dir_count = options_.allow_diagonal ? 8 : 4;

for (int d = 0; d < dir_count; ++d) {
  const int nx = cx + DIRS[d][0];
  const int ny = cy + DIRS[d][1];

  if (!inBounds(nx, ny)) continue;

  const unsigned int n_index = toIndex(nx, ny);

  if (closed[n_index]) continue;
  if (!isTraversable(n_index)) continue;

  const bool diagonal = (DIRS[d][0] != 0 && DIRS[d][1] != 0);

  if (diagonal) {
    const unsigned int adj1 = toIndex(cx + DIRS[d][0], cy);
    const unsigned int adj2 = toIndex(cx, cy + DIRS[d][1]);
    if (!isTraversable(adj1) || !isTraversable(adj2)) {
      continue;
    }
  }

  const double tentative_g =
    g_score[current.index] + moveCost(current.index, n_index, diagonal);

  if (tentative_g < g_score[n_index]) {
    g_score[n_index] = tentative_g;
    parent[n_index] = current.index;

    Node neighbor;
    neighbor.index = n_index;
    neighbor.g = tentative_g;
    neighbor.f = tentative_g + heuristic(n_index, goal_index);
    neighbor.parent = current.index;
    open_list.push(neighbor);

    if (!in_open[n_index]) {
      in_open[n_index] = 1;
      stats_.nodes_opened++;
    }
  }
}
```

**逐块解释**：

1. **越界**：直接跳过；
2. **closed**：已扩展，跳过；
3. **不可通行**：跳过；
4. **对角切角**：两个相邻直移格都必须可通行，否则跳过；
5. **算 tentative_g**：`g(cur) + move_cost`；
6. **松弛**：只有更优才更新 `g_score`、`parent`、push；
7. **统计**：第一次进 open list 才 `nodes_opened++`。

> 为什么切角检查要放在 `isTraversable(n_index)` 之后？
> 先确认目标格可走，再检查两个相邻格，逻辑上更顺，也少做一次无用检查。

#### 2.7.13 无路径

```cpp
if (!found) {
  // ... 计时 ...
  return Result::NO_PATH;
}
```

注意：`NO_PATH` 包括“真的没路”和“扩展超限”两种情况。
目前没有区分。生产环境可以加一个 `TIMEOUT`/`EXPANSION_LIMIT` 结果。

#### 2.7.14 回溯路径

```cpp
std::vector<GridCoord> reversed;
unsigned int idx = goal_index;
while (idx != start_index) {
  reversed.push_back({static_cast<int>(idx % width_),
                      static_cast<int>(idx / width_)});
  idx = parent[idx];
  if (reversed.size() > map_size) break;   // 防御：parent 链断裂
}
reversed.push_back(start);

path_.assign(reversed.rbegin(), reversed.rend());
```

- 从终点沿 `parent` 往回走；
- 先存成“终点 → 起点”；
- 再反转成“起点 → 终点”；
- 防御性检查防止 `parent` 链成环导致死循环。

#### 2.7.15 统计

```cpp
stats_.path_length = path_.size();
stats_.path_cost = g_score[goal_index];
stats_.planning_time_ms = ...;
```

- `path_cost` 用 `g_score[goal]`，不是重新累加；
- 时间用 `steady_clock`，不受系统时间调整影响。

### 2.8 `gridToWorld()`

```cpp
void AStarAlgorithm::gridToWorld(
  int gx, int gy, double origin_x, double origin_y,
  double resolution, double & wx, double & wy)
{
  wx = origin_x + (static_cast<double>(gx) + 0.5) * resolution;
  wy = origin_y + (static_cast<double>(gy) + 0.5) * resolution;
}
```

- `+0.5` 取格子中心；
- 这是纯数学函数，不依赖任何成员；
- 适配层插值时用它。

## 4. `astar_planner.cpp`：ROS 数据怎么进算法

### 4.1 `configure()`

```cpp
void AStarPlanner::configure(
  const rclcpp_lifecycle::LifecycleNode::WeakPtr & parent,
  std::string name,
  std::shared_ptr<tf2_ros::Buffer> tf,
  std::shared_ptr<nav2_costmap_2d::Costmap2DROS> costmap_ros)
{
  parent_node_ = parent;
  auto node = parent_node_.lock();
  if (!node) {
    throw nav2_core::PlannerException("Failed to lock parent node ...");
  }
  ...
}
```

**为什么先 `lock()` 再判空？**

`WeakPtr` 只是“弱引用”，父节点可能已经被销毁。`lock()` 成功才说明对象还在。
如果失败，抛异常，让 `planner_server` 的 configure 失败，而不是后面空指针崩溃。

```cpp
logger_ = node->get_logger();
clock_ = node->get_clock();

name_ = name;
tf_ = tf;
costmap_ros_ = costmap_ros;
global_frame_ = costmap_ros_->getGlobalFrameID();

astar_ = std::make_unique<AStarAlgorithm>();
```

- `logger_` 用父节点的 logger，日志前缀会是 `planner_server`；
- `clock_` 用父节点的 clock，仿真时 `use_sim_time` 才正确；
- `name_` 是实例名，例如 `GridBased`；
- `global_frame_` 从 costmap 拿，通常是 `map`；
- 创建算法对象。

#### 参数声明与读取

每个参数都是同样的三步：

```cpp
nav2_util::declare_parameter_if_not_declared(
  node, name_ + ".allow_diagonal", rclcpp::ParameterValue(true));
node->get_parameter(name_ + ".allow_diagonal", allow_diagonal_);
```

1. 如果参数没声明，用默认值声明；
2. 从节点读入成员。

**参数名 = `name_ + "." + 参数名`**。

> 如果 YAML 里没写，`declare_parameter_if_not_declared` 会声明默认值，
> `get_parameter` 读到默认值，不会报错。
> 如果 YAML 里写了但名字不对，代码读的是另一个参数，还是默认值——
> 这就是“调参没用”的根因。

#### 最后的日志

```cpp
RCLCPP_INFO(
  logger_,
  "AStarPlanner(%s) 已配置: allow_diagonal=%d, allow_unknown=%d, "
  "cost_weight=%.2f, heuristic_weight=%.2f, interpolation_resolution=%.3f",
  name_.c_str(), ...);
```

启动时看到这行，说明 `configure` 成功，参数也读到了。

### 4.2 `cleanup()` / `activate()` / `deactivate()`

```cpp

{
  RCLCPP_INFO(logger_, "AStarPlanner(%s) 清理资源", name_.c_str());

}
```

### 4.3 `createPlan()` 总览

```cpp
nav_msgs::msg::Path AStarPlanner::createPlan(
  const geometry_msgs::msg::PoseStamped & start,
  const geometry_msgs::msg::PoseStamped & goal,
  std::function<bool()> cancel_checker)
{
  // 1. 准备返回消息
  // 2. 防御性检查
  // 3. 取 costmap + 加锁
  // 4. worldToMap
  // 5. 终点障碍检查
  // 6. 起点=终点
  // 7. 拷贝 costmap
  // 8. 设置可通行判定 + 选项
  // 9. 调算法 + 翻译错误
  // 10. 插值 + 朝向
  return global_path;
}
```

下面逐段看。

#### 4.3.1 准备返回消息

```cpp
nav_msgs::msg::Path global_path;
global_path.header.stamp = clock_->now();
global_path.header.frame_id = global_frame_;
```

- `stamp` 用 ROS 时间；
- `frame_id` 必须是全局坐标系；
- 后面 `interpolatePath()` 会重新设置 header，但这里先设一份，保证早退路径也正确。

#### 4.3.2 防御性检查

```cpp
if (!astar_) {
  throw nav2_core::PlannerException("AStarPlanner 尚未 configure");
}

costmap_ = costmap_ros_->getCostmap();
if (!costmap_) {
  throw nav2_core::PlannerException("无法获取代价地图");
}
```

- 如果 `configure` 没调用或 `cleanup` 已释放，`astar_` 为空；
- `getCostmap()` 返回裸指针，可能为空（未配置）。

#### 4.3.3 加锁

```cpp
std::unique_lock<nav2_costmap_2d::Costmap2D::mutex_t> lock(
  *(costmap_->getMutex()));
```

- `unique_lock` 出作用域自动解锁；
- 锁的是 `Costmap2D` 的 mutex；
- 整个 `createPlan` 都持锁（本项目为教学简化）。

> 生产环境可以只锁“读地图 + 拷贝”这一段，然后释放锁再跑算法。
> 但要注意：`costmap_` 指针本身和元数据也可能变，释放锁后不要再访问。

#### 4.3.4 `worldToMap`

```cpp
if (!costmap_->worldToMap(
    start.pose.position.x, start.pose.position.y, mx_start, my_start))
{
  throw nav2_core::StartOutsideMapBounds(...);
}
```

`worldToMap` 内部大致是：

```text
mx = (wx - origin_x) / resolution
my = (wy - origin_y) / resolution
if 越界 return false
```

失败原因可能是：

- 坐标在地图外；
- 坐标是 `NaN`/`inf`；
- 地图尺寸为 0。

#### 4.3.5 终点障碍检查

```cpp
if (costmap_->getCost(mx_goal, my_goal) ==
    nav2_costmap_2d::LETHAL_OBSTACLE)
{
  throw nav2_core::GoalOccupied(...);
}
```

只检查 `254`：

- `253` 在本项目里按“可通行的高代价区”处理（注意：这是宽松策略，
  严格 footprint 检查下 253 可能已经碰撞）；
- `255` 交给 `allow_unknown`；
- 起点不检查（见算法层）。

#### 4.3.6 起点=终点

```cpp
if (mx_start == mx_goal && my_start == my_goal) {
  geometry_msgs::msg::PoseStamped pose;
  pose.header = global_path.header;
  pose.pose = start.pose;
  if (!use_final_approach_orientation_) {
    pose.pose.orientation = goal.pose.orientation;
  }
  global_path.poses.push_back(pose);
  return global_path;
}
```

两种朝向策略：

- `use_final_approach_orientation_ == false`：最终朝向 = 目标朝向（用户点的方向）；
- `true`：保留起点朝向（避免原地转向）。

#### 4.3.7 拷贝代价地图

```cpp
const unsigned int size_x = costmap_->getSizeInCellsX();
const unsigned int size_y = costmap_->getSizeInCellsY();
const unsigned char * char_map = costmap_->getCharMap();

std::vector<uint8_t> costs(
  char_map, char_map + static_cast<size_t>(size_x) * size_y);
astar_->setCostmap(costs, size_x, size_y);
```

- `getCharMap()` 返回 `unsigned char*`；
- 用迭代器区间构造 `vector<uint8_t>`，完成拷贝；
- 之后算法拥有自己的副本。

> 注意 `static_cast<size_t>(size_x) * size_y`，避免 `unsigned int` 乘法溢出
> （384×384 不会溢出，但大地图要注意）。

#### 4.3.8 可通行判定

```cpp
const bool allow_unknown = allow_unknown_;
astar_->setTraversabilityChecker(
  [allow_unknown](unsigned int, uint8_t cost) -> bool {
    if (cost == nav2_costmap_2d::NO_INFORMATION) {
      return allow_unknown;
    }
    return cost < nav2_costmap_2d::LETHAL_OBSTACLE;
  });
```

- lambda 捕获 `allow_unknown` 的**副本**；
- 255 由 `allow_unknown` 决定；
- 其余 `< 254` 可走，`>= 254` 不可走（实际只有 254）。

> 为什么不用 `this` 捕获？因为 lambda 可能比 `this` 活得久（虽然这里不会），
> 捕获副本更安全，也更清晰。

#### 4.3.9 同步选项

```cpp
astar_->setOptionOverrides(
  allow_diagonal_, allow_unknown_, cost_weight_,
  heuristic_weight_, max_expansions_);
```

每次规划前同步，保证参数变化能生效（虽然本项目没有动态参数）。

#### 4.3.10 调试日志

```cpp
RCLCPP_DEBUG(
  logger_,
  "A* 规划请求: 地图=%ux%u 起点=(%d,%d) 终点=(%d,%d)",

```

默认不打印，`--log-level debug` 时才显示。

```cpp
switch (result) {
```

#### 4.3.15 终点朝向

```cpp
if (!global_path.poses.empty()) {
  global_path.poses.back().pose.orientation = goal.pose.orientation;
}
```

先把最后一个点的朝向设成用户目标朝向。

```cpp
if (use_final_approach_orientation_ && global_path.poses.size() >= 2) {
  const auto & last = global_path.poses.back().pose.position;
  const auto & prev = global_path.poses[global_path.poses.size() - 2].pose.position;
  const double theta = std::atan2(last.y - prev.y, last.x - prev.x);
  global_path.poses.back().pose.orientation.x = 0.0;
  global_path.poses.back().pose.orientation.y = 0.0;
  global_path.poses.back().pose.orientation.z = std::sin(theta / 2.0);
  global_path.poses.back().pose.orientation.w = std::cos(theta / 2.0);
}
```

如果 `use_final_approach_orientation_ == true`，用倒数第二个点到最后一点的方向
作为最终朝向，避免机器人在终点原地转向。

### 4.4 `interpolatePath()`

#### 4.4.1 准备

```cpp
nav_msgs::msg::Path path;
path.header.stamp = clock_->now();
path.header.frame_id = global_frame_;

const double resolution = costmap->getResolution();
const double origin_x = costmap->getOriginX();
const double origin_y = costmap->getOriginY();

if (interpolation_resolution <= 0.0) {
  interpolation_resolution = resolution;
}
```

- 重新设置 header；
- 取地图分辨率/原点；
- 如果参数非法（≤0），退化为地图分辨率。

#### 4.4.2 加入起点

```cpp
double wx, wy;
AStarAlgorithm::gridToWorld(
  grid_path.front().x, grid_path.front().y,
  origin_x, origin_y, resolution, wx, wy);

geometry_msgs::msg::PoseStamped pose;
pose.header = path.header;
pose.pose.position.x = wx;
pose.pose.position.y = wy;
pose.pose.position.z = 0.0;
pose.pose.orientation.w = 1.0;
path.poses.push_back(pose);
```

- 取第一个格子中心；
- 朝向先设为单位四元数（后面统一算切线）。

#### 4.4.3 逐段插值

```cpp
for (size_t i = 1; i < grid_path.size(); ++i) {
  // 取相邻两个格子的世界坐标
  ...
  const double dx = wx_cur - wx_prev;
  const double dy = wy_cur - wy_prev;
  const double segment_length = std::hypot(dx, dy);

  const int num_steps = std::max(
    1, static_cast<int>(segment_length / interpolation_resolution));

  for (int s = 1; s <= num_steps; ++s) {
    const double t = static_cast<double>(s) / num_steps;
    ...
    pose.pose.position.x = wx_prev + t * dx;
    pose.pose.position.y = wy_prev + t * dy;
    ...
  }
}
```

**数学**：

```text
P(t) = P_prev + t * (P_cur - P_prev),  t ∈ [0, 1]
```

- `num_steps = max(1, floor(segment_length / interp))`；
- 每段至少插 1 个点（即终点）；
- `s` 从 1 开始，避免重复添加上一段的终点。

> 如果 `segment_length` 正好是 `interp` 的整数倍，点数刚好；
> 如果不是，最后一段会略短，但不会超过 `interp`。

#### 4.4.4 朝向

```cpp
for (size_t i = 0; i < path.poses.size(); ++i) {
  const size_t next = std::min(i + 1, path.poses.size() - 1);
  const size_t prev = (i == 0) ? 0 : i - 1;
  const double dx = path.poses[next].pose.position.x - path.poses[prev].pose.position.x;
  const double dy = path.poses[next].pose.position.y - path.poses[prev].pose.position.y;
  if (std::hypot(dx, dy) > 1e-9) {
    const double yaw = std::atan2(dy, dx);
    path.poses[i].pose.orientation.z = std::sin(yaw / 2.0);
    path.poses[i].pose.orientation.w = std::cos(yaw / 2.0);
  }
}
```

- 用“前一个点 → 后一个点”的方向作为切线；
- 第一个点用 `0 → 1`；
- 最后一个点用 `n-2 → n-1`；
- 如果两点重合（`hypot < 1e-9`），保留单位四元数。

> 为什么用中心差分（`next - prev`）而不是前向差分（`next - cur`）？
> 中心差分更平滑，转弯处朝向不会突变。

### 4.5 导出宏

```cpp
PLUGINLIB_EXPORT_CLASS(
  nav2_astar_planner::AStarPlanner, nav2_core::GlobalPlanner)
```

- 必须在**全局命名空间**（不在 `namespace` 里）；
- 两个参数：你的类、基类；
- 宏会生成 pluginlib 需要的工厂函数/符号；
- 没有它，`dlopen` 成功也找不到类。

## 5. 注册四件套：插件怎么被加载

### 5.1 `global_planner_plugin.xml`

```xml
<library path="nav2_astar_planner">
  <class type="nav2_astar_planner::AStarPlanner"
         base_class_type="nav2_core::GlobalPlanner">
    <description>基于 A* 算法的全局路径规划器（教学实现）</description>
  </class>
</library>
```

| 字段 | 值 | 规则 |
|---|---|---|
| `library path` | `nav2_astar_planner` | `.so` 文件名去掉 `lib` 和 `.so` |
| `type` | `nav2_astar_planner::AStarPlanner` | C++ 类全名 |
| `base_class_type` | `nav2_core::GlobalPlanner` | 基类全名 |
| `description` | 任意 | 给人看的 |

### 5.2 `package.xml`

```xml
<export>
  <build_type>ament_cmake</build_type>
  <nav2_core plugin="${prefix}/global_planner_plugin.xml"/>
</export>
```

`${prefix}` 是安装后的包目录。这行会让 ament 在：

```text
install/nav2_astar_planner/share/ament_index/resource_index/
  nav2_core__pluginlib__plugin/nav2_astar_planner
```

生成一个索引文件，内容是 XML 的相对路径。

> 注意索引目录名是 `nav2_core__pluginlib__plugin`，不是 `nav2_core`。
> 这是 pluginlib 的命名约定：`<base_package>__pluginlib__plugin`。

### 5.3 `CMakeLists.txt`

```cmake
pluginlib_export_plugin_description_file(nav2_core global_planner_plugin.xml)
install(FILES global_planner_plugin.xml DESTINATION share/${PROJECT_NAME})
```

- 第一行：把 XML 登记到 ament index；
- 第二行：把 XML 装到 `share/`，让索引里的路径能解析。

### 5.4 `.cpp`

```cpp
#include "pluginlib/class_list_macros.hpp"
PLUGINLIB_EXPORT_CLASS(
  nav2_astar_planner::AStarPlanner, nav2_core::GlobalPlanner)
```

### 5.5 完整加载链路

```text
planner_server 构造
  └─ ClassLoader<GlobalPlanner> loader("nav2_core", "nav2_core::GlobalPlanner")
       └─ 扫描 ament index
            └─ 找到 nav2_astar_planner 的 XML
                 └─ 读到 type="nav2_astar_planner::AStarPlanner"
                      └─ createUniqueInstance(...)
                           └─ dlopen("libnav2_astar_planner.so")
                                └─ 找 PLUGINLIB_EXPORT_CLASS 生成的符号
                                     └─ new AStarPlanner()
                                          └─ planner->configure(...)
```

```cpp
name_ = name;   // "GridBased"
```

`astar_simulation_launch.py` 用 `IncludeLaunchDescription` 复用官方
`tb3_simulation_launch.py`，只传 `params_file`。

- Gazebo、机器人模型、桥接、TF、RViz 全部沿用官方；
- 只替换规划器参数，风险最小；
- 官方更新时，仿真部分自动受益。

## 8. 修改指南：想改什么，改哪里

| 你想改 | 改哪个文件 | 注意 |
|---|---|---|
| 换启发式（曼哈顿/Octile/欧氏） | `astar_algorithm.cpp` 的 `heuristic()` | 必须匹配邻域 |
| 换邻域（4/8） | `Options::allow_diagonal` + `DIRS` | h 也要跟着换 |
| 换移动代价 | `moveCost()` | 保持非负 |
| 加地形代价 | `moveCost()` + `cost_weight` | 归一化量级 |
| 加路径平滑 | `interpolatePath()` 或后处理 | 不要破坏起终点 |
| 加终点容差 | `Options` + `plan()` + 适配层 | 参考 Navfn |
| 加新参数 | `configure()` + 成员 + YAML | 必须带 `name_` 前缀 |
| 加动态参数 | `activate()` 注册回调 | `deactivate()` 移除 |
| 换可通行规则 | `createPlan()` 的 lambda | 注意 253/254/255 |
| 加足迹碰撞检查 | `createPlan()` 或算法层 | 需要 footprint |
| 换算法（Dijkstra/Theta*） | `astar_algorithm.cpp` | 保持 `plan()` 契约 |
| 改返回消息 | `createPlan()` | 保持 frame_id/时间戳 |
| 改插件类型（Controller） | 换基类 + 核心方法 + XML | 见 05 第 9 节 |

### 8.1 不要改的地方（除非你很清楚）

| 地方 | 为什么 |
|---|---|
| `global_frame_` 的来源 | 必须和 costmap 一致 |
| `PLUGINLIB_EXPORT_CLASS` 的基类 | 必须和 XML 的 `base_class_type` 一致 |
| `package.xml` 的导出标签 | 少了插件就找不到 |
| 异常类型 | 影响行为树恢复 |
| `start`/`goal` 的坐标系假设 | 上游已经转换好，不要重复转 |
| costmap 锁 | 去掉会有竞态 |

## 9. 十个理解检查题

先自己回答，再看答案。

### 9.1 题目

1. `astar_algorithm.hpp` 为什么没有 ROS 头文件？
2. `in_open` 数组的作用是什么？它阻止重复 push 吗？
3. `Node::parent` 字段有用吗？
4. 起点在 254 时，算法为什么还继续？
5. 为什么终点检查用 `== 254`，而不是 `>= 253`？
6. `heuristic_weight` 和 `cost_weight` 分别影响什么？
7. `createPlan` 为什么不能返回空 `Path` 表示失败？
8. 为什么 `interpolatePath` 要给每个点设置朝向？
9. `use_final_approach_orientation` 解决什么问题？
10. 插件注册四件套具体是哪四个？各自作用是什么？

### 9.2 答案

1. 为了分层：算法层不依赖 ROS，可以单独编译、单测、复用。
2. 标记节点是否在 open list 中，只用于统计 `nodes_opened`；**不阻止**重复 push。
   重复 push 由 `closed` + 懒删除处理。
3. 目前没用到。回溯用的是 `parent` 数组；`Node::parent` 是冗余字段，可以删。
4. 机器人可能被推入障碍，或被膨胀层包围；拒绝起点没有意义，让搜索自然失败。
5. 253 是内切膨胀，不是物理障碍；但严格按 footprint 检查时它可能已经碰撞，
   是否允许走是策略问题。本项目选择允许，以保证贴墙起点能出发。
6. `heuristic_weight` 乘在 h 上，影响搜索方向/速度/最优性；
   `cost_weight` 加在移动代价上，影响路径是否远离高代价区。
7. 空 Path 会被上层当成“成功但没路径”，行为树的恢复逻辑不会触发；
   抛异常才能让 `planner_server` 填正确的 `error_code`。
8. 控制器需要知道每个路径点的朝向，才能算角速度；朝向沿切线更平滑。
9. 避免机器人到达终点后原地旋转到目标朝向；用路径切线作为末端朝向。
10. ① `package.xml` 的 `<nav2_core plugin=...>`；
    ② `CMakeLists` 的 `pluginlib_export_plugin_description_file`；
    ③ 插件 XML；
    ④ `.cpp` 的 `PLUGINLIB_EXPORT_CLASS`。

## 10. 改动实验：改一行，预测结果

> 做这些实验前先备份，或用 git 管理。每次只改一处，重新编译，观察日志。

### 实验 1：把可通行阈值改成 `< 253`

```cpp
// astar_algorithm.cpp 或 createPlan 的 lambda
return cost < 253;
```

预测：贴墙停车时起点可能是 253，A* 会报“无路可走”，扩展节点数很少。
验证：看日志 `扩展 N 节点`，N 会骤降。

### 实验 2：把启发式改成 0

```cpp
double heuristic(...) const { return 0.0; }
```

预测：A* 退化成 Dijkstra，扩展节点数明显增加，路径代价不变。
验证：对比 `--demo-map --compare` 的扩展数。

### 实验 3：去掉对角切角检查

注释掉：

```cpp
if (diagonal) { ... }
```

预测：路径会从两个障碍的缝隙斜穿，可能贴角。
验证：在 RViz 里看路径是否穿过障碍角。

### 实验 4：把 `heuristic_weight` 调到 3.0

```yaml
heuristic_weight: 3.0
```

预测：扩展节点数减少，规划更快，但路径可能变长/更贴墙。
验证：看日志的扩展数和路径代价。

### 实验 5：把 `interpolation_resolution` 调到 1.0

```yaml
interpolation_resolution: 1.0
```

预测：路径点变稀疏，控制器跟踪可能抖动或切角。
验证：`ros2 topic echo /plan` 看 `poses` 数量。

### 实验 6：注释掉 costmap 锁

注释掉：

```cpp
std::unique_lock<...> lock(...);
```

预测：多数时候看不出问题，但高负载/频繁更新时可能出现路径飘忽、偶发穿墙。
**不要在生产环境这样做。**

### 实验 7：把终点朝向那行删掉

```cpp
// global_path.poses.back().pose.orientation = goal.pose.orientation;
```

预测：终点朝向变成路径切线方向；如果 `use_final_approach_orientation=false`，
机器人可能不会转到用户指定朝向。

### 实验 8：把 `max_expansions` 设为 10

```yaml
max_expansions: 10
```

预测：稍微复杂的地图就报“无路可走”，但耗时很短。
验证：看日志扩展数被截断。
