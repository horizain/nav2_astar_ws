# 控制器实验手册

> **配套代码**：`src/nav2_controller_lab/`
> **理论背景**：先读 [08 控制器算法学习路线](08_控制器算法学习路线.md)。
>
> 这篇是“实验课”：用同一个 A* 全局规划器、同一张地图、同一个目标，
> 依次跑 PID / Pure Pursuit / Stanley / DWB-lite / MPPI-lite / MPC-lite，
> 记录数据，理解每个参数到底改变了什么。

## 1. 启动

```bash
./run_controller_lab.sh
```

操作：

1. RViz 里 **2D Pose Estimate**，在 `(-2.0, -0.5)` 拖出朝向；
2. 如果终端报 `Aborting bringup`，执行 `./activate_nav.sh`；
3. **Nav2 Goal** 点目标，例如 `(1.5, 0.5)`。

确认当前控制器：

```bash
ros2 param get /controller_server FollowPath.plugin
```

默认应为：

```text
nav2_controller_lab::PurePursuitController
```

## 2. 切换控制器

只改一个地方：

```text
src/nav2_controller_lab/params/nav2_params_controller_lab.yaml
```

`controller_server.ros__parameters.FollowPath.plugin`。

可选项：

```text
nav2_controller_lab::PidController
nav2_controller_lab::PurePursuitController
nav2_controller_lab::StanleyController
nav2_controller_lab::DwbController
nav2_controller_lab::MppiController
```

每个控制器的完整参数块见
[`src/nav2_controller_lab/README.md`](../src/nav2_controller_lab/README.md) 第 5 节。

> 修改 `plugin` 类型或参数后，需要重新启动 launch（参数在 `configure` 阶段读取）。
> 当前参数文件已经加载了 6 个实例，所以也可以直接用下面的运行时切换。

### 2.1 运行时切换（不用重启）

当前参数文件已经一次性加载 6 个实例：

```text
FollowPath (Pure Pursuit) / PID / Stanley / DWB / MPPI / MPC
```

直接发布实例名：

```bash
ros2 topic pub --once /controller_selector std_msgs/msg/String \
  "{data: DWB}" \
  --qos-durability transient_local \
  --qos-reliability reliable
```

切回默认：

```bash
ros2 topic pub --once /controller_selector std_msgs/msg/String \
  "{data: FollowPath}" \
  --qos-durability transient_local \
  --qos-reliability reliable
```

> 必须加 `--qos-durability transient_local`，因为行为树的
> `ControllerSelector` 订阅端是 transient_local。

### 2.2 RViz 面板

启动 `./run_controller_lab.sh` 后，RViz 左侧会出现 **Controller Lab** 面板：

- `Pure Pursuit / PID / Stanley / DWB-lite / MPPI-lite / MPC-lite` 六个按钮；
- 显示当前控制器和 `/cmd_vel`；
- “显示调试标记”复选框；
- `Controller Lab Markers` 显示 `/controller_lab/markers`：
  - 绿色：全局路径；
  - 黄色：前视点 + 机器人到前视点连线；
  - 蓝色：按当前速度预测的 2 秒轨迹；
  - 白色文字：控制器名、v/w。

如果面板没有自动出现：

```text
Panels → Add New Panel → nav2_controller_lab_rviz/Controller Lab
```

如果标记没有出现：

```text
Add → By topic → /controller_lab/markers → MarkerArray
```

> 修改 `params/*.yaml` 后要重新 `colcon build --packages-select nav2_controller_lab`
> （或使用 `--symlink-install`），因为 launch 读的是 `install/` 里的副本。

## 3. 实验一：Pure Pursuit 的 lookahead

固定：

- 全局规划器：A*
- 起点：`(-2.0, -0.5)`
- 终点：`(1.5, 0.5)`
- `max_linear_velocity: 0.5`

只改：

```yaml
lookahead_distance: 0.3
```

然后依次试：

| 组 | `lookahead_distance` | `min` | `max` |
|---|---:|---:|---:|
| A | 0.3 | 0.2 | 0.5 |
| B | 0.6 | 0.3 | 1.2 |
| C | 1.0 | 0.5 | 1.5 |
| D | 1.5 | 0.8 | 2.0 |

每组跑 3 次，记录：

| 指标 | 怎么取 |
|---|---|
| 到达时间 | `NavigateToPose` 总耗时 |
| 横向误差 | 机器人到 `/plan` 的距离 |
| 最大角速度 | `/cmd_vel` 的 `angular.z` |
| 是否碰撞 | Gazebo/RViz |
| 主观稳定性 | 摆动/切角 |

预期：

- A：更贴线，但容易左右摆动；
- B：较平衡；
- C/D：更稳，但弯道切内角，可能离障碍更近。

> 结论：`L` 不是越大越好，也不是越小越好。它是在“稳定性”和“贴线”
> 之间调平衡。

## 4. 实验二：PID vs Pure Pursuit vs Stanley

同一张地图、同一个目标，分别跑：

```yaml
# PID
plugin: "nav2_controller_lab::PidController"

# Pure Pursuit
plugin: "nav2_controller_lab::PurePursuitController"

# Stanley
plugin: "nav2_controller_lab::StanleyController"
```

记录：

| 控制器 | 到达时间 | 横向误差 | 最大角速度 | 弯道表现 | 备注 |
|---|---:|---:|---:|---|---|
| PID | | | | | 直线还行，弯道滞后 |
| Pure Pursuit | | | | | 切内弯 |
| Stanley | | | | | 更贴线，可能振荡 |

预期现象：

- PID 在直线上表现不差，但弯道有明显滞后；
- Pure Pursuit 稳定，但会切内弯；
- Stanley 更贴线，速度高时可能需要降低 `k_cross`。

> 这就是“PID 不是完整路径跟踪器”的直观证据：它只根据当前误差纠偏，
> 没有 lookahead，也没有对弯道的预判。

## 5. 实验三：DWB-lite 的障碍权重

切换：

```yaml
plugin: "nav2_controller_lab::DwbController"
```

在机器人前方放一个障碍（或在 Gazebo 里把机器人放到窄通道附近），
只改：

```yaml
obstacle_weight: 0.0
obstacle_weight: 50.0
obstacle_weight: 500.0
```

观察：

- 0：路径可能贴障碍；
- 50：开始绕行；
- 500：明显远离障碍，但可能绕远或卡住。

再改 `collision_threshold`：

```yaml
collision_threshold: 253   # 更保守
collision_threshold: 254   # 只把真实障碍当碰撞
```

> DWB 的价值是“显式评估未来轨迹 + 局部障碍”，这是 Pure Pursuit/Stanley
> 没有的。

## 6. 实验四：MPPI-lite 的温度与采样

切换：

```yaml
plugin: "nav2_controller_lab::MppiController"
```

### 6.1 温度

```yaml
temperature: 0.05
temperature: 0.3
temperature: 2.0
```

观察：

- 温度低：更“选最优”，可能抖动/激进；
- 温度高：更平滑，但可能不够贴线。

### 6.2 采样量

```yaml
batch_size: 20
batch_size: 100
batch_size: 300
```

观察：

- 采样少：快，但行为粗糙；
- 采样多：平滑，但 CPU 升高。

用 `top` 或 `ros2 topic hz /cmd_vel` 观察实时性。

> 官方 MPPI 默认 `batch_size: 2000`，因为它有高度优化的实现；
> 教学版为了可读性，默认 100。

## 7. 评价指标怎么采

### 7.1 横向误差

最简单的做法：录制 `/plan` 和 `/tf`，离线用 Python 计算机器人到路径折线的距离。
也可以直接在控制器日志里打印 `projection.distance`（需要自己加一行 DEBUG）。

### 7.2 最大角速度

```bash
ros2 topic echo /cmd_vel --field angular.z
```

### 7.3 到达时间

```bash
ros2 action send_goal /navigate_to_pose \
  nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.5, y: 0.5}, orientation: {w: 1.0}}}}" \
  --feedback
```

结果里的 `status` 和耗时就是指标。

### 7.4 轨迹录制

```bash
ros2 bag record /plan /cmd_vel /tf /tf_static -o controller_lab_run
```

后续可以离线画图，或在 RViz 里回放。

## 9. 常见问题

| 现象 | 检查 |
|---|---|
| 控制器不加载 | `ros2 param get /controller_server FollowPath.plugin` |
| 参数没生效 | `ros2 param list /controller_server \| grep FollowPath` |
| 机器人不动 | `ros2 topic echo /cmd_vel`；看控制器是否抛 `NoValidControl` |
| 原地转圈 | 检查路径 frame / 机器人朝向 / `map→odom` |
| Pure Pursuit 摆动 | 增大 `lookahead` |
| Stanley 振荡 | 降低 `k_cross`，降低速度 |
| DWB 不动 | 所有轨迹碰撞；调 `collision_threshold`、`obstacle_weight` |
| MPPI 很慢 | 降 `batch_size` / `time_steps` |
| MPC 抖动/很慢 | 降 `gradient_step` / `iterations` / `horizon_steps` |
| 到点不停 | 看 `goal_checker` 和 `goal_tolerance` |
