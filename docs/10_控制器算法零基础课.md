## 0. 先建立控制问题的图景

### 0.1 全局规划 vs 局部控制

```text
全局规划（A*）：
  输入：地图、起点、终点
  输出：一条从起点到终点的路径（nav_msgs/Path）
  频率：按需 / 约 1 Hz 重规划

局部控制（Controller）：
  输入：全局路径、机器人当前位姿、局部代价地图、当前速度
  输出：v（线速度）、ω（角速度）
  频率：约 10~20 Hz
```

全局规划只回答“大概走哪条路”；控制器回答“这一刻轮子该怎么转”。

### 0.2 差速机器人模型

本项目仿真的是差速底盘（TurtleBot3）：

```text
状态：x, y, θ
控制：v（前进速度 m/s）, ω（角速度 rad/s）

x'     = v cosθ
y'     = v sinθ
θ'     = ω
```

**关键约束**：差速车不能横着走。你不能直接命令 `v_y`。
所有控制器最终都必须输出 `v` 和 `ω`。

### 0.3 坐标系

```text
map（全局地图）
  └── odom（里程计连续坐标）
        └── base_link（机器人本体）
```

- 全局路径在 `map`；
- 局部代价地图和机器人位姿在 `odom`；
- 控制器必须做 TF 变换，否则路径会“错位”。

### 0.4 控制循环

```text
每个控制周期（20 Hz）：
  1. 取机器人当前位姿（odom）
  2. 取全局路径（map）
  3. 把路径变换到 odom
  4. 算一个控制量 (v, ω)
  5. 发布 /cmd_vel
  6. 等下一个周期
```

控制器是**闭环**：它不断看当前位姿，不断修正。

## 1. PID 从零开始

### 1.1 PID 是什么

PID 是最常见的反馈控制律：

```text
u(t) = Kp · e(t) + Ki · ∫e(t)dt + Kd · de(t)/dt
```

- `e(t)`：当前误差（目标 - 实际）
- `Kp`：比例项，误差越大，输出越大
- `Ki`：积分项，消除稳态误差
- `Kd`：微分项，抑制变化，增加阻尼

离散实现：

```text
integral += e * dt
derivative = (e - prev_e) / dt
u = Kp*e + Ki*integral + Kd*derivative
prev_e = e
```

### 1.2 用 PID 跟踪路径：先选误差

路径跟踪至少有两个误差：

| 误差 | 含义 |
|---|---|
| 航向误差 `e_θ` | 路径切线方向 - 车头方向 |
| 横向误差 `e_y` | 机器人到路径的垂直距离 |

本项目约定：

> **机器人在路径左侧时，`e_y > 0`。**

因此修正方向是：

```text
ω = kp_θ·e_θ + ki_θ·∫e_θ + kd_θ·d(e_θ)/dt - kp_y·e_y
```

`e_y` 前面是负号：机器人在左边，要向右转（负角速度）回到路径。

### 1.3 手算一个例子

路径沿 +x 方向，机器人位于 `(0, 1, 0)`：

```text
e_θ = 0
e_y = +1（机器人在路径左侧）
```

如果 `kp_y = 0.6`：

```text
ω = -0.6 rad/s
```

负角速度 = 顺时针 = 向右转，正确。

### 1.4 速度怎么给

最简单：

```text
v = v_max
```

更合理：

```text
v = v_max · (1 - 0.7·min(1, |e_θ|/θ_slow))
```

- 航向误差大时减速；
- 快到终点时按剩余距离减速。

### 1.5 PID 的问题

| 问题 | 原因 |
|---|---|
| 弯道滞后 | 只看当前误差，没有前视 |
| 高速振荡 | 增益固定，延迟相对变大 |
| 积分 windup | 输出饱和时积分继续累积 |
| 无法避障 | PID 不知道局部代价地图 |
| 不能处理运动学约束 | 需要额外把控制量映射到 v/ω |
| 参考点难选 | 最近点？前视点？按时间采样点？ |

结论：PID 是**内环/分量**，不是完整的路径跟踪器。

## 2. Pure Pursuit（纯跟踪）

### 2.1 直觉

不要盯着脚下，盯着前方一个点：

```text
                     ● P（前视点）
                    /
                   /  L
                  /
                 ● 机器人
```

机器人沿着“当前位置 → 前视点”的圆弧走。

### 2.2 几何推导

机器人坐标系下，前视点 `P = (x, y)`，距离 `L = √(x²+y²)`。

走一段圆弧，弦长 `L`，曲率 `κ = 1/R`。由几何关系：

```text
κ = 2y / (x² + y²) = 2y / L²
```

角速度：

```text
ω = v · κ = 2vy / L²
```

### 2.3 算法步骤

```text
1. 找到路径上离机器人最近的点 C
2. 从 C 沿路径向前走，找到距离机器人约 L 的点 P
3. 把 P 变换到机器人坐标系 (x, y)
4. κ = 2y / (x² + y²)
5. ω = v · κ
6. v 按曲率/终点距离/障碍调节
```

### 2.4 手算例子

机器人 `(0,0,0)`，路径沿 +x，前视点 `P=(2,0)`：

```text
x=2, y=0
κ = 0
ω = 0
```

前视点 `P=(2,1)`：

```text
x=2, y=1, L²=5
κ = 2/5 = 0.4
v=0.5 时 ω=0.2 rad/s
```

正角速度 = 逆时针 = 向左转，正确。

### 2.5 前视距离 L 的影响

| L | 效果 |
|---|---|
| 太小 | 贴线，但容易左右摆动 |
| 太大 | 稳定，但切内弯、离障碍近 |
| 自适应 `L = v·t` | 速度越快，看得越远 |

本项目参数：

```yaml
lookahead_distance: 0.6
min_lookahead_distance: 0.3
max_lookahead_distance: 1.2
use_velocity_scaled_lookahead: true
lookahead_time: 1.0
```

### 2.6 速度调节

```text
v = v_max
  × min(1, remaining / slow_radius)
  × (1 - curvature_slowdown · min(1, |κ|·v_max/ω_max))
```

- 快到终点减速；
- 曲率大时减速，避免甩出去。

### 2.7 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 左右摆动 | L 太小 | 增大 L |
| 切内弯 | L 太大 | 减小 L |
| 前视点在身后 | 路径起点/倒车 | 特殊处理或缩小 L |
| 原地转圈 | 位姿/坐标系错 | 检查 TF |
| 不减速 | 没做终点/曲率减速 | 加 `slowdown_radius` |

### 2.8 对应代码

- 核心：`pure_pursuit_core.cpp`
- 前视点：`path_utils.cpp` 的 `findLookaheadPoint()`
- 投影：`projectOntoPath()`
- 适配：`pure_pursuit_controller.cpp`

## 3. Stanley

### 3.1 直觉

Pure Pursuit 看前方点；Stanley 看**前轴到路径的横向误差**，
同时修正航向。

```text
δ = k_heading·ψ_e - atan(k_cross·e / (v + ε))
```

- `ψ_e`：航向误差；
- `e`：前轴到路径的横向误差（机器人在左为正）；
- `k_cross`：横向增益；
- 速度越低，`atan(e/v)` 越大，转向越激进。

### 3.2 差速车怎么用

Stanley 原本给阿克曼车算舵角 `δ`。差速车可以换算：

```text
ω = v · tan(δ) / wheelbase
```

或者直接用比例形式：

```text
ω = k_heading·ψ_e - k_cross·e/(v+ε)
```

### 3.3 手算例子

路径沿 +x，机器人 `(0,1,0)`：

```text
ψ_e = 0
e = +1
v = 0.5
k_cross = 1
δ = 0 - atan(1/0.5) = -1.107 rad
```

负舵角 = 向右转，回到路径，正确。

### 3.4 Pure Pursuit vs Stanley

| | Pure Pursuit | Stanley |
|---|---|---|
| 参考 | 前视点 | 前轴 + 最近点 |
| 横向误差 | 隐式 | 显式 |
| 弯道 | 易切内弯 | 更贴线 |
| 调参 | L 为主 | k_cross、速度相关 |
| 高速 | 较稳 | 可能振荡 |

### 3.5 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 高速振荡 | k_cross 太大 | 降 k_cross |
| 贴线但抖 | 横向增益过高 | 加低通/降增益 |
| 切内弯 | 前轴偏移/增益小 | 调 `front_axle_offset`、k_cross |
| 原地转圈 | 坐标系/符号错 | 检查 e 的符号 |

### 3.6 对应代码

- 核心：`stanley_core.cpp`
- 适配：`stanley_controller.cpp`

## 4. DWB-lite

### 4.1 从“反馈”到“采样”

PID/Pure Pursuit/Stanley 都是**反馈律**：根据当前误差算一个控制量。

DWB 换了个思路：

> 在每个周期采样多组 `(v, ω)`，向前模拟一小段轨迹，
> 给每条轨迹打分，选最好的。

```text
for v in [v_min ... v_max]:
  for ω in [-ω_max ... ω_max]:
    traj = rollout(robot, v, ω, horizon)
    cost = score(traj, global_path, local_costmap)
keep best
```

### 4.2 差速模型 rollout

```text
for step in 1..N:
  x += v cosθ dt
  y += v sinθ dt
  θ += ω dt
```

### 4.3 critics（评分项）

本项目 `trajectory_cost.cpp`：

| 项 | 作用 |
|---|---|
| `path_weight` | 离全局路径多远 |
| `goal_weight` | 离终点多远 |
| `obstacle_weight` | 局部代价地图障碍 |
| `heading_weight` | 与路径切线的夹角 |
| `velocity_weight` | 与期望速度的差 |
| `control_weight` | 角速度大小（平滑） |

```text
cost = w_path·path_dist
     + w_goal·goal_dist
     + w_obs·obstacle
     + w_heading·heading
     + w_vel·|v-v_des|
     + w_ctrl·|ω|
```

### 4.4 为什么 DWB 是“局部规划器”

它显式评估“未来会撞哪、离路径多远、朝哪走”，
而不是只用当前误差做反馈。这是 PID/Pure Pursuit 没有的。

### 4.5 参数影响

| 参数 | 调大 | 调小 |
|---|---|---|
| `linear_samples` | 更细，计算量更大 | 更粗 |
| `angular_samples` | 转向选择更多 | 可能错过窄缝 |
| `horizon` | 看得更远，计算量大 | 短视 |
| `obstacle_weight` | 更远离障碍 | 可能贴障碍 |
| `goal_weight` | 更积极冲目标 | 可能犹豫 |
| `collision_threshold` | 253 更保守 | 254 更宽松 |

### 4.6 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 不动 | 所有轨迹碰撞 | 降速、调 threshold、清代价地图 |
| 贴墙 | obstacle_weight 低 | 调大 |
| 犹豫/抖动 | 权重冲突 | 调小 control/path 权重 |
| 很慢 | 采样多/路径长 | 降 samples/horizon |

### 4.7 对应代码

- rollout：`trajectory_utils.cpp`
- 评分：`trajectory_cost.cpp`
- 采样：`dwb_core.cpp`
- 适配：`dwb_controller.cpp`

## 5. MPPI-lite

### 5.1 MPPI 是什么

MPPI = Model Predictive Path Integral，采样型模型预测控制。

和 DWB 的区别：

- DWB 每个周期独立采样 `(v, ω)`，选一条；
- MPPI 维护一条**控制序列** `U = [u0, u1, ..., uN-1]`，
  每次在它周围加噪声采样 K 条序列，模拟未来，
  按代价做**软最大加权**更新 `U`。

### 5.2 算法

```text
初始化 U（全 0 或上一周期解）

每个控制周期:
  for k in 1..K:
    U_k = U + noise_k
    traj_k = rollout(U_k)
    cost_k = score(traj_k)
  w_k = exp(-cost_k / λ) / Σ exp(-cost_j / λ)
  U = Σ w_k · U_k
  apply U[0]
  shift U
```

### 5.3 温度 λ

```text
w_k = softmax(-cost_k / λ)
```

| λ | 效果 |
|---|---|
| 很小 | 几乎只选最优，激进/抖 |
| 适中 | 平滑，兼顾多条候选 |
| 很大 | 平均化，可能不够贴线 |

### 5.4 为什么 MPPI 更“高级”

- 在控制序列空间优化，不是单步贪心；
- 软最大加权比“选一条”平滑；
- 能处理非凸代价、障碍、动力学约束；
- 但计算量大，参数多。

### 5.5 参数影响

| 参数 | 作用 |
|---|---|
| `batch_size` | 采样轨迹数，越大越平滑/越慢 |
| `time_steps` | 控制序列长度 |
| `model_dt` | 离散步长 |
| `vx_std`, `wz_std` | 噪声大小 |
| `temperature` | 软最大温度 |
| critics 权重 | 同 DWB |

### 5.6 对应代码

- 采样/加权：`mppi_core.cpp`
- 适配：`mppi_controller.cpp`

## 6. MPC：预测、约束和滚动优化

### 6.1 学习目标

能解释为什么MPC不是某一种固定求解器，能手算一次运动预测与加速度投影，并理解栅格代价下有限差分为什么会失效。本项目当前使用确定性控制块搜索，旧的梯度版本用于故障对照。

MPC每次预测一段未来控制序列，只执行第一条指令，下一次用新测量重算。MPPI也有滚动预测，但用随机采样和加权来求解；MPC这一思想并不要求必须使用梯度、QP或某个第三方库。

### 6.2 模型与数字例子

差速机器人简化为：
x[k+1]=x[k]+v[k]cos(theta[k])dt，
y[k+1]=y[k]+v[k]sin(theta[k])dt，
theta[k+1]=theta[k]+w[k]dt。

若x=y=theta=0，v=0.2m/s，w=0.4rad/s，dt=0.1s，第一步得到(0.02,0,0.04)。下一步用更新后的theta预测，不能一直沿初始朝向画直线。

预测步长model_dt=0.1s、15步对应1.5s预测；控制频率20Hz对应0.05s实际首指令间隔。两者含义不同，不可把预测间隔直接当作首指令加速度间隔。

### 6.3 当前算法的完整顺序

1. 读取机器人位姿、实际线速度和角速度、最新路径与局部代价地图。
2. 大转角时先尝试经过预测碰撞检查的减速/路径对齐。
3. 生成上一周期滚动解、停车、路径引导、多个速度和转向弧线初值。
4. 对每条序列施加速度和加速度约束，检查整条预测轨迹。
5. 评分包含路径/障碍/朝向/速度、近期参考点跟踪、末端参考距离、相邻控制差。
6. 每次调整连续三个预测步的线速度或角速度，接受更低代价候选；没有改善时缩小搜索幅度。
7. 执行最优序列第一条，保存并滚动其余序列；无可行解则清空旧解并报告失败。

普通重规划只更新路径，不清空热启动；热启动必须在新路径和新地图上重新评分，不能因为“上周期安全”就直接沿用。

### 6.4 为什么不再用旧的有限差分

局部地图是格子。例如左右扰动仍落在同一格，代价都为1000000，则数值梯度(1000000-1000000)/(2epsilon)=0。梯度为零只说明本次扰动没有看到变化，不说明存在可行解或已经最优。确定性模式搜索可以跨过这种小范围平台，但仍不是全局最优保证。

当前gradient_step、gradient_epsilon、line_search_steps仅保留参数兼容，不影响新求解。不要用调这些旧参数来解释当前运行变化。

### 6.5 加速度投影手算

实际v=0.10m/s，线加速度上限1m/s²，实际控制间隔0.05s，下一条v只能在[0.05,0.15]中。若候选0.4，先投影为0.15。随后预测步按0.1s允许变化0.1；不能每步都从零重新限幅。

w同理，3.2rad/s²乘0.05s得到首指令角速度变化上限0.16rad/s。平滑惩罚用于偏好，硬加速度约束用于限制，二者不能互相替代。

### 6.6 当前关键参数

| 参数 | 当前示例 | 解释 |
|---|---|---|
| horizon_steps / model_dt | 15 / 0.1 | 1.5秒预测，不等于控制周期 |
| iterations | 8 | 确定性搜索轮数 |
| max_linear_acceleration | 1.0 | 线速度变化约束 |
| max_angular_acceleration | 3.2 | 角速度变化约束 |
| path_weight / obstacle_weight | 5 / 8 | 跟踪与远离障碍的取舍 |
| collision_threshold | 253 | 内切区域及致命障碍不可进入 |
| goal_tolerance | 0.34m | 本项目MPC末端切换，须与Nav2容差配合 |

评分权重不能覆盖碰撞否决。A*和MPC必须同时拒绝253区域，否则一个规划“从墙边挤过去”，另一个只能停车。

### 6.7 运行与排错

```bash
python3 src/mini_slam/scripts/automated_session_test.py --domain 192 --controller MPC --stationary-seconds 5 --extended-navigation
```

先按[23](23_mini_slam完整导航实践.md)完成环境和构建。必须看到Selected controller: MPC和最终PASS。只看到插件创建日志不证明导航实际选择了它。

### 6.8 练习和答案

1. dt从0.05变0.1而加速度不变，单次允许速度变化如何变化？答：加倍，但前提是真实控制间隔也确实加倍。
2. 两个候选碰撞代价相同，梯度为零，能说明什么？答：只能说明该扰动未产生评分差异，不能说明可行或最优。
3. 冻结图的定位模式下，控制器可以不更新障碍地图吗？答：不能，位姿图冻结不等于环境不变。
4. 当前MPC是全局最优求解器吗？答：不是，是受约束的局部滚动搜索；路径质量、预测范围和代价设计仍可导致失败。

源码入口：mpc_core.cpp的compute/trajectoryCost，mpc_controller.hpp的末端处理，mpc_controller.cpp的costmap适配。后续源码导读见[12](12_控制器源码逐行导读.md)。

## 7. 六种方法对比

| 维度 | PID | Pure Pursuit | Stanley | DWB | MPPI | MPC |
|---|---|---|---|---|---|---|
| 本质 | 反馈律 | 几何跟踪 | 几何 + 横向误差 | 采样 + critics | 采样 + 软最大 | 滚动约束优化 |
| 参考 | 最近点 | 前视点 | 前轴最近点 | 多轨迹 | 多控制序列 | 一条控制序列 |
| 非完整约束 | 需映射 | 天然 | 天然 | 显式 | 显式 | 显式 |
| 障碍 | 不处理 | 不处理 | 不处理 | 处理 | 处理 | 处理 |
| 计算量 | 极低 | 低 | 低 | 中 | 高 | 中高 |
| 调参难度 | 中 | 低 | 中 | 高 | 很高 | 高 |
| 适合 | 教学基线 | 第一版 | 贴线 | 局部避障 | 平滑/研究 | 约束优化 |

### 推荐学习顺序

```text
PID（理解反馈）
  → Pure Pursuit（理解几何跟踪）
  → Stanley（理解横向误差）
  → DWB（理解采样 + critics）
  → MPPI（理解序列优化）
  → MPC（理解滚动约束优化与约束投影）
```

### 调参顺序

1. 先保证**能走**：降速，`obstacle_weight` 适中，`L` 适中；
2. 再看**稳定性**：调 `L` / `k_cross` / `temperature`；
3. 再看**贴线**：调 `path_weight` / `heading_weight`；
4. 最后看**避障**：调 `obstacle_weight` / `collision_threshold`；
5. 每次只改一个参数。

## 8. 练习与答案

### 练习 1：Pure Pursuit 手算

机器人 `(0,0,0)`，前视点 `(3,1)`，`v=0.5`。求 `κ` 和 `ω`。

**答案**：

```text
L² = 3²+1² = 10
κ = 2·1/10 = 0.2
ω = 0.5·0.2 = 0.1 rad/s
```

### 练习 2：PID 符号

机器人在路径左侧，`e_y>0`。PID 的横向项应该给正还是负角速度？

**答案**：负，向右修正。所以公式里是 `- kp_y·e_y`。

### 练习 3：L 的影响

Pure Pursuit 左右摆动，应该调大还是调小 L？

**答案**：调大。L 太小会过度反应。

### 练习 4：DWB 不动

DWB 所有轨迹都碰撞，可能是什么原因？

**答案**：局部代价地图障碍太近、`collision_threshold` 太保守、
速度太快、机器人被卡住、TF/代价地图错位。

### 练习 5：MPPI 温度

MPPI 抖动，`temperature` 应该调大还是调小？

**答案**：调大，让权重更平滑；但太大会不贴线。

### 练习 6：PID 能替代 DWB 吗？

**答案**：不能。PID 不处理局部障碍和轨迹可行性；
可以作为内环或 Stanley 的一项。

### 练习 7：MPPI 和 MPC 的核心区别？

**答案**：MPPI 用随机采样 + 软最大加权；本项目MPC用多初值确定性搜索优化控制序列。
两者都是滚动时域，但搜索方式不同。

## 9. 一页总结

```text
控制问题：输入路径 + 位姿 + 局部地图，输出 v/ω，20Hz 闭环。

PID：误差反馈；简单，但无前视/无障碍。
Pure Pursuit：前视点 + 曲率；第一版首选。
Stanley：横向误差 + 航向；更贴线。
DWB：采样 (v,ω) + rollout + critics；局部避障。
MPPI：采样控制序列 + 软最大；更平滑，更贵。
MPC：近期路径参考 + 多初值模式搜索 + 加速度投影；更“优化”，可能局部极小。

关键参数：
  L / k_cross / horizon / batch_size / temperature / max_linear_acceleration / iterations / critic 权重

关键工程点：
  map→odom TF、局部代价地图锁、参数前缀、异常、插件注册。
```
