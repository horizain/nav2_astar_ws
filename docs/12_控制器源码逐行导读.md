## 1. `controller_types.hpp`

### 1.1 `Pose2D`

```cpp
struct Pose2D
{
  double x{0.0};
  double y{0.0};
  double yaw{0.0};
};
```

单位：米、弧度。算法层只认这个，不认 `geometry_msgs`。

### 1.2 `Control`

```cpp
struct Control
{
  double linear{0.0};   // m/s
  double angular{0.0};  // rad/s
};
```

### 1.3 `ControlResult`

```cpp
struct ControlResult
{
  Control control;
  bool valid{true};
  double cost{0.0};
};
```

DWB/MPPI/MPC 可能找不到可行轨迹，用 `valid=false` 表示。

### 1.4 工具函数

```cpp
clamp(value, low, high)
normalizeAngle(angle)      // 到 [-pi, pi]
distance(a, b)
squaredDistance(a, b)
yawFromVector(dx, dy)
clampControl(cmd, max_v, max_w)
recomputePathYaw(path)      // 用相邻点重算切线
```

`normalizeAngle` 用：

```cpp
std::atan2(std::sin(angle), std::cos(angle))
```

比手写 while 循环更稳。

`recomputePathYaw` 用中心差分：

```cpp
prev = (i == 0) ? 0 : i - 1;
next = min(i + 1, size - 1);
yaw = atan2(path[next].y - path[prev].y,
            path[next].x - path[prev].x);
```

> 为什么重算？全局路径可能只有位置，或者朝向和切线不一致。
> 控制器只关心切线。

**自测**：

1. 为什么 core 层不用 `geometry_msgs::msg::PoseStamped`？
2. `normalizeAngle` 为什么不用 while 循环？
3. `recomputePathYaw` 为什么用中心差分？

## 2. `path_utils`：路径几何

### 2.1 `PathProjection`

```cpp
struct PathProjection
{
  size_t index;            // 投影所在段的起点
  Pose2D point;            // 路径上的投影点
  double distance;         // 机器人到投影点距离
  double signed_lateral;   // 机器人在路径左侧为正
  double path_yaw;         // 投影处切线
};
```

`signed_lateral` 的定义：

```cpp
rx = robot.x - point.x;
ry = robot.y - point.y;
signed_lateral = cos(yaw)*ry - sin(yaw)*rx;
```

这是 `cross(tangent, robot-point)`。路径沿 +x，机器人在 +y，值为正。

### 2.2 `projectOntoPath`

不是只找最近点，而是**逐段投影**：

```cpp
for each segment a->b:
  t = clamp(dot(robot-a, b-a) / |b-a|², 0, 1)
  point = a + t*(b-a)
  if distance(robot, point) < best:
    save
```

- `t` 夹在 `[0,1]`，保证投影落在线段内；
- `len2 <= eps` 的重复点跳过；
- 所有段退化时回退到第一个点。

### 2.3 `findLookaheadPoint`

```text
projection = projectOntoPath(robot, path)
if projection.distance >= L: 返回 projection.point
prev = projection.point
for i = projection.index .. n-2:
  next = path[i+1]
  if distance(robot,next) >= L:
    在 prev->next 上线性插值，返回
  prev = next
返回 path.back()
```

注意：

- 从投影点开始，不是从路径起点；
- 在最后一段做线性插值，所以前视点比路径点更平滑；
- 路径不够长时退回终点。

### 2.4 `remainingDistance`

从投影点沿路径到终点的弧长：

```text
distance(projection.point, path[index+1])
+ Σ distance(path[i], path[i+1])
```

用于：

- Pure Pursuit/Stanley 的到点减速；
- 判断是否到达目标。

### 2.5 `toRobotFrame`

```cpp
local_x =  cos(yaw)*dx + sin(yaw)*dy;
local_y = -sin(yaw)*dx + cos(yaw)*dy;
local_yaw = normalize(point.yaw - robot.yaw);
```

**自测**：

1. `signed_lateral` 为什么是 `cos·ry - sin·rx`？
2. 前视点为什么要在最后一段插值？
3. `remainingDistance` 和 `distanceToPath` 有什么区别？

## 3. `trajectory_utils`：差速 rollout

### 3.1 常量控制

```cpp
rolloutConstantControl(start, v, w, steps, dt)
```

生成 `steps+1` 个位姿（包含起点）。

### 3.2 控制序列

```cpp
rolloutControlSequence(start, controls, dt)
```

```text
pose = start
for control in controls:
  x += v cosθ dt
  y += v sinθ dt
  θ = normalize(θ + ω dt)
  push pose
```

> 这是最简单的差速模型，不含加速度/侧滑/轮胎模型。
> 教学够用；生产可用 Nav2 的 motion model。

## 4. `trajectory_cost`：DWB/MPPI/MPC 的 critics

### 4.1 参数

```cpp
struct TrajectoryCostParams
{
  double path_weight;
  double goal_weight;
  double obstacle_weight;
  double heading_weight;
  double velocity_weight;
  double control_weight;
  double collision_cost;
  int collision_threshold;
  double desired_linear_velocity;
};
```

### 4.2 评分

```text
对轨迹每个点：
  projection = projectOntoPath(point, path)
  path_cost += projection.distance
  heading_cost += |normalize(path_yaw - point.yaw)|
  cell = cost_at(x,y)
  if cell >= collision_threshold: return collision_cost
  obstacle_cost += cell/252

goal_cost = distance(traj.back(), path.back())
velocity_cost = |command_v - desired|
control_cost = |command_w|

cost = 加权和
```

关键点：

- 任一点碰撞 -> 直接返回巨大代价；
- 障碍代价按 0~252 归一化；
- 所有项按轨迹点数平均，避免长短轨迹不公平；
- goal 项不平均，直接看终点。

**自测**：

1. 为什么碰撞要直接返回 `collision_cost`？
2. 为什么要对 path/heading/obstacle 取平均？
3. `collision_threshold=253` 和 `254` 有什么区别？

## 5. `pid_core`

### 5.1 状态

```cpp
heading_integral_, previous_heading_error_, heading_initialized_
speed_integral_, previous_speed_error_, speed_initialized_
```

`reset()` 清空积分和微分历史。

### 5.2 `compute`

```text
if path empty or remaining <= goal_tolerance: reset, return 0

projection = projectOntoPath
heading_error = normalize(path_yaw - robot.yaw)

heading_integral += heading_error*dt (限幅)
heading_derivative = (heading_error - prev)/dt
ω = kp_θ·e_θ + ki_θ·I + kd_θ·D - kp_y·e_y
ω = clamp(ω, ±max_w)

desired_v = max_v · slowdown · heading_scale
speed_error = desired_v - current_speed
speed_integral += ...
v = desired_v + kp_v·e_v + ...
v = clamp(v, 0, max_v)
```

符号：

- `e_y > 0` 表示机器人在左侧；
- 修正项 `-kp_y·e_y`，向右转。

**自测**：

1. 为什么积分项要限幅？
2. 为什么 PID 在弯道会滞后？
3. `reset()` 什么时候被调用？

## 6. `pure_pursuit_core`

### 6.1 `compute`

```text
if path empty or remaining <= goal_tolerance: return 0

L = use_velocity_scaled ? |v|·lookahead_time : lookahead_distance
L = clamp(L, min, max)

target = findLookaheadPoint(robot, path, L)
local = toRobotFrame(robot, target)
L2 = local.x² + local.y²
if L2 < eps: return 0

κ = 2·local.y / L2

v = max_v
v *= min(1, remaining/slow_radius)
v *= 1 - curvature_slowdown·min(1, |κ|·max_v/max_w)
v = max(v, min_v)

ω = v·κ
clamp
```

### 6.2 关键点

- 前视点可能在前方、侧方，甚至后方；
- `local.y` 决定转向符号；
- 曲率大时减速；
- 到点前按剩余距离减速。

**自测**：

1. 为什么 `L` 要 clamp？
2. `κ = 2y/L²` 的几何含义？
3. 为什么曲率大要减速？

## 7. `stanley_core`

### 7.1 `compute`

```text
if path empty or remaining <= goal_tolerance: return 0

front = robot + front_axle_offset·[cosθ, sinθ]
projection = projectOntoPath(front, path)
heading_error = normalize(path_yaw - robot.yaw)

v = max_v · slowdown · heading_scale
v = clamp(v, min_v, max_v)

cross_term = atan(k_cross·e / max(v, 0.1))
δ = k_heading·heading_error - cross_term
δ = clamp(δ, ±max_steering)

if wheelbase > 0:
  ω = v·tan(δ)/wheelbase
else:
  ω = k_heading·heading_error - k_cross·e/max(v,0.1)
clamp
```

### 7.2 符号

`e = signed_lateral > 0` 表示前轴在路径左侧，要向右转：
`δ` 取负，`ω` 取负。

### 8.1 参数

struct DwbParams
{

## 9. `mppi_core`

### 9.1 状态

```cpp
std::vector<Control> nominal_;
std::mt19937 rng_;
bool initialized_;
```

`nominal_` 是控制序列；`reset()` 清空并按 seed 重置随机数。

### 9.2 `compute`

```text
if path empty or remaining <= goal: return 0

if !initialized or size != steps:
  nominal = 0.5·max_v, ω=0

for k in 1..K:
  sample = nominal
  for each control:
    v += N(0, vx_std)
    w += N(0, wz_std)
    clamp
  traj = rolloutControlSequence(robot, sample, dt)
  cost = evaluateTrajectory(... mean v/w ...)
  save sample/cost/min_cost

if min_cost >= collision_cost: return invalid

w_k = exp(-(cost_k-min_cost)/temperature)
normalize
updated = Σ w_k·sample_k
nominal = updated
control = nominal[0]
shift nominal
```

### 9.3 和 DWB 的区别

| DWB | MPPI |
|---|---|
| 采样 `(v,w)` 单步 | 采样控制序列 |
| 选最低代价 | 软最大加权 |
| 无状态 | 维护 nominal |
| 简单 | 平滑但更贵 |

**自测**：

1. 为什么 MPPI 要维护控制序列？
2. `temperature` 起什么作用？
3. 为什么 `min_cost >= collision_cost` 就无效？

## 9.5 mpc_core：当前实现

本节与当前源码同步。旧版有限差分/线搜索不再是正在执行的求解算法，数学背景和数字例子见[10第6节](10_控制器算法零基础课.md)。

### 9.5.1 MpcParams

速度上限、预测步数、预测dt、搜索iterations、线/角加速度、goal_tolerance、terminal_weight、smoothness_weight和评分参数。gradient_step、gradient_epsilon、line_search_steps为旧参数兼容项。

### 9.5.2 trajectoryCost

rolloutControlSequence先得到预测位姿，evaluateTrajectory检查障碍并给出基础评分。全局终点距离项被关闭，改为沿路径生成近期参考点，累积预测位置相对参考点的平方距离，末端也对齐近期参考。相邻控制量差提供平滑惩罚。

为什么不能只盯全局终点？绕障路线的第一步可能离最终目标更远，按全局直线距离评分容易把停车评成更优。

### 9.5.3 compute

```text
检查输入和末端状态
project(sequence):
  previous = 实际测量速度
  每步先限速度，再按加速度限变化
  第一条用实际控制dt，后续用model_dt
路径角度较大：
  预测减速旋转；整条轨迹安全则返回首条指令
consider(candidate):
  project、算代价、加首条与测量速度平滑项和近期转向评分
  更优且可行才替换best
consider(热启动、停车、路径引导、多速度、多弧线)
若没有可行候选：reset并报告invalid
循环iterations次：
  对每组三步的v/w做正负扰动
  只接受代价更低的候选；无改善则缩小扰动
输出best.front；保存best并滚动一位
```

不能只给最终输出限加速度，再假装原预测仍安全；本实现先投影整个候选再预测和评分。

### 9.5.4 插件适配

mpc_controller.cpp把worldToMap/getCost封装成cost_at，并把实际速度和控制dt传给核心。mpc_controller.hpp补充实际角速度输入，末端按直线距离进入朝向调整；普通setPlan不清空热启动，但所有旧候选在新环境重新评价。

大角度对齐是混合控制阶段，不是证明MPC能解决任意非凸问题。末端旋转也不应被描述为完整工业级footprint碰撞检查。

### 9.5.5 如何验证

test_controller_core.cpp包含前进、偏移修正、到点、全部碰撞、253区域拒绝、反向起步、闭环转弯与加速度变化、障碍解除恢复等测试。真实ROS链路还必须显式选择MPC跑extended-navigation；单测通过不能替代系统验收。

自测：为什么保留热启动却仍要每次重新评分？答：路径、地图和测量速度都可能变化，旧解只是初值，没有安全豁免权。

## 11. 六个 Controller 适配器

它们都只做两件事：

```cpp
configureParams(node)  // 读自己的参数
computeCommand(...)    // 调 core
```

例如 `PurePursuitController::configureParams`：

```cpp
declareAndGet(node, "lookahead_distance", ...);
...
params_.goal_tolerance = goal_tolerance_;
core_.params() = params_;
core_.reset();
RCLCPP_INFO(...);
```

`computeCommand`：

```cpp
return core_.compute(robot, path, current_speed);
```

DWB/MPPI/MPC 额外：

```cpp
bool needsCostmap() const override {return true;}

Control computeCommand(...) {
  auto cost_at = [this](double wx, double wy) -> uint8_t {
    unsigned mx, my;
    if (!costmap_->worldToMap(wx, wy, mx, my)) return 255;
    return costmap_->getCost(mx, my);
  };
  auto result = core_.compute(robot, path, cost_at, current_speed);
  if (!result.valid) throw nav2_core::NoValidControl(...);
  return result.control;
}
```

1. 为什么每个适配器都重复 `goal_tolerance_`？
2. DWB/MPPI/MPC 的 `cost_at` 为什么返回 255 表示越界？
3. 为什么 `configureParams` 里要 `core_.params() = params_`？

## 16. 改动实验

### 16.1 改 Pure Pursuit 的 L

```yaml
lookahead_distance: 0.3 → 0.6 → 1.0
```

观察：摆动 → 稳定 → 切内弯。

### 16.2 改 Stanley 符号

把 `- cross_term` 改成 `+ cross_term`：

预测：机器人会向错误方向转，偏离路径。

### 16.3 改 PID 积分

把 `ki_heading` 从 0 加到 1：

预测：弯道稳态误差变小，但可能过冲/windup。

### 16.4 改 DWB 障碍权重

```yaml
obstacle_weight: 0 → 100 → 500
```

预测：贴障碍 → 绕行 → 过度保守。

### 16.5 改 MPPI 温度

```yaml
temperature: 0.05 → 0.3 → 2.0
```

预测：抖动/激进 → 平衡 → 平滑但可能不贴线。

### 16.6 去掉 costmap 锁

注释 `ControllerBase` 里的 `unique_lock`：

预测：高负载下路径飘忽、偶发穿墙。**不要在生产环境这样做。**

## 17. 十一个理解检查题

1. 为什么 core 层不 include ROS？
2. `signed_lateral` 的符号约定是什么？
3. Pure Pursuit 的 `κ=2y/L²` 怎么来的？
4. Stanley 为什么要除以 `v`？
5. DWB 的 critics 分别对应什么？
6. MPPI 的 `temperature` 控制什么？
7. 当前MPC如何处理栅格评分平台和跨周期速度连续性？
8. `ControllerBase` 为什么要做 `map→odom` 变换？
9. 为什么读 costmap 要加锁？
10. 参数为什么要带实例名前缀？
11. 运行时切换控制器为什么要 `transient_local` QoS？

### 答案

1. 为了可单测、可复用、不把 ROS 类型拖进算法。
2. 机器人在路径左侧为正；修正时取负号。
3. 圆弧弦长/曲率几何关系。
4. 速度越低，横向误差应该产生更大的转向。
5. Path/Goal/Obstacle/Heading/Velocity/Control。
6. 软最大权重的平滑程度。
7. 多初值模式搜索避免仅依赖局部数值梯度；整个候选从实际速度出发按加速度约束投影。
8. 路径在 map，位姿/局部 costmap 在 odom。
9. costmap 有后台更新线程。
10. 多插件实例需要隔离参数。
11. `ControllerSelector` 的订阅端是 transient_local，普通 volatile 发布者可能匹配不上。
