## 2. 实验设计原则

### 2.1 控制变量

比较控制器时，必须固定：

- 地图；
- 起点、终点；
- 全局规划器（A* 参数不变）；
- 局部代价地图参数；
- 初始位姿；
- 速度上限（尽量一致）。

只改变控制器类型或一个参数。

### 2.2 重复次数

每个配置至少跑 3 次，取中位数。Gazebo/AMCL 有随机性。

### 2.3 记录模板

```text
日期：
配置：
控制器：
关键参数：
起点 / 终点：
到达时间：
横向误差 RMSE：
航向误差 RMSE：
最大 |v| / |ω|：
碰撞：
重规划次数：
主观稳定性：
备注：
```

## 3. 指标怎么采

### 3.1 到达时间

```bash
ros2 action send_goal /navigate_to_pose \
  nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.5, y: 0.5}, orientation: {w: 1.0}}}}" \
  --feedback
```

记录从 goal accepted 到 result。

### 3.2 横向误差

录制 `/plan` 和 `/tf`，离线计算：

```text
对每个机器人位姿：
  找 `/plan` 上最近线段
  算点到线段距离
  RMSE = sqrt(mean(d²))
```

也可以用可视化节点的 `path distance`（需要自己加日志）。

### 3.3 最大角速度

```bash
ros2 topic echo /cmd_vel --field angular.z
```

或录 bag 后分析。

### 3.4 轨迹

```bash
ros2 bag record /plan /cmd_vel /tf /tf_static -o controller_lab_run
```

### 3.5 计算量

- `top` 看 `controller_server` CPU；
- 控制器日志里的耗时（DWB/MPPI 可自己加计时）；
- `ros2 topic hz /cmd_vel` 看是否掉频。

## 4. 实验一：Pure Pursuit 的 L

固定 `vmax=0.5`，只改：

| 组 | `lookahead_distance` | `min` | `max` |
|---|---:|---:|---:|
| A | 0.3 | 0.2 | 0.5 |
| B | 0.6 | 0.3 | 1.2 |
| C | 1.0 | 0.5 | 1.5 |
| D | 1.5 | 0.8 | 2.0 |

预期：

```text
A：贴线但摆动
B：平衡
C：稳定但切内弯
D：更切内弯，可能离障碍近
```

记录表：

| 组 | 到达时间 | 横向 RMSE | 最大 ω | 碰撞 | 主观 |
|---|---:|---:|---:|---|---|
| A | | | | | |
| B | | | | | |
| C | | | | | |
| D | | | | | |

**结论应该能回答**：L 为什么不能太大/太小？

## 5. 实验二：PID vs Pure Pursuit vs Stanley

同一路径，只换控制器。

预期：

| 控制器 | 直线 | 弯道 | 高速 |
|---|---|---|---|
| PID | 好 | 滞后/稳态误差 | 易振荡 |
| Pure Pursuit | 好 | 切内弯 | 较稳 |
| Stanley | 好 | 更贴线 | 可能振荡 |

记录横向误差和最大角速度。

> 这个实验用来回答“为什么不直接用 PID”。

## 6. 实验三：DWB 的 critics

固定地图，只改一个权重：

### 6.1 `obstacle_weight`

```yaml
obstacle_weight: 0
obstacle_weight: 50
obstacle_weight: 100
obstacle_weight: 500
```

观察：

- 0：贴障碍；
- 50~100：正常绕行；
- 500：过度保守、绕远。

### 6.2 `path_weight`

```yaml
path_weight: 0.1
path_weight: 1.0
path_weight: 10.0
```

观察：是否更贴全局路径。

### 6.3 `horizon`

```yaml
horizon: 0.5
horizon: 1.5
horizon: 3.0
```

观察：短视 vs 提前避障；计算量变化。

### 6.4 `collision_threshold`

```yaml
collision_threshold: 253
collision_threshold: 254
```

253 更保守；254 只把物理障碍当碰撞。

## 7. 实验四：MPPI 的温度与采样

### 7.1 `temperature`

```yaml
temperature: 0.05
temperature: 0.3
temperature: 2.0
```

预期：

- 0.05：几乎选最优，可能抖；
- 0.3：平衡；
- 2.0：平滑，可能不贴线。

### 7.2 `batch_size`

```yaml
batch_size: 20
batch_size: 100
batch_size: 300
```

记录 CPU、平滑性、横向误差。

### 7.3 `vx_std / wz_std`

```yaml
vx_std: 0.05
vx_std: 0.15
vx_std: 0.3
```

噪声太小 -> 探索不足；太大 -> 抖。

## 7.5 实验五：MPC-lite 的 horizon 与迭代

### 7.5.1 `horizon_steps`

```yaml
horizon_steps: 5
horizon_steps: 10
horizon_steps: 20
```

观察：

- 5：短视，可能来不及避障；
- 10：平衡；
- 20：看得更远，但计算量线性增加。

### 7.5.2 `iterations`

```yaml
iterations: 2
iterations: 8
iterations: 20
```

观察：

- 2：优化不充分，行为接近初始猜测；
- 8：平衡；
- 20：更接近局部最优，但更慢，可能过拟合代价。

### 7.5.3 `gradient_step` 与线搜索

```yaml
gradient_step: 0.005
gradient_step: 0.05
gradient_step: 0.5
```

- 太小：几乎不动；
- 适中：稳定收敛；
- 太大：震荡，靠线搜索救回来，但计算量增加。

### 7.5.4 MPC vs MPPI

同一路径、同一速度，分别跑：

```text
MPPI: batch_size=100, time_steps=20
MPC : horizon_steps=10, iterations=8
```

记录：

| 指标 | MPPI | MPC |
|---|---:|---:|
| 到达时间 | | |
| 横向 RMSE | | |
| 最大 ω | | |
| CPU | | |
| 平滑性 | | |

预期：

- MPPI 更“随机探索”，可能更平滑；
- MPC 更“确定性优化”，可能更贴线，但可能陷入局部极小；
- MPC 的 `iterations × horizon` 是主要计算量。

## 8. 常见现象 → 原因 → 处理

### 8.1 控制器没加载

| 检查 | 命令 |
|---|---|
| ament 索引 | `cat install/.../nav2_core__pluginlib__plugin/...` |
| 符号 | `nm -D ... | grep PurePursuit` |
| 日志 | 启动日志 `Created controller :` |
| 参数 | `ros2 param get /controller_server FollowPath.plugin` |

### 8.2 控制器加载了但不走

```text
1. 有 /plan 吗？
   ros2 topic echo /plan --once
2. 有 /cmd_vel 吗？
   ros2 topic echo /cmd_vel
3. /cmd_vel 是零吗？
4. 有 TF 吗？
   ros2 run tf2_ros tf2_echo map base_link
5. 控制器报错了吗？
   看 controller_server 日志
```

可能原因：

- TF 未连通；
- 路径为空；
- 所有轨迹碰撞（DWB/MPPI/MPC）；
- 速度限制为 0；
- `goal_tolerance` 太大，控制器以为已到点；
- 碰撞监控/collision_monitor 把速度压成 0。

### 8.3 画圈/原地转

- 路径 frame 与 pose frame 不一致；
- 横向误差符号反了；
- 前视点在身后；
- Stanley 的 `e` 符号反了；
- 初始位姿错误。

### 8.4 左右摆动

| 控制器 | 处理 |
|---|---|
| Pure Pursuit | 增大 L |
| Stanley | 降低 `k_cross` |
| PID | 降 `kp_heading`/`kp_cross`，加 `kd` |
| DWB/MPPI | 降 `control_weight` 或调 `temperature` |
| MPC | 降 `gradient_step` / `iterations` |

### 8.5 切内弯

- Pure Pursuit L 太大；
- Stanley `k_cross` 太小；
- DWB `path_weight` 太小；
- 速度太快。

### 8.6 DWB/MPPI 不动

- 所有轨迹碰撞；
- `collision_threshold=253` 太保守；
- 局部代价地图有障碍；
- 机器人卡在墙边；
- `horizon`/`batch` 太小，没有可行解。

处理：

```yaml
collision_threshold: 254
obstacle_weight: 50
max_linear_velocity: 0.2
```

### 8.7 MPPI/MPC 很慢

- MPPI：降 `batch_size` / `time_steps`；
- MPC：降 `horizon_steps` / `iterations`；
- 增大 `model_dt`；
- 减少路径长度/控制频率。

### 8.8 参数改了没生效

launch 读的是 `install/` 副本：

```bash
colcon build --packages-select nav2_controller_lab
source install/setup.bash
```

或改 `install/.../params/...`（不推荐）。

### 8.9 运行时切换没反应

- `/controller_selector` QoS 不对：

```bash
--qos-durability transient_local --qos-reliability reliable
```

- `controller_plugins` 没加载目标实例；
- 当前 action 还没结束；取消后重新发目标。

### 8.10 RViz 面板/标记不显示

面板：

```text
Panels → Add New Panel → nav2_controller_lab_rviz/Controller Lab
```

标记：

```text
Add → By topic → /controller_lab/markers → MarkerArray
```

检查可视化节点：

```bash
ros2 node list | grep controller_lab_visualizer
ros2 topic hz /controller_lab/markers
```

## 9. 已知环境问题

### 9.1 TF 树不连通

现象：

```text
Could not find a connection between 'odom' and 'base_link'
```



## 10. 性能分析

### 10.1 控制频率

```bash
ros2 topic hz /cmd_vel
```

低于 20 Hz 可能：

- 控制器计算太慢；
- CPU 被 Gazebo 占用；
- DWB/MPPI/MPC 参数太大。

### 10.2 单周期耗时

在 `ControllerBase::computeVelocityCommands` 里加计时：

```cpp
auto t0 = std::chrono::steady_clock::now();
// ...
auto dt = std::chrono::duration<double, std::milli>(
  std::chrono::steady_clock::now() - t0).count();
RCLCPP_DEBUG(logger_, "control cost %.3f ms", dt);
```

### 10.3 调参优先级

```text
1. 先保证稳定、不撞
2. 再保证贴线
3. 再追求速度
4. 最后优化平滑性
```
