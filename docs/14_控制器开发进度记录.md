## 阶段 1：分层设计

### 目标

复用 A* 项目的经验：

```text
纯算法（无 ROS）→ ROS 适配层 → pluginlib 注册
```

### 目录

```text
nav2_controller_lab/
├── include/nav2_controller_lab/
│   ├── controller_types.hpp
│   ├── path_utils.hpp
│   ├── trajectory_utils.hpp
│   ├── trajectory_cost.hpp
│   ├── *_core.hpp
│   ├── controller_base.hpp
│   └── *_controller.hpp
├── src/
├── test/
├── params/
├── launch/
└── rviz/
```

### 设计决策

- **算法核心不 include ROS**：可单测、可复用；
- **适配层只做翻译**：TF、costmap、参数、异常、消息；
- **每个控制器一个具体类**：pluginlib 需要具体类；
- **公共基类**：生命周期、TF、限速、`TwistStamped` 统一。

### 结果

`controller_types.hpp` 只依赖标准库；所有 core 可以独立编译。

## 阶段 2：几何控制器

### Pure Pursuit

实现：

- `projectOntoPath()`：逐段投影；
- `findLookaheadPoint()`：沿路径插值；
- `PurePursuitCore::compute()`：`κ = 2y/L²`，`ω = vκ`；
- 速度按剩余距离/曲率减速。

### Stanley

实现：

- 前轴偏移；
- 横向误差 + 航向误差；
- `δ = k_heading·ψ_e - atan(k_cross·e/v)`；
- 差速车用 `ω = v tan(δ)/wheelbase`。

### 第一次符号坑

最初 Stanley 写成：

```cpp
steering = heading_error + cross_term;
```

测试 `StanleyCore.OffsetProducesCorrectTurnDirection` 失败：
机器人在路径左侧，期望向右修正（负 ω），实际给正 ω。

修复：

```cpp
steering = k_heading * heading_error - cross_term;
```

PID 也把 `+ kp_cross * signed_lateral` 改成 `- kp_cross * signed_lateral`。

**教训**：

> 路径跟踪的符号约定必须写清楚：`signed_lateral` 正方向是什么，
> 修正项该加还是该减。测试要专门覆盖“偏移方向”。

## 阶段 3：采样与优化控制器

### DWB-lite

实现：

- `rolloutConstantControl()`；
- `evaluateTrajectory()`；
- 采样 `(v, ω)` 网格；
- critics：path/goal/obstacle/heading/velocity/control。

### MPPI-lite

实现：

- 维护 `nominal_` 控制序列；
- 高斯噪声采样；
- softmax 加权；
- 滚动时域。

### MPC-lite

实现：

- 维护 `nominal_` 控制序列；
- 有限差分梯度；
- 投影到控制约束；
- 回溯线搜索；
- 复用 `TrajectoryCost`，加 terminal/smoothness。

### 设计取舍

| 决策 | 原因 |
|---|---|
| 默认 DWB 7×11 采样 | 教学可读，计算量可控 |
| MPPI 100×20 | 比官方 2000 小，但保留结构 |
| 简化差速模型 | 不引入车辆动力学 |
| 共用 `TrajectoryCost` | 避免 DWB/MPPI/MPC 多套评分 |

### 测试

`DwbCore.ChoosesForwardOnClearStraightPath`、
`DwbCore.RejectsAllCollidingTrajectories`、
`MppiCore` 同理。

## 阶段 4：ControllerBase 适配层

### 做了什么

- 生命周期：configure/activate/deactivate/cleanup；
- 参数前缀：`name_ + ".xxx"`；
- 路径 `map → odom` 逐点 TF；
- 局部 costmap 锁；
- 速度限制；
- `TwistStamped` 封装；
- 异常映射。

### 关键决策

**路径变换用当前时间**：

```cpp
transformed.header.stamp = clock_->now();
```

如果用规划时刻的旧时间戳，TF 历史可能把路径拉偏。

**costmap 锁放在基类**：

```cpp
if (needsCostmap()) {
  std::unique_lock<...> lock(*(costmap_->getMutex()));
  command = computeCommand(...);
}
```

DWB/MPPI/MPC 只需要实现 `needsCostmap() == true`。

**参数读取模板**：

```cpp
declareAndGet(node, "lookahead_distance", default, member);
// → FollowPath.lookahead_distance
```

## 阶段 7：多实例与运行时切换

### 问题

最初 YAML 只有：

```yaml
controller_plugins: ["FollowPath"]
```

只能启动一个控制器，无法运行时切换。

### 修改

```yaml
controller_plugins: ["FollowPath", "PID", "Stanley", "DWB", "MPPI", "MPC"]
```

每个实例独立参数块。

### 运行时切换

```bash
ros2 topic pub --once /controller_selector std_msgs/msg/String \
  "{data: MPPI}" \
  --qos-durability transient_local \
  --qos-reliability reliable
```

### 关键坑：install 副本

修改了 `src/.../params/*.yaml` 后直接启动，发现只加载了 `FollowPath`。
原因：launch 读取的是 `install/.../params/*.yaml`，没有重新 build。

**修复**：

```bash
colcon build --packages-select nav2_controller_lab
```

或开发时：

```bash
colcon build --symlink-install ...
```

**教训**：

> ROS 2 launch 读 install 副本。改参数后不 build，运行时还是旧参数。
> 这是最容易“以为代码没生效”的坑之一。

- 发布 `/controller_selector`；
- 显示当前控制器和 `/cmd_vel`；

### 可视化节点

- 订阅 `/plan`、`/cmd_vel`、`/controller_selector`；
- 发布 `/controller_lab/markers`；
- 绿色路径、黄色前视点、蓝色预测轨迹、白色文字。

### 关键坑

- `tf2::getYaw(geometry_msgs::Quaternion)` 需要链接 `tf2_geometry_msgs`；
  为减少依赖，改成手写四元数转 yaw。

- 面板发布 `/controller_selector` 必须用 transient_local，和 BT 订阅端匹配。

## 教训汇总

1. **符号约定要写清楚**：`signed_lateral` 正方向、修正项符号；
2. **测试要覆盖方向**：不仅测“有没有输出”，还要测“转哪边”；
3. **参数前缀不能漏**：`name_ + ".xxx"`；
4. **install 副本要重建**：改 YAML 后 `colcon build`；
5. **QoS 要匹配**：`/controller_selector` 用 transient_local；
6. **TF 是控制器第一坑**：`map→odom` 不通，一切都不对；
7. **局部 costmap 要加锁**：否则路径飘忽；
8. **运行时切换不是改参数**：是多实例 + selector；
9. **RViz 插件类名/XML/配置要一致**；
10. **端到端失败先查 TF 和进程，不要先怀疑算法**。
