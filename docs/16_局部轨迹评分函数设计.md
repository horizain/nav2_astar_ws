## 0. 三分钟版（赶时间看这里）

DWB-lite 冻结不是 bug，是**价值观（评分权重）的结构性后果**：

```text
旧价值观：  障碍代价权重 100  ≫  前进收益权重 2
            → 在膨胀场里，"前进"要先交几十年的过路费，
              "原地"只交当前格子的租金 → 原地永远是总分最小解 → 冻结

新价值观（对齐官方 DWB）：  前进收益 24  ≫  贴路径 8  ≫  障碍平手裁决 2
            + 碰撞二值化：撞上 253/254/255 整条轨迹一票否决
            → 前进收益在全场处处赢 ~18 分 → 10 秒穿缝到达
```

一句话记住：**碰撞用否决，不用罚分；罚分只用来裁决平局。**

## 1. 心智模型：局部控制器每个周期在干什么

先把 DWB 类控制器（DWB / MPPI / MPC 本质相同）的一个控制周期拆开：

```text
            ┌────────────── 每周期（本机 ~6Hz）──────────────┐
            │                                                │
输入 →      │  ① 生成候选：把 (v,w) 网格 or 噪声序列 按运动模型  │
局部代价地图 │     "演" 1.5 秒 → N 条未来轨迹                   │
全局路径    │  ② 打分：对每条轨迹算 cost（评分函数）            │
当前位姿    │  ③ 选择：选 cost 最小的那条的第一个控制 (v*, w*)   │
            └────────────────────────────────────────────────┘
输出 →      (v*, w*) 发给底盘，下个周期重来
```

三个要点，后面反复用到：

1. **打分的是"未来 1.5 秒的整条轨迹"，不是当前这一步**。所以评分函数
   评价的是一个"计划"，不是一个"动作"。
2. **"选最小"意味着：任何一项的权重配错，都会扭曲全部排序**。
   评分函数里没有"第二名的安慰奖"——最小值之外全是废案。
3. **运动模型是"恒定控制"外推**（`rolloutConstantControl`）：假设这 1.5 秒
   里一直保持 (v,w)。所以"轨迹末端离终点更近"严格对应"更快的前进"。

而"好轨迹"的定义在直觉上是三句话：

```text
A. 别撞          → 硬约束（否决），不是软代价
B. 沿着路前进    → 主收益（这项必须赢）
C. 别贴着障碍飞  → 平手裁决（同样安全时选更远的那条）
```

记住 A/B/C，本文所有数字都是在检查这三句话有没有被权重忠实翻译。

## 2. 评分函数解剖：六项各是什么、对应官方哪个 critic

我们实验室的评分函数在 `trajectory_cost.cpp::evaluateTrajectory`
（DWB / MPPI / MPC 三个控制器共用）：

```cpp
cost = path_weight      × path_cost      +   // 轨迹离路径的平均距离（米）
       goal_weight      × goal_cost      +   // 轨迹末端离路径终点的距离（米）
       obstacle_weight  × obstacle_cost  +   // 沿途代价地图值的平均（归一化 /252）
       heading_weight   × heading_cost   +   // 轨迹朝向与路径切线的平均夹角（弧度）
       velocity_weight  × velocity_cost  +   // |v - 期望巡航速度|（米/秒）
       control_weight   × control_cost       // |w|（弧度/秒，抑制乱转）
```

逐项解剖表（**单位**列决定了它的数值范围，这是所有比例问题的根源）：

| 项 | 单位/量纲 | 数值范围 | 官方 DWB 对应（`nav2_dwb_controller/dwb_critics/`） | 它奖励什么 | 它的副作用 |
|---|---|---|---|---|---|
| path_cost | 米（轨迹逐点路径距离的**均值**） | 0 ~ 几米 | `PathDistCritic`（默认 scale 32） | 贴着全局路径走 | 路径弯时会惩罚"抄近路"——通常这是好事 |
| goal_cost | 米（**轨迹末端**→路径终点，不取均值） | 0 ~ 全程长 | `GoalDistCritic`（默认 scale 24） | **前进**：末端越接近终点分越低 | 这是唯一持续奖励"往前走"的项 |
| obstacle_cost | 归一化（raw/252，轨迹逐点**均值**） | 0 ~ 1 | `BaseObstacleCritic`（默认 scale **0.02**） | 远离障碍（软性） | **权重一大，就变成"前进过路费"——冻结的元凶** |
| heading_cost | 弧度（均值） | 0 ~ π | `PathAlignCritic`（默认关闭 scale 0） | 朝向对齐路径切线 | 调头时惩罚很大，会阻止转身 |
| velocity_cost | 米/秒（离巡航速的偏差） | 0 ~ v_max | 无（速度窗口约束） | 维持巡航速度 | 若期望速度设 0，它会奖励原地！ |
| control_cost | 弧度/秒（|w|） | 0 ~ w_max | `OscillationCritic` 等 | 平滑、省电 | 太大会限制必要转向 |

两个容易忽视的细节：

- **obstacle 是均值，不是最大值**：一条轨迹哪怕 15 个点里只有一点擦到
  高代价区，也只按 1/15 计入。反过来，一条"全程泡在膨胀场里"的轨迹，
  每个点都在交租。
- **goal 是轨迹末端单点**：只看 rollout 结束时走到哪。这是"前进收益"的
  数学载体——它把"速度"换算成了"位置收益"。

> **官方源码对照**（想读真源码，按这个表找文件）：
>
> | 我们的项 | 官方文件 | 关键源码位置 |
> |---|---|---|
> | obstacle | `dwb_critics/src/base_obstacle.cpp` | `scorePose()` + `isValidCost()`（第 76-96 行） |
> | path/goal | `dwb_critics/src/map_grid.cpp` | 距离场传播（BFS），不是几何投影 |
> | heading | `dwb_critics/src/path_align.cpp` | forward_point_distance 前视点设计 |
> | 停车/朝向 | `dwb_critics/src/rotate_to_goal.cpp` | 官方的"终点旋转"阶段 |

```text
path_cost   = 0（全程骑在路径线上，投影距离恒 0）

obstacle    = Σcost=559，均值 559÷16 = 34.94 raw

```

```text
旧权重（path=1  goal=2   obstacle=100）：
```

## 4. 冻结的完整解剖

### 4.1 解析膨胀场：让"手算"成为可能

真实代价地图从激光雷达来，无法手算。但膨胀层有确定公式
（`nav2_costmap_2d::InflationLayer`）：

```text
d = 到最近障碍物表面的距离
cost(d) = 252 · exp( -λ · (d - r_inscr) / (R - r_inscr) )     当 r_inscr ≤ d < R
cost(d) = 253                                                  当 d < r_inscr（内切区）
cost(d) = 0                                                    当 d ≥ R

其中：R = inflation_radius = 0.70m
      r_inscr = robot_radius = 0.22m（机器人中心进入即碰撞）
      λ = cost_scaling_factor = 3.0
```

障碍物是 9 个圆柱（半径 0.15m，位于 (±1.1, ±1.1) 等 3×3 网格点）+ 六边形墙。
`docs/tools/dwb_scoring_demo.py` 用这套公式重建了代价场，并与仿真实拍
对照验证过：实拍 OccupancyGrid 里出现的 `99` 经翻译表
（`costmap_2d_publisher.cpp:102`）反查就是 raw **253**，解析值在同一位置
误差不超过 1 格（0.05m 栅格离散化）。

2. **冻结是自强化不动点**。机器人在场内时，"原地"每个周期交固定租金

   处处碾压障碍租金（满打满算 2 分）。没有相变，只有前进。

### 4.4 阈值 254 的第二宗罪：贴边合法

旧配置 `collision_threshold=254` 只否决撞上 LETHAL(254) 的轨迹。
**253（INSCRIBED，机器人中心进入必碰撞）却是合法分数**——看新权重表里
那个刺眼的 `1000000.0×`（w=+0.38/+0.76 的全速轨迹撞进内切区被否决）。
旧配置下同样的轨迹会**合法获选**，机器人会贴到离障碍 4cm 才由
下一步的采样重新裁决。官方 `isValidCost`（`base_obstacle.cpp:91-96`）
的语义是三值同罪：

```cpp
bool BaseObstacleCritic::isValidCost(const unsigned char cost)
{
  return cost != LETHAL_OBSTACLE &&            // 254
         cost != INSCRIBED_INFLATED_OBSTACLE && // 253
         cost != NO_INFORMATION;                // 255
}
```

## 5. 官方 DWB 的设计哲学：三条铁律

把官方默认参数（`nav2_bringup/params/nav2_multirobot_params_1.yaml:118-124`）
和 `base_obstacle.cpp` 放在一起，三条设计原则自己浮出来：

```yaml
critics: ["RotateToGoal", "Oscillation", "BaseObstacle", "GoalAlign",
          "PathAlign", "PathDist", "GoalDist"]
BaseObstacle.scale: 0.02     # ← 障碍权重：几乎为零！
PathAlign.scale: 0.0         # ← 默认关闭
GoalAlign.scale: 0.0         # ← 默认关闭
PathDist.scale: 32.0         # ← 贴路径：主导项之一
GoalDist.scale: 24.0         # ← 前进收益：主导项之一
RotateToGoal.scale: 32.0     # ← 终点旋转（对应我们的 rotateInPlace）
```

| 铁律 | 官方实现 | 我们旧配置违反之处 |
|---|---|---|
| **① 碰撞是二值的** | `isValidCost`：253/254/255 直接抛异常否决整条轨迹 | threshold=254 放过 253 |
| **② 不撞时，障碍只是平手裁决** | BaseObstacle.scale=0.02：raw 满值 252×0.02≈5 分，而 GoalDist 一步就赚 24×0.75=18 | obstacle=100：满值 100 分，压倒一切 |
| **③ 前进与贴路径是主导项** | GoalDist 24 + PathDist 32 | goal=2、path=1，被障碍碾压 |

**为什么官方敢把障碍权重设成 0.02？** 因为"别撞"根本不靠软惩罚实现——
靠①的一票否决。软惩罚的职责只剩"在都安全的候选里，偏向离障碍更远的"。
**把安全职责塞进软惩罚，就是冻结的根源**：安全是"0/1"问题，
软惩罚是"连续"问题，用连续项做 0/1 决策，边界上必然产生
"一动不如一静"的假最优。

> 这个模式在机器人之外随处可见：把"红线"写进 KPI 扣分项（而不是一票
> 否决），员工就会在红线边缘集体躺平。**约束的正确形态是否决，不是罚分。**

## 6. 解冻手术：三刀

### 第一刀：碰撞二值化

```yaml
collision_threshold: 254   →   253   # 253/254/255 同罪（对齐官方 isValidCost）
```

### 第二刀：前进收益升为主导（单位换算要对齐）

官方 BaseObstacle 的贡献范围：raw 代价 × 0.02 ∈ [0, 5.04]。
我们的 obstacle 项已归一化（raw/252 ∈ [0,1]），要贡献同一个范围，
权重应取 5.04×252/252……直接对齐**数量级与角色**：

```yaml
obstacle_weight: 100.0   →   2.0    # 满值贡献 2 分 ≪ 前进一步 18 分
goal_weight:      2.0    →   24.0   # 对齐官方 GoalDist.scale=24
path_weight:      1.0    →   8.0    # 对齐官方 PathDist.scale=32 的相对地位
```

校验数字：全速一步（0.75m rollout）的 goal 收益 = 24×0.75 = **18 分**；
obstacle 满值（全程贴着 252 的格子走）= **2 分**。前进收益 9 倍于最坏租金，
膨胀场里 typical 租金 ~0.28 分（§3.3 手算）——**没有相变空间**。

### 第三刀：知其边界——MPPI 为什么不用改？

MPPI 用同一评分函数但 obstacle_weight=100 也活着（46s 到达），为什么？
因为 MPPI 不是"选最小"而是**软最大加权**：100 条采样按
`exp(-cost/temperature)` 加权平均成控制序列。就算最贵的轨迹也能分到
一点点权重，输出是"全体的加权平均"——被推着穿过高代价区，
永远不会凝固在单点上。**min-cost 选择 + 高障碍权重 = 冻结；
softmax 加权 + 同样的权重 = 慢但不冻**。同一价值观，两种选择机制，
两种命运——这是 DWB 与 MPPI 最本质的区别。

（MPC 与 DWB 同属"选最优"家族，`obstacle_weight: 100` 的天价租金问题
**大概率同样存在**，作为本文练习 3 留给读者。）

租金差/步长**：0.1386×2 / 0.75 ≈ 0.37（理论），实际因 path/heading 项
略高。自己用 demo 验证。
</details>

## 10. 教训汇总

1. **评分函数是控制器的价值观**；权重不是"参数"，是"伦理"。改权重前
   先问：这个比例在奖励什么、惩罚什么、它的 0/1 边界在哪。
2. **约束用否决，不用罚分**。安全（碰撞）、上限这类"红线"必须是
   一票否决；软惩罚只做平手裁决。罚分做红线，必然制造"躺平解"。
3. **主导项必须赢**：前进收益（goal 项）的每步收益要 >> 最坏租金，
   否则"原地"成为不动点。官方比例（24 vs 0.02×252≈5）是几十年
   社区调出来的平衡，别乱翻。
4. **别信直觉，信表格**：直觉说"冻结=v=0 赢"，表格说"先爬 0.19m，
   爬到场边才冻"——机理比直觉细一层，而这层恰好就是实车行为
   （模型预测 x=-1.80 vs 实车 -1.81）。
5. **离线复算是调评分器的唯一正道**：0.1 秒一张 77 格评分表，
   先扫参数再上实车；实车一次 e2e 的成本是它的几千倍。
6. **同一评分函数 + 不同选择机制 = 不同物种**：min-cost 会凝固在
   局部最优，softmax 会被推着走。比较控制器时，先确认评分可比，
   再比较行为。
7. **模型可以精确到厘米**：几何 + 公式 + 与实拍对齐（±1 格），就能
   在文档里"手算"出实车行为——这才是可复现的教学。
