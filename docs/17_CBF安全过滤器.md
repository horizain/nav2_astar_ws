# 17 · CBF 安全过滤器——控制屏障函数从公式到实车

> **本篇回答的问题**：控制器（DWB/MPPI/MPC）再聪明也可能输出危险指令——
> 规划滞后、感知延迟、参数没调好、或者干脆是个学习出来的黑盒策略。
> 怎么**保证机器人永不碰撞**，而不是"希望它别撞"？
>
> 答案是本篇的主角：**CBF（Control Barrier Function，控制屏障函数）安全过滤器**

> 它是 2025-2026 年"学习控制 + 形式化安全"方向的基石组件（详见 doc 15 §0 的

>

## 0. 三分钟版

```text
问题：控制器输出的指令 v_nominal 可能撞墙，谁来兜底？

CBF 的答案：定义一个"屏障函数" h(x) = 到障碍的距离 − 安全余量，
           并要求系统状态满足：ḣ ≥ −α·h   （α 是一个增益函数）

读这句话：h 越大（离障碍越远），允许的接近速度越快；
          h → 0（逼近屏障），允许的接近速度也 → 0；
          h < 0（已经越界），条件强制 ḣ > 0（必须退出去）。
          ——一条不等式同时编码了"减速、停住、倒车退出"三层行为。

实现：把 ḣ ≥ −α·h 整理成对 v 的线性约束，取所有障碍约束的交集，
     把标称指令"裁剪"进可行域。对差速机器人，这个裁剪有解析解。
```

一句话记住：**控制器负责"想去哪"，CBF 负责"绝不去死"。**

## 1. 为什么安全层必须独立

先看架构。控制器实验室的速度链路（doc 15 §1 的拓扑加一层）：

```text
controller_server（六种控制器之一，输出 cmd_vel_nav）
  → velocity_smoother（加速度限幅，输出 cmd_vel_smoothed）
  → cbf_safety_filter（本篇主角：CBF 屏障过滤，输出 cmd_vel_cbf）  ← 新增
  → collision_monitor（nav2 自带，最后防线：碰撞在即的离散停/慢，输出 cmd_vel）
  → gz 桥 → 轮子
```

为什么不把安全逻辑写进每个控制器？三个理由：

1. **控制器有无数种**（我们实验室就有六种，真实世界更多：学习策略、遥操、
   视觉端到端……）。安全逻辑写 N 遍 = 维护 N 遍、漏 N−1 遍。
2. **安全性的数学要求与控制目标冲突**。doc 16 证明过：把"别撞"做成
   软惩罚，控制器会把它当"过路费"讨价还价（冻结/贴边）。安全不是
   目标函数的一项，是**硬约束**——约束的执行者应该独立于目标优化者。
3. **可验证性**。一个 200 行的独立过滤器，单测可以覆盖全部数学行为；
   塞进几万行的控制器里则无法审计。

这就是业界"分层防御"（defense in depth）的标准做法：**规划器负责舒适、
控制器负责跟踪、CBF 负责屏障、collision_monitor 负责最后的离散刹车。**
每层的失败模式互不相同，一层失效还有下一层。

## 2. 数学从零推导（不跳步）

### 2.1 安全集与前向不变性

定义屏障函数：

```text
h(x) = dist(机器人中心, 障碍物表面) − d_safe
```

- h > 0：安全（还有余量）
- h = 0：在屏障上（本设计取 d_safe = 机器人外接半径 0.22，即"贴到即停"）
- h < 0：已侵入（碰撞或进入禁区）

**安全集** C = {x : h(x) ≥ 0}。我们要的不是"某一刻安全"，而是
**永远安全**——数学上叫**前向不变性**（forward invariance）：

> 若初始 h(x₀) ≥ 0，则对所有 t > 0 都有 h(x(t)) ≥ 0。

### 2.2 从 Nagumo 条件到 CBF 条件

什么时候集合 C 是前向不变的？**Nagumo 定理**给出几何答案：

> 在集合边界（h = 0）上，只要状态的速度指向集合内部（或与边界相切），
> 即 ḣ ≥ 0，状态就出不去。

直观理解：站在悬崖边，只要每一步的位移都不朝悬崖外，你就掉不下去。
对被控系统，ḣ 由控制输入 u 决定，所以条件变成：

> **存在控制 u，使得 ḣ(x, u) ≥ 0（在 h = 0 处）**。

要求"ḣ ≥ 0"太苛刻（很多任务需要偶尔贴着屏障走）。CBF 的做法是放宽为
**与 h 成比例的容忍度**——引入 class-K 函数 α（严格递增、α(0)=0，
我们用线性 α(h) = k·h）：

```text
CBF 条件：  ḣ(x, u) ≥ −α(h(x))

h 很大   →  −α(h) 是很大的负数 → 几乎任何 u 都满足（畅通无阻）
h → 0    →  −α(h) → 0         → ḣ 至少不能为负（贴屏障必须相切或远离）
h < 0    →  −α(h) > 0         → ḣ 必须为正（强制退出！内置恢复行为）
```

一条不等式，三层行为，自动切换——这就是它的优雅之处。
可以证明（Ames et al. 2017 的核心定理，本文不展开证明细节）：
满足该条件的系统，从 C 内出发**永远留在 C 内**，且 h < 0 时指数收敛回 C。

### 2.3 差速机器人的 ḣ：逐符号推导

差速机器人状态 (x, y, ψ)，控制 (v, ω)。障碍点 p（世界系固定）。
设 d = |p − 机器人位置|，障碍相对机器人的方位角为 θ。

```text
h = d − d_safe
ḣ = ḋ                    （d_safe 是常数）
ḋ = d/dt |p − q|，q = 机器人位置
   = (p − q)ᵀ / |p − q| · (ṗ − q̇)
   = (− ê)ᵀ · (−v·[cosψ, sinψ]ᵀ)      （ṗ = 0 静态障碍；q̇ = 速度向量）
   = v · êᵀ[cosψ, sinψ]ᵀ
   = v · cos(θ)                        （ê 是指向障碍的单位向量）
     ─────┬─────
     注意符号：机器人朝障碍开 → d 减小 → ḋ < 0 → cos(θ) 对"朝向障碍"为正

所以：  ḣ = −v·cos(θ)
```

**关键观察 1**：ω（角速度）不出现在 ḣ 里！因为差速机器人绕中心旋转，
中心位置不动 → 到障碍的距离不变。**一阶 CBF 不约束转向**
（这既是解析解的来源，也是已知局限——footprint 角落会随旋转摆动，
见 §8 后续可做）。

**关键观察 2**：ḣ 对 v 是**线性**的！把 CBF 条件代入：

```text
−v·cos(θ) ≥ −α·h        （对每个障碍点/扫描束 i）
⟺   v·cos(θ_i) ≤ α·h_i
```

### 2.4 QP 形式与解析解

CBF 的通用求解形式是一个二次规划（QP）：

```text
min   (v − v_nom)² + (ω − ω_nom)²        （离标称指令尽量近，尊重控制意图）
s.t.  v·cos(θ_i) ≤ α·h_i   （∀ 障碍束 i）
      v_min ≤ v ≤ v_max    （底盘物理限幅）
```

约束对 v 线性、与 ω 无关 → **整个 QP 退化成一维区间裁剪**：

```text
对每束 i：
  cos(θ_i) > 0（障碍在前方） → v ≤ α·h_i / cos(θ_i)   → 收集为上界 ub_i
  cos(θ_i) < 0（障碍在后方） → v ≥ α·h_i / cos(θ_i)   → 收集为下界 lb_i
  |cos(θ_i)| ≈ 0（切向）     → 无约束，跳过

v_ub = min(物理上限, 所有 ub_i)     v_lb = max(物理下限, 所有 lb_i)

若 v_lb ≤ v_ub：  v* = clamp(v_nom, v_lb, v_ub)     ω* = ω_nom
若 v_lb >  v_ub：  前后夹击，可行域为空 → 最安全裁决 = 停车
```

**没有求解器依赖、没有迭代、微秒级完成**——这是差速机器人 + 静态障碍
的特例红利。多障碍只是多几条不等式，交集还是区间。

> 逐符号手算例（下面 §5 实验会实测验证）：正前方 0.5m 有一根柱子，
> d_safe=0.3，α=2 → h = 0.5−0.3 = 0.2，cos(θ)=1
> → ub = 2×0.2/1 = **0.4 m/s**。标称 0.5 被裁到 0.4：
> 机器人以 0.4 m/s 逼近，h 以每秒 0.4 递减，0.25 秒后 h=0.1 → ub=0.2，
> 再 0.25 秒后 h=0 → v*=0 —— **平滑的指数式逼近，永不越界**。

## 3. 实现解剖（`cbf_core.hpp/cpp`）

纯算法核心，不依赖 ROS（项目铁律），55 个单测里的 8 个属于它：

```cpp
CbfResult CbfFilter::filter(nominal_v, nominal_w, scan)
{
  // ① 逐束外参补偿 → 中心系点 (px, py)，中心距离 d，屏障 h = d − d_safe
  // ② 切向束跳过（|cosθ| < ε）：一阶下切向运动不改变距离
  // ③ cos(θ) > 0 收集上界，cos(θ) < 0 收集下界
  // ④ v_lb > v_ub → infeasible（停车）；否则 clamp 标称指令
  // ⑤ 诊断信息：min_h（最小屏障值）、binding_index（谁摁住了我）
}
```

两个实现细节值得单独讲：

**外参补偿（§4 第二课的核心）**。扫描束给出的是"雷达 → 障碍"的距离，
而屏障 h 需要的是"机器人中心 → 障碍"的距离。雷达不在中心时两者差最多
6.4cm（TB3 waffle）。补偿就是把点变换到中心系再算：

```text
点(中心系) = (range·cosψ + lx,  range·sinψ + ly)      lx/ly = 雷达安装偏移
d = √(px² + py²)     θ = atan2(py, px)     cos(θ) = px/d
```

**诊断输出**。`binding_index` 告诉你是哪一束摁住了机器人——实车排障时
这条信息价值千金（§4 第一课就靠它定位的）。

## 4. 实车踩坑三课（每个都有完整排查实录）

### 第一课：d_safe 必须与规划器的余量语义对齐

**现象**：CBF 上线后 DWB 导航退化——先是在余量边界抖动（413 次拦截），
然后蠕行失速、恢复行为断裂，最终 ABORTED。

**排查**：CBF 自己的拦截日志（`binding_index` + `min_h`）显示机器人
反复被摁在 h≈0 处；对照 DWB 侧它每周期仍报 v=0.5——**两个模块在打架**。

**根因**：d_safe 的三种取值对应三种系统行为（这是本课的精髓）：

| d_safe | 与系统的关系 | 实车行为 |
|---|---|---|
| 0.30（舒适余量） | > 规划器保证的走廊净空（A* 中线离柱面 0.40m，DWB 游走 ±0.13m） | CBF 在 DWB 的"合法"轨迹上拦停 → 打架/极限环 |
| 0.25 | 贴着游走下界 | 瓶颈处 h≈0 → 允许速度≈0 → 蠕行失速 |
| 0.24 | +1cm | 磨蹭 + 恢复行为（spin/backup）被 CBF 拦截而断裂 → ABORTED |
| **0.22（=机器人半径）** | **= DWB 碰撞阈值 253 的内切语义** | **DWB 合法轨迹全部在屏障内，CBF 只拦真碰撞 → 10 秒级 PASS** |

**教训**：**安全层的屏障语义必须与上游的碰撞语义一致**（本仓库里就是
`collision_threshold: 253` ⇔ 内切半径 0.22 ⇔ d_safe）。
舒适余量属于规划器的代价场（inflation_radius 管），不属于安全屏障。
安全层越权，整个系统就精神分裂。

### 第二课：雷达外参——安全层的第一杀手

**现象**：d_safe=0.22 后大部分路程正常，但机器人会在特定位置莫名停住，
CBF 日志显示 `拦截 v 0.50 → 0.01 (min_h≈0)`，束缚点指向侧后方扫描束。

**排查**：把束缚束的 (ψ, range) 和同步采到的机器人位姿放一起对账——
发现束的原始 range 比解析几何算出的"中心距"短了 ~6cm。

**根因**：查 `gz_waffle.sdf.xacro` 的 lidar_joint：

```xml
<pose>-0.064 0 0.121 0 0 0</pose>    ← 雷达在中心后方 6.4cm、上方 12.1cm
```

雷达不在中心！侧向束的原始 range ≠ 中心距离：一个"切向掠过"的束
（真实中心距 0.24，本不该约束）被当成"侵入屏障"（raw range 0.222 < 0.22）。
**外参没校准的安全层会系统性地误拦合法运动。**

**修复**：逐束外参补偿（§3 的 px/py 变换），加两个单测锁定：

```text
LidarOffsetCompensationPreventsFalseBarrier：实车案例数字，补偿前 v 被裁到 0.013（假死）
OffsetMakesFrontalMarginHonest：前方束的补偿方向（雷达在后 → 前方 h 更紧）
```

**验证**：拦截次数从 **413 次（补偿前）降到 16 次（补偿后）**，且 16 次
全部发生在真实的贴近场景。**教训**：安全层上线前，先校准传感器外参；
否则屏障守的是一个虚构的几何。

### 第三课：层间交互——安全系统之间的组合陷阱

**现象**：机器人因意外侵入屏障（h=−0.08）时，CBF 正确输出 −0.34 倒车
脱离，但机器人纹丝不动。

**排查**：逐级抓话题——CBF 输出正常（`cbf=−0.36`），但 `/cmd_vel` 上
**一条消息都没有**。读 `collision_monitor_node.cpp:213-224`：

```cpp
if (robot_action.req_vel.isZero()) {
    ...
    } else if (now() - stop_stamp_ > stop_pub_timeout_) {
      return;   // 零速持续 2 秒后，停止发布 cmd_vel（省带宽的官方特性）
```

**根因**：这是 nav2 的正常功能——零速 2 秒后停止发布。但与 CBF 的
"侵入→倒车"组合后：collision_monitor 在某个瞬间输出了零 → 2 秒后
停止发布 → CBF 的倒车指令再也没有机会到达底盘 → 倒车恢复被上游
"静音"。**两个各自正确的安全机制，组合出一个死锁。**

**处置**：本仓库接受此行为并记录在案（侵入场景本来就罕见，人工介入
或重新触发导航即可恢复）；真正的修复方向是把 CBF 的"侵入恢复"状态
显式告知上游（如发布 cbf_state 话题让 BT 感知）。**教训**：安全系统
叠加时，逐一测试"层间每一种状态组合"，这是安全工程里最贵的学费。

```text
出生 (-2.0,-0.5) → (-0.02,-0.45) → (0.18,-0.37) → (1.13,0.51) → ✅ SUCCEEDED
CBF 拦截 16 次（外参补偿前同类场景要拦 413 次，几乎全是误拦）

```

证据：`docs/results/logs/e2e_dwb_cbf_success.log`。

### 5.3 核心实验：同一指令"裸奔 vs 过滤"的 h(t)

工具：`docs/tools/cbf_experiment.py`（机器人面向 0.4m 外的障碍，恒定
0.2 m/s 直冲，记录 h 与过滤器实际输出）。

**基线（指令直捣底盘，无保护）**——`logs/cbf_exp_baseline_contact.log`：

```text
t=2.3  h=+0.120        t=3.8  h=+0.001   ← 屏障穿越点
t=4.3  h=−0.095        t=6.3  h=−0.095   ← 持续接触/推挤 6 秒
……机器人顶在障碍上直到实验结束
```

**CBF（同一指令经过滤器）**——`logs/cbf_exp_smooth_stop.log`：

```text
t=2.2  h=+0.318  cbf_out=+0.20   ← 全速（h 大，随便走）
t=4.2  h=+0.088  cbf_out=+0.12   ← 开始减速
t=5.2  h=+0.058  cbf_out=+0.06   ← 继续平滑下降
t=6.2  h=+0.045  cbf_out=+0.00   ← 到达平衡点
t=9.7  h=+0.044  cbf_out=+0.00   ← 稳稳停住，h 从未越界
```

对照读法：**同一条指令，唯一区别是走不走 CBF。** 裸奔的 h 曲线直穿
零点砸到 −0.10；CBF 的 h 曲线被"软着陆"在 +0.04——这正是 §2.4
手算的指数式逼近在实车上的样子（h 越小 → 允许速度越小 → h 下降越慢
→ 渐近停靠，永不越界）。

**第三段证据（侵入恢复）**：机器人已在屏障内（h=−0.08）时，CBF 输出
`−0.34 m/s` 倒车（§2.2 的"h<0 → ḣ>0"分支）——内置恢复行为，
无需任何额外代码。

## 6. 方法论：怎么复现与怎么玩


## 7. 手算练习（先自己算，再看答案）

### 练习 1

正前方障碍 h=0.15，α=2，cos(θ)=1。CBF 允许的最大前进速度是多少？
机器人以此速度匀速逼近，多少秒后 h 减半？

<details><summary>答案</summary>

ub = 2×0.15/1 = **0.30 m/s**。h 递减率 = ḣ = −0.30 → 0.075s 后 h=0.075。
但减速后允许速度也减半（v=0.15）→ 实际是**指数收敛**：h(t) = h₀·e^(−αt)
（把 ḣ ≥ −αh 取等号解出来），e^(−2t)=0.5 → t ≈ 0.35s。
这就是"软着陆"的数学形状——也是为什么实验里 cbf_out 是阶梯式下降。
</details>

### 练习 2

机器人右侧 0.5m 有障碍（θ=+90°），正前方 0.6m 有障碍（θ=0°），
d_safe=0.22，α=2。h 分别是多少？哪个约束有效？

<details><summary>答案</summary>

右：h = 0.5−0.22 = 0.28，cos(90°)=0 < ε → **切向跳过，无约束**
（前进会增大右侧距离，本就安全）。
前：h = 0.38，cos=1 → ub = 0.76 → 超过 v_max=0.5 → **不起作用**。
两条约束都"隐形"，标称 0.5 全速通过——CBF 的"隐形性"正是它
不打扰控制器的关键。
</details>

### 练习 3（开放）

雷达在中心后方 6.4cm（lx=−0.064）。一束 ψ=−60°、range=0.30 的读数，
对应的中心系点坐标、中心距离、方位角各是多少？不补偿时 h 会差多少？

<details><summary>答案</summary>

中心系点 = (0.30·cos(−60°) − 0.064, 0.30·sin(−60°)) = (0.15−0.064, −0.26)
= (0.086, −0.26)。中心距离 = √(0.086²+0.26²) = **0.274**；方位角
θ = atan2(−0.26, 0.086) = **−71.7°**（不是 −60°！）。
不补偿时把 range 当中心距：h 差 0.274−0.30 = **−0.026**，且约束角度
差 11.7°——补偿改变的不只是 h，还有约束本身的强度（cosθ）。
</details>

## 8. 教训汇总

1. **安全是硬约束不是软惩罚**（doc 16 的镜像结论）：目标优化者与
   约束执行者必须分离，否则约束会被"讨价还价"。
2. **屏障语义必须与上游碰撞语义一致**：d_safe = 规划器的内切语义半径。
   安全层越权（更大的余量），整层系统精神分裂。
3. **外参校准是安全层的第一课**：雷达不在中心时，raw range ≠ 屏障距离。
   逐束补偿，并把补偿写进测试。
4. **一条不等式三层行为**：h>0 允许、h≈0 停住、h<0 退出——CBF 把
   "减速/停止/恢复"统一进了一个优雅的形式，不需要状态机。
5. **诊断输出是排障的生命线**：`min_h` + `binding_index` 让"谁摁住了
   机器人"变成一条日志的事。
6. **安全系统叠加要测组合**：每层单独都对，组合可能死锁
   （collision_monitor 的零速停发 × CBF 倒车）。分层防御的代价是
   组合状态空间，测试矩阵别省。
7. **一阶 CBF 不约束 ω**：旋转不受屏障管（点机器人假设）。窄缝里
   原地旋转可能甩到障碍——footprint CBF（每个 footprint 角点单独建束）
   是标准解法，见后续可做。

## 9. 后续可做

- [ ] **footprint CBF**：对机器人外接圆上 8 个采样点分别建束
      （每点的 ḣ 含 ω 项），把旋转也纳入屏障——窄缝掉头场景需要。
- [ ] **高阶 CBF**：机器人有加速度限幅（velocity_smoother 的 max_accel），
      一阶 CBF 的 ḣ 约束可能被执行延迟破坏；二阶 CBF（把 ḣ 当状态）
      是标准解。
- [ ] **离散时间 CBF**：本实现以 ~20Hz 离散运行 + scan 5Hz，采样间隔里
      h 最多下降 v_max·Δt；理论上的修正是把 α·h 里扣掉采样补偿项。
- [ ] **CBF 与 MPPI critics 融合**：把屏障条件作为 MPPI 采样分布的
      支撑集（拒绝采样），比事后裁剪更平滑——2025 年多篇论文的路线。
- [ ] **侵入恢复的上游联动**：CBF 发布 `cbf_state` 话题，BT 感知到
      "屏障拦截中"时主动放弃当前路径重新规划（解决 §4 第三课的组合死锁）。

## 附 A：公式速查卡

```text
屏障：        h = d(中心, 障碍表面) − d_safe
CBF 条件：    ḣ ≥ −α·h          （α(h)=k·h，class-K 线性）
差速运动学：  ḣ = −v·cos(θ)     （θ=障碍方位角；ω 一阶不出现）
约束形式：    v·cos(θ) ≤ α·h    （对 v 线性 → QP 有解析解）
前向束：      v ≤ α·h / cos(θ)  （上界）
后向束：      v ≥ α·h / cos(θ)  （下界）
切向束：      |cos(θ)| < ε → 跳过
可行域：      [max(下界们), min(上界们)]，空 → 停车
指数收敛：    ḣ = −αh 的等号解 h(t) = h₀·e^(−αt)（软着陆的形状）

TB3 waffle 雷达外参：lidar_joint pose = (−0.064, 0, 0.121)
中心系点：    (range·cosψ + lx, range·sinψ + ly)
```
