## 1. 技巧 1+2：控制环被代价地图"拖着走"（收益最大的调优）

### 1.1 现象与原理

doc 15 记录过：控制环只跑 5-8Hz（目标 20Hz）。当时归因于"等 costmap 更新"，
但只修了进度检查，没动等待本身。这次把机制读透
（`controller_server.cpp:524-532`）：

```cpp
while (!costmap_ros_->isCurrent()) {          // 每个控制周期先等 costmap"新鲜"
  if (now() - waiting_start > costmap_update_timeout_) throw ...;
  r.sleep();
}
```

两个参数在这里会合：

- `local_costmap.update_frequency: 5.0` —— 代价地图自己 5Hz 才更新一次
- `costmap_update_timeout: 0.30` —— 控制器每个周期最多等它 300ms

costmap 5Hz 刷新 → 控制器平均每周期干等 ~100-200ms → 控制环 5-8Hz。

### 1.2 调优（两处，都已应用到 `nav2_params_controller_lab.yaml`）

```yaml
controller_server:
  ros__parameters:
    costmap_update_timeout: 0.05    # 0.30 → 0.05：不再长等
local_costmap:
  local_costmap:
    ros__parameters:
      update_frequency: 20.0        # 5.0 → 20.0：与控制器同频
```

安全依据：控制环用上一次周期的代价地图是否危险？本链路下面还有
CBF 屏障（连续）+ collision_monitor（离散）两道独立防线兜底，
控制环拿 50ms 旧的地图完全可接受。

### 1.3 实测

```bash
# 运行中采样控制环频率（注意类型是 Twist 不是 TwistStamped！）
python3 -c "
import rclpy, time
from rclpy.node import Node
from geometry_msgs.msg import Twist   # 本构建 cmd_vel_nav 是 Twist
rclpy.init(); n = Node('probe')
n.set_parameters([rclpy.parameter.Parameter(
    'use_sim_time', rclpy.parameter.Parameter.Type.BOOL, True)])
cnt = [0]
n.create_subscription(Twist, 'cmd_vel_nav', lambda m: cnt.__setitem__(0, cnt[0]+1), 10)
end = time.time()+8
while time.time() < end: rclpy.spin_once(n, timeout_sec=0.1)
print(f'{cnt[0]/8:.2f} Hz')"
```

- MPPI（计算最重的控制器）：**5.5-8.3 Hz → 19.62 Hz**
- 超速警告（`Control loop missed its desired rate`）：每次运行 20+ 条 → **0-3 条**
- CPU 代价：controller_server 总占用 15.2%（单核百分比，32 核机器忽略不计）

### 1.4 一个重要反例：频率 ≠ 到达时长

调优后 MPPI 端到端 157-162s（调优前 46s）——**变慢了**！诚实归因：

1. 对比混入变量：46s 那次走的是中线穿缝（~4.2m），调优后两次都绕了
   北线（~7m）——**A* 重规划的路径选择有运行间随机性**，
   MPPI 的到达时长由路径长度主导，不由控制环频率主导。
2. 控制环频率提升的价值是**响应性**（避障反应延迟 100ms → 50ms）
   和**采样密度**（MPPI 每秒多算一倍的轨迹批），不是"到达更快"。
3. 关掉 CBF 做的变量分离（`enabled false`）：161.9s——证明慢不是
   CBF 造成的，路径随机性 + MPPI 的固有谨慎爬行才是。

> **教训：别把"更快"和"更快到达"混为一谈。** 优化前先问清楚
> 你要优化的指标到底是什么。时长类指标要做 N 次取中位数，
> 单次对比会自己骗自己。

## 2. 技巧 3：传感器"慢"先查配置，别急着怪环境

**反转了一个旧结论**。doc 15/17 里我们把"激光只有 ~5Hz"归因于
"WSL2 headless 渲染瓶颈"。这次追查 SDF 源头
（`gz_waffle.sdf.xacro:140`）：

```xml
<sensor name="hls_lfcd_lds" type="gpu_lidar">
  <update_rate>5</update_rate>     ← 标称就是 5Hz！
```

**实测 5Hz = 配置 5Hz，零损失。** 渲染瓶颈根本不存在（IMU 同文件里
配了 200Hz，跑起来也是足额的）。深度相机同为 5Hz（380 行）。

排查口诀（这次通用化）：

```bash
# 传感器慢？三步定位：
# ① 查配置标称值（SDF/URDF/xacro 的 update_rate）
grep -n "update_rate" /opt/ros/jazzy/share/nav2_minimal_tb3_sim/urdf/gz_waffle.sdf.xacro
# ② 实测实际值（rclpy 计数，别用 ros2 topic hz——本机 CLI 不稳）
# ③ 对不上才查环境（渲染后端/网络/DDS），对上了就改配置

# 想提频：复制 SDF 到自己工程，改 update_rate，用 robot_sdf 参数传入
# （官方 tb3_simulation_launch.py 支持 robot_sdf 参数——不要直接改 /opt）
```

> **教训：报错和环境慢，先怀疑配置。** 修改 `/opt/ros` 下的文件会在
> apt 升级时丢失；正确做法是复制到自己的包再通过参数传入。

## 3. 技巧 4：把 DDS 发现域限制在本机

**问题**：WSL2 的虚拟网卡会参与 DDS 组播发现，局域网里任何 ROS 设备
（或虚拟交换机的广播噪声）都会拖慢/干扰发现——doc 03/15 的服务超时、
话题丢失都与此有关。

**做法**（Jazzy 的标准姿势，两个进程都要设）：

```bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
```

**实测**：连续 3 个会话 bringup 全部干净（对比此前 ~5 次里 1 次
amcl 没起来）。样本量小，不下强结论；但这是零成本的标准操作，
值得常驻 `~/.bashrc`。

**注意**：多机协作时不要设 LOCALHOST（会互相看不见）。

## 4. 技巧 5：自动化里"验证-重试"是唯一可靠的姿势

doc 15 坑一的完整沉淀。本机实测的可靠性排序：

| 方式 | 实测可靠性 | 说明 |
|---|---|---|
| rclpy 直调 service | ~0/3（本机服务响应常超时） | 但请求-应答语义仍是对的 |
| 话题连发 5 次 | 高（配合验证） | volatile QoS 单发会丢 |
| **service → 话题连发 → 验证 map→odom → 重试×3** | **3/3 全成功** | e2e_nav_test.py 的现行实现 |

核心原则（doc 15 教训 #1 的工程化）：

```python
# 伪代码框架——"发布成功"永远不等于"送达"
for attempt in range(3):
    service_call() or topic_burst(5)      # 两条腿走路
    if verify_effect():                    # 以对端反应为准（TF 出现）
        return True
    time.sleep(1)                          # 冷却后重试
```

同类验证点：生命周期激活也加了重试（DDS 服务响应超时会吞掉
change_state 的响应，实测 planner_server 偶发卡在 inactive）。

## 5. 技巧 6：`--symlink-install`——参数文件改完即生效

**痛点**（doc 14 教训 #4）：改了 `params/*.yaml` 后必须 `colcon build`
才生效——因为 install/ 下是构建时的拷贝。改参数 → 编译 1 分钟 → 忘编译
→ "改了没生效"排查半天。

**做法与实测**：

```bash
colcon build --packages-select nav2_controller_lab --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
# 之后 install 副本变成软链接：
ls -la install/nav2_controller_lab/share/nav2_controller_lab/params/*.yaml
# lrwxrwxrwx ... yaml → 源文件
```

实测验证：重建后（6.9s）install 副本变为 `lrwxrwxrwx` 软链接；
`cp src/...yaml install/...yaml` 直接报 **"are the same file"** ——
改源文件即生效，零构建。**适用**：yaml/launch/rviz/urdf 这类资源文件；
**不适用**：C++ 代码（还是得编译）。

> 注意：`--symlink-install` 和普通 build 不要来回混用同一个 workspace
> 的同一包（链接和拷贝会打架）；团队统一一种。

**真实翻车（2026-11-15）**：只对 `nav2_controller_lab` 跑过一次
`--symlink-install`，之后又用普通 build。普通 install 会顺着已有软链接
把文件写回 `build/`，并不会把链接换成副本；后来清理 build 目录，链接
全部悬挂，于是出现“install 目录明明存在，包却找不到”：

- `source install/setup.bash` 报
  `not found: .../install/nav2_controller_lab/share/.../local_setup.bash`；
- `local_setup.dsv` 悬挂 → 该前缀根本没加进 `AMENT_PREFIX_PATH`；
- `share/ament_index/resource_index/packages/<pkg>` 悬挂 →
  `ros2 pkg prefix` 报 `Package not found`。

修复时**不能只删 `build/`**：必须把 `install/<pkg>` 也删掉，再普通构建，
否则新文件仍会顺着旧链接写回 build。工作空间自带的脚本把这件事封装好了：

```bash
cd ~/ros2_jazzy/nav2_astar_ws
./check_workspace.sh          # 只诊断：悬挂链接 + 干净 shell 三级 source
./check_workspace.sh --fix    # 备份 install/<pkg>、清 build/<pkg>、普通重建
```

## 7. 排障技巧集（docs 15-17 的浓缩索引）

| 技巧 | 一句话 | 详见 |
|---|---|---|
| **CLI 不可信** | `ros2 topic pub --once` 的 `-p` 冲突、service call 挂起；自动化一律 rclpy 直调 + 验证重试 | doc 15 坑一 |
| **sim-time 探针陷阱** | `use_sim_time` 节点的 `now()` 在首帧 /clock 前是 0，计时循环先等时钟 | doc 15 坑二 |
| **周期性报错 = 定时器** | 报错间隔对账参数里的时间常量（如 `movement_time_allowance: 10`） | doc 15 坑三 |
| **接口契约的隐含条款** | goal checker 查 yaw → 控制器必须做终点旋转；读官方插件的对应实现 | doc 15 坑四 |
| **消息类型先查再用** | 本构建 `cmd_vel_nav` 是 Twist 不是 TwistStamped（`ros2 topic info -v` 一查便知） | 本篇实测 |
| **pkill 三连坑** | bracket 模式防自杀；同行裸串会破坏保护；清理永远单独跑 | doc 17 实操 |
| **bash 语法坑** | `a && b &` 把整条链后台化（source 全丢）；用 `;` 分行或花括号分组 | 本篇实操 |
| **JS 没有 Math.copysign** | "朝零收敛"的递减必须用 `Math.sign(turnRem)*stepRot`——`turnRem -= |step|` 在 turnRem<0 时会越减越远（无限旋转死锁，可视化网站实测） | doc 22 配套网站 |
| **进程清理清单** | 强杀后清 SHM（`fastrtps_*` + `sem.fastrtps_*`）；模式串见 doc 15 §7.2 | doc 03 §6.3 |
| **评分器离线复算** | 改权重先跑 `dwb_scoring_demo.py`（0.1s 一张表），再上实车 | doc 16 |
| **安全层上线三查** | d_safe 对齐内切语义、雷达外参补偿、层间状态组合 | doc 17 |
