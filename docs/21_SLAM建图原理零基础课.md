## 1. 问题定义：漂移是必然的（手算）

里程计 = 轮子转了多少圈 × 轮周长。误差来源：轮径磨损、地面打滑、
齿轮间隙。**关键性质：误差随时间累积（积分器）**。

手算：轮径标称 6.6cm，实际磨损 6.4cm（偏差 3%）。机器人走 5m：

```text
里程计读数 = 5.00 m（按标称轮径换算）
真实位移   = 5.00 × (6.4/6.6) ≈ 4.85 m      → 误差 15cm
```

走 50 米误差 1.5 米。更糟的是**航向误差**：轮距差 2%，原地转 360°
实际转 367°——方向错了，之后每一步都跟着错。所以：

> 纯里程计在几十秒后必然失去位置（本机 gz 里程计 11 秒导航就漂了
> ~3cm，doc 17 探针实测）。SLAM 的本质 = 用**外部观测（激光/相机）**
> 不断把漂移拉回来。

## 2. 概率地基：贝叶斯滤波（SLAM 的数学语言）

### 2.0 直觉：为什么必须用概率

确定性思维说"机器人在 (2.3, 1.1)"。但轮子会打滑、激光有噪声、
地图有误差——**你对位置的知识永远是不完美的**。硬给一个数 = 假装
自己不糊涂。正确的表达是一个**概率分布**："60% 在格子 2，20% 在
格子 1，20% 在格子 3"——这叫**信念（belief）**。SLAM 全文都在回答：
"信念怎么随'我动了'和'我看到了'而更新？"

### 2.1 场景设定

三格走廊，格子 1、3 有门。机器人传感器只能报"门/非门"：

```text
 ┌─────┬─────┬─────┐
 │ 门1 │     │ 门3 │      传感器模型：
 │ (1) │ (2) │ (3) │    P(报门|真有门) = 0.8    （正常）
 └─────┴─────┴─────┘    P(报门|没门)   = 0.2    （误报率）
   ↑初始时完全不知道位置 → 信念均匀 [1/3, 1/3, 1/3]
```

运动模型：命令右移一格 → 80% 成功右移、20% 打滑原地；
格子 3 的右墙挡住，向右命令在格子 3 等价于不动。

实验序列：**测到"门" → 右移一格 → 再测到"门"**。

### 2.2 第一步：观测更新（测到"门"）

规则：每个格子，把信念乘以"这个格子下会报门的概率"：

| 格子 | 旧信念 | 是门? | 乘数 | 未归一化 | 归一化(÷0.6) |
|---|---|---|---|---|---|
| 1 | 0.333 | 有 | 0.8 | 0.2667 | **0.4444** |
| 2 | 0.333 | 无 | 0.2 | 0.0667 | **0.1111** |
| 3 | 0.333 | 有 | 0.8 | 0.2667 | **0.4444** |

> 归一化是为了让信念总和保持 1（概率的守恒律）。0.6 = 未归一化之和。

**读数**：门 1 和门 3 各拿走一半信念（0.444 vs 0.444 平分）——
"只测一次门"**无法区分两个门**。这个多峰是世界对称造成的，
不是算法的错。

### 2.3 第二步：预测（右移一格）

规则：新信念[格子i] = Σ 从各格子按运动模型流进 i 的信念：

| 来源 | 概率流 | 去向 |
|---|---|---|
| 格子 1 | 0.4444 × 0.8 右移 | → 格子 2 |
| 格子 1 | 0.4444 × 0.2 打滑 | → 格子 1 |
| 格子 2 | 0.1111 × 0.8 右移 | → 格子 3 |
| 格子 2 | 0.1111 × 0.2 打滑 | → 格子 2 |
| 格子 3 | 0.4444 × 1.0（右墙挡住=原地） | → 格子 3 |

汇总：

| 格子 | 计算 | 预测后 |
|---|---|---|
| 1 | 0.4444 × 0.2 | **0.0889** |
| 2 | 0.4444×0.8 + 0.1111×0.2 | **0.3778** |
| 3 | 0.1111×0.8 + 0.4444×1.0 | **0.5333** |

**读数**：两个峰被运动"摊开"——左峰流进格子 2，右峰留在格子 3。
信念总和仍为 1（预测是概率守恒的重分配，doc 16 的"评分器价值观"
在概率上的对应物）。

### 2.4 第三步：再测"门"

| 格子 | 预测后 | 是门? | 乘数 | 未归一化(η=0.5733) | 归一化 |
|---|---|---|---|---|---|
| 1 | 0.0889 | 有 | 0.8 | 0.0711 | **0.1240** |
| 2 | 0.3778 | 无 | 0.2 | 0.0756 | **0.1318** |
| 3 | 0.5333 | 有 | 0.8 | 0.4267 | **0.7442** |

**读数**：**74% 锁定格子 3**。一次运动 + 一次观测打破了对称。
这就是 AMCL 粒子滤波定位的原理（把分布换成 N 个粒子）。

### 2.5 跑工具验证

```bash
python3 docs/tools/slam_playground.py --demo 2
```

真实输出（与上表逐数一致）：

```text
  先验                     [0.3333, 0.3333, 0.3333]
  （观测1 未归一化 [0.2667, 0.0667, 0.2667]，η=0.6000）
  观测1(报门)后             [0.4444, 0.1111, 0.4444]
  （预测：80%右移 / 20%原地；格子3右墙=原地）
  预测(右移)后              [0.0889, 0.3778, 0.5333]
  （观测2 未归一化 [0.0711, 0.0756, 0.4267]，η=0.5733）
  观测2(报门)后             [0.1240, 0.1318, 0.7442]
```

### 2.6 对数几率（log-odds）：把乘法变加法

概率只能取 [0,1]，连乘一堆小概率会数值下溢。SLAM 通用技巧是换成
log-odds：

```text
l = ln( p / (1−p) )          p = 1 / (1 + e^(−l))     （互逆）

p=0.5 → l=0        p=0.7 → l=ln(7/3)=0.847        p=0.3 → l=−0.847
```

妙处：**贝叶斯更新 = 加法**（乘 p 一次 = l 加一项）。§3 的栅格建图
全靠它。

## 3. 建图的最小单元：占据栅格（已知位姿怎么画地图）

### 3.0 直觉

激光一束 = 一次"探索"：**光束打到的地方有墙，光束路过的地方没墙**。
每个格子像一个"投票箱"：每次观测投一票（占据/自由），格子按票数
更新自己的"占据概率"。投票不能一次定终身——噪声票会被后续票对冲。

### 3.1 反演传感器模型（inverse sensor model）

```text
        机器人          束中（自由证据）        束端（占据证据）
          ●━━━━━━━━━━━━━━━━━━━━━━━━━■
        格子0      格子1,2,3,4…        格子N（±1 格宽）
```

```text
光束终点附近的格子（±1 格）→ 被占据    P(occ) = 0.7    → l = +0.847
光束沿途穿过的格子          → 是自由的 P(occ) = 0.3    → l = −0.847
光束没扫到的格子            → 不更新    P(occ) = 0.5    → l = 0
```

### 3.2 更新公式

```text
l_t = l_(t−1) + l_meas − l_0          l_0 = ln(0.5/0.5) = 0
```

减 l_0 的作用：让证据**可对冲**——多次观测只叠加净效果。

### 3.3 跑工具：一面墙是怎么被"画"出来的

场景：12 格 1D 世界，机器人站格子 2，朝右发 6 格长的激光束
（束端 = 格子 8 的墙）。连续测 3 次，再加一束"噪声穿透"：

```bash
python3 docs/tools/slam_playground.py --demo 1
```

真实输出（第 1 束 + 每束后的栅格快照）：

```text
--- 第 1 束：右方 6 格处有墙（正常回波） ---
   格     更新前l         证据     更新后l     更新后p
   3    0.000    自-0.847   -0.847    0.300
   4    0.000    自-0.847   -0.847    0.300
   5    0.000    自-0.847   -0.847    0.300
   6    0.000    自-0.847   -0.847    0.300
   7    0.000    自-0.847   -0.847    0.300
   8    0.000    占+0.847    0.847    0.700
  栅格快照  [+++.....#+++]   (#=占据 >65%, +=未知, .=自由 <35%)

--- 第 2 束：同上（再测一次） ---
   8    0.847    占+0.847    1.695    0.845
  ...
```

**读数**：
- 格子 8（墙）：一次占据证据 → p=0.700；两次 → l=1.695 → p=0.845；
  三次 → l=2.54 → p=0.927。**证据越多越确信**（指数逼近但永不到 1）。
- 格子 3-7（束中）：一路降到 p=0.155 甚至更低——"激光穿过=没墙"
  的证据在累积。
- `[+++.....#+++]`：# 是墙（格子 8），点是被"打通"的走廊，
  `+` 是没扫到的未知区。**地图就是这样一格一格投票投出来的。**

### 3.4 证据对冲：噪声票会被洗掉（第 4 束）

工具里的第 4 束模拟噪声：束长 3（假回波把格子 5 标成占据）：

```text
   5   -1.695    占+0.847   -0.847    0.300     ← 一票占据被洗掉
```

格子 5 此前累计了 2 次"自由"（l=−1.695），加一次错误"占据"
（+0.847）后回到 −0.847（p=0.30）——**单次噪声伤不了累积的证据**。
这就是动态物体（人走过）不留永久幽灵墙的数学根基（doc 22 抗干扰）。

## 4. EKF-SLAM：位姿未知时的"同时"估计

### 4.0 直觉

§3 假设"位姿已知"——现在撕掉这个假设。EKF 的做法：

```text
把"机器人位姿"和"所有路标位置"打包成一个向量，
用一个高斯分布（均值 + 协方差矩阵）描述对它们的全部认知：

     x = [机器人位置, 路标位置]         Σ = [[σ机器人², 关联],[关联, σ路标²]]

预测 = "我动了" → 均值平移、不确定性变大（协方差膨胀）
更新 = "我看到了" → 不确定性收缩，且各个量之间产生关联
```

生活比喻：你蒙眼被带进一栋楼，走了几步（预测：更糊涂），摸到了
"消防栓"（更新：楼里所有跟消防栓有关的位置推理都变准了——
且你对"自己走了多远"的判断和"消防栓在哪"的判断从此绑在一起）。

### 4.1 手算全过程（1D 机器人 + 1 个路标）

状态 x = [机器人位置, 路标位置]，先验（高斯）：

```text
x̄ = [1.0, 3.0]，Σ = [[1.5, 0], [0, 0.5]]
```

**预测步**：机器人前进 u=1（运动噪声 σ²=0.5 只作用在机器人；
路标不会自己动）：

```text
x̄ = [2.0, 3.0]              （均值平移）
Σ = [[1.5+0.5, 0], [0, 0.5]] = [[2.0, 0], [0, 0.5]]   （膨胀）
```

**更新步**：观测到"路标在机器人前方 1.2m"（按估计应预测为
3.0−2.0 = 1.0m，0.2 的偏差来自观测噪声，方差 R=0.25）。
观测方程 z = 路标 − 机器人：

```text
H = [−1, +1]                （z 对状态的雅可比：z 对 x 求 −1、对 m 求 +1）
残差 = z − H·x̄ = 1.2 − 1.0 = 0.2
S = H·Σ·Hᵀ + R = (−1)²·2.0 + 1²·0.5 + 0.25 = 2.75
K = Σ·Hᵀ/S = [−2.0, 0.5]/2.75 = [−0.727, +0.182]     （卡尔曼增益）
```

**卡尔曼增益的直觉**：K 是"观测的话听几成"。
- K_机器人 = −0.727：残差 0.2 里，机器人位置该被修正 −0.145
  （还要乘 −1 的符号 → 机器人往回挪 0.145，因为"路标比我预想的远
  0.2"意味着"我比预想的靠前了"）
- K_路标 = +0.182：路标跟着被微调 +0.036

修正与收缩：

```text
x = [2.0, 3.0] + [−0.727, 0.182]×0.2 = [1.855, 3.036]
Σ = (I − K·H)·Σ = [[0.545, 0.364], [0.364, 0.409]]
```

### 4.2 跑工具验证

```bash
python3 docs/tools/slam_playground.py --demo 3
```

真实输出：

```text
预测后        x = [2. 3.], Σ =
[[2.  0. ]
 [0.  0.5]]
  （机器人位置 1.0→2.0；方差 1.5→2.0 膨胀；路标不变）

观测 z=1.2    预测值 H·x = 3.0−2.0 = 1.0
残差 = 1.2 − 1.0 = 0.2
S = H·Σ·Hᵀ+R = 2.0+0.5+0.25 = 2.75
K = Σ·Hᵀ/S = [−2.0, 0.5]/2.75 = [-0.727, +0.182]

更新后        x = [1.85454545 3.03636364]
Σ =
[[0.54545455 0.36363636]
 [0.36363636 0.40909091]]
```

与手算逐数一致。**读数**：
- 机器人方差 2.0 → **0.545**（观测把不确定性吸走了）
- 交叉协方差 **0.364 ≠ 0**：机器人和路标从此关联
- 路标估计 3.0 → 3.036：机器人的位置不确定性"传染"给了路标

### 4.3 EKF-SLAM 的宿命：相关性链条与规模爆炸

每观测一个新路标，它就通过机器人位姿与**所有旧路标**产生关联——
协方差矩阵几乎全满。n 个路标 → O(n²) 矩阵，1000 个路标 = 100 万个数
每次更新。这就是 EKF-SLAM 被淘汰的原因。但它的**相关性洞察**统治了
后续所有 SLAM：一旦回环，全图一起校正（§7 会再见到这一幕）。

## 5. 粒子滤波路线：用"一群假设"代替一个分布

### 5.0 直觉

高斯假设扛不住多峰（"走廊两头长得一样，我可能在 A 也可能在 B"——
强行用单峰高斯等于对一半可能性装瞎）。粒子滤波用 **N 个加权假设**
采样整个信念分布：一群"如果我在这里呢？"的平行宇宙。

三步循环：**按运动模型抖动粒子 → 按观测加权 → 按权重重采样**
（权重高的繁殖，权重低的淘汰）。

### 5.1 场景与跑工具

```text
1D 世界 [0, 7m]，门在 1.0m 和 3.3m（非对称间距，故意打破对称）
传感器：报"到最近门的距离"（σ=0.05）
运动：前进 0.7m（σ=0.03）
机器人真实位置：从 2.15m 出发（粒子不知道）
粒子：200 个，均匀撒满 [0,7]
```

```bash
python3 docs/tools/slam_playground.py --demo 4
```

真实输出：

```text
  初始均匀    [####...####...####...####...####...###.]  n=200
  测距 z=0.85  [..............##......##....##......##.]  n=200
      → 存活簇（多峰）：[1.8, 2.2, 2.2, 4.4]
  移动+测距   [..............................#.......]  n=200
      → 真值 2.87，粒子均值 2.85
  再移+测距   [.................##................]  n=200
      → 真值 3.62，粒子均值 3.60，标准差 0.033
```

（直方图 36 格，每格 0.19m；`#` = 有粒子存活）

### 5.2 读数（三幕剧）

1. **初始均匀**：完全迷失——粒子撒满整个世界。
2. **第一次测距**：只留下 4 个存活簇（比如 1.8/2.2/2.2/4.4）——
   "到最近门 0.85m"的位置有多个。**多峰不是 bug，是诚实**。
3. **移动 0.7m + 再测距**：三个簇里的粒子跟着平移，然后被新观测
   大批处决（门间距 1.0/3.3 的不对称性开始起作用）。
4. **第三次测距**：只剩一个簇，粒子均值 3.60 vs 真值 3.62，
   标准差 0.033 —— **锁定**。粒子标准差 = 定位置信度。

### 5.3 FastSLAM / Gmapping：粒子 + 每粒子一张地图

- **FastSLAM**（2003）：条件独立性洞察——已知机器人轨迹，各路标
  独立 → 每个粒子带 N 个独立小 EKF（每个路标一个），把 EKF-SLAM
  的 O(n²) 打成 O(n·logN)。
- **Gmapping**（2007）：RBPF + 栅格地图（每个粒子背一张全地图）
  + 改进提议分布（先扫描匹配再采样，减少所需粒子数）。ROS1 时代
  默认，现已停止维护——但"粒子=假设集"的思想活在 **AMCL**
  （定位版粒子滤波，本仓库一直在用）里。

**代价**：覆盖多峰需要粒子数；粒子带地图 → 内存 N×地图。
世界一大就撑不住 → 图优化（§7）登场。

## 6. 扫描匹配：两帧激光怎么对齐（前端的核心）

### 6.0 直觉

"我看到了一排墙点，上一帧的地图里也有这排墙点——把我的新帧
平移旋转一下，什么时候两组点最重合？"——重合度最高的那个位姿，
就是"我这步实际走了多少"的估计。这个相对位姿就是位姿图的一条边
（§7）。

### 6.1 相关性扫描匹配（correlative scan matching）

slam_toolbox 与 Cartographer 前端的主力。思路朴素但稳：在搜索窗口内
枚举所有 (dx, dy, dθ) 偏移，把激光点按候选偏移投影到**已有地图**上
取代价求和，最优者为匹配结果。

### 6.2 手算 + 跑工具

地图 5×5，代价：墙格=10，自由格=0。墙在 x=3 列：

```text
 ┌───┬───┬───┬───┬───┐
 │   │   │   │ 墙│   │   行3
 ├───┼───┼───┼───┼───┤
 │   │   │   │ 墙│   │   行2
 ├───┼───┼───┼───┼───┤
 │   │   │ 激│ 墙│   │   行1     激光点 S = {(2,1),(2,2),(2,3)}
 ├───┼───┼───┼───┼───┤   （机器人看到墙前一排）
```

总分 = 匹配代价 + λ·‖偏移 − 里程计预测‖²（λ=2，里程计预测 (+0.1, 0)）：

```bash
python3 docs/tools/slam_playground.py --demo 5
```

真实输出：

```text
候选(dx,dy)     投影后代价     里程计罚     总分
(  0,  0)              0       0.02     0.02 ← 最优   [(2,1)=0 (2,2)=0 (2,3)=0]
(+1, 0)              30       2.42    32.42   [(3,1)=10 (3,2)=10 (3,3)=10]
(-1, 0)               0       2.42     2.42   [(1,1)=0 (1,2)=0 (1,3)=0]
(  0, 1)              0       2.02     2.02   [(2,2)=0 (2,3)=0 (2,4)=0]
(  0,-1)              0       2.02     2.02   [(2,0)=0 (2,1)=0 (2,2)=0]
(+1, 1)              20       3.62    23.62   [(3,2)=10 (3,3)=10 (3,4)=0]
```

**读数**：
- (0,0) 和 (−1,0) 匹配代价打平（都是 0）——**纯匹配分有歧义**
- 里程计先验罚项破平局 → 最优 (+0,+0)
- (+1,0) 撞墙代价 30 → 直接否决（doc 16"碰撞一票否决"同款）

### 6.3 ICP 与多分辨率

- **ICP**（迭代最近点）：按最近点配对 → 解最小二乘平移/旋转 → 迭代。
  需要较好初值，否则局部最优。
- **工程解法是两段式**：粗搜索（correlative，大步长扫全窗口）→
  精搜索（ICP 或高分辨率 correlative）。Cartographer 用多分辨率
  体素图加速粗搜；slam_toolbox 用 `correlation_search_space_*`
  参数控制窗口与步长（doc 22 §1.2 逐条讲）。

## 7. 图优化 SLAM：全局求解让所有观测自洽

### 7.0 直觉：为什么需要它

里程计漂移（§1）让"按里程计拼起来的地图"越拼越歪——走一圈回到
原点，地图上的"原点"却偏了 0.2m。扫描匹配能纠正**相邻两帧**的
相对运动，但**相对运动的误差也在累积**。出路：当机器人回到去过
的地方（**回环**），加一条约束说"这里就是你 20 分钟前的位置"——
然后**全局求解**让所有约束尽量同时成立，把漂移"均摊"回整条轨迹。

```text
位姿图：  ● x1 ──里程计── ● x2 ──里程计── ● x3
          └──────────── 回环约束 ────────────┘
求解：让所有边（弹簧）同时尽量满足 → 弹簧网平衡 = 全图校正
```

### 7.1 数学形式

```text
min J = Σ_边 ‖f(边) − 观测‖²_Σ          （‖·‖²_Σ = 按 1/σ² 加权）
```

每条边是一个"软弹簧"：σ 小 = 硬弹簧（信任度高），σ 大 = 软弹簧。

### 7.2 手算：三节点 + 一次回环（本篇最重要的手算）

1D 机器人，三个位姿，x1 锚定在 0：

```text
里程计边：x2 − x1 = 1.0 (σ=0.1)     x3 − x2 = 1.0 (σ=0.1)
回环边：  x3 − x1 = 1.8 (σ=0.2)     ← 里程计积分说是 2.0（漂移 0.2）
```

最小化：J = (x2−x1−1)²/0.01 + (x3−x2−1)²/0.01 + (x3−x1−1.8)²/0.04

```text
∂J/∂x2 = 0：(x2−1) − (x3−x2−1) = 0   →  2x2 = x3
∂J/∂x3 = 0：200(x3−x2−1) + 50(x3−1.8) = 0
            → 4(x3−x2−1) + (x3−1.8) = 0  →  5x3 − 4x2 = 5.8
代入 2x2 = x3： 3x3 = 5.8  →  x3 = 1.933,  x2 = 0.967
```

直觉校验（精度加权平均）：里程计链给出 x3 = 2.0（精度
1/(0.01+0.01) = 50），回环给出 x3 = 1.8（精度 25）：

```text
x3 = (2.0×50 + 1.8×25)/(50+25) = 145/75 = 1.933  ✓ 与上式一致
```

**读图**：
- 回环把 x3 从漂移值 2.0 **拉回 1.933**
- x2 也被顺带拉到 0.967——**一个回环约束改善整条链**（全局平滑）
- 权重 = 1/σ²：越信任的约束拉力越大。调参调的就是信任分配
  （slam_toolbox 里对应 `distance_variance_penalty` 等与回环响应
  阈值，doc 22 逐条讲）

### 7.3 跑工具验证

```bash
python3 docs/tools/slam_playground.py --demo 6
```

真实输出：

```text
正规方程 H = AᵀWA =
[[150.  -50.]
 [-50.  125.]]
g = AᵀWb = [ 75. 125.]
解：x1=0.0000, x2=0.9667, x3=1.9333

互验（精度加权）：里程计链 x3=2.0 精度 50，回环 x3=1.8 精度 25
  x3 = (2.0×50 + 1.8×25)/(75) = 1.9333  ✓ 与求解一致
```

### 7.4 回环检测：怎么知道"回到原地"？

- **位姿距离**：候选节点距当前位姿 < 阈值（本机
  `loop_search_maximum_distance: 3.0`）
- **匹配验证**：该处的扫描匹配响应 ≥ 阈值
  （`loop_match_minimum_response_coarse: 0.35 / fine: 0.45`）——
  "位姿近"不够，"扫描长得像"才算回环（防相似走廊误配）
- **视觉 SLAM**：图像描述子检索（BoW 词袋）"见过的地方"

## 8. 现代实现对照：Cartographer / SLAM Toolbox / 视觉 / 学习时代

| 维度 | Cartographer (2016) | SLAM Toolbox (2019) | 视觉 SLAM (ORB-SLAM3) | 学习时代 (2023-) |
|---|---|---|---|---|
| 前端 | correlative + 多分辨率体素图 | correlative + Ceres 精化 | 特征点（ORB）/直接法 | 学习特征 / 可微优化 |
| 表征 | 子图（submap）序列 | 位姿图 + 栅格地图 | 稀疏点云地图 | 神经隐式 / 可微地图 |
| 回环 | 分支定位（branch & bound） | 距离 + 匹配响应阈值 | BoW 图像检索 | 学习检索 / 端到端 |
| 特色 | 工程质量、2D/3D、多传感器 | **lifelong 续建**、序列化、ROS2 原生 | 视觉惯性、轻量 | 端到端可微、语义 |
| 适用 | 高精度/多传感器 | **2D 服务机器人（本仓库）** | 相机为主 | 研究前沿 |

**Cartographer 的子图概念**（值得一懂）：不是一整张地图，而是把轨迹
切成一个个子图（各 ~90 帧），匹配与回环发生在"扫描↔子图"之间；
建完的子图冻结，只优化活跃子图——内存与计算都可控。

**SLAM Toolbox 的工程取舍**（Steve Macenski 设计）：同步/异步两种
模式（本机 online_sync）、**lifelong 模式**（机器人第二天继续昨天的
地图——"地图是活的"）、位姿图序列化存盘、直接对接 nav2 的 /map 发布
（doc 20 用的就是它）。

**学习时代的两个落地方向**：①学习组件嵌入经典框架（学习特征/深度
替换手工前端，后端仍是图优化）；②端到端可微 SLAM（DROID-SLAM：
整个 SLAM 做成可微网络，GPU 联合优化）。

## 9. 手算练习（先自己做，再看答案）

### 练习 1（log-odds，跑 --demo 1 对照）

某格子被观测 5 次：2 次占据、3 次自由（p_occ=0.7, p_free=0.3,
先验 0.5）。最终占据概率？

<details><summary>答案</summary>

l = 2×0.847 − 3×0.847 = −0.847 → p = 1/(1+e^{0.847}) = 1/2.333 = **0.30**。
恰好等于单次"自由"观测的模型值——多占的那次被多自由的那次对冲。
log-odds 加法结构的直觉：证据可以完全抵消。
</details>

### 练习 2（EKF：路标完全已知时）

§4.2 中若路标位置完全精确（σ²=0），更新后机器人方差是多少？
（先验 x̄=[2.0,3.0]、Σ̄=[[2.0,0],[0,0]]、z=1.2、R=0.25。）

<details><summary>答案</summary>

S = 2.0 + 0.25 = 2.25，K = [−2.0, 0]/2.25 = [−0.889, 0]。
I − KH = [[0.111, 0.889], [0, 1]] → Σ' = [[0.222, 0], [0, 0]]。
机器人方差 2.0 → **0.222**。直觉校验（精度加权）：
1/(1/2.0 + 1/0.25) = 1/(0.5+4) = 0.222 ✓。
运动预测（σ²=2.0）远不如"已知路标 + 观测"（0.25）可信，
所以机器人位置主要听观测的。**用 --demo 3 把路标方差改成 0 跑一遍，
亲眼看 0.222**。
</details>

### 练习 3（回环变准了会怎样）

§7.2 若回环精度提高到 σ=0.1（权重 100），x3 变多少？

<details><summary>答案</summary>

∂/∂x3 = 0：200(x3−x2−1) + 200(x3−1.8) = 0 → x3−x2−1 = −(x3−1.8)
→ 2x3 − x2 = 2.8；∂/∂x2 不变 → x2 = x3/2 → 1.5x3 = 2.8 →
**x3 = 1.867**（x2 = 0.933）。
回环越准，解越贴近回环的值（1.8）。这解释了为什么回环观测的
σ（信任度）是全图质量的总开关。
</details>

## 10. 常见误区

1. **SLAM ≠ 一个算法**，是一个框架（贝叶斯滤波/图优化）+ 五个可替换零件。
2. **地图不是照片**，是概率场——"墙"只是 p>阈值 的格子，会随观测更新
   （doc 22 抗干扰的根基）。
3. **里程计是起点不是答案**：它提供初始猜测（扫描匹配的先验、图的初值），
   精度由外部观测兜底。
4. **回环是 SLAM 的灵魂**：没有回环，图优化只是"局部平滑的里程计"；
   回环约束的 σ 是全图质量的总开关。
5. **高斯假设会被多峰世界打爆**（走廊两头长得一样）→ 粒子滤波/多假设——
   demo 4 的四峰画面就是直观证据；doc 16"多峰评分陷阱"是同款问题。
6. **手算容易错，数值验证是刚需**：本篇的 EKF 数值初稿就错过一次
   （预测步忘了加运动量），靠 playground 跑出来才修正——这也是
   "文档里只嵌真实工具输出"的原因。
