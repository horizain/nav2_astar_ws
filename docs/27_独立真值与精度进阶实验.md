# 27 独立真值与精度进阶实验

## 1 学习目标和边界

学会回答“定位到底多准、底盘到点到底多准”，而不是把5cm地图分辨率、静止漂移或35cm成功容差当成精度。先完成[25评价工具](25_导航评价工具与公平实验.md)。

本课是仿真测量和容差实验，不是实体机器人精度认证。短距离、理想环境中的小误差不能外推到长走廊、多人动态场景或真实硬件。

## 2 真值从哪里来

实验给临时机器人模型加入Gazebo OdometryPublisher系统，读取模型世界位姿，并桥接到独立的/teaching/ground_truth。它不读mini_slam估计，也不是轮速/odom；真值TF话题不桥接进ROS /tf，避免真值反过来帮助被测定位。

依据：[Gazebo Sim 8官方参数说明](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1OdometryPublisher.html)与[官方实现](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/odometry_publisher/OdometryPublisher.cc)。本机插件已实测发布，采样20Hz，真值额外噪声设0。传感器和物理系统仍按实验模型工作。

误差定义是mini_slam的map→base_link估计对齐到独立模型位姿后的差，不是两个同源里程计的差。

## 3 坐标对齐必须事先声明

标准实验出生在world=(0,0,0)，mini_slam初始map原点也定义为该出生位姿，故固定map←world为单位变换。

原沙盒会话出生在world=(-2,-0.5,0)，对应map←world平移(2,0.5)、旋转0。该变换来自明确出生配置，不是每一帧用估计轨迹重拟合。

若换了出生位置、坐标轴、机器人基准点或地图来源，旧变换不能照搬。应先验证静止基准点和旋转方向；不同坐标系未经对齐时工具应显示未匹配/未知，不能报大误差或0误差冒充结论。

## 4 基线命令

先按23完成三级source：

```bash
python3 src/mini_slam/scripts/automated_session_test.py --domain 202 --controller MPC --stationary-seconds 5 --ground-truth
python3 docs/tools/run_navigation_lesson.py --scenario straight --controller MPC --repeat 3 --domain 203
```

前者是会话功能验收，后者是固定世界/目标。输出中的robot模型、world、params、events.jsonl、report.json都是测量依据，不能只保留一个RMSE数字。

开发过程中一次短会话获得235个匹配样本，位置RMSE约0.0206m、P95约0.0377m、最大约0.0629m；仅用于演示报告读法，不作为当前系统的统计性能承诺。这组样本含不同阶段，不能与只取导航阶段的统计直接比较。

## 5 逐步收紧容差

默认导航基线位置0.35m、角度0.25rad。不要直接承诺1cm。

```bash
python3 docs/tools/run_navigation_lesson.py --scenario straight --controller MPC --repeat 3 --xy-tolerance 0.20 --yaw-tolerance 0.0873 --domain 203
python3 docs/tools/run_navigation_lesson.py --scenario straight --controller MPC --repeat 3 --xy-tolerance 0.10 --yaw-tolerance 0.0873 --domain 203
```

0.0873rad约5°。运行器只在本次临时参数文件中修改容差，将所选控制器末端切换距离设为位置容差的0.8倍；仓库默认参数不被覆盖。

每个档位记录全部成功/失败、真实末端误差、角差、耗时、控制误差和计算P95。失败时不自动调回宽容差再算成功。3次只是课堂重复示例，不能给出可靠量产置信区间。

## 6 四类误差如何区分

| 表现 | 优先检查 |
|---|---|
| 估计末端小，真实末端大 | 定位/坐标对齐/采样时间 |
| 定位误差小，估计与真实末端都大 | 目标容差、控制与末端阶段 |
| 静止很好，移动误差增大 | 时间同步、运动模型、扫描匹配 |
| 普通路段好，大转角或重载后跳变 | 外参、图加载先验、TF所有权 |

如果把truth接进TF或控制反馈，实验就从“测量定位”变成“用真值导航”，必须作为另一种对照实验单独标注。

## 7 分阶段统计而非堆样本

全局localization_vs_truth包含本次采集期间的所有位姿，可能有建图、等待、窗口保留。各run的同名字段只覆盖该目标时段。长时间停车能增加大量容易的样本，因此公平对比应使用一致阶段并报告运动/静止分别统计。

匹配时间差会影响运动误差。默认最近邻允许0.1s；应检查matched_samples和unmatched_pose_samples，并通过缩小窗口做敏感性分析。坐标固定对齐不能消除时间偏差。

## 8 图表

```bash
python3 docs/tools/plot_navigation_report.py /tmp/你的实验目录/events.jsonl --report /tmp/你的实验目录/metrics/report.json --output /tmp/新的精度实验.png
```

图有估计/真值轨迹、四段线/角速度和插件耗时。图中的轨迹含目标结束后的记录，不能把曲线最后一个点与report的终态前采样端点混作同一时刻。

## 9 验收和答案

必做：一份含真值的完整报告、一份缺真值的未知报告、两档容差各至少3次记录、一次改变时间匹配窗口的重算，保留失败。

为什么不能从出生点自动拟合每一时刻的map←world？答：会抵消本来需要测量的漂移。
为什么10cm容差下成功不等于最大误差10cm？答：状态式到点检查、采样时刻和定位误差都可能不同，须看真值实测。
如果误差主要来自定位，继续调MPC是否足够？答：不足，应先处理定位和测量链路。

## 10 进阶案例：栅格中心不等于点击的目标

最初三次10cm/约5°实验都返回SUCCEEDED，但真实末端位置误差约11.19、9.31、11.01cm。不能据此写成“保证10cm”。

插件级测试进一步发现：A*格子路径转换为连续坐标后，以末格中心代替了原始目标；同格起终点还返回了起点。5cm栅格会引入最多约3.54cm的中心量化距离，它是接口转换偏差，不是扫描匹配精度极限。

当前适配层保留连续起点和目标，只在已验证的起终格内修正端点，重算段朝向，仍先拒绝253/254目标。对应回归见[test_planner_contract.cpp](../src/nav2_astar_planner/test/test_planner_contract.cpp)。搜索启发式、格子路径和障碍规则没有因此放宽。

报告新增last_plan_goal_offset_m显示实际路径终点与请求目标的偏差，time_offset_s显示估计与真值匹配时差。修正前后的原始记录都应保留；不能把一次改善外推成所有地图与硬件都能达到同样精度。
