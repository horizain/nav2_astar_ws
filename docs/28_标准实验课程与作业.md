# 28 标准实验课程与作业

## 1 教学安排

本课把原理、源码、操作、评价串成可验收作业。先修会一点C++与终端；不要求事先学过最优化。建议每个实验采用“先预测→再运行→解释差异→改一个因素→复测”的顺序，时间按学生基础调整。

| 单元 | 学习目标 | 先读 | 必交产物 |
|---|---|---|---|
| 1 初次运行 | 独立构建并解释系统组成 | 05、23 | 环境记录、启动与成功导航证据 |
| 2 A* | 手算g/h/f、理解半径与253语义 | 04、07 | 5×5手算、253墙/绕行测试 |
| 3 控制器 | 理解反馈、预测和约束 | 10、12 | 一种控制器公式与源码对应 |
| 4 SLAM | 理解匹配、位姿图、闭环和冻结图 | 21、mini_slam文档 | 成套地图与重载记录 |
| 5 系统诊断 | 区分控制器、安全层与底盘 | 24、26 | 一次失败的证据链 |
| 6 公平评价 | 用相同条件比较算法 | 25、本课 | 原始数据、分类结果、对比表 |
| 7 精度进阶 | 区分定位与末端误差 | 27 | 真值/对齐说明、重复实验 |

## 2 固定场景

teaching_scenarios.py生成6m×6m房间，机器人在世界原点出生，世界几何和目标固定。地图由mini_slam原地一整圈观测生成，随后冻结图定位；导航使用自己的A*和所选控制器，安全层保持开启。

| 场景名 | 目标和几何 | 预期功能行为 |
|---|---|---|
| straight | (1.6,0,0) | 成功到点 |
| arc | (1.2,1.2,π/2) | 转向后成功 |
| right_angle | (1.4,0,π/2)→(1.4,1.4,π/2) | 两次目标都成功 |
| narrow_passage | 宽约0.9m通道，目标(2,0,0) | 正常通过，不关闭安全层 |
| blocked | 贯通房间的墙阻断目标 | 任务被拒绝/中止，不能穿墙 |
| unreachable | 目标(3.5,0,0)，在房间外 | 任务被拒绝/中止 |
| cancel_replan | 运动中取消，再发第二目标 | 已取消，然后新目标成功 |

arc固定的是目标，不是强制圆弧参考路径；right_angle是两段目标任务，不宣称规划器一定输出数学上尖锐的90°折线。

固定实验把A*的allow_unknown设为false，防止从未观察的墙外绕过去；这项政策写进临时params.yaml。不要与默认会话的未知区政策混为一谈。

## 3 单次实验命令

按23先完成source：

```bash
python3 docs/tools/run_navigation_lesson.py --scenario straight --controller MPC --domain 203
python3 docs/tools/run_navigation_lesson.py --scenario right_angle --controller MPC --domain 203
python3 docs/tools/run_navigation_lesson.py --scenario blocked --controller MPC --domain 203
python3 docs/tools/run_navigation_lesson.py --scenario cancel_replan --controller MPC --domain 203
```

需要观看时加--gui；只在成功后保留窗口可加--hold-seconds 60。实验目录以UUID区分，不覆盖同名地图。封路实验打印PASS表示“正确拒绝了任务”，报告Action仍然是aborted，不会伪造成succeeded。

## 4 控制器公平对比

```bash
python3 docs/tools/run_lesson_suite.py --controllers FollowPath PID Stanley DWB MPPI MPC --scenarios straight arc --repeat 3 --domain 203
```

先做一次熟悉过程，再做至少3次课堂对比。每次都是新仿真、同一场景生成规则和同一目标，参数哈希、世界哈希和代码状态都保存。传感器噪声与物理积分仍可能变化，不能保证每次地图字节完全一致。

suite.json记录全部尝试和原始目录；某个控制器失败不会让运行器删掉这行或自动换目标。子实验非零退出也继续收集后面的比较项，最后整体返回失败，提醒读者检查。

建议表格列：控制器、到点尝试数、成功率、位置/角度真值误差、耗时中位数与P95、横向误差RMSE、计算P95/最大、控制错误次数。只有一次实验时写n=1，不得写“稳定优于”。

## 5 作业逐项要求

作业A：画出map→odom→base_link以及四段速度话题。标出每个变换和速度由谁负责。验收：不能把map_server说成定位器。

作业B：手算一条会进入253内切区的短路，再解释为何路径规划器和控制器要一致拒绝它。验收：用固定小地图测试证明绕行，而不是拿真人遥控靠墙试撞。

作业C：使用两种控制器完成同一固定场景，各保留全部报告。若一个失败，先定位失败阶段，再谈算法优劣。验收：不能把Action成功率与按设计取消混算。

作业D：将10cm到点容差实验结果与默认35cm基线比较。验收：区分容差和真值实测，回答是否以更长时间或更大指令变化换取小误差。

作业E：设计一个不修改源码的反例。可以是目标变成障碍、初始位姿错误或地图文件缺失。验收：记录最先出现的证据和系统怎样拒绝/恢复，不只截最后一个ERROR。

## 6 评分建议

原理解释25%，可复现性25%，数据与口径25%，故障分析15%，独立改进10%。界面漂亮不能代替原始数据；所有实验都失败但能准确定位和解释，也应得到相应的分析分。

## 7 教师检查表与答案

- 环境能否从干净终端按文档启动？检查三级source和实际包前缀。
- 运行中显示的actual controller是否与实验要求一致？看插件诊断，不只看按钮。
- 是否保留了失败、超时和取消？看suite.json和每目标result。
- 定位RMSE有没有独立真值与固定对齐？无真值必须写未知。
- 35cm是不是被当成测得精度？如果是，要求重写结论。
- 蓝线是不是被说成MPC最优预测？当前它是底盘指令匀速外推，应纠正。
- 如果窄通道失败，是否先关闭安全过滤器？当前主课不允许以此当正常修复，应解释阻塞来源。

进阶选修可再做动态障碍、自动探索、多目标调度或完整候选轨迹可视化；它们不能替代以上基础验收。
