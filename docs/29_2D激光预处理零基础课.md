## 0. 学习地图与三分钟版

### 0.1 一句话版本

**雷达报告的是它看到的，不是世界是的。** 预处理就是把"它看到的"
翻译回"世界是的"——删掉它编的、摆正它拍歪的、认出它拍到的"人"。

### 0.2 五个零件，各治一种谎言

| 零件 | 治什么谎言 | 本篇 | 配套演示 |
|---|---|---|---|
| 清洗链 ①-④ | 编造的回波：无回波、椒盐、鬼点、掠射阴影 | §3-§6 | `test_filters`（每类病灶种一个，零误删断言） |
| deskew ⑤ | 拍歪的照片：一帧扫描里机器人还在动 | §7 | `test_deskew`（解析真值对照） |
| 聚类 ⑥ | "哪些点是同一个东西" | §8 | `test_cluster`（远墙不碎、近物不粘） |
| 动态判别 ⑦ | 把人画进地图里 | §9 | `test_dynamic`（透视记忆） |
| 多帧融合 ⑧ | 单帧太稀 | §10 | `test_accumulate` |

### 0.3 三分钟版本（先看一遍，学完再回来核对）

一帧激光不是照片，是 **180 束独立测量的列表**。每束都可能撒谎：
没有回波时它编一个占位值；灰尘挡路它报一个"半米外的假墙"；
光束跨过门口时一半能量打在前墙一半打在后墙，它报一个**中间距离**——
于是门口长出一道不存在的墙（鬼点）；光束贴着柱子边缘擦过去，
它说"我看到了柱子后面的东西"——那个 hit 挪一毫米就没了（掠射阴影）。

更要命的是**时间**：一束激光从第 0 号打到第 179 号要几十毫秒，
机器人还在动。第 179 号束看到的世界，比第 0 号束"旧"了
几十毫秒。不校正，直墙就是斜的；这就是运动畸变。

而下游的配准（ICP）会把这一切照单全收——
鬼点当真墙、拖影当真弧——然后把**你地图上的错误**钉死在
"算法配准精度"头上。预处理是配准的地基。

## 2. 世界观：极坐标是一等公民

### 2.0 直觉

市面上的代码一拿到激光就转成点云（x, y 列表）。**本包拒绝这么做**，
主数据结构是原始极坐标：

```cpp
struct PolarScan {
    double stamp, beam_dt;        // 时间：扫描起始时刻、束间时间
    double angle_min, angle_inc;  // 角度表
    std::vector<double> range;     // 距离数组；NaN = 无效束
};
```

### 2.1 为什么（推导"转点云会丢掉什么"）

检查 §3-§7 每个算法需要什么信息：

| 算法 | 需要的信息 | 点云里有吗 |
|---|---|---|
| 椒盐判据 | "左右邻居"是哪两束 | ❌ 无序点云没有邻居 |
| 鬼点判据 | 两侧真表面的**坡度** | ❌ 同上 |
| 掠射阴影 | 相邻束的**顺序**与几何 | ❌ 同上 |
| deskew | 每束的**采样时刻** | ❌ 转完点云时间就没了 |

束序编码了两样东西：**邻接**（第 i 束和第 i+1 束看的是相邻方向，
它们的回波大概率来自同一面墙的相邻位置）和**时间**（束号 × 束间隔
= 采样时刻）。这两样在转点云的那一刻就永远丢了，而后面每一个算法
都靠它们活着。所以链路约定：

```text
原始极坐标 → 逐束清洗（NaN 掉坏束，数组不动——束序就是拓扑）
           → 最后一步才转点云
```

**NaN 语义**：所有算子遇到 NaN 直接跳过，绝不"猜一个值填上"。
数据清洗的第一原则是**不制造数据**。

## 3. 病灶① 无效回波：雷达说"81.83 米"

### 3.0 直觉

CARMEN 日志里 Intel 那台 SICK 雷达没有回波时会填 `81.83`——
一个比雷达量程还大的占位值。转点云时如果不拦，它就是一根
"81 米长的刺"，从墙一直戳出地图外。另外还有：负值、0.01 以下
（贴脸反射）、超量程真值。

### 3.1 判据与代码

```cpp
if (!std::isfinite(r)) continue;        // 解析期 NaN：无回波
if (r < p.min_range || r > p.max_range)  // 盲区 / 超量程
    r = kNaN;
```

`min_range = 0.05`（雷达盲区：比这近的回波是镜头内反射），
`max_range = 30`（挡占位值）。它是链上**唯一必须最先跑**的一步：
后面所有"邻居比较"都会被超界值污染。

### 3.2 常见错误

把 `r = 0` 当真距离 → 一束"打到自己"的墙画在传感器原点。
真实雷达驱动（ros 驱动层）已经把这类值写成 `NaN/inf`——
**但离线日志和某些国产雷达会填 0 或量程值**，门控是最后的防线。

## 4. 病灶② 椒盐孤点：墙上的"一根刺"

### 4.0 直觉（这束激光遇到了什么）

粉尘飘过光路、雨滴、一缕烟雾：光束打到 2 米外的飘尘上，报一个
"2 米"。左右邻居都好好打在 8 米的墙上。这就是椒盐——
**单束、突跳、两侧邻居一致**。

### 4.1 判据推导

把三个 range 排出来：`rL`（左邻）、`r`（本束）、`rR`（右邻）。

椒盐的签名是"三个都不一样但有两个一样"：

```text
|r − rL| > J  且  |r − rR| > J     ← 本束离两侧都远（突跳）
|rL − rR| < J                       ← 邻居彼此一致（真表面连续）
```

J 默认 0.35 m。**第二条是灵魂**，下面手算说明为什么。

### 4.2 手算：为什么"邻居一致"不可省

反例场景——**墙角台阶**（真实结构，不是椒盐）：

```text
束号:      ... 98    99    100   101   102 ...
真实距离:  ... 3.00  3.00  3.05  6.00  6.00 ...
                              ↑ 墙角边缘束：贴着左墙
```

对束 100 用判据：`|r − rL| = |3.05 − 3.00| = 0.05 < J` → 第一条就不过，
安全。但假设有人把判据写成"离任一侧远就删"（漏掉第一条的 AND）：
`|r − rR| = 2.95 > J` → 束 100 被删 → **地图上墙角缺一块**。
"邻居一致"（`|rL − rR| = 3.0 > J`，不一致）正是把台阶和椒盐
区分开的那条证据。

### 4.3 诚实边界：细杆 = 椒盐（几何上不可分）

一根电线/椅子腿在 8 m 外只占一束：它同样满足"单束、突跳、两侧一致"。
**在纯几何下它和粉尘是同一个东西**，任何判据都救不了它——救它需要
别的信息维度（强度通道、多帧一致性）。所以判据文档里钉着一句：

> 别把 jump 调小来"救"细杆——那会把噪声也救回来。

### 4.4 跑工具

```text
$ ./build/test_filters
test_filters: OK        # 组合场景断言：总删除恰好 = 病灶数（零误删）
```

## 5. 病灶③ 混合像素（鬼点）：门口长出的"墙"

**全课的主战役。** 这个判据死了三次才活下来，每次死法都是一节课。

### 5.0 物理直觉：光束是怎么"劈叉"的

激光不是一条几何线，是一束**有发散角的能量锥**。当它扫过一个
深度不连续的边缘（门口、柱子、箱子角），锥的前半打在近表面、
后半打在远表面。接收器按能量质心算距离——报一个**介于两者之间的
值**。门口两边明明什么都没有，地图上却长出一道墙。这就是鬼点
（mixed pixel）。

推导它"必然报中间值"：设光束能量分配比例为 α:(1−α) 打在距离
r₁ 和 r₂ 上，接收器按飞行时间加权 → 报距离 ≈ αr₁ + (1−α)r₂。
α 任何取值，结果都落在 (r₁, r₂) **开区间内**。所以判据可以写成：
**在两侧真表面的深度跳变"之间"的回波 = 嫌疑人**。

### 5.1 v1：跳变 + 居中（第一版，当天暴毙）

```text
两侧邻居差 > 0.5（有跳变）
且 r 严格落在两者之间（带 5cm 边距）
→ 删
```

Intel 实测——**灾难**：

```text
总束 540000（3000 帧），鬼点判掉 56697 —— 10.5%！
单帧 scan#1000 一口气判掉 25 束
```

### 5.2 验尸：为什么直墙会被当成鬼点

看 scan#1000 的真实数据（−5° 到 −8° 方向，一条斜着看的走廊墙）：

```text
束号:   81     83     85     86     87
距离:   9.24   10.04  16.51  16.63  17.73    （单位 m）
```

相邻差 1~3 m。这不是跳变，是**渐变**。为什么直墙会渐变？
推导：设墙与机器人前进方向夹角很小（掠射），墙的横向距离为 d，
方位角 a 处的回波距离是

```text
r(a) = d / sin(a)
dr/da = −d·cos(a) / sin²(a)
```

代数字：d = 2 m、a = 7°（对应 r ≈ 16.5 m 处）、束间 1° = 0.01745 rad：

```text
Δr(每束) ≈ 2 × 0.9925 / 0.01234 × 0.01745 ≈ 2.8 m
```

**1° 束距在 16 m 掠射墙上，相邻差天然就是 1~3 m。** "两侧邻居差 > 0.5"
对渐变墙永远成立；"本束落在两侧之间"对任何单调序列永远成立
（中间的数当然在两边之间）。v1 把整段走廊判成了鬼点。

> **这一步的教学价值**：失败的原因不是代码 bug，是**判据没考虑
> "渐变"这个合法形态**。设计者一开始只想到"两个平面 + 中间假点"
> 一种几何，忘了"一个斜面"在 range 空间里长得一模一样。

### 5.3 v2：加"局部平坦"（第二版，还是死）

直觉修正：真鬼点两侧是**平面**（各自相邻束一致），渐变墙两侧
**还在渐变**。加一条：`|rL − rLL| < 0.2`（左表面平坦）或右侧同理。

Intel 实测：鬼点降到 7 束/帧——**但合成测试炸了**：低角度扫墙
（20° 入射）时坡度 0.3~0.4 m/束，固定容差 0.2 判"不平"，
好，可掠射墙坡度 1~3 m 也判"不平"——同一个容差在近处太松、
远处太紧。**固定阈值在"量随距离增长"的量上永远两头不讨好**。

### 5.4 v3 的级联事故（第三版，死于一个连锁反应）

把平坦容差改成随距离缩放后，组合测试又炸了。现场还原：

1. 门控删掉第 5 束（真病灶）→ 数组上留了个 NaN 洞；
2. 第 4 束的"两侧邻居"现在隔着一个洞——邻居差 = **两束的坡度累积**，
   从 0.4 m 涨到 0.77 m，过了跳变线；
3. 第 4 束被判鬼点删掉 → 洞变宽；
4. 第 6 束的邻居隔两个洞……**每删一束，跨度 +1，"跳变" = 坡度 ×
   跨度继续涨**——级联吃掉整段墙（实测一次删了 26 束）。

> **教训**：v1~v3 都在"比较什么"上打转，v4 才意识到该**比较的
> 是量纲**——"邻居差"里混着坡度和跳变两种成分，必须先除掉坡度。
> 这就是"怎么想出来的"：不是灵感，是验尸报告读出来的。

### 5.5 v4（终版）：四件套，每一条对应一次死亡

```cpp
// (a) 跳变按邻居跨度归一，压过"较干净一侧"的局部坡度
jump > max(J, slope_factor · span · min(slope_L, slope_R))
//     span = 两侧邻居隔几束——gating 挖洞会加宽它（级联事故的直接修复）

// (b) 居中用比例边距（贴边 = 真表面延续，居中 = 分裂假回波）
r > min + max(0.05, 0.15·jump)  且  r < max − max(0.05, 0.15·jump)

// (c) 至少一侧是"可靠表面"（坡度在随距离缩放的容差内）
slope_L < max(0.10, 4·r_L·Δθ)  或  slope_R < max(0.10, 4·r_R·Δθ)
```

两个不容易想见的细节：

- **为什么 (a) 用 `min`（两侧坡度取小）？** 成对鬼点会互相污染自己
  一侧的坡度（我的右邻居是另一个鬼点，坡度算出来是鬼点间的差）。
  取 `min` 的语义是："**干净的那一侧**才是'这里有两个不同深度表面'
  的证人"。当时加了 `max` 版本，门口成对鬼点全部漏网，测试抓的。
- **为什么 (c) 是"或"不是"且"？** 同一条死亡记录：成对鬼点判据 (c)
  要求两侧都平时，第一个鬼点的右侧坡度算进了第二个鬼点 → 全漏。
  "且"改"或"，成对场景塌缩正常，渐变墙由 (a) 挡住。

**执行顺序**也是设计的一部分：从左到右单遍，**删掉的束当场写 NaN**。
第二个鬼点评估时左侧邻居自动跳过已删的第一个、直接以真墙面为界
（链式塌缩）。这个机制在 v3 是事故放大器，在 v4 的 (a)(c) 保护下
变成正常收敛——同一个机制，判据对了它就是 feature。

### 5.6 读数 + 注入实验

Intel 上的数字：0.56%→ 椒盐之外，鬼点稳定在 **2.05%**
（门口、立柱、遮挡边界 + 边界侵蚀）。单帧典型 1~3 束。

§11 的注入实验（往真实扫描种已知鬼点）：**种 324 / 检出 316，
召回 97.5%**。

### 5.7 诚实边界：边界侵蚀

跳变处的"过渡束"（斜走廊边缘那 1~2 束）和真鬼点在 1° 分辨率下
**逐束不可分**——它们就是同一个东西。删除它们是工程标准取舍：
损失边缘一两束信息，换地图不长重影。判据注释里钉着这段话，
防止后人"优化"掉这条边界。

## 6. 病灶④ 掠射阴影：贴边擦过去的 hit

### 6.0 直觉

柱子右边缘，光束没打在柱面上，而是**贴着边缘擦过去**打到了 4 m 外
的地板。这个 hit 可靠吗？光束方向偏 0.1°、雷达装歪 1 mm——它
就变成另一个完全不同的读数。它是"柱子的影子"，机器人一挪它就变，
画进地图就是一根会走路的鬼墙。

### 6.1 判据推导（Borg–Boniello 阴影角的思想）

取相邻两 hit 点 pᵢ, pⱼ，连线方向 c = pⱼ − pᵢ。算光束 j 与 c 的夹角：

```text
cos βⱼ = (uⱼ · c) / |c|        uⱼ = (cos aⱼ, sin aⱼ) 光束方向
βⱼ < λ（默认 10°）→ 光束 j 与两点连线几乎共线
                     → pᵢ 就躺在光束 j 的路上 → j 的 hit 蹭着 pᵢ 的边缘
```

**只删远侧**：近侧是遮挡物本体，删它就是把柱子削掉一块。

**链式掠射自动断**：第一束删掉变 NaN，下一对的几何量全 NaN，
比较不成立 → 不再级联。这是"坏数据传播中断"的最小实现——
比显式写一个"已删标记"省一整个状态机。

### 6.2 和鬼点的关系：同一物理现象的两面

鬼点是"能量劈叉报中间值"（**距离**不对）；阴影是"几何上擦边
（**这个 hit 本身**不可信）。门口场景里经常先被 ③ 删几束、
剩下贴边的又被 ④ 收走——测试里专门断言了这种连带
（"远侧贴边束被 deshadow 连带剔除（合法掠射）"）。

Intel 实测 3.08%。和鬼点加起来 5.1%——**遮挡边界两侧永远是
重灾区**，这在建图上的意义是：门口/柱子边永远要预留 1~2 束的
信息损失，规划时别贴着它们走。

## 7. 病灶⑤ 运动畸变：一帧扫描里机器人还在动

### 7.0 引入：先算一笔账

1 m/s 的机器人、SICK 一圈 25 ms（国产雷达 50~100 ms）：

```text
扫描期间机器人挪动 = 1 m/s × 0.025 s = 2.5 cm
```

每束激光的采样时刻都不同：第 179 号束看到的世界比第 0 号束"旧"
25 ms。全部当成同一瞬间拍的，误差就是：**平移 → 每点错位 ≤ 2.5 cm；
旋转 ω=1 rad/s → 远处 5 m 的点错位 2r·sin(ωT/2) ≈ 12.5 cm**。
旋转在远墙上被距离放大——这是 deskew 的主要收益来源
（后面 Intel 实测里旋转 0.033 rad 在 13 m 外造成 **0.43 m** 错位）。

### 7.1 推导：逐束校正的完整公式链

记 p(t) 为里程计位姿、bᵢ = rᵢ(cos aᵢ, sin aᵢ) 为第 i 束的传感器系坐标。
**第 i 束的真实世界位置**由**它自己的时刻**的位姿给出：

```text
wᵢ = p(tᵢ) ∘ bᵢ            （∘ 是 SE(2) 复合：旋转 + 平移）
```

整帧要能当作**一帧刚体扫描**喂给下游 ICP（配准假设点云整体
可被一个刚体变换对齐），必须统一到**某一时刻**的坐标系。
选**扫描起始帧** p(t₀)（不是"平均时刻"——每帧的平均时刻都不同，
位姿链没法递推）：

```text
deskew(bᵢ) = p(t₀)⁻¹ ∘ p(tᵢ) ∘ bᵢ
```

p(tᵢ) 从哪来？**里程计插值**：取 tᵢ 前后两个 ODOM 样本线性插值
（角度走最短差）。这就是 ch05 说的"ICP 的初值来自里程计"的
孪生句：**deskew 的真值来源也是里程计**。

### 7.2 测试设计：解析真值对照法

合成场景里一切可解析：圆形围栏半径 R、机器人恒速平移/旋转。
真值 = 按公式手推出来的点位置；未校正误差 = 公式里故意去掉
p(tᵢ) 那一项。实测输出：

```text
$ ./build/test_deskew
  平移 1m/s: deskew 最大误差 0.00000m, 未校正最大误差 0.099m
  旋转 1rad/s: deskew 最大误差 0.00000m, 未校正最大误差 0.495m
test_deskew: OK
```

**读数**：0.099 m = 1 m/s × 0.1s（扫描历时），和账目分毫不差；
0.495 m ≈ 2×5×sin(0.05)——旋转被半径放大。deskew 误差到 1e-6
以下（纯插值数值噪声级）。

### 7.3 诚实边界一：束时序是假设

deskew 的输入是每束的**时刻** tᵢ = t₀ + i·beam_dt。真实雷达的
束间时序要么来自协议（逐束时间戳），要么实测标定。
**CARMEN 日志只有扫描级时间戳**——beam_dt 是我们估的
（相邻扫描间隔 × 1/4，夹在 [0.02, 0.4] s）。诚实处理：
`--scan-duration` 参数暴露这个假设，`DeskewResult::corrected`
标记"到底校正了没有"，无时序时**回退不装**。

### 7.4 诚实边界二：评估教给我们的事（全课最重要一节）

deskew 算法对了，收益就一定有吗？§11 的下游消融给出了冷酷的答案——
**在 Intel 上无法证明收益**：扫了三种时序假设（前向 0.022s /
后向 −0.022s / 近似关闭 0.001s），下游 ICP 指标全都不优于 clean：

```text
clean             RMS中位 0.0059  墙厚 0.0149  世界格数 14630
full(+deskew 前)  RMS中位 0.0075  墙厚 0.0161  世界格数 16067
full(+deskew 后)  RMS中位 0.0078  墙厚 0.0171  世界格数 16823
```

两个原因，都是硬的：**束时序是猜的**（猜错 = 注入反向畸变）+
**Intel 里程计质量差**（deskew 的上限就是它）。更微妙的是长链混沌：
13k 帧的帧间 ICP 链对毫米级扰动敏感——0.001s 的校正（亚毫米点位移）
都能让轨迹宏观形态改变，指标抖动大到淹没 deskew 本来的效应。

**结论的正确姿势**：不是"deskew 没用"，是"**在这份没有逐束时序、
里程计又烂的数据上，无法验证它的收益**"。要验证，需要
逐束时间戳 + 好里程计的数据（现代雷达协议自带；Gazebo 仿真可注入
真值）。这条记录的元价值：**评估工具先拦住了我们自己人**——
没有消融实验，我们会拿着合成测试的 1e-6 到处宣称 deskew 有益。

## 8. 聚类与线段：给后面两块打地基

### 8.0 直觉

"哪些点是同一个物理物体"——动态判别（这个人是不是一簇）和
多帧融合都先要这个答案。

### 8.1 为什么固定阈值必然失败（推导）

相邻束打到同一面平墙，笛卡尔间距 ≈ r·Δθ。8 m 的墙比 1 m 的箱子
间距大 8 倍——固定阈值要么把远墙剪碎、要么把近处两个物体粘成一团。
**束间距还随入射角恶化**：掠射时两点间距 = r·Δθ/sin(入射角)。
所以阈值必须自适应：

```text
break(i, i+1) ⇔ dist(pᵢ, pⱼ) > base + stretch · r_near · Δθ
```

base 0.06 m（近场分辨），stretch 3（容忍 3 倍伸展 ≈ 19° 入射）。
少于 3 点的簇直接不输出（残余噪声，§4-§6 的漏网之鱼）。

### 8.2 线段提取：split-and-merge

对每簇递归：首尾连线做弦，最远点超阈值就从那里劈。教学用它
做"结构残差"指标（§11 的帧残差），工程上它是线特征 SLAM 的基础。

```text
$ ./build/test_cluster
  L 形 → 2 段线            # 51+51 点的直角折线劈成两段，各残差 < 2cm
test_cluster: OK
```

## 9. 动态障碍：透视记忆（两段坑史）

### 9.0 直觉：福尔摩斯式的推理

一个人现在站在走廊中间。地图怎么知道他是"人"而不是"新墙"？

> 这里三个月前我们看穿过。——看穿过的位置上**现在**站着的东西，
> 一定是**后来**出现的。

反过来墙为什么永远安全：射线打到墙就**停**，墙所在的格子
只积累"未知"或"被击中"，永远不会变成"自由"。
**"被透视过"（free）和"从未见过"（unknown）是两种状态**——
新人站在从未观察过的区域里，我们诚实地不知道他是不是动态。

### 9.1 实现：一个只记"自由证据"的 log-odds 栅格

```cpp
ray_free(sensor, end):    沿途格 += kFree(−0.4)   // 不记占据！
seen_through_ratio(pts): 簇内格子 ≤ −1.0 的比例    // "被透视过"的判据
```

判别次序**先判后记**：本帧自己不能给本帧作证。

### 9.2 坑史一：噪声穿透（掠射射线会"穿墙"）

Intel 实测现象：同一面远墙**逐帧**被判动态，方向固定复现
（r≈10 m，掠射方向）。验尸：掠射射线几乎贴着墙跑，测距噪声 ±2 cm
让射线的**路径**偶尔越过墙格——墙自己的格子被记上"自由证据"，
然后墙被自己的记忆指控。修复：**端点格周围 1 格（Chebyshev）
禁记 free**。

> 和 21 课的"射线末段不许污染端点格"是同一课的两个变体——
> 任何"沿路径记账"的算法都要防路径溢出到端点。

### 9.3 坑史二：记忆必须衰减（时效 = 位姿链短时一致性）

不衰减版本 Intel 全程虚警 **5.4 簇/帧**——80 分钟前的自由证据
还在作证。加衰减 `decay = 0.98`（每帧全体 ×0.98，
半衰期 = ln2/|ln 0.98| ≈ 34 帧 ≈ 13 s @ Intel 帧率）后降到 **1.8**。

为什么半衰期不能更长：透视记忆的空间精度由**位姿链的短时漂移**
决定——链漂 0.15 m，8 s 前的"自由"就错位到墙上去了。衰减系数的
物理含义就是"我只信位姿链在这么短时间内还没漂歪"。

### 9.4 诚实边界

判据是"**曾经空过**"——从数据集一开始就站在那里的人会被当成静态。
判决需要轨迹级确认（多帧位置一致性 → 跟踪），那是下一块砖。
当前输出语义是**"动态候选"**，不是"动态判决"。

```text
$ ./build/test_dynamic
  人(被透视区) ratio=1.00  墙 ratio=0.00  盲区 ratio=0.00
test_dynamic: OK
```

## 10. 多帧融合：单帧太稀

8 m 墙上 1° 束距的点间隙 7 cm，柱子正面只有 2~3 个点——
point-to-line ICP 要的是结构密度。把最近 16 帧用**各自配准位姿**
拼到一起（都做过 deskew，所以是"运动补偿过的融合"，
不是把畸变云胡乱堆一起），密度翻 16 倍。窗口取 16 帧 ≈ 2~4 s：
短到位姿链漂移可忽略、长到密度收益拿满。

## 11. 怎么知道做得好不好：三层评估方法论

**这是全课收口，也是最容易造假的一层。** 前处理没有 ground truth，
"删了多少点"不等于"删得对"。三层，各管一摊：

| 层 | 回答什么 | 方法 |
|---|---|---|
| ① 合成真值 | 算法对不对 | 解析真值单测（§4-§9 的 OK） |
| ② 注入实验 | 真实数据上灵不灵 | **往真实扫描种已知病灶**，数召回和误杀 |
| ③ 下游消融 | 到底值不值得 | raw/clean/full 三条 ICP 链，比配准质量和地图锐利度 |

### 11.1 注入实验（比纯合成硬在哪）

纯合成的场景是**你想象的世界**，噪声特性也是你编的。注入实验只
伪造**病灶本身**：找真实扫描里"两侧一致"的平表面，把某束挪 1 m
（粉尘的标准形态）；找"两侧平坦的真跳变"，把远侧换成中点
（鬼点的标准形态）。数据其余的一切统计特性（噪声、走廊、遮挡）
全是真的。

```text
$ ./build/laser_prep_eval --input ../mini_slam/data/intel.clf --inject 2000
椒盐: 种 7935 / 检出 7893（召回 99.5%）
鬼点: 种 324  / 检出 316 （召回 97.5%）
误杀: 201 束（占 0.0558%，基线本来就删的不计）
```

### 11.2 下游消融（最终裁判）

同一份数据、同一条 ICP 位姿链，只换前处理。指标全是下游的：
ICP 收敛 RMS（配准残差）、墙厚（世界点云局部 PCA 的最小特征值开方——
漂移/重影把墙画厚）、世界格数（同面积点云越稀碎说明漂移越重）。

```text
配置   RMS中位    RMS95   帧残差  墙厚(m)   格数
raw      0.0064   0.0168   ...   0.0156   15944
clean    0.0059   0.0153   ...   0.0149   14630     ← 全指标改善
full     0.0075   0.0243   ...   0.0161   16067     ← deskew 不升反降
```

**读数**：清洗链的收益被下游证明（RMS −8%、墙厚 −4%）；
deskew 的收益无法在此数据证明（§7.5 的时序+里程计+混沌三重绞索）。

### 11.3 评估工具先评估了评估工具

消融表第一版跑出来 RMS 全是 0——查了半天，`run_chain` 忘了
`acc.push`：目标地图永远是空的，**ICP 从来没真正跑过**，三组
"对比"比了个寂寞。这行注释现在钉在代码里。教训：**评估工具
自己的每条数字也要有被怀疑和被验证的机制**——最好让它的输出
在某个人工可核对的量上过一遍（比如：raw 链的帧数和 RMS 样本数
应该等于配准成功的帧数）。

## 14. 总结：三条带走的思维

1. **数据结构先于算法**：极坐标不是"原始格式"，是保住邻接与时间
   两个信息维度的容器。转点云是单行道，过了就回不去。
2. **每个判据至少死一次**：本包四个清洗器三个死于同一种死法——
   判据里混进了没归一的量（坡度 vs 跳变）。设计前先问：
   我比较的两个数，量纲一致吗？
3. **下游是唯一裁判**：清洗链的 99.5% 召回很漂亮，但真正让人
   信服的是 ICP RMS 降了 8%；deskew 的 1e-6 单测很漂亮，但
   消融实验说"此数据无法证明收益"时，必须接受。**会拦住自己人
   的评估，才是好评估。**
