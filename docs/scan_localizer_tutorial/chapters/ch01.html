    1.2主动重建：先写出四个最小操作

    先不要打开生产头文件。新建 se2_min.cpp，按下面的契约从空白实现；完成后再折叠答案对照。位姿三元组统一为 (x, y, theta)，平移单位是米，角度单位是弧度。

    1. Pose2::operator*：把右操作数表示的位姿复合到左操作数坐标系，角度归一化到 $(-\pi,\pi]$。
    2. Pose2::inverse：返回同一个刚体变换的逆，必须满足 $T\cdot T^{-1}=T^{-1}\cdot T=I$。
    3. transform_scan：把一组已经位于参考系的二维点旋转、平移到位姿所在系。
    4. map_to_odom：输入同一时刻的 T_map_base 与 T_odom_base，返回二者的修正链。
    最小参考实现（C++20，可复制后独立编译）
    se2_min.cpp · 教学最小版
    #include <cmath>
#include <numbers>
#include <vector>

inline double wrap_angle(double a)
{
  double r = std::remainder(a, 2.0 * std::numbers::pi);
  if (r <= -std::numbers::pi) { r += 2.0 * std::numbers::pi; }
  return r;
}

struct Vec2 {
  double px{0.0}, py{0.0};
  Vec2() = default;
  Vec2(double x, double y) : px(x), py(y) {}
  double x() const { return px; }
  double y() const { return py; }
};

struct Pose2 {
  double x{0.0}, y{0.0}, theta{0.0};

  Pose2 operator*(const Pose2 & o) const {
    const double c = std::cos(theta), s = std::sin(theta);
    return {x + c * o.x - s * o.y,
            y + s * o.x + c * o.y,
            wrap_angle(theta + o.theta)};
  }

  Pose2 inverse() const {
    const double c = std::cos(theta), s = std::sin(theta);
    return {-(c * x + s * y),
            -(-s * x + c * y),
            wrap_angle(-theta)};
  }
};

template<typename It>
std::vector<Vec2> transform_scan(
  const Pose2 & pose, It begin, It end)
{
  std::vector<Vec2> out;
  const double c = std::cos(pose.theta), s = std::sin(pose.theta);
  for (It it = begin; it != end; ++it) {
    const double px = it->x(), py = it->y();
    out.emplace_back(pose.x + c * px - s * py,
                     pose.y + s * px + c * py);
  }
  return out;
}

Pose2 map_to_odom(
  const Pose2 & map_to_base, const Pose2 & odom_to_base)
{
  return map_to_base * odom_to_base.inverse();
}
    最小版刻意省略了什么？

    生产 se2.hpp 使用 Eigen::Vector2d，为 wrap_angle 增加 NaN/inf 防护，并提供写入复用输出缓冲的 transform_scan 重载。这些是接口与热路径增强；四个核心等式与最小版完全相同，稍后会在真实源码步进器中逐段补齐。

    1.3用一组可手算的数验证四个操作

    选择 $90^\circ$ 旋转，让 $\cos(\pi/2)=0,\ \sin(\pi/2)=1$，从而把符号错误直接暴露出来。定义：

    本章固定数值例（角度均为弧度）
    $$A=(1,0,\pi/2),\quad B=(1,0,0),\quad M=T_{\text{map}\leftarrow\text{base}}=(2,1,\pi/2)$$ $$O=T_{\text{odom}\leftarrow\text{base}}=(1,0,0),\quad p_{\text{base}}=(1,0.5)$$
    1. 复合：$A\cdot B=(1+0\cdot1-1\cdot0,\ 0+1\cdot1+0\cdot0,\ \pi/2)=(1,1,\pi/2)$。
    2. 求逆：$M^{-1}=(-(0\cdot2+1\cdot1),\ -(-1\cdot2+0\cdot1),\ -\pi/2)=(-1,2,-\pi/2)$。
    3. 求 map → odom：$O^{-1}=(-1,0,0)$，所以 $C=M\cdot O^{-1}=(2,1+1\cdot(-1),\pi/2)=(2,0,\pi/2)$。
    4. 回代：$C\cdot O=(2,0,\pi/2)\cdot(1,0,0)=(2,1,\pi/2)=M$。链式恒等式闭合。
    5. 点云：$O p_{\text{base}}=(2,0.5)$；再用修正量得到 $C(2,0.5)=(1.5,2)$，与直接计算 $M p_{\text{base}}$ 完全一致。
    以上面板由 S.poseMul、S.poseInv、S.mapToOdom 与 S.transformScan 直接计算，不在页面里另写一套几何实现。浮点回代可能残留约 $10^{-16}$ 的误差。

    1.4把公式推导清楚：旋转谁、右乘谁

    用齐次矩阵表示位姿：

    SE(2) 的矩阵、复合与逆
    $$T(x,y,\theta)=\begin{bmatrix}R(\theta)&\mathbf t\\0&1\end{bmatrix},\qquad R(\theta)=\begin{bmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{bmatrix}$$ $$T_1T_2=\begin{bmatrix}R_1R_2&\mathbf t_1+R_1\mathbf t_2\\0&1\end{bmatrix}$$ $$T^{-1}=\begin{bmatrix}R^\mathsf T&-R^\mathsf T\mathbf t\\0&1\end{bmatrix}$$

    把矩阵展开，就得到 operator* 与 inverse() 的三元组形式。关键是 $T_1\cdot T_2$ 先按 $T_1$ 的方向旋转 $T_2$ 的平移，不是把两个平移直接相加。

    三元组形式与点变换
    $$T_1\cdot T_2=\left(x_1+c_1x_2-s_1y_2,\ y_1+s_1x_2+c_1y_2,\ \operatorname{wrap}(\theta_1+\theta_2)\right)$$ $$T^{-1}=\left(-(cx+sy),\ -(-sx+cy),\ \operatorname{wrap}(-\theta)\right)$$ $$\mathbf p_{\text{new}}=R(\theta)\mathbf p+\mathbf t=T\cdot(\mathbf p,1)$$

    这也解释了 transform_scan：它对每个点执行的就是上式；当只有一个点时，结果等价于 S.poseMul(pose, {x: p.x, y: p.y, theta: 0}) 的平移部分。

    同一扫描时刻 $t$ 的 TF 链满足 $M(t)=C(t)\cdot O(t)$。要解出 $C(t)$，必须在等式右边乘 $O(t)^{-1}$：

    map → odom：右乘逆，不能反过来
    $$M=C\,O\ \Longrightarrow\ M O^{-1}=C O O^{-1}=C$$ $$T_{\text{map}\leftarrow\text{odom}}=T_{\text{map}\leftarrow\text{base}}\cdot\bigl(T_{\text{odom}\leftarrow\text{base}}\bigr)^{-1}$$

    若错写成 $O^{-1}M$，得到的是把地图位姿变换到 odom 系的另一种量，通常不能补回 odom → base。判断顺序最可靠的办法是回代：$C\cdot O$ 必须重新得到 $M$。

    1.6只做连接：TF 外参、时间戳与 PGM Y 翻转

    这三件事发生在 SE(2) 核心之外，但会决定它是否被正确使用
    • TF 方向与时间戳：本章箭头统一写成 T_child_parent，例如 T_map_base 把 base 点变到 map。生产代码用同一扫描时刻的 last_pose_ 与 odom_at_last_scan_ 求修正，不能混用异步到达的最新里程计。
    • base → laser 是完整 3D 外参：倒装雷达的 roll=π 会在平面点云上产生 $y\mapsto-y$ 镜像，不能用一个普通 2D 旋转角冒充。应先用 TF2 的 3D 变换把点投到 base_link，再交给本章的 transform_scan。
    • PGM Y 翻转是存储约定：PGM 第 0 行在顶部，ROS OccupancyGrid 的 iy=0 在底部，因此装载时使用 row_pgm = h - 1 - iy。它与 map → odom 的群运算无关，不能靠修改 TF 来补偿。

    1.7从最小版读向生产版

    C++20 与热路径设计
    • std::remainder(a, kTwoPi)：以 $O(1)$ 完成角度归一化；生产版先用 std::isfinite 拒绝 NaN/inf，避免异常值继续污染位姿。
    • if constexpr (std::random_access_iterator<It>)：只有随机访问迭代器才在编译期保留 distance + reserve 分支，链表等迭代器不会背上无效操作。
    • out.clear() 与输出引用：清空元素但保留容量，循环中复用成员向量，避免每帧重新分配。返回向量版只是便利包装，生产热路径优先复用缓冲版。

    1.9思考题与自检

    1. 为什么 map_to_odom 必须右乘 odom_to_base.inverse()，而不是左乘？
    因为目标恒等式是 M = C * O，其中 C 把 odom 点变到 map，O 把 base 点变到 odom。右乘 O⁻¹ 后得到 C = M * O⁻¹；左乘得到的是 O⁻¹ * M，坐标系顺序不同，回代不能闭合。
    2. 已经拿到雷达局部点后，为什么不能把倒装雷达简单设成 theta = π？
    平面旋转 π 会把 (x,y) 变成 (-x,-y)；绕 X 轴倒装 roll=π 则把 (x,y,z) 变成 (x,-y,-z)，投影到平面后是左右镜像。二者不是同一个刚体变换。必须通过完整 3D TF 外参先转换到 base_link。
    3. PGM 地图上下颠倒时，调整 map → odom 能修复吗？
    不能。PGM 行翻转错误发生在图像/栅格装载阶段，改变的是地图数据本身的行语义；map → odom 只修正同一地图内 odom 与 map 的坐标关系。应修正 row_pgm = h - 1 - iy，而不是污染 TF。
