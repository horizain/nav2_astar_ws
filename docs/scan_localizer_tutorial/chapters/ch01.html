    1.1直觉与交互实验室：定位到底在算什么？

    建图（SLAM）是拿着空白画纸一边走路一边画房间；而已知地图定位（Localization）是手里已经有了一张精确蓝图（例如 warehouse.pgm），机器人要每秒 10~40 次回答同一个问题：“我现在在蓝图里的哪个 $(x, y, \theta)$ 位置？”

    如果只靠轮子编码器（里程计 odom）累加，打滑和轮径误差会让机器人轨迹越走越偏（下图红点）；加入雷达与地图匹配修正后，我们算出了修正量 map → odom，把整帧激光重新对齐回真实的墙体（蓝点）。请拖动下方滑块直观感受。

    1.2公式推导：激光点云、$SE(2)$ 群与 TF 逆合成

    第一步：极坐标转传感器局部笛卡尔点云。一帧 LaserScan 给我们一串距离数组 $r_i$，第 $i$ 束光线角度为 $\phi_i = \phi_{\min} + i \cdot \Delta\phi$，转成传感器坐标系下的二维点：

    激光点云 + 3D 外参投影到车体 base_link
    $$\mathbf{p}_{\text{laser}} = \begin{bmatrix} r_i \cos\phi_i \\ r_i \sin\phi_i \\ 0 \end{bmatrix}, \qquad \mathbf{p}_{\text{base}} = R_{b\leftarrow l}\,\mathbf{p}_{\text{laser}} + \mathbf{t}_{b\leftarrow l}$$

    如果雷达在实体车上是倒装的（即安装绕 X 轴旋转 $\text{roll}=\pi$），那么旋转矩阵 $R_x(\pi)=\mathrm{diag}(1,-1,-1)$ 会让激光在车体坐标系中左右翻转（$y \mapsto -y$）。必须通过 TF2 查出完整的 3D 刚体变换并投影回 2D，绝不能只传 `(lx, ly, ltheta)`！

    第二步：$SE(2)$ 群复合与群逆。平面位姿 $T = (x, y, \theta) \in SE(2)$ 代表“先旋转 $\theta$、再平移 $(x, y)$”。其复合与群逆公式如下：

    SE(2) 复合、点变换与群逆公式
    $$T_1 \cdot T_2 = \begin{bmatrix} x_1 + c_1 x_2 - s_1 y_2 \\ y_1 + s_1 x_2 + c_1 y_2 \\ \mathrm{wrap}(\theta_1 + \theta_2) \end{bmatrix}, \qquad T^{-1} = \begin{bmatrix} -(c\,x + s\,y) \\ -(-s\,x + c\,y) \\ \mathrm{wrap}(-\theta) \end{bmatrix}$$ $$\text{其中 } c = \cos\theta,\; s = \sin\theta$$

    第三步：为什么必须广播 map → odom？ROS TF 树是一棵单亲树（每个子坐标系只能有一个父节点）。里程计节点已经在高速广播 odom → base_link（$T_{o\leftarrow b}$），定位节点算出车体在地图的真实位姿 $T_{m\leftarrow b}$ 后，根据链式恒等式 $T_{m\leftarrow b} = T_{m\leftarrow o}\cdot T_{o\leftarrow b}$，右乘 $T_{o\leftarrow b}^{-1}$ 即得：

    map → odom 求解恒等式
    $$T_{\text{map}\leftarrow \text{odom}} \;=\; T_{\text{map}\leftarrow \text{base}}(t_{\text{scan}}) \;\cdot\; \bigl(T_{\text{odom}\leftarrow \text{base}}(t_{\text{scan}})\bigr)^{-1}$$

    1.3核心源码逐行剖析

    include/scan_localizer/se2.hpp : L34-94
    // O(1) 安全角度归一化至 (-kPi, kPi]；非有限输入（±inf / NaN）返回 0.0
inline double wrap_angle(double a)
{
  if (!std::isfinite(a)) { return 0.0; }
  double r = std::remainder(a, kTwoPi);
  if (r <= -kPi) { r += kTwoPi; }
  else if (r > kPi) { r -= kTwoPi; }
  return r;
}

struct Pose2 {
  double x{0.0}, y{0.0}, theta{0.0};
  Pose2 operator*(const Pose2 & o) const {
    const double c = std::cos(theta), s = std::sin(theta);
    return {x + c * o.x - s * o.y, y + s * o.x + c * o.y, wrap_angle(theta + o.theta)};
  }
  Pose2 inverse() const {
    const double c = std::cos(theta), s = std::sin(theta);
    return {-(c * x + s * y), -(-s * x + c * y), wrap_angle(-theta)};
  }
};

// 缓冲复用重载：avoid heap malloc inside hot loops
template<typename It>
inline void transform_scan(const Pose2 & pose, It begin, It end, std::vector<Vec2> & out) {
  out.clear();
  if constexpr (std::random_access_iterator<It>) {
    out.reserve(static_cast<std::size_t>(std::distance(begin, end)));
  }
  const double c = std::cos(pose.theta), s = std::sin(pose.theta);
  for (It it = begin; it != end; ++it) {
    const double px = it->x(), py = it->y();
    out.emplace_back(pose.x + c * px - s * py, pose.y + s * px + c * py);
  }
}

    1.4语法解码（Syntax Spotlight）

    C++20 现代特性在底层底座中的应用
    • std::remainder(a, kTwoPi) 替代 while (a > pi)：若传感器异常吐出 $a = 10^{12}$，经典 while 循环会卡死 CPU，而 std::remainder 是硬件/库级 $O(1)$ 浮点取余。加上 std::isfinite(a) 防护，彻底消灭 NaN 污染。
    • if constexpr (std::random_access_iterator<It>)：C++20 Concept + 编译期分支。传入 std::vector 迭代器时直接一次性 reserve()，传入链表等单向迭代器时编译器直接裁剪该语句。
    • out.clear() + 复用输出引用：热路径里不重新 return std::vector 触发堆分配，而是把成员向量清零尺寸但保留容量。

    1.5工程技巧与踩坑复盘

    Phase 1 & Phase 3 真实踩坑档案
    • 坑 1：PGM 第 0 行在顶部，ROS OccupancyGrid iy=0 在底部（map_io.cpp:L369）。如果不写 row_pgm = h - 1 - iy，从 nav2_map_server 加载进来的地图上下颠倒，全图定位必然失败！
    • 坑 2：map_to_odom() 混用时间戳（localizer_core.cpp:L274）。必须使用上一帧扫描时刻锚定的 odom_at_last_scan_ 求逆，而不是直接用异步到达的最新 last_odom_，否则高速行驶时 TF 会产生周期性抖动锯齿。
    • 坑 3：倒装雷达（roll = π）：仅靠 2D 参数 (laser_x, laser_y, laser_theta) 无法表达左右镜像；生产代码中必须优先查 TF2 的 3D 四元数与平移（localizer_node.cpp:L1217-1293）。

    1.6思考题与自检

    1. 为什么在 LocalizerNode 启动后，即使机器人完全静止，也不建议停止发布 map → odom？
    因为 Nav2 的代价地图和规划器依赖 TF 缓冲查询实时位姿，若 TF 超过 transform_tolerance（默认 0.1s）没有新变换就会报错超时。所以工程上需要 tf_keepalive_timer_ 定时重广播最近一次 map → odom，配合未来的略微外推时间戳 stamp + transform_tolerance。
    2. 栅格索引 worldToGridIndex 和双线性插值坐标 worldToGridF 为什么相差 0.5？
    在 ROS 语义中，格子 (ix, iy) 占据的矩形区域是 $[x_0 + ix\cdot r,\; x_0 + (ix+1)\cdot r)$，所以它的中心在 $x_0 + (ix + 0.5)\cdot r$。双线性插值必须以“格心”为顶点网格，因此连续格心坐标需要减 0.5，保证落在格心正好对应整数下标。
