    2.1为什么不能直接用 0/100 黑白占据栅格定位？

    黑白栅格里只有“是墙（100）”和“不是墙（0）”两种跳变信号。假如机器人猜的位姿只偏了 10 厘米，激光点落在了白色空白区，在 0/100 栅格上读到的值是纯粹的 0，没有任何梯度告诉你“往左走还是往右走才能碰回墙”。

    MapField 的哲学是：一次性把占据栅格变成“有坡度的连续山谷”，于是 Correlative、Field-GN、ICP-P2P、粒子滤波与全局 B&B 全部都能直接复用这一份数据。点击或拖动画布自由增删墙体，实时观察四层场变化：

    2.2O(HW) 精确欧氏距离变换（EDT）与抛物线下包络

    在一张 $800 \times 600$ 的地图上暴力找每个格子到最近墙壁的距离需要 $O(H^2 W^2)$ 次比较，无法接受。Felzenszwalb & Huttenlocher（以及 Meijster）把 2D 平方距离巧妙拆成两次 1D 扫描：

    2D EDT 的行列可分离性与抛物线下包络交点
    $$D_f(x) = \min_{p} \Bigl((x - p)^2 + f(p)\Bigr)$$ $$\text{两条抛物线 } p < q \text{ 的交点横坐标：}\quad s = \left\lfloor \frac{(f(q) + q^2) - (f(p) + p^2)}{2(q - p)} \right\rfloor$$

    每扫过一个点 $q$，若新抛物线与栈顶 $v[k]$ 的交点 $s \le z[k]$，说明原本的栈顶完全被遮挡在上方，弹出它！整个序列每个下标至多入栈出栈一次，所以是严格的线性复杂度 $O(N)$。

    2.3双向 EDT → SDF、双线性解析梯度与 swmax_ 金字塔

    • 双向 EDT 构 SDF：分别对占据格做一次 EDT 得 $d_{\text{occ}}$、对自由格做一次 EDT 得 $d_{\text{free}}$。自由空间 $\text{SDF} = +\sqrt{d_{\text{occ}}}\cdot r > 0$，墙体表面 $=0$，墙体内部深度为负值 $<0$。
    • 双线性插值与解析梯度：在相邻四个格心 $(v_{00}, v_{10}, v_{01}, v_{11})$ 上做双线性插值，$x$ 方向偏导 $\frac{\partial \text{SDF}}{\partial x}$ 就是水平差分插值再除以分辨率 $r$！
    • 滑窗最大值栈 swmax_：第 $k$ 层的每个像素记录以它为锚点的 $2^k \times 2^k$ 窗口内似然场的最大值：dst[y][x] = max(src[y][x], src[y][x+h], src[y+h][x], src[y+h][x+h])，第 6 章的 B&B 全局搜全靠它给出不漏解的紧致上界。

    2.4核心源码逐行剖析

    src/map_field.cpp : L35-43 & L257-275
    // 精确向下取整：C++ '/' 对负数向零截断，会使抛物线交点偏大 1 格！
inline std::int64_t floor_div(std::int64_t num, std::int64_t den) {
  std::int64_t q = num / den;
  const std::int64_t r = num % den;
  if (r != 0 && ((r < 0) != (den < 0))) { --q; }
  return q;
}

// O(HW) 构建第 k 层 2^k × 2^k 滑窗最大值金字塔（只依赖前一层间隔 h = 2^(k-1)）
for (int y = 0; y < grid_->height; ++y) {
  const int yh = std::min(y + h, grid_->height - 1);
  for (int x = 0; x < grid_->width; ++x) {
    const int xh = std::min(x + h, grid_->width - 1);
    float m = src.data[row_y + ux];
    m = std::max(m, src.data[row_y + uxh]);
    m = std::max(m, src.data[row_yh + ux]);
    m = std::max(m, src.data[row_yh + uxh]);
    dst.data[row_y + ux] = m;
  }
}

    2.5工程技巧与踩坑复盘

    为什么 edt1d([9, 100, 4]) 曾算出错误的 9？

    当 $p=0, q=2, f=[9, 100, 4]$ 时，交点分子为 $(4+4)-(9+0) = -1$，分母为 $4$。数学向下取整 $\lfloor -1/4 \rfloor = -1$，而 C++ 原生整数除法 (-1)/4 = 0（向零截断）。在 $q=1$ 被提前错误判定或分段边界上产生 1 格错位，把真实结果 $[8, 5, 4]$ 算成了 $[9, 5, 4]$。使用 int64_t 配合 floor_div 才彻底修复该 Bug（test_map_field.cpp 有专项回归测试）。

    共享只读所有权消除 UAF

    早期版本 MapField 持有原始指针 const OccupancyGrid * grid_，一旦调用方栈上局部 grid 析构便触发 Use-After-Free。重构后统一改为私有 std::shared_ptr<const OccupancyGrid> grid_（map_field.hpp:L162），即使热切图期间后台仍在读取旧地图也绝对安全。

    2.6思考题与自检

    1. 未知栅格（c = -1）应该赋予正 SDF、零 SDF 还是负 SDF？
    必须赋予有界负值（非 0），似然打分为低背景值 unknown_score_ = 0.10。若未知区给 SDF=0，相当于把没探明的地方都当成“墙表面”，匹配器会把扫描点吸进未知黑洞里！
