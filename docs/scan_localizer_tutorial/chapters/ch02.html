    2.1为什么不能直接用 0/100 黑白占据栅格定位？

    黑白栅格里只有“是墙（100）”和“不是墙（0）”两种跳变信号。假如机器人猜的位姿只偏了 10 厘米，激光点落在了白色空白区，在 0/100 栅格上读到的值是纯粹的 0，没有任何梯度告诉你“往左走还是往右走才能碰回墙”。

    MapField 的哲学是：一次性把占据栅格变成“有坡度的连续山谷”，于是 Correlative、Field-GN、ICP-P2P、粒子滤波与全局 B&B 全部都能直接复用这一份数据。点击或拖动画布自由增删墙体，实时观察四层场变化：

    2.2O(HW) 精确欧氏距离变换（EDT）与抛物线下包络

    在一张 $800 \times 600$ 的地图上暴力找每个格子到最近墙壁的距离需要 $O(H^2 W^2)$ 次比较，无法接受。Felzenszwalb & Huttenlocher（以及 Meijster）把 2D 平方距离巧妙拆成两次 1D 扫描：

    2D EDT 的行列可分离性与抛物线下包络交点
    $$D_f(x) = \min_{p} \Bigl((x - p)^2 + f(p)\Bigr)$$ $$\text{两条抛物线 } p < q \text{ 的交点横坐标：}\quad s = \left\lfloor \frac{(f(q) + q^2) - (f(p) + p^2)}{2(q - p)} \right\rfloor$$

    每扫过一个点 $q$，若新抛物线与栈顶 $v[k]$ 的交点 $s \le z[k]$，说明原本的栈顶完全被遮挡在上方，弹出它！整个序列每个下标至多入栈出栈一次，所以是严格的线性复杂度 $O(N)$。

    1D EDT 抛物线下包络构建步进器交互动画 2B
    先分清：1D 平方距离不是 2D 欧氏距离

    edt1d 回答的是一维问题：out[q] = minₚ((q-p)² + f[p])。它的输入 f[p] 可以是一维种子代价，也可以是二维列扫描后保留下来的纵向代价平方；输出始终以格子单位的平方距离计。

    真正的 2D EDT 分两遍：先逐列求最近种子的曼哈顿步数 $g(y,x)$，再对每一行构造 $f(x)=g(y,x)^2$ 并调用 edt1d。于是 $(x-p_x)^2$ 与 $(y-p_y)^2$ 精确相加，得到 $D^2(x,y)$；只有随后开平方并乘地图分辨率 $r$，才变成米制欧氏距离。

    2.3从空白文件开始：先写一个能跑的精确 edt1d

    第一版只守住四个契约：输入输出长度一致；空输入直接返回；交点负数必须向下取整；平方与下标使用 int64_t。我们直接实现线性下包络，不先用 $O(N^2)$ 暴力版替代它。

    3. 最后运行 f = {9, 100, 4}，确认终端输出 8 5 4。
    教学最小版：可独立编译的 edt1d_min.cpp
    #include <cstddef>
#include <cstdint>
#include <iostream>
#include <vector>

std::int64_t floor_div(std::int64_t num, std::int64_t den) {
  std::int64_t q = num / den;
  const std::int64_t r = num % den;
  if (r != 0 && ((r < 0) != (den < 0))) { --q; }
  return q;
}

void edt1d(const std::vector<std::int64_t> & f,
           std::vector<std::int64_t> & out) {
  const std::size_t n = f.size();
  out.assign(n, 0);
  if (n == 0) { return; }

  constexpr std::int64_t kZNeg = -(std::int64_t{1} << 60);
  constexpr std::int64_t kZPos = +(std::int64_t{1} << 60);
  std::vector<std::int64_t> v(n, 0), z(n + 1, 0);
  std::int64_t k = 0;
  v[0] = 0;
  z[0] = kZNeg;
  z[1] = kZPos;

  // 第一遍：构建整数轴上的抛物线下包络。
  for (std::size_t qi = 1; qi < n; ++qi) {
    const std::int64_t q = static_cast<std::int64_t>(qi);
    std::int64_t p = v[static_cast<std::size_t>(k)];
    std::int64_t s = floor_div(
      (f[qi] + q * q) - (f[static_cast<std::size_t>(p)] + p * p),
      2 * (q - p));
    while (s <= z[static_cast<std::size_t>(k)]) {
      --k;
      p = v[static_cast<std::size_t>(k)];
      s = floor_div(
        (f[qi] + q * q) - (f[static_cast<std::size_t>(p)] + p * p),
        2 * (q - p));
    }
    ++k;
    v[static_cast<std::size_t>(k)] = q;
    z[static_cast<std::size_t>(k)] = s;
    z[static_cast<std::size_t>(k + 1)] = kZPos;
  }

  // 第二遍：沿分界指针向右查询每条抛物线。
  k = 0;
  for (std::size_t qi = 0; qi < n; ++qi) {
    const std::int64_t q = static_cast<std::int64_t>(qi);
    while (z[static_cast<std::size_t>(k + 1)] < q) { ++k; }
    const std::int64_t p = v[static_cast<std::size_t>(k)];
    const std::int64_t d = q - p;
    out[qi] = d * d + f[static_cast<std::size_t>(p)];
  }
}

int main() {
  const std::vector<std::int64_t> f = {9, 100, 4};
  std::vector<std::int64_t> out;
  edt1d(f, out);
  for (std::size_t i = 0; i < out.size(); ++i) {
    if (i != 0) { std::cout << ' '; }
    std::cout << out[i];
  }
  std::cout << '\n';
  return 0;
}

    2.4把 f = [9, 100, 4] 逐步算到 [8, 5, 4]

    令 $P_p(x)=(x-p)^2+f[p]$。本例专门暴露负数交点：如果使用 C++ 原生整数除法，最后会把第一格错算成 9。

    1. 初始化 $q=0$：只有顶点 $p=0$，所以 v=[0]、z=[-∞,+∞]，尚无需计算 $s$。
    2. 扫描 $q=1$：与 $p=0$ 的交点 $s=\left\lfloor\frac{(100+1)-(9+0)}{2(1-0)}\right\rfloor=46$。因为 $46\le z[0]=-\infty$ 不成立，保留 0 并压入 1，得到 v=[0,1]、z=[-∞,46,+∞]。
    3. 扫描 $q=2$，第一次比较 $p=1$：$s=\left\lfloor\frac{(4+4)-(100+1)}{2(2-1)}\right\rfloor=\left\lfloor-93/2\right\rfloor=-47$。因为 $-47\le z[1]=46$，弹出顶点 1。
    4. 弹栈后比较 $p=0$：$s=\left\lfloor\frac{(4+4)-(9+0)}{2(2-0)}\right\rfloor=\left\lfloor-1/4\right\rfloor=-1$。因为 $-1\le z[0]=-\infty$ 不成立，保留 0 并压入 2，最终 v=[0,2]、z=[-∞,-1,+∞]。
    5. 查询输出：$q=0$ 已满足 $z[1]=-1<0$，因此选 $p=2$，得 $(-2)^2+4=8$；$q=1$ 同样选 $p=2$，得 $(-1)^2+4=5$；$q=2$ 选 $p=2$，得 $0^2+4=4$。
    负分子修正与最终结果
    $$\lfloor -1/4 \rfloor = -1,\qquad \operatorname{trunc}(-1/4)=0$$ $$\operatorname{edt1d}([9,100,4])=[8,5,4],\qquad v=[0,2],\qquad z=[-\infty,-1,+\infty]$$
    为什么错用除法会稳定得到 [9, 5, 4]？

    把第 4 步的 $s=-1$ 错写为 0 后，分界变成 z=[-∞,0,+∞]。查询 $q=0$ 时条件 z[1] < q 不成立，仍选 $p=0$，于是输出 9；$q=1,2$ 仍选 $p=2$。这不是随机误差，而是负交点被向右推了一格。

    2.5真实栈状态步进器：v、z、popped 与 s

    下方不运行另一份算法：每一步都直接读取 S.edt1dWithTrace([9, 100, 4]).steps。popped 是该次扫描实际弹出的顶点；面板中的 s 显示弹栈结束后最终接受的交点，也就是新栈顶对应的 z[k]。

    1 / 3

    每一步都要守住的不变量
    • v[] 是顶点下标栈：v[k]=p 表示抛物线 $P_p(x)=(x-p)^2+f[p]$ 仍在当前下包络上；它不是函数值栈。
    • z[] 是相邻顶点的整数分界栈：z[k] 分隔 v[k-1] 与 v[k]，两端用哨兵覆盖 $(-\infty,+\infty)$；查询时用 z[k+1] < q 右移。
    • 弹栈条件必须是 s <= z[k]：等号也不能保留旧顶点，因为整数定义域里它已经没有任何独占采样点。popped 只是被遮蔽的顶点，不是被删除的输入。
    • s 必须向下取整：真实分界取决于满足 $P_q\le P_p$ 的最小整数 $q$；floor_div 保证负分子不会向零截断。
    • 严格 $O(N)$：每条抛物线至多入栈一次、出栈一次，构建的比较均摊常数；查询指针只从左向右移动一次。没有嵌套的正向搜索。

    2.7双向 EDT → SDF、双线性解析梯度与 swmax_ 金字塔

    • 双向 EDT 构 SDF：分别对占据格做一次 EDT 得 $d_{\text{occ}}$、对自由格做一次 EDT 得 $d_{\text{free}}$。自由空间 $\text{SDF} = +\sqrt{d_{\text{occ}}}\cdot r > 0$，墙体表面 $=0$，墙体内部深度为负值 $<0$。
    • 双线性插值与解析梯度：在相邻四个格心 $(v_{00}, v_{10}, v_{01}, v_{11})$ 上做双线性插值，$x$ 方向偏导 $\frac{\partial \text{SDF}}{\partial x}$ 就是水平差分插值再除以分辨率 $r$！
    • 滑窗最大值栈 swmax_：第 $k$ 层的每个像素记录以它为锚点的 $2^k \times 2^k$ 窗口内似然场的最大值：dst[y][x] = max(src[y][x], src[y][x+h], src[y+h][x], src[y+h][x+h])，第 6 章的 B&B 全局搜全靠它给出不漏解的紧致上界。

    2.9工程技巧与踩坑复盘

    为什么 edt1d([9, 100, 4]) 曾算出错误的 9？

    当 $p=0, q=2, f=[9, 100, 4]$ 时，交点分子为 $(4+4)-(9+0) = -1$，分母为 $4$。数学向下取整 $\lfloor -1/4 \rfloor = -1$，而 C++ 原生整数除法 (-1)/4 = 0（向零截断）。这会把最终分界从 z[1]=-1 错写为 0，使查询 $q=0$ 时仍选顶点 0，于是真实结果 $[8, 5, 4]$ 被算成 $[9, 5, 4]$。使用 int64_t 配合 floor_div 才彻底修复该 Bug（test_map_field.cpp 有专项回归测试）。

    共享只读所有权消除 UAF

    早期版本 MapField 持有原始指针 const OccupancyGrid * grid_，一旦调用方栈上局部 grid 析构便触发 Use-After-Free。重构后统一改为私有 std::shared_ptr<const OccupancyGrid> grid_（map_field.hpp:L162），即使热切图期间后台仍在读取旧地图也绝对安全。
