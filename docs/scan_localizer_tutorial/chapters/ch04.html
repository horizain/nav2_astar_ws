    4.2从空白文件开始：先写一个能跑的最小内核

    先不要追求生产级。我们的第一版只回答四个问题：当前点离墙多远？每个点该信多少？往哪个方向修？这一步有多大？ 暂时不计算协方差，也不做历史最优回滚。

    两个常见的朴素写法为什么会失败？
    • 直接最小化点到离散墙格中心的距离：扫描点会被吸到格心，形成量化平台，难以达到亚胞元精度。
    • 所有点等权平方误差：一个近距行人或货箱就能把整帧解拖偏；必须引入 Huber 权重与残差截断。
    教学最小版：只实现一轮 Field-GN，故意省略生产防御与协方差
    MatchResult fieldGnStepMinimal(
  const MapField & field, const Pose2 & prior,
  const Scan & scan, const MatchOptions & opt)
{
  MatchResult res;
  if (!field.valid() || scan.points.size() < 5) { return res; }

  Pose2 p = prior;
  Eigen::Matrix3d H = Eigen::Matrix3d::Zero();
  Eigen::Vector3d b = Eigen::Vector3d::Zero();
  int used = 0;
  const double c = std::cos(p.theta), s = std::sin(p.theta);
  const auto & grid = field.grid();

  for (const auto & pt : scan.points) {
    if (!std::isfinite(pt.x()) || !std::isfinite(pt.y())) { continue; }
    const double wx = p.x + c * pt.x() - s * pt.y();
    const double wy = p.y + s * pt.x() + c * pt.y();
    const auto g = grid.worldToGridF(wx, wy);
    Eigen::Vector2d grad;
    const double r = field.sdf(g.x(), g.y(), & grad);
    if (std::abs(r) > opt.trim_dist) { continue; }

    const double ar = std::abs(r);
    const double w = ar <= opt.huber_delta ? 1.0
      : opt.huber_delta / std::max(ar, 1e-9);
    const double jth = grad.x() * (-(wy - p.y))
      + grad.y() * (wx - p.x);
    const Eigen::Vector3d J(grad.x(), grad.y(), jth);
    H += w * J * J.transpose();
    b += w * J * r;
    ++used;
  }
  if (used < 5) { return res; }

  Eigen::Matrix3d Hd = H;
  Hd.diagonal().array() +=
    1e-6 * H.diagonal().array().max(1.0);
  const Eigen::Vector3d dp = Hd.ldlt().solve(-b);
  if (!dp.allFinite()) { return res; }

  const double nl = dp.head<2>().norm();
  const double clip = std::min(1.0,
    std::min(0.2 / std::max(nl, 1e-9),
             0.1 / std::max(std::abs(dp(2)), 1e-9)));
  p.x += clip * dp(0);
  p.y += clip * dp(1);
  p.theta = wrap_angle(p.theta + clip * dp(2));

  res.pose = p;
  res.valid = true;
  return res;
}

    4.3公式推导：为什么不需要数据关联？

    对于世界系点 $\mathbf{p}_{w,i} = T(\boldsymbol{\xi})\mathbf{p}_i$，点-线 ICP 衡量它到墙体切线的垂直法向距离。距离场 $\text{SDF}(\mathbf{p}_{w,i})$ 正好是到最近墙壁表面的有向距离，其梯度 $\nabla \text{SDF}$ 就是表面单位法向量。

    链式法则雅可比 + Huber IRLS 正规方程
    $$r_i(\boldsymbol{\xi}) = \text{SDF}\bigl(\mathbf{p}_{w,i}(\boldsymbol{\xi})\bigr), \qquad \mathbf{J}_i = \frac{\partial r_i}{\partial \boldsymbol{\xi}} = \begin{bmatrix} g_x & g_y \end{bmatrix} \begin{bmatrix} 1 & 0 & -(w_{y,i} - p_y) \\ 0 & 1 & +(w_{x,i} - p_x) \end{bmatrix}$$ $$w_i = \begin{cases} 0 & |r_i| > d_{\text{trim}} \\ 1 & |r_i| \le \delta \\ \delta / |r_i| & \text{otherwise} \end{cases}, \qquad \left(\sum w_i \mathbf{J}_i^\top \mathbf{J}_i + \lambda I\right)\Delta\boldsymbol{\xi} = -\sum w_i \mathbf{J}_i^\top r_i$$

    代码里的 H 是 $\sum w_i J_i^\top J_i$，b 是 $\sum w_i J_i r_i$。前者描述“哪些方向被充分约束”，后者描述“当前残差把解往哪推”。二者必须来自同一次 eval_pose(p)。

    4.4一轮 GN 的完整数值演算

    下面用一个可以手算的例子把符号落到数值上。地图里只有一面竖直墙，零面位于 $x=0.05\text{ m}$；初始位姿 $p=(-0.15,0,0)$，5 个车体系点为 $(0,y_i)$，其中 $y_i=-2,-1,0,1,2$。

    1. 每个点的世界坐标都是 $(-0.15,y_i)$，所以 $r_i=0.20\text{ m}$，$\nabla \text{SDF}=(-1,0)$。
    2. 取 $\delta=0.10\text{ m}$，则 Huber 权重 $w_i=\delta/|r_i|=0.5$。
    3. 每个点的雅可比 $J_i=(-1,0,y_i)$，于是 $H=\sum 0.5J_i^\top J_i=\operatorname{diag}(2.5,0,5)$。
    4. $b=\sum 0.5J_i r_i=(-0.5,0,0)^\top$，所以 $-b=(0.5,0,0)^\top$。
    5. 阻尼项仅 $10^{-6}$ 量级，可近似认为 $dp\approx H^{-1}(-b)=(0.2,0,0)^\top$。
    6. 步长未超过 $0.2\text{ m}$ 护栏，因此 $p_{\text{next}}=(0.05,0,0)$，恰好走到墙面零面。
    先检查符号，再检查矩阵

    墙在机器人右侧，SDF 梯度指向左侧 $(-1,0)$，残差为正；因此 $b_x$ 为负，解方程时取 $-b$ 后 $dp_x$ 为正。如果这里符号反了，再漂亮的矩阵推导也会把机器人推离墙面。

    4.6两级组合：为什么精修前还要粗捕获？

    Field-GN 很快，但它是局部优化器：初值离正确盆地太远时仍可能陷进局部极小。生产默认方案先用 Correlative 抓住大致位姿，再让 Field-GN 精修。

    src/matchers.cpp : L691-705
    MatchResult ComposedMatcher::match(
  const MapField & field, const Pose2 & prior,
  const Scan & scan, const MatchOptions & opt) const
{
  MatchResult coarse = coarse_->match(field, prior, scan, opt);
  if (!coarse.valid || !fine_) { return coarse; }
  MatchResult fine = fine_->match(field, coarse.pose, scan, opt);
  if (!fine.valid || fine.score + 0.05 < coarse.score) {
    return coarse;
  }
  return fine;
}

    最后三行是一道安全护栏：精修失败，或得分比粗解低超过 0.05，就退回粗匹配。局部精修不应该有权把已经找到的更好解“修坏”。

    4.7生产实现最容易漏掉的四个细节

    1. 更新最优记录与更新位姿的顺序

    best_pose 和 ravg 属于当前位姿 $p^{(k)}$。必须先保存本轮成绩，再执行 $p \leftarrow p + dp$；否则会把“新位姿”和“旧位姿的成绩”错配。

    2. 最后一跳可能没有被评估

    如果收敛判断发生在更新后并立即 break，循环不会再次进入 eval_pose。生产实现因此在循环结束后补评估一次终态，只有更优才采纳。

    3. 协方差绝不能使用带阻尼的 Hd

    阻尼只帮助求解步长。把 Hd 送进 cov_from_hessian 会人为抬高不可观测方向的特征值，让长走廊误以为自己沿轴方向也很确定。

    4. Eigen 表达式与求值时机

    H += w * J * J.transpose() 会立即累加到矩阵；而 cov = 0.5 * (cov + cov.transpose()) 涉及转置别名，生产代码使用 .eval() 明确物化中间结果，避免 Eigen 的惰性求值造成覆盖冲突。
