    6.2分支定界的可采纳上界：为什么剪枝不会漏真解

    直接遍历全球地图 $W \times H \times N_\theta$ 个格点代价很高。Cartographer 与 scan_localizer 用 swmax_[level] 在常数时间内读出“一个 $2^{\ell}\times 2^{\ell}$ 大块里的最高可能似然”：

    可采纳上界不等式（对块内每个离散位姿都成立）
    $$B\bigl(\text{block }[b_x,b_x+2^\ell)\times[b_y,b_y+2^\ell),\theta\bigr) =\frac{1}{N}\sum_{i=1}^N\max_{(\delta x,\delta y)\in[0,2^\ell)^2} L(c_{x,i}+b_x+\delta x,\;c_{y,i}+b_y+\delta y) \;\ge\;\max_{\boldsymbol{\xi}\in\text{block}}S(\boldsymbol{\xi})$$

    关键不是“上界看起来很大”，而是任何块内叶子的精确分数都不会超过它。优先队列每次弹出 bound 最大的节点；一旦已经收满 top-K 个互相独立的峰，令 worst_kept 为其中最低分，则队首满足 bound <= worst_kept 时，整棵剩余队列都不可能产生更优候选，可以一次结束搜索。

    三条不变量
    • 上界只能高估，不能低估：完全越界的光束记 0；部分越界时不得用边界夹紧值制造虚假高分。
    • 队首是全局最大上界：优先队列必须按 bound 降序，不是按格子编号或广度优先顺序。
    • 剪枝阈值来自已保留峰：Top-K 未满时不能提前剪；NMS 合并或替换候选后必须重算 worst_kept。

    6.3从空白文件重建最小 B&B：优先队列、上界剪枝与 Top-K NMS

    先只实现下面四个部件，再考虑性能：① 以 {bound, level, bx, by, aidx} 为节点的最大堆；② 从金字塔读块上界；③ 四分裂到 level 0 后精确打分；④ 固定容量 Top-K 与空间/角度 NMS。页面不会另造一份可执行算法，所有交互数字仍来自现有 S.globalCorrelativeBnB；这里给出的是实现契约与伪代码。

    部件最小契约出错时最常见的结果
    最大堆push 后父节点不小于子节点；pop 返回当前最大 bound把最小堆当最大堆，提前剪掉真正高分的队列尾部/队首
    块上界evalBound(level,bx,by,angle) 对块内任意叶子分数都是上界漏光束、错误平移旋转方向或越界记负分，破坏可采纳性
    四分裂level > 0 时生成四个 2^(level-1) 子块；level 0 才精确评分把 span 当成半宽，重复搜索或漏掉四分之一区域
    Top-K NMS同一峰保留最高分；未满 K 时 worst_kept=0；满 K 后保存 K 个不同峰的最低分相邻格子占满 K 个名额，真正全局峰被第 K 个重复峰误剪
    minimal_bnb.pseudo · 教学伪代码，不是第二份实现
    Node = { bound, level, bx, by, aidx }
pq = MaxHeap(key = bound)
hyps = []                         // 最多 K 个不同峰
worst_kept = 0.0

for each top-level block:
    b = evalBound(level, bx, by, angle)
    if b > 0.05: pq.push(Node(b, level, bx, by, angle))

while pq not empty:
    node = pq.pop_max()
    if size(hyps) == K and node.bound <= worst_kept:
        break                     // 队首即队列最大上界，剩余节点全部可剪

    if node.level == 0:
        score = exact_score(node) // 逐点似然平均值；越界点为 0
        if score <= 0.10: continue
        cand = { score, bx, by, aidx }
        if exists h in hyps where same_mode(h, cand):
            keep the higher-scoring member of that mode
        else if size(hyps) < K:
            hyps.push(cand)
        else if cand.score > worst_kept:
            replace the lowest-scoring hypothesis with cand
        worst_kept = (size(hyps) == K) ? min_score(hyps) : 0.0
        continue

    half = 1 << (node.level - 1)
    for dy in {0, 1}, dx in {0, 1}:
        child = { bx: node.bx + dx * half,
                  by: node.by + dy * half,
                  level: node.level - 1, aidx: node.aidx }
        if child intersects free-space bounding box:
            b = evalBound(child)
            if b > 0.05 and (size(hyps) < K or b > worst_kept):
                pq.push(Node(b, child))

sort hyps by score descending
refine each hypothesis in a small continuous window
run final NMS again               // 精修后相邻峰可能重新靠在一起

    生产 C++ 的 NMS 阈值为 0.50m 与 0.35rad（matchers.cpp:L839-855）；当前教学数学核为了动画可读性使用 0.80m 与 0.45rad。两者都遵循同一契约，但数值面板展示的是教学核返回值，不能把阈值差异误判为随机误差。

    6.5粒子滤波对照：从“一峰答案”到“加权多峰分布”

    6.6公平计时：先对齐观测预算，再讨论快慢

    不能把“B&B 一帧”与“PF 随机初始化后再迭代若干帧”直接相除。下面的受控微基准分成两个观测预算：1 帧任务比较 B&B 完整全局解与 PF 全局初始化 + 1 次更新；10 帧任务让 B&B 对每帧各解一次，PF 只初始化一次并做 10 次预测/更新。两侧读取完全相同的扫描序列。

    计时口径
    • performance.now() 只包住算法调用；地图构建、扫描生成、真值推进、误差计算、表格与画布渲染全部在计时区外。
    • 每个任务预热 2 次，再测 7 次并取中位数；PF 使用可复现的固定种子序列，B&B 为确定性计算。
    • 最终误差与 ESS 取自“耗时中位数对应的那次试验”；成功率单独统计 7 次，避免用失败运行制造虚假加速比。
    • 通过门限定为平移误差 <0.5m 且角误差 <0.35rad，只用于同一张表的验收，不是算法内部参数。
    • 这是当前浏览器中的 JavaScript 教学核微基准，不能替代 C++/ROS 的 E8 实验，也不代表不同硬件上的绝对毫秒数。

    6.8工程踩坑复盘：B&B 为何曾在冷启动卡死或误剪

    Phase 2 修复：100% 激光越界剔除 + worst_kept 更新错乱（matchers.cpp:L796-913）

    早期逻辑“只要有一束激光越界就丢弃整个候选方块”，会让大厅边缘的合法方块全部消失，优先队列提前变空。正确做法是只对整块完全越界的光束记 0，并把机器人位姿搜索框限制在自由空间外接矩形内。另一处 Bug 是多峰去重/替换后未重算第 K 优阈值，导致真解被过时的 worst_kept 误剪。

    PF 的三处数值护栏
    • 倒车时 |rot1| > π/2 要翻转 rot1 += π 并将平移取反，避免 ±π 附近噪声爆炸（particle_filter.cpp:L129-136）。
    • 似然连乘改为对数累加，归一化时减 max_lw；非有限权重回退为均匀分布，避免全零或 NaN（L183-236）。
    • 角度均值使用 atan2(Σw sinθ, Σw cosθ)，不能直接平均 ±179°（L256-290）。
