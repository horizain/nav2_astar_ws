    8.2Lifecycle：资源不是构造函数随手创建的

    先分清两套状态机：LocalizerCore 的 UNINIT / TRACKING / DEGRADED / LOST / GLOBAL 描述“定位是否可信”；LifecycleNode 的 UNCONFIGURED / INACTIVE / ACTIVE 描述“节点是否拥有资源、是否允许输出”。两者不能互相替代。

    初始状态：UNCONFIGURED；不创建核心、TF 或发布器。

CallbackReturn LocalizerNode::on_activate(const State &)
{
  if (pose_pub_) {pose_pub_->on_activate();}
  if (status_pub_) {status_pub_->on_activate();}
  if (hypotheses_pub_) {hypotheses_pub_->on_activate();}
  active_.store(true);
  return CallbackReturn::SUCCESS;
}

CallbackReturn LocalizerNode::on_deactivate(const State &)
{
  active_.store(false);                           // 先停止接收新工作
  if (pose_pub_) {pose_pub_->on_deactivate();}
  if (status_pub_) {status_pub_->on_deactivate();}
  if (hypotheses_pub_) {hypotheses_pub_->on_deactivate();}
  return CallbackReturn::SUCCESS;
}

CallbackReturn LocalizerNode::on_cleanup(const State &)
{
  resetResources();
  return CallbackReturn::SUCCESS;
}

CallbackReturn LocalizerNode::on_shutdown(const State &)
{
  resetResources();
  return CallbackReturn::SUCCESS;
}

void LocalizerNode::resetResources()
{
  active_.store(false);
  // cancel timers; remove parameter callback; reset subscriptions/publishers/TF ...
  std::lock_guard<std::mutex> lk(state_mtx_);
  core_.reset();
  field_.reset();
  grid_.reset();
  matcher_.reset();
  imu_started_ = false;                           // 防止下一轮继承旧航向锚
  odom_buffer_.clear();
  last_scan_.points.clear();
  pending_hypotheses_.clear();
  global_alternates_.clear();
}

    回调组的真实归属：不要照抄注释想当然

    回调实际回调组为什么真实源码
    /odom /imusensor_cb_group_短临界区写入时间戳缓冲；地图重构建时仍可推进。L764-772
    /scanwork_cb_group_扫描会调用核心、可能触发全局搜索，并与地图/服务共享工作线程序列。L758-762

    “锁外构场”不等于“scan 一定同时继续跑”

    两个回调组都是 MutuallyExclusive。真实代码把 /scan 放在 work_cb_group_，因此同组的地图构建回调执行期间，scan 回调仍须等待；锁外构建直接保护的是可并行的 /odom /imu 传感器回调，并把状态锁占用缩到最短。是否真正并行还取决于 executor；单线程 executor 不会并行。组件容器 component_container_mt 才提供多线程调度条件。

    8.3applyMap：锁外造好，锁内一次提交

    地图场、NDT 或匹配器的构建可能耗时数十毫秒。错误做法是拿着 state_mtx_ 从栅格一路建到匹配器，期间所有需要读取核心状态的线程一起等待。正确做法把过程分成“验证 → 复制构建参数 → 锁外构建 → 锁内原子交换”四段。

    教学最小版：applyMap 的提交边界（对应 L890-963）
    bool LocalizerNode::applyMap(
  std::shared_ptr<OccupancyGrid> grid, bool keep_pose)
{
  if (!grid || grid->width <= 0 || grid->height <= 0 ||
      !isFinitePositive(grid->resolution)) {
    return false;
  }
  const std::size_t expected =
    static_cast<std::size_t>(grid->width) * grid->height;
  if (grid->cells.size() != expected) {return false;}

  double sigma = 0.20;
  std::string matcher_name;
  double ndt_voxel = 0.5;
  {
    std::lock_guard<std::mutex> lk(state_mtx_);   // 只复制参数
    sigma = likelihood_sigma_;
    matcher_name = matcher_name_;
    ndt_voxel = ndt_voxel_;
  }

  // 耗时工作全部在锁外；失败时旧 grid_/field_/matcher_ 完全没动。
  auto field = std::make_shared<MapField>();
  if (!field->build(grid, sigma)) {return false;}
  auto matcher = make_matcher(matcher_name, grid.get(), ndt_voxel);
  if (!matcher) {return false;}

  {
    std::lock_guard<std::mutex> lk(state_mtx_);   // 只提交一致视图
    if (!core_) {return false;}
    const bool first = !map_received_;
    grid_ = std::move(grid);
    field_ = std::move(field);
    matcher_ = std::move(matcher);
    pending_hypotheses_.clear();
    global_alternates_.clear();
    stable_tracking_count_ = 0;
    core_->set_map(field_);
    core_->set_matcher(matcher_);
    map_received_ = true;
    if (!first && !keep_pose) {
      core_->request_global();                     // 热切图且不保位姿
    }
  }
  return true;
}
    阶段持锁？成功语义失败语义
    尺寸、分辨率、胞元数验证否得到可构建的输入快照。立即返回，不分配新地图资源。
    复制 sigma / matcher / voxel是，极短本次构建使用一份一致参数。不修改参数。
    MapField::build / make_matcher否新地图与新匹配器同时就绪。任一失败，旧地图继续服务；绝不能提交半成品。
    交换三个地图成员并更新核心是，极短读取者只能看到交换前或交换后的完整地图视图。core_ 已不存在时返回 false，不写地图成员。
    这里的“原子”是逻辑原子，不是 std::atomic 指针魔法

    生产代码用同一把 state_mtx_ 保护 grid_ / field_ / matcher_ / core_ 的整套切换。若逐个成员加锁或先更新 field_ 后更新 matcher_，读取者可能看到“新场配旧匹配器”。

    失败路径与热切语义
    • 构建失败：局部新对象销毁，旧地图不变。上游若忽略 applyMap() 的 bool，会把“切换失败”误报成“切换成功”。
    • 首图：first=true，不会仅因切图调用 request_global()；初始定位仍按核心状态机处理。
    • 后续地图：keep_pose=true 保留位姿；为 false 时请求全局重定位，因为新地图里的旧坐标不再天然可信。
    • 顺序：互相排斥的 work 回调组串行化本节点的地图请求；原子交换不提供跨任意线程的“最后请求获胜”版本号。

    8.4onScan：一帧扫描只有一个时间锚

    激光消息的到达时刻、消息头时刻、当前最新里程计时刻不是同一个概念。匹配需要的是“这束激光在 header.stamp 时，雷达相对 base 在哪里，机器人相对 odom 在哪里”。因此外参 TF 与 odom 都按扫描时刻查询，而不是按回调开始时的 now()。

    C++ 风格伪代码：扫描时刻对齐与双重提交检查（L1189-1336）
    void LocalizerNode::onScan(const LaserScan::SharedPtr & m)
{
  if (!active_.load() || !m) {return;}

  // 1. 锁内只复制配置；没有地图或核心就直接返回。
  std::string base_frame;
  int min_pts = 10;
  double tf_timeout = 0.05;
  {
    std::lock_guard<std::mutex> lk(state_mtx_);
    if (!map_received_ || !core_) {return;}
    base_frame = base_frame_;
    min_pts = min_scan_points_;
    tf_timeout = tf_lookup_timeout_;
  }

  const rclcpp::Time scan_stamp(m->header.stamp);

  // 2. base_frame -> laser_frame 也查 scan_stamp，保留 roll/pitch/z 外参。
  //    仅 ExtrapolationException 回退到 latest；其他 TF 失败走 2D 参数。
  Scan scan = preprocess_scan_at(m, base_frame, scan_stamp, tf_timeout);
  if (static_cast<int>(scan.points.size()) < min_pts) {return;}

  // 3. odom -> base_link 查同一个 scan_stamp：TF 优先，环形缓冲插值兜底。
  Pose2 odom_at_scan{};
  bool odom_stale = false;
  const bool have_odom = lookupOdomAt(scan_stamp, odom_at_scan, odom_stale);

  OutputSnapshot snap;
  {
    std::lock_guard<std::mutex> lk(state_mtx_);
    if (!active_.load() || !map_received_ || !core_) {return;}
    if (have_odom) {core_->on_odom(odom_at_scan);}
    last_scan_ = scan;
    has_last_scan_ = true;
    const CoreOutput out = core_->on_scan(scan);
    snap = buildSnapshotLocked(out, odom_stale);
  }                                                   // 状态锁在这里释放

  publishOutputs(snap, scan_stamp.nanoseconds() == 0 ? now() : scan_stamp);
}

bool LocalizerNode::lookupOdomAt(const rclcpp::Time & stamp,
                                 Pose2 & out, bool & stale)
{
  stale = false;
  // 优先：lookupTransform(odom_frame, base_frame, stamp, timeout)
  // 捕获 TransformException 后才进入下列 /odom 缓冲回退。

  std::lock_guard<std::mutex> lk(state_mtx_);
  if (odom_buffer_.empty()) {return false;}
  if (stamp > odom_buffer_.back().stamp &&
      (stamp - odom_buffer_.back().stamp).seconds() > odom_timeout_) {
    stale = true;                                   // 告警，不直接丢帧
  }
  if (stamp <= odom_buffer_.front().stamp) {
    out = odom_buffer_.front().pose; return true;    // 端点钳制
  }
  if (stamp >= odom_buffer_.back().stamp) {
    out = odom_buffer_.back().pose; return true;
  }
  for (std::size_t i = 0; i + 1 < odom_buffer_.size(); ++i) {
    const auto & a = odom_buffer_[i];
    const auto & b = odom_buffer_[i + 1];
    if (a.stamp <= stamp && stamp <= b.stamp) {
      const double dt = (b.stamp - a.stamp).seconds();
      const double alpha = dt > 1e-9
        ? std::clamp((stamp - a.stamp).seconds() / dt, 0.0, 1.0) : 0.0;
      out.x = a.pose.x + alpha * (b.pose.x - a.pose.x);
      out.y = a.pose.y + alpha * (b.pose.y - a.pose.y);
      out.theta = wrap_angle(
        a.pose.theta + alpha * wrap_angle(b.pose.theta - a.pose.theta));
      return true;
    }
  }
  out = odom_buffer_.back().pose;
  return true;
}

    角度插值必须先对 b.theta - a.theta 做 wrap_angle。否则从 +179° 到 -179° 会误走 358°，而不是跨过 ±π 的 2°。生产实现见 L1170-1186。

    失败/边界生产代码怎么做为什么不是直接丢帧
    扫描头时间戳为 0TF 查询 latest；输出时刻改用 now()。兼容未填时间戳的驱动，但不能恢复已经丢失的测量时刻。
    base→laser 精确时刻外推失败仅对 ExtrapolationException 再查 latest；其他异常使用 2D 外参参数。静态外参通常变化很慢；动态外参缺失则仍可能引入误差。
    odom TF 缺失回退到带时间戳的 /odom 环形缓冲并插值。保留扫描时刻对齐，而不是拿最新 odom 顶替。
    缓冲为空have_odom=false；本帧不调用 core_->on_odom()。核心沿用已有运动锚；冷启动时是否可定位由核心状态机决定。
    扫描晚于缓冲末端且超时仍取末端样本，但 odom_stale=true，诊断在 TRACKING 时升为 WARN。stale 是质量信号，不是硬拒绝；是否丢弃应由系统策略决定。
    有效点少于 min_scan_points在更新核心前返回。避免用不可靠稀疏扫描污染滤波器。
    预处理期间被 deactivate / cleanup锁内二次检查 active_ / map_received_ / core_ 后返回。入口检查不足以覆盖整个异步生命周期。

    8.5OutputSnapshot：把一致视图带出锁

    DDS publish() 可能因序列化、背压或进程内分发而阻塞。如果发布时仍持有 state_mtx_，一个慢订阅者就能拖住 odom、IMU、参数与地图状态读取。生产代码先在锁内复制一份自洽快照，再在锁外构造消息并发布。

    教学最小版：快照所有权与锁外发布（hpp:L87-100；cpp:L1520-1592）
    struct OutputSnapshot {
  CoreOutput out;                                  // 位姿、协方差、状态、分数
  Pose2 map_to_odom;
  bool publish_tf{false};
  bool fine_on{false};
  bool odom_stale{false};
  bool tf_broadcast{true};
  double transform_tolerance{0.1};
  std::string map_frame;
  std::string odom_frame;
  std::string base_frame;
  std::vector<Pose2> hypotheses;                  // 值复制，不借引用
};

OutputSnapshot LocalizerNode::buildSnapshotLocked(
  const CoreOutput & out, bool odom_stale) const
{
  OutputSnapshot snap;                             // 调用者已持有 state_mtx_
  snap.out = out;
  snap.publish_tf = tf_broadcast_ && core_ &&
    core_->state() != LocState::UNINIT;
  if (snap.publish_tf) {snap.map_to_odom = core_->map_to_odom();}
  snap.odom_stale = odom_stale;
  snap.map_frame = map_frame_;
  snap.odom_frame = odom_frame_;
  snap.base_frame = base_frame_;
  if (out.state != LocState::UNINIT) {
    snap.hypotheses.push_back(out.pose);
  }
  for (const auto & h : pending_hypotheses_) {
    snap.hypotheses.push_back(h);
  }
  for (const auto & h : global_alternates_) {
    snap.hypotheses.push_back(h);
  }
  if (core_) {
    const auto core_hyps = core_->hypothesis_poses();
    snap.hypotheses.insert(
      snap.hypotheses.end(), core_hyps.begin(), core_hyps.end());
  }
  return snap;
}

void LocalizerNode::publishOutputs(
  const OutputSnapshot & snap, const rclcpp::Time & stamp)
{
  if (!active_.load()) {return;}                    // 无 state_mtx_

  if (snap.publish_tf && tf_broadcaster_) {
    geometry_msgs::msg::TransformStamped tf;
    tf.header.stamp = stamp + rclcpp::Duration::from_seconds(
      snap.transform_tolerance);
    tf.header.frame_id = snap.map_frame;
    tf.child_frame_id = snap.odom_frame;
    tf.transform.translation.x = snap.map_to_odom.x;
    tf.transform.translation.y = snap.map_to_odom.y;
    tf.transform.rotation.z = std::sin(0.5 * snap.map_to_odom.theta);
    tf.transform.rotation.w = std::cos(0.5 * snap.map_to_odom.theta);
    tf_broadcaster_->sendTransform(tf);
  }
  if (pose_pub_ && pose_pub_->is_activated()) {
    geometry_msgs::msg::PoseWithCovarianceStamped pm;
    pm.header.stamp = stamp;
    pm.header.frame_id = snap.map_frame;
    const auto & p = snap.out.pose;
    pm.pose.pose.position.x = p.x;
    pm.pose.pose.position.y = p.y;
    pm.pose.pose.orientation.z = std::sin(0.5 * p.theta);
    pm.pose.pose.orientation.w = std::cos(0.5 * p.theta);
    pm.pose.covariance.fill(0.0);
    constexpr int kIdx[3] = {0, 1, 5};              // x, y, yaw
    for (int i = 0; i < 3; ++i) {
      for (int j = 0; j < 3; ++j) {
        pm.pose.covariance[6 * kIdx[i] + kIdx[j]] = snap.out.covariance(i, j);
      }
    }
    pose_pub_->publish(pm);                        // 慢在这里也不持状态锁
  }
  // ... hypotheses 与 DiagnosticArray 同样只读 snap ...
}
    快照保证的与不保证的
    • 保证：位姿、map→odom、坐标系、诊断与候选假设来自同一个临界区视图，不会出现“位姿是新的、map_frame 是旧的”这种撕裂。
    • 保证：publish() 不持有 state_mtx_，消除“发布路径等状态锁、状态路径等发布回调”的锁耦合。
    • 不保证：订阅者收到时状态仍是最新。快照是线性化视图，不是实时订阅；时间戳必须保留测量时刻。
    • 不保证：快照替代 Lifecycle 同步。active_ 与发布器激活检查是闸门；deactivate 与在途发布之间仍存在过渡窗口，不应把它描述成硬实时截止。
    6×6 协方差：2D 位姿占 {0, 1, 5}，不是 {0, 1, 2}

    标准顺序是 [x, y, z, roll, pitch, yaw]。因此 yaw 方差在行主序 6×5+5=35；[14] 属于 z 方差，必须保持 0。真实代码在 L1583-1590 先 fill(0.0) 再写 3×3 槽位，集成测试同时检查 [0] / [7] / [35] > 0 与 [14] == 0。

    症状先检查哪里错误修法正确修法
    configure 后仍无输出Lifecycle 是否到 ACTIVE；发布器是否激活；active_ 是否为 true。在构造函数里偷偷 activate。由 lifecycle_manager 走 configure → activate；演示 autostart 只作为显式覆写。
    切图期间 odom 延迟尖刺构建 MapField / matcher 时是否持 state_mtx_。把锁换成读写锁后仍覆盖整个构建。锁外构建，锁内只交换整套成员。
    新地图构建失败却“黑屏”applyMap() 的 false 是否被上报；旧地图是否被提前清空。先 field_.reset() 再构建新的。新对象全部就绪后才提交；失败保留旧视图。
    转弯时定位系统性滞后外参与 odom 是否按 scan_stamp 查询。用回调里的最新 TF / odom。同一扫描时刻查询；TF 失败再用时间戳缓冲插值。
    odom 停更但 scan 仍持续odom_stale 与诊断 WARN。把陈旧外推当成新鲜测量。保留端点估计、显式标记 stale，并由上层决定降级策略。
    慢订阅者拖住整个节点publish() 是否位于状态锁外。只缩小消息队列，锁仍跨 DDS 调用。锁内构造 OutputSnapshot，锁外发布。
    IMU 一帧收不到发布者是否 BestEffort；订阅是否使用 SensorDataQoS。盲目增大可靠队列。传感器流使用匹配的 SensorDataQoS；地图仍用 transient_local。
    热调 likelihood_sigma 后异常onSetParameters 是否先验证完整参数批次。逐个写入成员，后续校验失败也不回滚。先算 next 配置并全部校验，再一次性提交。

    8.93 道练习与验收

    不要只记答案。先说出状态、资源或时间戳发生了什么，再提交检查。

    完成标准
    • 能徒手画出 UNCONFIGURED → INACTIVE → ACTIVE → INACTIVE → UNCONFIGURED，并指出 configure 失败的回滚与 cleanup 后重新 configure 的状态归零。

    • 能说明外参与 odom 都按 scan_stamp 对齐；环形缓冲对角度先 wrap 再插值，超时端点会标记 stale 而不是静默当作新鲜数据。
