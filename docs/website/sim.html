完整 SLAM 长什么样？

先看现象，再拆零件。这一讲是一个活的 SLAM：机器人自动探索六边形场地， 激光逐帧扫描、地图一格一格生长、扫描匹配把里程计漂移拉回来、覆盖完成后自动回环。

下面每一讲都从这团"完整体验"里抽出一个零件讲透。

0SLAM 管线全景图（每一讲对应一个框）

轮式里程计 ──┐ 「我大概走了这么远」（必然漂移） ├──> 扫描匹配 ══> 位姿序列 ──> 占据栅格建图 ──> 地图 激光雷达 帧 t ──┘ ▲ │ （第①讲） │ │ │ │ 「把两帧激光对齐， │ 每帧激光画一次地图 │ 修正里程计漂移」 ▼ │ （第⑤讲） 地图 + 粒子滤波定位 ──> 在已有地图上定位 │ （第②③④讲） └──> 回环检测：『我绕回来了！』 ──> 图优化全局拉直 ──> 消除累积漂移 （第⑥讲）

右上角这条主线（扫描匹配 → 建图）是"边走边建图"（在线 SLAM）； 底下那条（回环 → 图优化）是"发现走错、全局纠错"。真实 slam_toolbox 两条都在跑。

👀 观察任务
  • 地图生长：激光束扫过的地方，自由空间被"挖"出来，墙体浮现 —— 这就是第①讲的 log-odds 投票
  • 绿色轨迹 vs 红色估计：轨迹很快分叉 —— 这就是里程计漂移（第②讲起修正它）
  • 扫描匹配拉回：红色估计每隔几帧突然"跳"回绿色轨迹附近 —— 这就是第⑤讲
  • 回到起点：绕场一圈回来时地图会"咔"一下对齐 —— 这就是第⑥讲回环

1看点① 地图生长：自由空间是被"挖"出来的

注意看：墙不是画上去的，是激光束路径上的格子被一路标成"自由"， 只有束端那个格子投"占据"票。

一束激光 r = 2.3 m： 路径上的格子 → l += −0.847（自由票） 束端的格子 → l += +0.847（占据票） 没扫到的格子 → 不动（保持未知灰）

反复扫描后，灰色未知区域被"挖空"成白色自由区，黑墙浮现。 前方那团灰色 —— 是还没扫到的区域，不是墙。

2看点② 漂移与拉回：红色为什么总是"迟到"

绿色 = 机器人真实走过的位置（仿真里的上帝视角）。 红色 = 系统对机器人位置的估计 —— 它只有轮速计和激光，没有上帝视角。

两个现象：

  • 红绿轨迹逐渐分叉：轮速计积分误差在累积（直觉①）
  • 红色每隔几帧突然跳一下：扫描匹配发现"按里程计摆在这里，激光和地图对不上"， 于是把估计拉回最贴合的位置（第⑤讲的相关性评分）
    • 跳变 = 修正。没有跳变的 SLAM 才可怕 —— 说明它对漂移无感。

    3看点③ 回环：绕回来那一刻发生了什么

    机器人回到出发点附近时，注意地图与轨迹的瞬间对齐。

    这不是运气好，是三步接力：

    ① 检测「我好像回来了」 → 当前扫描与地图历史区域匹配成功 ② 生成一条回环约束边 → 「起点与终点其实是同一个地方」 ③ 图优化全局求解 → 把所有位姿节点当成弹簧网，整体拉直

    在没有回环检测的方案里（纯里程计建图），绕一圈回来会发现 墙错位、墙变厚、甚至墙断开 —— 累积漂移的物证。

    4仿真 ↔ 真实系统对照表

    仿真里的部件真实 slam_toolbox 对应本课哪一讲
    六边形场地 + 圆柱你映射的真实房间—
    理想激光（无噪声开关可调）rplidar / livox + 噪声标定⑦ 工程实战
    轮速积分（带漂移系数）/odom 话题（轮式/IMU 融合）直觉① + ⑦
    相关性评分对齐correlation_search_space_* 参数⑤ 扫描匹配
    log-odds 栅格/map 话题 + PGM 文件① 栅格建图
    覆盖判定自动结束手动判断"建好了"（看地图稳定性）⑦ 工程实战

    仿真故意做了可调噪声：把传感器噪声调大，你会看到墙变厚、匹配跳变更频繁 —— 这就是第⑦讲"为什么要标定"的预告。
