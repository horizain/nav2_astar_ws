第 3 章 · 传感器与仿真器

3.1激光雷达是怎么"看见"的？

常见的 2D 激光雷达（如思岚 RPLIDAR 系列）核心是一个高速旋转的激光测距头： 每转一圈向四周发射上百束激光，每束光碰到障碍物反射回来，记录"发射→返回"的时间差 （ToF，Time of Flight），乘以光速的一半就得到距离。一圈扫完，你得到的是一组 极坐标点 $(r_i, \varphi_i)$——"在方向 $\varphi_i$ 上，距离 $r_i$ 处有个东西"。

参数典型值（课程仿真）真实器件（RPLIDAR S2）
视场角 FOV360°360°
每圈光束数120~3200
最大量程9 m30 m
测距噪声 σ2 cm~2 cm
扫描频率20 Hz（仿真控制周期）10 Hz

两个对 SLAM 至关重要的物理事实：(1) 每束光只返回"最近的"那个障碍的距离—— 光不会穿透第一面墙再测到第二面墙；(2) 超出量程就"没有回波"—— 代码里用 inf 表示，处理不当会污染地图（第 6 章踩坑）。

3.2光线投射：一束光的数学

仿真器的核心问题：给定位姿和方向，求光束撞上哪条线段、距离多少。 我们的"世界"用一组线段表示（外墙 + 障碍物轮廓），每束光是一条射线：

$$ \text{光束：}\;\mathbf{p}(t) = \mathbf{o} + t\,\mathbf{d},\ t \ge 0 \qquad \text{线段：}\;\mathbf{q}(u) = \mathbf{a} + u\,(\mathbf{b}-\mathbf{a}),\ 0\le u\le 1 $$

令 $\mathbf{p}(t)=\mathbf{q}(u)$，用二维叉积解这个 2×2 线性方程组（叉积 $\mathbf{u}\times\mathbf{v} = u_x v_y - u_y v_x$ 就是行列式），得到经典闭式解：

$$ t = \frac{(\mathbf{a}-\mathbf{o})\times(\mathbf{b}-\mathbf{a})}{\mathbf{d}\times(\mathbf{b}-\mathbf{a})}, \qquad u = \frac{(\mathbf{a}-\mathbf{o})\times\mathbf{d}}{\mathbf{d}\times(\mathbf{b}-\mathbf{a})} $$

合法命中需要四个条件：$t>0$（向前）、$t\le$ 量程、$0\le u\le 1$（落在线段上）、 分母非零（不平行）。对所有线段取最小 $t$ 即该方向的真实距离。这就是"解析求交"—— 没有近似、没有像素化，一束光的误差只剩测量噪声。

world.py —— 光线投射（核心约 20 行）
def raycast(self, poses, angles, max_range):
    """从位姿 poses 沿机体系角度 angles 发射激光，返回距离数组。
    公式：t = (a-o)×(b-a) / (d×(b-a))，u = (a-o)×d / (d×(b-a))"""
    seg = self.segments
    a = seg[:, 0:2]                      # 每条线段起点 (M,2)
    e = seg[:, 2:4] - a                  # 每条线段方向 (M,2)
    g = angles[None, :] + yaw[:, None]   # 全局光束角度 (N,B)
    d = np.stack([np.cos(g), np.sin(g)], axis=-1)
    dist = np.full((N, B), np.inf)
    for i in range(0, N, chunk):         # 分块防内存爆炸
        oc = o[i:i+n][:, None, :]        # 光束原点
        ao = (a - oc)[:, None, :, :]     # a - o
        denom = cross2(dc, ee)           # d × e        (n,B,M)
        t = cross2(ao, ee) / denom       # 沿光束的参数
        u = cross2(ao, dc) / denom       # 沿线段的参数
        valid = (np.abs(denom) > 1e-12) & (t > 0.02) & \
                (t <= max_range) & (u >= 0) & (u <= 1)
        dist[i:i+n] = np.where(valid, t, np.inf).min(axis=2)
    return dist
为什么用线段而不是像素地图？

常见的替代方案是把世界渲染成图片再"沿着光线走格子"（DDA）。解析求交有三个优势： 零近似误差（决定 SLAM 评估指标是否可信）、速度快（NumPy 批量算 26 条线段 × 120 束只要几十微秒）、 可微可改（以后想给世界加圆弧、加门缝都容易）。真实激光雷达的物理模型同样是"光束打到几何表面"，一一对应。

3.3差速机器人：一阶运动学模型

课程机器人是经典的差速底盘（两个驱动轮 + 万向轮）。它的瞬时运动只有两个自由度： 前进速度 $v$ 和原地自转角速度 $\omega$。这构成著名的独轮车（unicycle）模型：

$$ \dot{x} = v\cos\theta,\qquad \dot{y} = v\sin\theta,\qquad \dot{\theta} = \omega $$

它是非线性的（$\theta$ 藏在 $\cos/\sin$ 里），且当 $v=0$ 时机器人无法横移—— 这就是"非完整约束"（不能像坦克一样原地平移）。仿真中用一阶欧拉积分离散化： 控制周期 50 ms 内速度视为常量，

$$ x_{k+1} = x_k + v_k\cos\theta_k\,\Delta t,\quad y_{k+1} = y_k + v_k\sin\theta_k\,\Delta t,\quad \theta_{k+1} = \theta_k + \omega_k\,\Delta t $$

50 ms / 0.55 m·s⁻¹ 时每步只挪 2.75 cm，欧拉积分误差完全淹没在传感器噪声之下—— 够用的模型就是好模型。（第 9 章 MPC 会直接沿用这个模型做线性化。）

robot.py —— 运动学与里程计噪声（节选）
class Robot:
    def __init__(self, world, pose0=(2.0, 2.0, 0.0), dt=0.05):
        self.true_pose = np.array(pose0, float)   # 真值（上帝视角）
        self.odom_pose = np.array(pose0, float)   # 里程计"自以为"的位姿
        # 里程计噪声：每步独立的测量误差，误差随时间累积
        self.odom_std_v = 0.045                   # 线速度测量噪声 (m/s)
        self.odom_std_w = 0.055                   # 角速度测量噪声 (rad/s)

    def command(self, v, w):
        # 真值：加微小的"打滑"噪声后积分
        self.true_pose = self._integrate(
            self.true_pose, v + N(0, 0.008), w + N(0, 0.010), self.dt)
        # 里程计：加*更大*的测量噪声后积分 —— 漂移之源
        self.odom_pose = self._integrate(
            self.odom_pose, v + N(0, self.odom_std_v),
            w + N(0, self.odom_std_w), self.dt)

    def scan(self):
        """以真值位姿打一帧带噪激光（真实机器人只能拿到这份数据）"""
        raw = self.lidar.scan(self.world, self.true_pose)  # raycast + N(0, 0.02)
        return raw
踩坑提醒 · 仿真器的"作弊"陷阱

SLAM 算法只允许访问 robot.scan()（带噪激光）和里程计。 任何用到 robot.true_pose 的算法都是作弊。真值只在两处合法出现： 机器人物理运动（command 内部）和最后的评估打分（ATE）。 全课程都会用这个纪律要求代码。

3.4让机器人自己动起来：航点跟踪

SLAM 需要机器人"动起来"才有数据。我们先用一个极简控制器——纯追踪（P 控制版） ——让机器人依次驶向一组航点（它的"巡逻路线"）：

$$ e_\theta = \mathrm{wrap}\big(\mathrm{atan2}(y^*-y,\ x^*-x) - \theta\big),\qquad \omega = \mathrm{clip}(k_w\, e_\theta,\ \pm 1.5),\qquad v = \begin{cases} v_0, & |e_\theta| < 0.7 \\ 0.35\,v_0, & \text{否则} \end{cases} $$

$\mathrm{wrap}$ 把角度差归一化到 $(-\pi, \pi)$——不归一化的话，机器人会为了"把角度误差从 350° 修到 0°"而疯转一整圈。 这个 30 行的控制器在第 9 章还会以"对照组"身份出场：你会发现 MPC 在同样的场景下完胜它。

练习 1 · 给世界加一个圆形柱子
圆没法用有限条线段完美表示，用 N=32 段折线逼近即可： 在 _build_default_map 里加一段循环生成圆心 (12, 8)、半径 0.9 的 32 边形。 重新跑 raycast 检查：从 (10,6) 向 45° 方向的光束距离应变成 ≈ 3.4 m。逼近精度 σ ≈ R(1−cos(π/N)) ≈ 4 mm， 远小于传感器噪声，说明"折线表示圆"对 SLAM 完全够用。
练习 2 · 光束数与角分辨率的定量关系
量程 r 处两相邻光束打在同一面墙上的间距 ≈ 2πr/B。B=120、r=9 m 时 ≈ 47 cm —— 看似很大，但相邻扫描帧（0.8 m 间隔）间"墙点重合"远不止靠相邻光束， ICP 用的是整体轮廓约束。把 B 降到 60 再玩第 5 章的 ICP 仿真，对比 RMSE 的上升幅度即可亲证。
