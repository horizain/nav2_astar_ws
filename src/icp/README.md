# ICP 2D 激光扫描配准（Point-to-Line ICP）

现代 C++23、零第三方依赖的 2D 激光扫描匹配（scan matching）实现，
含一个 fork-join 线程池的吞吐优化版本，以及与 mini_slam
（Olson 2009 相关匹配器）的对比基准。

## 算法

- **Point-to-Line 残差**（Censi PL-ICP 思路）：对应点的局部直线由
  （最近点, 次近点）估计，比点到点收敛更快、更准
- **线段投影检验**：点在直线上的投影必须落在 [q1,q2] 线段内，
  否则该直线不代表点处的局部表面——直接丢弃（不退化到点到点）。
  这挡住了视野盲区孤儿点与柱子等细结构的"跨面伪匹配"
- **Gauss-Newton**：3×3 正规方程 Cramer 求解，每轮 O(n)
- **Huber 鲁棒核** + **自适应对应距离门限**
  `gate = clamp(3×上轮RMS, 0.25m, 2.0m)`：大初始误差时宽松，
  收敛后收紧到下限剔除结构外点
- **收敛判据**：位姿增量 < 1e-6，或 RMS 连续停滞（噪声底部振荡）
- **错误处理**：`std::expected`，无异常

## 工程（fast_icp）

| 技术 | 说明 |
|---|---|
| 扁平中位数 KD-tree | 每节点一个点、24B 节点、flat 数组 DFS 连续存放；一次查询同时返回最近+次近 |
| **延迟剪枝** | 远侧子树入栈时携带分割面距离，弹出时用已收紧的 d2 复检——比"入栈时判断"少访问大量子树（实测 3.7× 查询加速） |
| cmov 更新 | 最近/次近的三目更新编译为 cmov，无分支误预测 |
| fork-join 线程池 | spin-then-park（自旋 ~1ms 再挂起），对应点搜索按 chunk 并行；per-chunk 累加器 128B 对齐，零伪共享 |
| 稳态零分配 | 所有缓冲预分配，`align()` 不触碰堆 |

经验教训（都有实测背书）：
- **线程池启动竞态**：worker 若在首轮 gen 递增后才读初值，会误判"该轮已处理"
  → 主线程死等。绑核到冷核时近乎必现（worker 启动被拉长）。修复：构造函数用
  ready 闩锁等所有 worker 完成初始化
- **超时轮询不是挂起**：cv 带超时的 wait 会让空闲 worker 周期性自旋
  （实测设计会烧 ~50% 核）；mutex+predicate 协议本身无丢失唤醒，用无界等待
- **float32 在 ~1k 点规模无收益**（计算瓶颈不在内存带宽）——改回 double，
  两个实现逐位一致
- **叶桶（bucket leaf）KD-tree 在此规模反而慢 3.6×**：每叶固定扫 16 点，
  总点距计算量 2.5×，桶内选择循环分支误预测严重
- 平衡中位数树建树时**偶数大小的子区间会产生空右区间**，必须显式处理
  （缺失时 `span[0]` 是 UB，会静默产生坐标垃圾的假节点）

## 基准（vs mini_slam CorrelativeMatcher）

数据：270° FOV 射线求交仿真（12×8 房间+柱子+凸台），两视角部分重叠，
高斯点噪声；同一编译器与优化 flags（g++-14 -O3 -march=native）。
mini_slam 用其默认两级搜索窗口。Ryzen 9 7945HX（16C32T）。

| 场景 | | FastICP 16线程(物理核) | mini_slam | 加速比 |
|---|---|---|---|---|
| A 小漂移 σ=10mm 初值 0.12m/0.08rad | 速度 | 78 µs（最小 62） | 3314 µs | **43×** |
| | 精度 | **2.0mm / 1.2mrad** | 25.7mm / 7.5mrad | |
| B 大漂移 0.41m/0.25rad σ=20mm | 速度 | 129 µs（最小 107） | 6718 µs | **52×** |
| | 精度 | **10.4mm / 2.5mrad** | 25.5mm / 6.25mrad | |
| C 强噪声 σ=50mm | 速度 | 94 µs（最小 75） | 2473 µs | **26×** |
| | 精度 | **8.9mm / 5.1mrad** | 36.1mm / 12.5mrad | |

线程池线程数建议设为**物理核数**（16），而非硬件并发数（32 逻辑）：
SMT 兄弟线程自旋会争抢物理核流水线，均值延迟差 ~2×。
`threads=0` 已默认自动检测物理核数（Linux 解析 /proc/cpuinfo，SMT 去重）。

## 优化杠杆实测（收益与代价）

| 杠杆 | 单线程收益 | 16线程收益 | 代价/边界 |
|---|---|---|---|
| 对应点缓存（年龄判据惰性重验证，`cache_correspondences`） | **3.4×**（85.8→25.2 µs/轮） | ~1.1×（撞上同步开销地板） | 强噪声下精度降 2-6×（C 场景 8.9→53mm），默认关 |
| 完美初值（杠杆2天花板：里程计预测） | 1.75×（7→4 轮） | **2.2×**（78→36 µs） | 现实中预测不完美，期望 1.2-1.5× |
| 大地图内存布局（float 节点/Morton 序，未实施） | 108k 点图查询 ~1µs/点（L3/内存带宽瓶颈，是 1k 点的 15×） | 同左 | **真实 SLAM 场景的主要剩余空间** |

关键发现：
- **杠杆不叠加**：缓存砍掉的是并行已经摊薄的部分，16 线程下收益从 3.4× 缩水到 ~1.1×；
  并行化后瓶颈从"计算量"移到"迭代数 × 同步"，**减迭代（更好的初值/混合引导）
  成为多线程下最高 ROI 的杠杆**
- 缓存有精度代价：冻结的对应关系固化噪声偏差——追求配准度时关闭
  （默认关，与参考实现逐位一致）
- 惰性重验证用**年龄判据**（累计位移 ≤ 建缓存时最近距离）而非严格的
  最近点身份判据——严格版在稠密地图（点距 ~2mm << 点到墙噪声 ~1cm）上
  永不命中，实测反而变慢 3.5%

## 低频部署配置（10-30Hz 雷达）

实测预算：30Hz 帧间隔 33.3ms，2 线程 + 核绑定 + 线程池深度挂起状态下
单帧配准均值 589µs / 最差 867µs（**占预算 2.6%**，含冷启动唤醒）；
10Hz 时仅 ~0.9%。结论：算力预算富余 30-100×，配置应往"少"配：

| 项 | 建议 | 理由 |
|---|---|---|
| 线程数 | `threads=2`（1 worker + SLAM 主线程） | 最差 867µs ≪ 33ms；16 线程配置留给离线批处理（地图合并/重定位） |
| 绑核 | SLAM 主线程钉一个固定物理核（如 cpu3），worker 钉相邻核（`pin_base_core=2`），避开 cpu0/1（内核/ROS 常驻），SMT 兄弟留空 | 免迁移抖动；主-辅核共享 L3 延迟最低 |
| 缓存友好 | **控制工作集**：与裁剪后的局部子图匹配（~10m 窗口，几千点，树 <200KB 常驻 L2），而不是整张地图 | 108k 点全图匹配 1T 要 7.4ms（预算的 22%）——该裁剪数据，而不是加线程 |
| 对应点缓存 | 保持关闭 | 精度优先（与参考实现逐位一致）；速度预算富余 30×，3.4× 的收益无处可用 |
| 功耗 | 线程池在帧间隙真正深度挂起（无界 cv 等待） | 每 33ms 唤醒一次 ~200µs，占空比 0.6%；其余 99.4% 时间核可进深睡眠 |

注意事项：
- DVFS：33ms 空闲可能让核降频，冷频下单帧最差放大 2-3×（仍 ≤4ms ≪ 预算）；
  抖动敏感时只给 SLAM 两个核设 performance governor
- 帧预算的大头是**别的组件**：mini_slam 闭环相关匹配（3-7ms/次）、SPA 优化突发
  —— ICP 的 <1ms 是零头，省下的 14 个核留给它们



## 强扩展性（单核 → 32 线程，场景 A 数据）

| 线程 | 1 | 2 | 4 | 8 | 12 | 16 | 24 | 32(SMT) |
|---|---|---|---|---|---|---|---|---|
| 加速比 | 1.0 | 1.9 | 3.9 | 7.0 | 8.7 | 8.6 | 10.1 | **2.4** |
| 效率 | 100% | 94% | 96% | 87% | 73% | 54% | 42% | 7% |

- 1→8 线程：**87-96% 并行效率**（7 轮迭代 × ~5µs/轮/线程的工作粒度下相当好）
- ≥12 线程：每轮并行工作仅 ~5µs，fork-join 同步开销占比上升
- 32 逻辑线程：**均值崩塌**（SMT 兄弟争抢物理核）但最小值仍最优（54.5µs）——
  延迟敏感选物理核数，吞吐优先才考虑 SMT
- 参考点云增大到 5400（扫描 vs 地图）后，16 线程效率回升到 ~68%
  （单轮工作量变大，同步开销被摊薄）
- Amdahl 反推串行分数 ~3-5%（归并累加器 + Cramer 解 + 位姿更新）

参考结构构建：KD-tree ~25-38 µs vs 似然场 ~480-520 µs（15-20×）。
单线程 FastICP ≈ 750 µs（与参考实现 975 µs 同量级），多线程 ~10×。
无噪声数据下 ICP 收敛到 **0.05mm / 0.006mrad**（机器精度级）。

mini_slam 的精度受其细搜索量化（±1.9mm 步长 × 模糊场分辨率）限制，
但它是**穷举窗口内全局最优**，对坏初值免疫；ICP 是局部方法，依赖
里程计先验——两者是互补关系（slam_toolbox 实际上也是两者结合）。

## 构建

```bash
cmake -B build && cmake --build build
./build/icp     # demo：合成房间配准
./build/bench   # vs mini_slam 基准
./build/dbg     # 诊断：数据自检/一致性/性能剖析
ICP_TRACE=1 ./build/dbg  # 逐迭代追踪
```

依赖：CMake ≥ 3.28、GCC 14（`bench` 需 mini_slam 的 core 源码路径，
默认指向本机的 ROS 2 工作空间，可用 `-DMINI_SLAM_CORE=...` 覆盖）。

## C++23 特性使用

`std::expected`（含 monadic）、`std::print/println`、`std::generator`
（协程：仿真器惰性生成扫描束）、`std::ranges::nth_element`、
designated initializers、`std::jthread`、`std::span`。
