# laser_prep_lab —— 2D 激光雷达工程算法实验室

2D 激光雷达在"能跑 SLAM"之前要先解决的一堆真实工程问题。本包是
这些前处理算法的可测试实现：**配准（ICP）不是本包的职责**——那在
[`../icp`](../icp/README.md)（Point-to-Line ICP + FastICP），
本包的位姿链直接调用它。

## 算法链（按执行顺序）

```
PolarScan（原始距离数组，NaN=无效——清洗类算法依赖束序拓扑）
  ① range_gate   量程/无效门控：0 回波、NaN、超量程（占位值 81.83 在这挡掉）
  ② despike      椒盐孤点：单束突跳 + 两侧邻居一致
  ③ demix        混合像素（鬼点）：深度跳变区间"中部"的桥接假回波
  ④ deshadow     掠射阴影：光束贴障碍边缘擦过去的远回波
  ⑤ deskew       运动畸变校正：逐束查里程计位姿，拉回扫描起始帧
  ⑥ cluster      自适应断裂聚类（阈值随距离缩放）
       └─ lines  split-and-merge 线段提取
  ⑦ judge        动态障碍判别：簇所在格子此前被射线"透视"过 → 动态
  ⑧ accumulate    多帧融合：位姿补偿拼接最近 K 帧
```

## 数据结构与设计约定

- **极坐标为中心**：①-⑤ 全部定义在有序距离数组上（束序 = 拓扑），
  洗完才转点云。无序点云里"相邻束"和"每束时刻"都已经丢了。
- **无效 = NaN，不猜值**：所有算子跳过 NaN，绝不制造数据。
- **类型复用 `icp::Point2/Pose2`**：deskew 输出直接喂 `icp::align`。
- **分类计数**：FilterStats 按四类报数——"删了多少、为什么"必须可交代。

  墙角台阶不是椒盐、贴边中间值不是鬼点。

## 踩坑记录（都在代码注释里钉着对应位置）

这些是本包最有教学价值的部分——每个判据的"第四个条件"都是踩出来的：

1. **鬼点 vs 斜走廊墙（demix 的四件套判据）**：1° 束距在 16m 处的
   合法掠射墙相邻差就有 1m+。初版"跳变 + 居中"判据把 Intel 的走廊
   整段当鬼点删（10.5% 的束）。四件套：跳变按邻居跨度归一压过
   局部坡度（gating 挖洞会加宽跨度引发级联——真实踩坑）、比例
   居中、任一侧可靠（成对鬼点互相污染坡度，min 取干净侧）。
2. **透视记忆的噪声穿透（ray_free 端点净空）**：掠射射线几乎贴墙跑，
   ±2cm 测距噪声让路径"穿透"墙格——墙被自己的自由证据标记，
   同一面远墙逐帧被判动态。修复：端点格周围 1 格（Chebyshev）禁记 free。
   与栅格地图"路径点不许污染端点格"是同一课的两个变体。
3. **透视记忆必须衰减**：不衰减的版本在 Intel 全程虚警 5.4 簇/帧
   （80 分钟前的自由证据还在作证）。衰减系数 = 位姿链短时一致性的
   时间上限，给长了反而虚警。
4. **demix 的边界 UB**：右侧无邻居时 `ri = -1` 漏出边界检查，
   `range[-1]` 越界读——静态检查器不一定抓得住，测试里以"零误删"
   断言兜底。

## 已知边界（诚实记录）

- **deskew 的束时序是假设**：CARMEN 日志只有扫描级时间戳，扫描时长
  按"相邻扫描间隔 × 0.25"估计。真实束时序要么来自雷达协议（逐束
  时间戳），要么实测标定——`--scan-duration` 可覆盖。
- **动态判别是"候选"不是"判决"**：Intel 上 ~1.8 簇/帧被标记
  （衰减 + 端点净空 + 0.15m 格子后从 5.4 压下来），其中仍有掠射
  墙的系统性格点。判决需要轨迹级确认（多帧位置一致性）——跟踪
  模块是自然的下一步。
- **椒盐判据天然吃细杆**：单束细结构与噪声在几何上不可分。要救
  细杆靠多帧一致性或强度通道，别调 jump 硬救（会救回噪声）。
- **单帧细杆/椒盐 → 都交给多帧**：accumulate 融合窗内持续出现的
  结构是真实的，瞬态的是噪声——这是"时间维滤波"的思想。

## 效果怎么评估（`laser_prep_eval`）

前处理自己没有 ground truth，"删了多少点"不等于"删得对"。三层评估：

```bash
./build/laser_prep_eval --input ../mini_slam/data/intel.clf --inject 2000
# 可选：--max-scans N 控混沌（长链对初值敏感）/ --scan-duration 扫时序假设
```

**① 病灶注入**（真实扫描 + 已知病灶副本，位置已知）：

| 病灶 | 召回 | 误杀 |
|---|---|---|
| 椒盐 7935 个 | **99.5%** | 0.056%（基线本来就删的不计） |
| 鬼点 324 个 | **97.5%** | 同上计入 |

**② 下游消融**（最终裁判——同一 ICP 位姿链，换前处理）：

| 配置 | RMS 中位 | RMS 95% | 墙厚 | 世界格数 |
|---|---|---|---|---|
| raw | 0.0064 | 0.0168 | 0.0156 | 15944 |
| clean | **0.0059** | **0.0153** | **0.0149** | **14630** |
| full(clean+deskew) | 0.0075 | 0.0243 | 0.0161 | 16067 |

- **清洗链的收益被下游证明**：RMS −8%、墙厚 −4%、点云致密度 +8%，
  三个独立指标同向改善。
- **deskew 在此数据集上无法证明收益**（诚实结论）：扫了前向/后向/
  微小时序三种假设都不改善。原因：CARMEN 日志没有逐束时序（时序
  是猜的）+ Intel 里程计质量差；且 13k 帧的帧间链对毫米级扰动混沌
  敏感（1ms 校正都能改变轨迹宏观形态）。deskew 的正确性由合成
  真值单测保证（误差 1e-6），**收益验证需要带逐束时间戳 + 好里程计
  的数据**——现代雷达协议自带逐束时序，Gazebo 仿真可注入真值。
  这就是"评估告诉你什么不能下结论"的活例子。

## 路线图

- 轨迹级动态确认（多帧簇位置一致性 → 跟踪）
- ROS 节点 + Gazebo 在线链路（对齐 mini_slam 的 launch 结构；
  deskew 的收益验证需要仿真的逐束时序 + 真值运动）
- 强度通道滤波（玻璃/镜面/粉尘按强度分）
- 把清洗后的扫描喂 `icp::align` 与原始扫描对拍：清洗对配准精度
  的定量收益——本链路存在的最终意义
