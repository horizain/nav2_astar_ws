# 01 定位模式：图冻结的位姿跟踪

对应 slam_toolbox 的 localization 模式（`mode:=localization`）：
机器人持有一张已建好的地图，只做"我在哪"的连续回答，不再改图。

## 动机

建图模式和定位模式对系统的要求完全相反：

| | 建图模式 | 定位模式 |
|---|---|---|
| 图 | 每帧可能加节点/边 | **冻结** |
| SPA | 闭环时触发 | 不触发 |
| /map | 周期性重绘 | 不发（由 map_server 提供） |
| 输出 | 地图 + 轨迹 | 稳定的 map→odom TF |

如果用建图模式跑定位，会发生三件坏事：节点数无限增长（内存）、
每次闭环重摆历史位姿（TF 抖动）、重绘地图（浪费）。

## slam_toolbox 的做法

localization 模式下它仍然维护一个"局部图"：新扫描匹配进地图但不把
节点交给全局优化器，代价图只覆盖局部窗口。这是为了吸收局部漂移。
我们的 v1 实现更简单：**完全冻结图，纯匹配跟踪**。漂移由里程计质量
决定（仿真近乎零漂移；`test_localization` 实测最大跟踪误差 7.1cm）。

## 我们的设计

```
Mapper::localize(scan, odom):
  1. 先验 = 上次修正位姿 ⊕ (上次定位里程计⁻¹ ∘ 当前里程计)
     —— 首帧直接信任里程计（调用方保证起点一致）
  2. 参照场 = 定位窗口(localization_window=10m)内所有建图节点的扫描
  3. correlative 匹配（窗口 = 顺序匹配 ×2，允许吸收重启位姿差）
  4. response ≥ loc_min_response(0.15) → 采纳修正位姿
     否则 → 退回先验，valid=false（调用方自行决定是否报警）
  5. 更新跟踪状态（last_loc_pose / last_loc_odom），图不动
```

关键代码：
- `core/src/mapper.cpp` 的 `Mapper::localize()`
- `ros/mini_slam_node.hpp` 的 `worker_loop` / `process_one`：扫描先在
  `scan_callback` 入队，worker 再按 `mode` 分发；定位模式下 TF 直接由
  `修正位姿 ∘ 里程计⁻¹` 构造，`publish_map()` 在 localization 模式直接
  返回（不发 /map，地图由 map_server 提供）。

## 启动与初始化

- **自动加载**：`graph_path` 非空时，节点在创建订阅/timer/worker 之前
  加载该图。mapping 模式加载失败只打 WARN 并以空图继续；localization
  模式加载失败会抛 `std::invalid_argument`，进程打印 FATAL 后退出——不会
  带着空图假装在定位。
- **空图启动**：localization 模式未设置 `graph_path` 时打 WARN：图加载前
  `localize` 会退回里程计，可稍后调用 `load_graph` 或发布 `/initialpose`。
- **`/initialpose`**：只在 localization 模式且图非空时生效；位姿会先按
  `header.frame_id → map_frame` 做 TF 变换，时间戳用消息自带的
  `header.stamp`（为 0 时退回 `now()`），并立即更新 map→odom TF 快照，
  不等下一帧扫描。
- **TF 时间戳**：`publish_tf()` 使用"最近一帧实际处理完的扫描时间"
  （latest processed scan timestamp），mapping/localization 都记录；候选
  时间小于上次已发布值时沿用旧值（单调保护），还没有任何时间戳时不发 TF。
  `header.stamp` 不再用 `now()` 给 TF 打戳。

## 验证（test_localization.cpp）

1. 建图阶段：合成世界走 1.5m 方形环路 → 12 节点入图
2. 切定位模式：重走同一环路（里程计加 2cm 重放噪声）
   - 24 帧全部 valid，跟踪误差 max **7.1cm**
   - 节点数保持 12 不变（图冻结 ✓）
3. 传送门测试：里程计先验瞬移到场外 → valid=false，位姿退回先验

## 踩坑

- 单测环路边长从 1.0m 放大到 1.5m：1m 环路只有 8 个节点，凑不满
  "节点数 > 10" 的断言——**小场景测试别忘了节点密度**。
- "场外定位退回先验"的断言最初写成 1e-6：先验是"上次位姿 ⊕ 增量"
  的组合结果，与传送目标差厘米级——断言要测语义（"没乱跳"）而不是
  位相等。
