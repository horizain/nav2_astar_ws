# 02 位姿图序列化：让 SLAM 结果"活"过断电

对应 slam_toolbox 的 `serialize/deserialize`（.posegraph 文件）。
没有序列化，SLAM 的产出只有一张栅格图；有了它，**位姿图本身成为资产**——
可以恢复继续定位、离线分析、分享给别的机器。

## 为什么"只存栅格图"不够

栅格图（pgm）回答"世界长什么样"，但丢失了：
- 每帧扫描的原始点云（定位模式建匹配场必需）
- 位姿图的边与信息矩阵（恢复后还能继续优化）
- 节点间的拓扑关系（闭环结构）

所以序列化必须存**图 + 扫描点云**，这正是 slam_toolbox .posegraph
文件的内容构成。

## 格式设计（MINISLAMGRAPHV2）

```
magic[16] "MINISLAMGRAPHV2"
u32 顶点数 N
N × { id, odom位姿, map位姿, 有无扫描, [扫描时间戳, 点数, 点×(x,y)] }
u32 边数 M
M × { from, to, 相对观测z, info_x, info_y, info_theta, 是否闭环 }
```

V2 的 `info_x/info_y` 是世界（map）坐标系轴向的平移信息；读取时仍兼容
V1：V1 的各向同性 `info_xy` 会展开成 `info_x = info_y = info_xy`。

设计取舍：
- **扫描点云跟图走**：定位模式建匹配场需要扫描点云，光存位姿恢复不了定位。
- **odom 位姿与 map 位姿都存**：map→odom TF 依赖两者（定位重启时的先验链）。
- **本机字节序直写**：教学实现优先简单，跨架构交换应改为定长小端编码。
- 顶部 magic + 数量上限校验：坏文件返回 `std::expected` 的错误而不是崩溃。

## 节点层用法与 `graph_path`

`save_graph` / `load_graph` 都是 `std_srvs/srv/Trigger`，不带路径参数；
路径统一来自节点参数 `graph_path`（为空时默认 `mini_slam_graph.mmpg`）。
因此：

- **启动**：`graph_path` 非空时节点自动加载；mapping 模式失败只 WARN 并
  以空图继续，localization 模式失败抛错退出。
- **运行期**：`ros2 param set /mini_slam_node graph_path <path>` 只改变
  后续 save/load 的默认路径，**不会立即加载**；要加载需再调用
  `load_graph` 服务。
- **加载后状态**：`Mapper::load_graph` 会 `rebuild_index()`，清零统计与
  定位跟踪状态；节点层同时清空旧 map→odom TF 快照并使地图渲染缓存失效，
  旧图的状态不会残留到新图。

## 关键代码

- `core/src/serialization.cpp`：save/load 的 POD 直写直读
- `core/src/mapper.cpp` 的 `Mapper::save_graph / load_graph`：
  load 后 `rebuild_index()`（空间索引重建）并清零统计与定位跟踪状态

## 验证（test_serialization.cpp）

1. 建图（11 节点 / 65 边）→ 保存 → 加载 → 顶点位姿、扫描点数、边结构
   **逐位对账**（误差 < 1e-12）
2. 加载的图直接跑定位模式：单帧扫描定位到建图轨迹中段，误差 < 0.15m
3. 垃圾文件 → `expected` 返回明确错误，不崩溃

## 踩坑

- `load_graph` 与 `Mapper::load_graph` 是两个东西：前者返回图对象，
  后者还负责重置统计/定位状态——包装层签名是 `(path, err*)`，
  底层是 `(path)` 返回 expected，写测试时别混用。
