# 04 图连通链：karto 式闭环候选搜索

对应 libkarto 的闭环候选机制：候选不是"半径内的散点集合"，而是
"从最近空间邻居出发、沿图边 BFS 得到的**拓扑连贯轨迹段**"。

## 动机：空间邻居集合的缺陷

两条平行走廊相距 1m 时，站在走廊 B 中段做半径查询，会把走廊 A 的节点
也抓进候选。用这样的集合建匹配场，得到的是"两个世界的叠加"，匹配得分
再高也不代表真实闭环。测试用例（test_connected_chain.cpp）构造了 exactly
这个场景：

```
走廊 A：id 0-49，y=0      ┌──────────── corridor A ───────────┐
走廊 B：id 50-99，y=1.0   └────── corridor B（1m 之下）───────┘
空间查询 1.5m：A=5, B=5    ← 跨走廊污染实锤
连通链 from B：只有 B 的节点  ← 拓扑连贯
```

## 设计

PoseGraph 维护双向邻接表（add_edge 时同步维护），新增：

```cpp
connected_chain(seed, max_nodes, max_depth, exclude)
  // 从 seed 沿边 BFS：闭环边也算一跳（它正是连通远处的关键）
```

Mapper::try_loop_close 的候选流程升级为：
```
空间种子（半径 3m + 时间间隔 ≥20 帧）→ 取最近种子
→ BFS 连通链（≤ 3×chain_size 节点，深度 6 跳，排除当前节点）
→ 链上过滤：距离 ≤ 2×loop_search_distance 且 时间间隔 ≥20 帧
→ 链大小 ≥ loop_min_chain_size 才进入匹配
```

注意：BFS 必须允许穿过**闭环边**——旧闭环正是把远处的旧轨迹连通进
候选的关键路径。

## 验证（test_connected_chain.cpp）

- 平行走廊场景：链 from B 不混入 A ✓，链沿走廊延展 ≥10 节点 ✓
- 空间查询对照：同位置抓到 A=5/B=5（证明污染真实存在）✓

## 踩坑

- BFS 深度 6 只覆盖 ±6 节点（0.5m 间隔 → 13 个），链大小断言
  需要与深度匹配——深度和链长是两个独立旋钮。
