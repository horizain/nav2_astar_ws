# 07 参数体系与服务接口：把能力暴露成可操作的工具

对应 slam_toolbox 的运行时接口：`serialize_map/deserialize_map` 服务、
`mode` 切换、几十个可调参数。

## 执行器与 TF 线程模型（生产入口）

`ros/mini_slam_node.cpp` 用多线程执行器，不再是单线程 `rclcpp::spin`：

```cpp
rclcpp::executors::MultiThreadedExecutor exec(rclcpp::ExecutorOptions(), 4);
auto node = std::make_shared<MiniSlamNode>();   // 构造抛异常就不 add_node
exec.add_node(node);
exec.spin();
```

构造失败（非法启动参数等）仍走 FATAL + 退出码 1 的路径。

`TransformListener` 用 `spin_thread=true`：tf2_ros 会为 `/tf`、`/tf_static`
建**独立 callback group + 独立 SingleThreadedExecutor + 专用线程**，并自行
`buffer_.setUsingDedicatedThread(true)`（所以节点里不再手工设置这个标志）。

为什么必须这样：`scan_callback` 做外参 TF lookup 时最长等 20ms。旧写法
（`spin_thread=false` + 默认 callback group）下，等待的 scan 回调占住了唯一
能处理 `/tf` 的执行器线程，TF 即使已经在队列里也进不了 buffer。实测
（`test_node_concurrency` 的"动态 TF 晚于扫描 5ms 到达"用例）：

| 配置 | 20 帧中处理成功 |
|---|---|
| `spin_thread=false`（旧） | 0 帧（每帧都 `Lookup would require extrapolation`） |
| `spin_thread=true`（现） | 20 帧 |

注意 rclcpp 语义：节点默认 callback group 是 MutuallyExclusive，所以
scan/odom/服务/参数/timer 之间**仍然串行**（多线程执行器只是提供了并行能力）。
真正的并发来自三条独立线程：main executor、TF 专用线程、worker。

锁顺序（Phase 4A 复核，无反向嵌套）：

- `publish_map()`：先 `map_cache_mutex_` → 再 `mapper_mutex_`；
- `publish_tf()` / 服务 / 参数回调 / `initialpose_callback` / `process_one()`：
  只取 `mapper_mutex_`；
- marker timer / marker feedback（Phase 4C）：都只取 `mapper_mutex_` 做图操作，
  且都在**释放后**才调 `InteractiveMarkerServer`。注意库会在**持有自己递归锁**
  时分发 feedback 回调，所以 feedback 路径的实际顺序是
  `server.mutex_ → mapper_mutex_`；timer 路径是 `mapper_mutex_`（快照）→
  释放 → `server.mutex_`。timer 从不在持有 `mapper_mutex_` 时碰 server，
  因此无环；
- `scan_callback`：`odom_mutex_`（取 odom）→ `proc_mutex_`（入队），两把锁
  不嵌套持有；
- `worker_loop()`：`proc_mutex_` 只在出队时短暂持有，出锁后才进
  `mapper_mutex_`；
- 参数回调里重建 timer 放在释放 `mapper_mutex_` 之后（避免"回调等锁 /
  重建等回调"）。
- TF 专用线程只写 tf2 buffer，不碰上面任何一把锁。

## 设计

### 运行时切模式（图保留）

```
ros2 param set /mini_slam_node mode localization   # 建完图切定位
ros2 param set /mini_slam_node mode mapping        # 切回建图
```

实现：`add_on_set_parameters_callback`（Jazzy 签名是
`const std::vector<rclcpp::Parameter>&`，不是单参数——版本坑）。
切换时**图保留**：mapping↔localization 只是 Mapper 状态位的翻转，
定位模式不发布 `/map`（地图交给 map_server）。

### 图的保存/加载服务

```
ros2 param set /mini_slam_node graph_path ~/maps/lab.mmpg
ros2 service call /mini_slam_node/save_graph std_srvs/srv/Trigger
ros2 service call /mini_slam_node/load_graph std_srvs/srv/Trigger
```

路径统一走 `graph_path` 参数（避免自定义 srv 文件；Trigger 的 message
字段回传结果与错误信息）：

- **启动时自动加载**：`graph_path` 非空 → 节点在订阅/timer/worker 之前
  加载该图。mapping 模式失败只 WARN 并以空图继续；localization 模式
  失败直接抛 `std::invalid_argument`，节点 FATAL 退出。
- **运行时修改 `graph_path`**：只改变后续 `save_graph` / `load_graph`
  的默认路径，**不会立即加载**；要加载必须再调用 `load_graph`。
- 服务不带路径；`graph_path` 为空时默认文件是 `mini_slam_graph.mmpg`。
- `load_graph` 成功后：`rebuild_index()`、清空旧 map→odom TF 快照/定位
  跟踪状态，并使地图渲染缓存失效。

### 状态服务

```
ros2 service call /mini_slam_node/get_stats std_srvs/srv/Trigger
→ message: "模式=mapping 扫描=922 节点=116 闭环=12 SPA=12 点云=7422"
```

### TF 与 `/initialpose`

- `publish_tf()` 使用 **latest processed scan timestamp**：mapping 和
  localization 模式在每帧真正处理完后记录该扫描的 `stamp`；TF 用它打戳，
  不用 `now()`。
- `/initialpose` 成功受理后立即更新 TF 快照，时间戳用消息自带的
  `header.stamp`（为 0 时退回 `now()`）。
- 单调性保护：候选时间小于上次已发布值时沿用上次的值，避免
  `TF_OLD_DATA`；还没有任何时间戳时不发布 TF。
- `/initialpose` 只在 localization 模式且图非空时生效。

### 扫描外参与 TF 失败策略

- `scan_callback` 按 `header.stamp` 把端点从 `scan.frame_id` 变到
  `base_frame`；只取平面 x/y/yaw，z/roll/pitch 投影掉（2D SLAM 不做三维修正）。
- `scan.frame_id` 为空或已经等于 `base_frame` 时视为无外参（恒等）。
- `lookupTransform` 失败：**丢弃该帧**，不静默当恒等继续算；用
  `WARN_THROTTLE` 5s 限频告警（target/source/原因）。
- `/initialpose` 的 `frame_id` 不是 `map_frame` 时同样按消息时间戳变换；
  失败则丢弃并限频告警。

### 地图发布与输出

- `publish_map()` 渲染用 `Params::map_range_max`（不是 `scan_range_max`：
  后者只控制匹配/入图的最远点）。
- 渲染缓存键：mode、图顶点数、边数、`stats.nodes/solves`、
  resolution、map_range_max、map_margin、map_output_prefix，另加
  `/load_graph` 递增的 generation。**不包含 `stats.scans`**：它每处理
  一帧扫描就 +1，放进去会让秒级 map timer 每个周期都 miss。命中时直接复用上次渲染好的
  `OccupancyGrid`（shared_ptr 快照，锁外发布），不复制图、不重渲染。
- **Phase 4B 增量渲染**：缓存未命中时不再无条件全量渲染，而是走
  `IncrementalMapBuilder::update()`：
  - **增量路径**（只追加顶点，且新扫描不改变地图 origin/width/height）：
    只对 `[applied_vertices_, graph.size())` 的新顶点做射线更新，历史扫描
    直接复用已有 log-odds 栅格；随后只重算 `-1/0/100` 阈值转换
    （O(地图格数)，不重算历史射线）。
  - **全量重建路径**：`force_full`（`/load_graph` 导致 generation 变化）、
    首次渲染、resolution/map_range_max/margin 变化、
    `pose_revision()` 变化（SPA 重摆位姿、手动改位姿、`set_scan` 稀疏化）、
    顶点数回退（换图）、新扫描导致地图边界扩张。
  - 边界扩张时**不做格子搬移**（会引入重采样误差），直接全量重建。
    因此增量结果与 `MapBuilder::render()` 在 resolution/origin/width/height/
    data 上逐位一致。
- `PoseGraph::pose_revision()` 是增量失效信号：`set_scan()` 自动递增；
  SPA 求解后与 `load_graph` 成功后由 `Mapper` 显式递增；
  `add_vertex`/`add_edge` 不递增（新增顶点由顶点数发现）。
- `map_output_prefix` 非空时输出 `<prefix>.png/.meta/.pgm/.yaml`；
  YAML 是 map_server 格式（`image` 指向 PGM basename）。每个文件先写
  `.tmp` 再 rename，YAML 最后写——注意这是**逐文件原子替换**，不是
  整套文件的事务。仅缓存未命中时写文件；命中但目标 `.yaml` 不存在时
  会从缓存补写一次。
- `header.stamp` 仍是 `now()`：地图是"当前发布时刻"的快照，不是扫描时刻。
- 线程约束：`IncrementalMapBuilder` 只在 `map_cache_mutex_` 内访问，
  不引入新的 `mapper_mutex_` 依赖；渲染仍在 `mapper_mutex_` 之外进行。

### 参数表（节点实际声明）

| 参数 | 默认 | 运行时可改 | 说明 |
|---|---|---|---|
| mode | mapping | ✅ | mapping / localization |
| graph_path | "" | ✅ | 启动时自动加载；运行期修改只影响 save/load 默认路径 |
| map_output_prefix | "" | ✅ | 地图输出前缀；空 = 不写文件 |
| map_update_interval | 5.0 | ✅ | /map 发布周期 (s)，改后重建 timer |
| transform_publish_period | 0.05 | ✅ | map→odom TF 周期 (s)，改后重建 timer |
| processing_queue_size | 10 | ✅ | 异步处理队列长度 |
| resolution | 0.05 | ✅ | 栅格/匹配场分辨率 (m) |
| minimum_travel_distance | 0.5 | ✅ | 平移超过才入图 (m) |
| minimum_travel_heading | 0.5 | ✅ | 转角超过才入图 (rad) |
| scan_range_max | 12.0 | ✅ | 匹配/入图用的最远点 (m) |
| loop_search_maximum_distance | 3.0 | ✅ | 闭环候选空间半径 (m) |
| loop_match_minimum_chain_size | 10 | ✅ | 候选链最小帧数 |
| loop_match_minimum_response_coarse | 0.40 | ✅ | 粗匹配得分阈值 |
| loop_match_minimum_response_fine | 0.50 | ✅ | 细匹配得分阈值 |
| sparsify_enabled | false | ✅ | 地图稀疏化开关 |
| sparsify_keep_radius | 0.8 | ✅ | 保留点铺点间距 (m) |
| sparsify_min_keep_recent | 50 | ✅ | 最近 N 帧永不剪枝 |
| sparsify_every | 50 | ✅ | 每 N 个节点跑一次剪枝 |
| localization_window | 10.0 | ✅ | 定位参照场半径 (m) |
| enable_interactive_markers | false | ❌ | 交互式 marker（RViz 拖拽节点）总开关，启动期决定是否创建 server，运行期拒绝修改 |
| interactive_marker_max_vertices | 200 | ✅ | 最多显示的可拖拽节点数（≥1）；超出后均匀抽样 + 保证含最新节点 |
| scan_topic | scan | ❌ | 绑定订阅，运行时拒绝修改，需重启 |
| odom_topic | odom | ❌ | 同上 |
| map_frame | map | ❌ | 绑定 TF 树/发布帧，需重启 |
| odom_frame | odom | ❌ | 同上 |
| base_frame | base_footprint | ❌ | 扫描外参目标帧，需重启 |
| use_sim_time | false | — | rclcpp 内置参数；启动前用 launch/`--ros-args` 设置 |

未声明为 ROS 参数的 core 默认值：`map_range_max=10.0`、`map_margin=1.0`
（地图渲染用；目前只能改代码/默认值）。

启动期会集中校验全部参数（非法值带参数名抛出，节点直接退出）；
`scan_topic` / `odom_topic` / `map_frame` / `odom_frame` / `base_frame` /
`enable_interactive_markers` 在运行期会明确返回 `successful=false` 与
"运行时不支持修改，请通过 launch 参数重启节点"，而不是接受后静默不生效；
`interactive_marker_max_vertices` 运行期可改（必须 ≥ 1），下一个 marker timer
周期（0.5s）生效。

## 跨进程 `ros2 param set` 验证（CLI 层）

进程内 `node->set_parameter()` 只验证回调逻辑；"另一个进程的 `ros2` CLI
能不能发现节点、拿到参数服务、触发同一条回调"是另一条链路（DDS 发现 +
`ros2param`）。回归测试：`ros/tests/test_param_cli.sh`（ctest 名
`test_param_cli`，CMake 传 `$<TARGET_FILE:mini_slam_node>`）。

### 本机可用/不可用的发现配置（WSL2 + Jazzy，实测）

| 配置 | 结果 |
|---|---|
| 默认 `rmw_fastrtps_cpp`，任意 domain | 跨进程发现全失败：`ros2 node list` 为空，param 报 `Node not found` |
| fastrtps + `ROS_LOCALHOST_ONLY=1` / `LOCALHOST` / `ROS_STATIC_PEERS=127.0.0.1` | 仍然失败 |
| `rmw_cyclonedds_cpp` + `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` | `node list` 能看到节点，但 `param list/get/set` 报 `Wait for service timed out waiting for parameter services` |
| **`rmw_cyclonedds_cpp` + `ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET` + 独立 domain** | **可用**（node list / param list / set / get 全部正常） |

所以"Node not found"不是节点参数服务没起（`ros2 service list` 里
`/mini_slam_node/set_parameters` 一直都在），而是本机 Fast DDS 的跨进程发现
在这个网络命名空间里不通。脚本因此显式钉住：

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export ROS_DOMAIN_ID=95              # 测试专用，避免撞上正在跑的节点
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
unset ROS_LOCALHOST_ONLY            # 已弃用，且和上面的组合互斥
```

手工验证（与脚本同一套环境）：

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp ROS_DOMAIN_ID=95
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
ros2 run mini_slam mini_slam_node &          # 或 build/mini_slam_node
ros2 node list                              # /mini_slam_node
ros2 param list /mini_slam_node
ros2 param set /mini_slam_node minimum_travel_distance 0.7   # Set parameter successful
ros2 param set /mini_slam_node loop_match_minimum_response_coarse -1.0  # Setting parameter failed: ... 必须在 [0,1]
ros2 param set /mini_slam_node scan_topic scan2              # Setting parameter failed: ... 运行时不支持修改
```

脚本覆盖：20s 内看到节点、`param list` 可见、合法值 set+get 读回 0.7、
越界值被拒绝且原值不变（0.4）、`scan_topic` 被拒绝且提示"运行时不支持修改"、
`scan_topic` 原值不变；失败时打印 `node list` / `param list` / 节点日志并把
退出码置为 1。

**坑**：`ros2 param set` 在参数被回调拒绝时**返回码仍是 0**（ros2cli 行为），
所以脚本必须断言输出文本（`Setting parameter successful` /
`Setting parameter failed`），不能只看 `$?`。

## 诚实边界

slam_toolbox 的 **interactive SLAM** 在本仓库只复刻了"能力层 + 标准
InteractiveMarkers 拖拽"（见 [08 交互式建图](08_交互式建图.md)）：拖动单个
节点 → 固定该节点 + node0 重跑 SPA → 重建索引/地图。自研 RViz panel、
子图整体拖拽、撤销栈、交互式闭环确认都没有做——那些是 UI 工程，与算法语义
无关。

## 踩坑

- Jazzy 的 `add_on_set_parameters_callback` 回调签名是
  `std::vector<rclcpp::Parameter>`——网上大量老教程是单参数版本，直接抄会
  编译失败。
- 服务用 Trigger 而不是自定义 srv：省去 msg/srv 生成链；代价是路径要
  走参数传递（先 set param 再 call）。
- 改 `map_update_interval` / `transform_publish_period` 会重建 timer。
  重建必须放在释放 `mapper_mutex_` 之后：timer 回调可能正在等锁，持锁
  重建会形成"回调等锁 / 重建等回调"的死锁。
- TF 用扫描时间戳而非 `now()`：仿真/回放中 `now()` 容易领先数据时间，
  造成外推和 `TF_OLD_DATA`。
- 单线程 `rclcpp::spin` + `TransformListener(spin_thread=false)` 是隐藏的
  丢帧来源：scan 里带 timeout 的 `lookupTransform` 把 TF 回调堵在同一条
  执行器线程上，等待必然超时。改成多线程执行器 + TF 专用线程后解决
  （见上文实测 0/20 → 20/20）。
- 跨进程 `ros2 param set` 报 `Node not found` 时先怀疑 RMW 发现而不是节点
  参数服务：本机 Fast DDS 不通、Cyclone + SUBNET 通（见上表）。
